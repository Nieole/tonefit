# 装配与管线

## 负责

**次序只在这一处说。** 哪个环节先走、检查点与确认点问在哪儿、环节之间递什么，由 `run` /
`process_volume`（`lib.rs` 根）一处说了算；`pipeline` 里的每个环节只管自己那一截。

入口是 `Request`，出口是 `Report`。命令行与会话都只是它之上的薄层。

## 定点

- **所有模式走同一个入口。** 转换与预览是同一个 `run`，区别只在 mode：预览只算不写——画质分照求、
  报告照出，**输出**（页、记录、输出容器）一个都不落盘。开工前探输出目录那一下不在里面：探针探完就删。
  **拒绝开始**说的是**参数**，两种模式的参数是同一份，那几种拒绝在预览里照样咬人——预览要是答不出
  「你这个输出目录根本用不了」，那份报告就在撒谎。
- **一卷走过三段**：幂等这一道 → 分析环节 → 汇总（只在 `--envelope` 那条路上在场）→ 写出环节。
- **两个检查点与一个确认点各管一件事**：检查点问「这一趟还走不走」（卷边界那个管做完再停，
  页边界那个管立即停止）；确认点问「这一卷的写出环节还做不做」，每卷一次（ADR 0013、ADR 0012）。
  分析环节里按下的做完再停不替用户回答确认点。
- **拒绝开始发生在开工之前**，一页都不做：处理范围为空、输出落在源里、输出目录写不进去、
  两样东西撞同一个去处、点名的路径点不开。例外只有一个：覆盖项把候选集裁空时，抖动那一维要真撞上
  那一页才拦得住，那时先做完的卷已经在盘上。
- **清点之后才出的错记为卷转换失败**，其余卷照做、报告照出——它指得出是哪一卷、也说得出为什么。
- **含坏页的卷整卷写进隔离目录**（输出目录下的 `_isolated/`），容器形态照旧；隔离过的卷不被跳过。
- **立即停止掉的那一卷不进报告**，最终位置上一个字节都没动过——下一趟幂等因此不会误判它做完了。
- **请求是快照**：`Request` 在起线程那一刻定住，改了不影响正跑的那一趟。
- **`cost` 是另一件量具，只在 `profiling` 特性下存在**：按阶段（解码、转灰、裁白边、缩放、画质分、
  量化、编码）累计各线程墙钟之和，只印到 stderr。它不是卷级计时——那是产品输出，按段分、进报告——
  两者不许合流。闸门第三条（`--features profiling`）是它唯一的编译覆盖。

## 边界

- 不实现任何环节，只排它们；环节的边界与理由写在各自的模块上。
- 不印字、不碰终端：进度交给观察者，文字交给[界面层](cli.md)。

决定出处：ADR 0012、ADR 0013。
