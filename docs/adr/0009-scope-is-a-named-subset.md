# ADR 0009：处理点名的子集，介质按路径探测

状态：已采纳（2026-08-25）；决定第 1 条修订（2026-09-03，点名的路径展开成一批卷，见 ADR 0014）

## 背景

tonefit 的输入是别处管理的漫画库。库的组织、命名、增删由用户和他的其它工具负责，
tonefit 不是库管理器：它拿到一批页，产出一批适配某块面板的页。
一次调用的作用域是卷——一个目录或一个归档。用户点名要处理哪些卷。

I/O 策略不能按机器一次性决定。机械盘上并发随机读会互相打断寻道，
吞吐反而低于串行；固态盘上并发是纯收益。而一台机器的存储是混合的，
同一次运行里，源卷可能在机械盘的仓库盘上，输出目录可能在系统固态盘上。
「这台机器是 HDD 还是 SSD」 这个问题没有答案。

## 决定

1. **处理范围是用户点名的子集。** 不做全库扫描，不维护全库索引，不监听文件系统事件。
   源库只读——tonefit 从不改写、移动或删除源文件，输出是写到别处的设备优化副本。

   点名的是**在哪里找**，不是**找到什么**：一个点名的路径展开成它底下的那一批卷
   （ADR 0014），发现只在那棵子树里走。范围仍是用户界定的——他点名哪里，
   tonefit 就只看哪里；他不点名的地方，一个字节都不读。
2. **介质探测按路径进行。** 给定一个路径，先解析到它所在的卷/挂载点，再查该卷的寻道惩罚，
   据此决定这条 I/O 通道的并发度。同一次运行里不同路径各自判定，互不影响。
3. **NAS 与网络路径按未知处理**，取保守并发度，不假装它是本地盘的某一种。

## 后果

**好的：**

- 每次运行的工作量由用户界定，冷启动即可用，不需要先建库。
- 源库只读消除了整类破坏性失败，用户不必备份就敢试。
- 跨盘运行不再被最慢的那块盘的策略拖累。
- 断点续传与增量扫描从「必需」降为「有用」：重跑一个点名的子集是分钟级的事，
  不是要靠状态数据库才敢做的事。

**要认的代价：**

- 用户要自己知道**哪里**有该处理的卷。点名一个目录就把它底下的卷全找出来（ADR 0014），
  因此这笔负担落在「点哪几个地方」上，不是「点哪几个卷」上。
- 按路径探测要缓存（每页查一次挂载表不可接受），缓存就有失效问题：
  运行期间挂载点变化、符号链接与 junction 跨卷、容器内的绑定挂载都会让探测结果失真。
- **NAS 的最优策略尚未测量。** 它既不是 HDD 也不是 SSD，保守并发度多半留了性能在桌上。
- 幂等仍需自己保证：输出 PNG 写入 tEXt 自描述元数据，重跑时据此跳过没变的卷
  （字段、作用域与跳过的单位见 ADR 0006：位深按卷取上包络并加迟滞）。
  没有它，二次处理会静默累积劣化——对已量化到 2bit 的页再做一次量化与抖动，
  判据看不出问题，眼睛看得出。

## 备选方案

- **全库扫描 + 索引数据库**——库管理器的职责，且要求写权限与常驻进程，与源库只读冲突。
- **watch 模式跟随文件系统事件**——把一次性工具变成常驻服务，收益不抵复杂度。
- **按次运行探测一次介质**——混合存储下必然对一半路径给出错误答案。
- **让用户用命令行开关声明介质类型**——把可自动获知的事实变成用户必答题，且答错无提示。
- **就地覆盖源文件**——省一份存储，但不可逆，且与 tEXt 幂等机制互相削弱。

## 不要做的「简化」

「既然扫描很便宜，默认就把源库根目录整个当作范围，用户不点名时全跑。」
这一步把只读子集工具变回了库管理器：它需要索引来避免重复全跑，
需要断点续传来应付中途失败，需要监听来知道库变没变——本 ADR 关掉的三件事一次性全部回来。
范围为空时报错退出，不要猜。
