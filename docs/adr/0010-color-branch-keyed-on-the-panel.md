# ADR 0010：彩页按 profile 分流，彩色是面板的第四项

状态：已采纳（2026-08-25）

## 背景

ADR 0005 决定第 4 条与 ADR 0006 决定第 5 条都以「彩色 profile 下……」开头，但 P0 里没有彩色 profile 可谈：
面板的主键是分辨率 + PPI + 灰阶数三项，没有地方放「显示不显示彩色」，
spec 的 Out of Scope 又把「Kaleido 彩色面板的专属分支」整个划在范围外。
两篇 ADR 因此各有一半落不了地——彩色分支没有 profile 可挂，代码里写出来也一行跑不到。

另有三件事没有被任何一篇 ADR 说死：彩页按什么判据识别出来、彩页参不参与几何门、彩页什么时候写出去。

## 决定

1. **面板增第四项属性「彩色」，它进主键。** Kaleido 面板与同分辨率同 PPI 的纯黑白 e-ink 是**两块**面板：
   同一卷在它们上面输出不同。内置表随之收 Kaleido 型号。分辨率与 PPI 填**黑白那一层**的规格——
   面板主键、目标尺寸与判据的低通核都由它推出；灰阶数仍是 16，Kaleido 是黑白面板加一层彩色滤光片。

2. **彩页识别有两维判据，两个数都是未标定占位值**：单个像素的**色度幅度**（sRGB 三分量极差）要过一道地板，
   过地板的像素要占到一个**比例**。不取「色度非零」，因为有损转码会给消色像素添上几级色度——
   B 类素材整批是 8bit YUV420 的有损 AVIF（见 measurements 的《B 类素材普查》），照非零判，
   那 97% 的近灰度页会整批被判成彩页。
   《B 类素材普查》的「97% 近灰度，3% 彩色」是**分布**，不是判据形态：那一节没有给出它是怎么数出来的，
   这两个数因此不能说成是从它标定来的。

3. **识别对每一页都做，与 profile 无关；分流才看 profile。** 黑白 profile 下彩页转灰、走与其它页相同的灰度路径
   （ADR 0005 决定第 4 条），但它仍然是一张彩页，`Report` 分得清——
   「这台设备为什么没留住颜色」只有这样才答得出来。

4. **彩色分支上的页不参与几何门。** 门撑的是抖动与面板灰阶那道硬上界（ADR 0007、ADR 0003），
   两者只作用在灰度路径上；彩页既不量化也不抖动，它的几何事实对那两件事没有说话的资格。
   让它关掉整卷的抖动，就是让一条不受影响的路径去削掉另一条路径的收益。
   门因此是**分支的函数**，不是页的常量：同一张彩页在黑白 profile 下转灰走灰度路径，它的几何这时就说了算。

5. **彩页的写出按阅读顺序落位，与灰度页同一遍。这修订 ADR 0005 决定第 4 条的「第一遍即写出」。**
   那一句要保的是彩页**离开灰度管线的时刻**——不进缓存、不求判据、不进上包络，三条原样成立，
   第一遍完成解码、识别、缩放与编码。写出的时刻另有一条约束压着它：
   归档卷的成员按**写入顺序**排，而页名的字典序与阅读顺序本来就对不上（`1` `2` `10`）。
   彩页在第一遍就写进归档，混排卷的成员顺序会变成「先全部彩页、再全部灰度页」，
   按归档顺序翻页的阅读器于是跳着读。归档成员顺序是产品的正确性，内存是效率，正确性优先。

6. **彩色分支只做缩放：不量化、不抖动、没有判据。** 缩放逐通道走灰度那条路径——
   预缩是等权块平均、残差段是卷积重采样，两级都逐通道独立，分平面跑与交织跑逐字节相同。
   编码取真彩色与调色板中体积较小者，与灰度那一侧同一条规则（ADR 0004：调色板模式在编码器接口以内）。

## 后果

**好的：**

- ADR 0005 决定第 4 条与 ADR 0006 决定第 5 条里「彩色 profile 下……」那几句第一次有了可跑、可测的落点。
- 彩页与灰度页的卷级统计彻底分开：`Envelope` 的主体页数与离群页数只数灰度页，驱动页也只可能是一张灰度页。
- 识别与分流分开，一张彩页在黑白设备上的去向在报告里说得出来（spec 的 story 15、16）。

**要认的代价：**

- **越过了 spec 的 Out of Scope。** 那一条写着「Kaleido 彩色面板的专属分支」不在 P0。
  本决定只收了其中最小的一块——面板多一项属性、彩页只缩放不量化——
  Kaleido 真正专属的那些（彩色分辨率折半、CFA 感知的锐化、色域映射、彩色判据）一件都没做，仍在范围外。
- **Kaleido 面板的一切数值尚未测量。** 彩色滤光片让彩色内容的实际分辨率降到黑白层之下（各家口径是一半）。
  P0 的彩色分支只做缩放，这个折减到不了任何判定上；要利用它得先测。
- **彩页识别的两个数未标定。** 地板过低，有损转码的灰度页会被判成彩页，在彩色设备上白付体积；
  过高，淡彩页会被转灰。
- **彩色分支编好的字节要在内存里等到写出那一遍，且不受 `--cache-budget` 约束。**
  那是编码后的 PNG，比参照小；全彩卷上它是峰值内存的主项，而那样的卷灰度缓存正好是空的。
  真要把它纳入预算，得让缓存收字节块而不只是收参照——那是另一次改动。
- **彩色分支上没有判据，也就没有质量下限。** 写出的是缩放结果本身，好坏全看缩放。

## 备选方案

- **不做彩色分支，把两篇 ADR 的彩色那一半挂起。** P0 的内置表本来就没有彩色面板，
  代码里那条分支一行都跑不到，也测不了。不选的理由是它把两篇 ADR 的一半变成无限期的空头承诺，
  而承诺的那件事只要面板多一项属性就成立。
- **彩页在第一遍即写出，照 ADR 0005 的字面。** 省下等在内存里的那些字节。不选的理由在决定第 5 条。
- **只让归档卷推迟写出，目录卷第一遍就落盘。** `Sink::Directory` 没有顺序约束，
  散页输出确实可以当场写完就把字节放掉，峰值内存只在归档卷上多付。不选的理由是它让
  **峰值内存随容器形态而变**：同一卷解包成目录跑与打包成 CBZ 跑，`--cache-budget` 之外的那部分占用不一样，
  而报告里没有一个字解释得了这个差别。真要拿回这块内存，该做的是让缓存收字节块——
  那样两种容器一致，且整个落在 `--cache-budget` 以内。
- **彩页也进灰度缓存，只是不进上包络。** 统一了两条分支的内存账。不选的理由是缓存存的是**参照**，
  而彩页没有参照可存：进去的会是另一种东西，`CacheUsage` 那几个数随之不再是同一个量。
- **只看颜色类型判彩页。** 零成本，一个像素都不用读。不选的理由在决定第 2 条：
  B 类整批是 RGB 编码的有损 AVIF。

## 不要做的「简化」

**「彩色面板就是灰阶数更多的面板」**——把彩色折进 `gray_levels` 的一个更大取值，主键不必动，
`BitDepth::candidates` 那道裁剪顺手就放宽了，`Panel` 一个字段都不用加。

它不成立。灰阶数是**黑白那一层**的物理级数，Kaleido 的黑白层仍是 16 级；彩色是另一个维度，
不是同一把尺上更靠后的一格。折过去之后，灰度页会在彩色面板上被裁出 8bit 候选，
而那一档在黑白层上根本显示不出来——ADR 0003 关掉的正是这个口子。
