# ADR 0015：归档格式认四种，输出一律 `.cbz`，固实的先摊开

状态：已采纳（2026-09-03）；三条决定全部实现，四个格式一个不缺
（`volume-discovery/02`、`05`、`06`）。决定第 1 条**就地修订过一次**
（2026-09-08，`p4-parking-lot/17`）：松的是「这一份是不是另一份的续」这半句，
不是「是哪一种格式」那半句——修订的内容与理由写在那一条自己底下。
《背景》与《后果》里「`.rar` 默认固实」那两句**说法就地订正**
（2026-09-10，`p4-parking-lot/25`；实测：`.rar` 默认不固实），三条决定一格没动。

## 背景

漫画卷在真实的库里不是一种打法。`.cbz` 是阅读器那边的约定，而同一份内容在下载、
转手、重新打包的路上常常就叫 `.zip`——它们是同一种字节，只有扩展名不同。
`.rar` 与 `.7z` 也在流通，尤其是成套的旧资源。

拒绝一个 `.zip` 说不出道理：读它的代码一行都不用改。而收下它之后，输出该叫什么就成了
一个必须回答的问题——输出容器至今是「输入是什么形态，输出就是什么形态」。

`.rar` 与 `.7z` 则是另一件事。两者都**可能是固实归档**：整批成员压成一条连续的流，
取第 N 个成员要从它所在的块头一路解起。而 tonefit 在一卷上要把源字节**读两遍**——
幂等那一道一遍、第一遍一遍（见 `CONTEXT.md` 的《管线》）——按成员随机取的话，
单次是 O(N)、整卷是 O(N²)。

**默认值两边并不相同**（`volume-discovery/06` 造夹具时实测）：`.7z` **默认固实**（7-Zip），
而 `.rar` **默认不固实**——固实要打包时显式打开（WinRAR 的 `-s`）。两个默认值都说不出
真实库里那一批到底固实不固实：那些包多半是别人打的。决定第 3 条因此**不靠默认值站住**，
它按格式一刀切、根本不探；一刀切在非固实的 `.rar` 上白付什么，见《后果》。

## 决定

1. **格式集是四个扩展名**：`.cbz` / `.zip` / `.rar` / `.7z`。**是哪一种格式**只看扩展名、
   大小写不敏感，不去嗅内容——点名的路径是不是一个卷，要在读任何字节之前就答得出
   （撞车查在开工前，见 ADR 0009 与 `crate::run`）。

   **「这一份是不是另一份的续」是另一问，那一问看内容。** 分卷 `.rar` 的每一份都叫
   `.rar`：`第01卷.part1.rar` 与 `第01卷.part2.rar` 在名字上分不出谁是谁的续，而一份恰好
   起了 `x.part2.rar` 这个名字的**单份**包与真的续那一份逐字相同。按名字猜，猜错哪一边
   都要付代价：把单份包当成续就把它整个丢掉，把续当成单份包就出两份重名不同的产物、
   其中一份是重复的（那正是修订前盘上发生的事）。因此归档候选这一头多读一次**归档头里
   的分卷标志**（`source::split_part_of`）：续的那几份不成卷，头一份的卷名取
   **分卷序列**的名字（`第01卷`，见 `CONTEXT.md`）。

   **松的只有这半句，另外半句一格没动。** 格式还没认出来之前照旧一个字节都不读——
   这一问只在**已经按扩展名认得是 `.rar`** 之后才问得起；它只读归档头、一个内容字节都
   不解，读取形态因此照旧在打开卷之前就定死了（决定第 3 条）。要认的也只有 `.rar`
   一种打法：`.7z.001`、`.z01`、老式的 `.r00`，续那几份的扩展名根本不在格式集里，
   发现列不出它们，头一份本来就自己成一个卷、跨卷读完。

2. **归档卷的输出扩展名一律 `.cbz`**，输入是四个里的哪一个都不带过来。
   产物是给阅读器的，而 `.cbz` 是那边认的名字。归一发生在「卷名 + 容器形态 → 输出位置」
   那一步，因此**幂等的去处也按归一后的名字算**：`第10话.zip` 与 `第10话.cbz`
   指着同一份输出。

3. **读取形态按格式分，不逐卷探固实与否**：

   | 格式 | 读法 | 理由 |
   |---|---|---|
   | `.cbz` / `.zip` | 今天这条：`by_index` 随机取 | 每个成员各自 deflate，随机取 O(1)，摊开是白付一次全量写盘 |
   | `.rar` / `.7z` | **开工前整卷摊到临时目录**，之后完全按目录卷走 | 固实归档取第 N 个成员要从块头解起，随机取 O(N)、全卷 O(N²)，而源字节读两遍 |

   摊开借**溢写**那套 `tempfile` 机制（`CONTEXT.md` 的《管线》），
   **不新开预算旋钮**：`--cache-budget` 限的是内存，
   磁盘今天没有旋钮，加一个会让「限制占用」这件事有两个说法。摊了多少字节印进那一卷的报告；
   磁盘不够是**卷级失败**，其余卷照做。

   `.rar` 的依赖带 UnRAR 许可（禁止据其反推解压算法），要在 `THIRD-PARTY-NOTICES.md`
   与 `licenses/` 各留一份。`.7z` 取纯 Rust 实现。

三条一次立全，落地分了三张票（`volume-discovery/02`、`05`、`06`）：
`.zip` 与输出归一在 `02`，`.7z` 与摊开那条路在 `05`，`.rar` 与它那份许可在 `06`。
拒绝那句话报的是**格式集自己**（`source::listed_archive_extensions`），
今天那句话报的是 `.cbz / .zip / .rar / .7z`。

## 后果

**好的：**

- 一个 `.zip` 直接就能跑，用户不必先改名——而改名这件事，工具做得比人可靠。
- 输出名只取决于卷名。「看着输出认得出是哪一卷」这条约定因此在四种输入下同形，
  幂等也不必知道上一趟的源是怎么打的包。
- 固实那两种格式的代价被**关在一处**：摊开一次之后，下游看到的就是一个目录卷，
  读取层、缓存、幂等、隔离没有一处需要认识「固实」这个概念。
- 读法按格式定，因此**在打开卷之前就定得下来**——不必先解一遍才知道该怎么解。

**要认的代价：**

- 归一带出一种新的撞车：同一目录下的 `第10话.zip` 与 `第10话.cbz` 落到同一个去处。
  这道拒绝与卷名撞车共用一处（`crate::run`），但**措辞要分得开**：卷名撞车分批处理就绕过去了，
  这一对不行——它们的卷名本来就相同。
- 摊开要磁盘。一卷几百兆的 `.rar` 在处理它的那一段里，临时目录上就压着几百兆，
  而这件事没有旋钮可调。
- 按格式一刀切，非固实的 `.rar` 也照样摊开，白付一次全量写盘。**非固实正是 `.rar` 的默认**
  （见《背景》），这一笔因此未必是少数情形——要不要为它回到《备选方案》里
  「逐卷探固实与否」那一条，记在 `CONTEXT.md` 的《尚未确立》。
- UnRAR 许可是一条真实的分发约束，不是形式：它跟着二进制走。
- 每一个 `.rar` 候选**多开一次归档头**（决定第 1 条修订带来的那一次）。这一笔换回来的
  比它大：续的那几份从此连预扫都不开，而从前每一份都要被 UnRAR 整套列一遍。

  **这一次开头顺带推翻了上一条原先给的理由。** 它原先写着「逐卷探固实与否要先读一遍
  归档头，而那正是这条决定想省掉的那一次」——`.rar` 那一头从此开都开了，而固实那一位
  （`ArchiveFlags::SOLID`）就在同一个头里，一分钱不多花。决定第 3 条**照旧按格式分**
  （`p4-parking-lot/17` 不动它，票面写着「固实与否仍不探」），但它在 `.rar` 上剩下的理由
  只有《备选方案》里那一条：**两条读取路径都要留着、都要测**，而收益只落在
  「关掉了固实的 rar」这一小撮上。要不要因此改口，是另一张票的事（停车场 Q332）。

## 备选方案

- **只认 `.cbz`**——今天的做法。代价是把一件工具做得比人可靠的事（改扩展名）退回给用户，
  而 `.zip` 与 `.cbz` 的读取代码是同一份。
- **输出跟着输入的扩展名走**（`.zip` 进 `.zip` 出）——省掉归一那道撞车，代价是产出一批
  阅读器不认的名字，而那正是这个工具存在的理由。
- **嗅内容而不看扩展名**——认得更准，但要在「这是不是一个卷」这个问题上先读字节，
  而撞车查在开工前、一个字节都还没读。
- **续不续也按名字认**（末级分量像 `.partN` 就当它是续的那一份）——省掉那一次开归档头，
  代价是一份恰好这么起名的单份包被整个丢掉，而它在盘上一个字节的产物都不会有。
  名字是用户起的，内容是打包器写的；这一问的答案在后者手上。
- **`.rar` / `.7z` 也按成员随机取**——不写临时文件，代价是整卷 O(N²)，
  一个几百页的卷上这不是常数差别。
- **逐卷探固实与否，非固实的走随机取**——省掉一部分摊开，代价是两条读取路径都要留着、
  都要测，而收益只落在「关掉了固实的 rar」这一小撮上。
- **给摊开单开一个磁盘预算旋钮**——说得通，但「限制占用」这件事会有两个说法，
  而用户分不清哪一个管哪一半。

## 不要做的「简化」

**「既然 `.zip` 与 `.cbz` 是同一种字节，撞车时自动挑一个就好了。」**
挑哪一个都是替用户做决定，而两份包的内容并不保证相同——一份可能是另一份的旧版。
撞车一律拒绝，理由与那道拒绝自己写着的「不替用户改名」是同一条（见 `crate::run` 的
`ensure_no_two_volumes_share_an_output`）：静默地挑一个，用户看着输出认不出是哪一份。

**「摊开既然要写盘，顺手把 `.cbz` 也摊开，下游就只剩一种容器了。」**
那是给每一卷白付一次全量写盘，而 `.cbz` 的随机取本来就是 O(1)。
统一的是**读取层看到的形态**，不是磁盘上的形态——收敛点在 `crate::source::Volume`，
不在临时目录。
