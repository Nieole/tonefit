# ADR 0020：输出容器只有目录与 CBZ

状态：已采纳（2026-09-17）

## 背景

今天输出容器的形态**派生自源**：`sink` 的模块文档第一句就是「与源对称：输入是目录就写目录，
输入是归档就写归档」，归档的扩展名再归一成 `.cbz`（ADR 0015 决定第 2 条）。
它不是用户选得动的一维。

提出来要改的有三层，由浅入深：把它变成自由维度（`--container directory|cbz`）；
加别的归档格式（CB7 / CBR）；以及面向阅读器的容器（EPUB / KEPUB / PDF）——
最后这一层的说法是，它能把这个工具从图像转换器变成电子墨水漫画发布工具。

三层都要先过同一道测量。《真机像素完整性》在 BOOX Poke6 与 Kobo Libra 2 上量出：
两台设备的系统自带阅读器都逐像素原样贴；而**要害是缩放系数是不是 1**。同一台机器、同一张图，
换成 KOReader 开着白边裁切，抖动块与同均值实心块「糊成一片，分不开」、1 像素周期光栅
「糊，无纹理」。那一节的结论是：阅读器自己再缩一次的话，抖动连同 1 像素周期的结构一起被抹平——
**那时抖动做了等于没做，字节还照付**。

整条产品链挂在这个 1.0 倍上：目标尺寸有一条边贴住面板（几何门问的就是这个），
面板这一层的适配因此是 1.0 倍；ADR 0007 把抖动挂在它上面，ADR 0003 的灰阶硬上界
与逐页灰阶档位判定也只在像素原样贴上去时才兑现得了。

## 决定

1. **输出容器只有两种形态：目录与 `.cbz`**，且形态照旧**派生自源**，不成为用户选得动的一维。
   没有 `--container`。
2. **不做 EPUB / KEPUB / PDF 输出。**它们的渲染器按视口排版，1.0 倍保不住。
3. **不做 CB7 / CBR 输出。**`.cbz` 是阅读器认的名字（ADR 0015 决定第 2 条），
   换一种归档格式在阅读器那一侧换不到任何东西。
4. **翻案的条件是一格测量，不是一次表态**：在目标设备的自带阅读器里打开一份固定布局 EPUB
   （或 PDF），按《灰阶测试图》那两问的头一问看——抖动块与同均值实心块分不分得开。
   分得开，第 2 条重开；分不开，这一条就是终局。

## 后果

**好的：**

- 「看着输出认得出是哪一卷」在四种输入下同形（ADR 0015），而输出侧不多出一条维度：
  输出布局、撞名检测、《借住的卷》、幂等读回，四样各自的规则一处不动——
  它们全挂在「与源对称」这一条上。
- 逐页灰阶档位判定、抖动、纸色提白这三件事付出去的字节，在产物被打开时**确实换得到东西**。
- 参数哈希不多一项，预设不多一个字段，幂等不多一种形态。

**要认的代价：**

- **Kobo 的 EPUB/KEPUB 链路与 Kindle 的 Send to Kindle 链路用不上**，
  那两条在生态里是真实存在的分发路径。用户要走它们得自己拿产物再转一道——
  而那一道多半就是第 4 条要拦的那一道。
- CB7 在体积上对 CBZ 有真实优势（`.7z` 的压缩率）。归档里躺的是已经压过的 PNG，
  这一段还剩多少**没有量过**，放弃它是在一个未知数上放弃。
- 第 4 条那格测量**没有做**。这条决定眼下站在「1.0 倍保不住」这个推断上，
  而推断的依据（《真机像素完整性》）量的是图片阅读器，不是 EPUB/PDF 渲染器。
  **推断很强，但它是推断。**

## 备选方案

- **`--container` 成为自由维度，目录源也出得了 cbz**：收益是省一次手工打包，
  代价是输出布局、撞名、借住的卷、幂等读回四套规则各要重新定义一遍，
  而「目录源要 cbz 产物」这个需求一条真实证据都没有。
- **只做 PDF、不做 EPUB**：PDF 的固定布局看起来最接近「原样贴」，但它的页面单位是点不是像素，
  渲染器照旧按视口缩；而且它把一卷压成一个文件，《按页跳过》与《留下的页》
  那套逐页幂等失去落脚点。
- **做 EPUB，但把图按面板分辨率嵌进去、用 CSS 钉死像素尺寸**：钉得住的是 CSS 像素，
  不是设备像素；两者之间还隔着阅读器的设备像素比与它自己的重采样。
- **做 CB7**：收益只在库的体积上，而那是库管理器的职责（ADR 0009 关掉的方向）。

## 不要做的「简化」

**「先把输出容器抽成接口，具体做哪几种以后再说——接口总不会错。」**——接口本身不错，
错的是它会把这条决定的理由冲掉。今天「输出是什么形态」有一个**唯一答案、而且答得出来的地方**
（`source::Container`，派生自源）；抽成接口之后它变成一个等人来填的洞，
而填洞的人看不见《真机像素完整性》那张表。**这条决定不做接口，正是为了让下一个想加格式的人
先撞上第 4 条那格测量。**

**「EPUB 里躺的也是原图，阅读器总不至于去改它。」**——这正是要测的那一句。
《真机像素完整性》里同一台机器、同一张图，只换一个阅读器就从「非常明显可分」变成「糊成一片」；
而糊的来源并不是某个叫「缩放」的开关，是**裁边改变了页尺寸、随后的适配不再是 1.0 倍**。
EPUB 的排版层做的恰好是同一类事，只是改尺寸的理由换成了视口。
