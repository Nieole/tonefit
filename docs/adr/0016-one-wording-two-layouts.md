# ADR 0016：措辞一处，排版两处

状态：已采纳（2026-09-04）

## 背景

`p1-session` spec 立过一条，说的是命令行与会话拿同一份数据：

> 一卷跑完的事件带着 `VolumeReport`，因此**事件流就是报告的增量**。命令行攒完在最后一次性渲染，
> 会话攒到哪儿画到哪儿，两者拿的是同一份数据。渲染也共用一套——措辞不该有两个版本。

末一句被读成了「两头调同一个函数、拿同一段**文字**」。`render::volume` 与 `render::pages`
因此返回 `String`，会话把那几段推进一个段落、按宽度折行画出来——屏上于是是一整段纯文本，
与命令行印出来的逐字节相同。

P3 要把报告分成钉住的总览与一张**卷表**：一卷一行、列对齐、窄屏按固定次序砍列、
按行的类型上色。表吃的是**格**——卷名、页数、基准档、驱动页各占一列。
而今天交到会话手上的是一段拼死了的字符串：列对不齐、字段取不出来、状态标不上颜色，
三件事全卡在这一点上。

会话要从那一段里把字段抠回来，只能回头去认字符串——切 `·`、找「基准档」那三个字。
**那等于给措辞开了第二个出处**：措辞一改，会话当场认错，而且没有任何一条用例会红。

## 决定

1. **卷级与逐页那两段出的是一组「行」，每一行带着它是什么行、以及若干「格」。**
   一行对应报告上的一行；一格装一个值。`render::volume` 与 `render::pages` 的返回值
   从 `String` 变成 `Vec<Row>`。

2. **格里装的是值，不是摆法。** 缩进、前缀、列头、**格与格之间**的分隔符与单位一律不进格。
   一个数在纯文本里跟着「页」、在表里挂在列头下面，那是两副排版各自的事。

   **一格的值本身是一串东西时，怎么串起来仍是措辞**（各候选的判据 `1bit+FS 32.000 ·
   2bit 20.000 · …`、点名的头几页 `001.png、002.png，另有 5 页`）：串出来的整串是**一格**，
   而「一串东西怎么说」与「一个数怎么写」同属措辞。分不清的话，两副排版就各串各的，
   同一件事当场有了两个说法。

3. **排版从此两副，措辞仍只有一处。** 纯文本那一副是 `render::plain`——命令行印出去的、
   会话退出时留在 stdout 上的、以及会话报告区眼下画的都是它。表那一副是会话自己的事。
   「一个判定该怎么说」仍只有 `render` 一处，变的只是「摆在哪儿」。

4. **已经成句的那几段不拆成格。** 报告末尾那几小结、互锁那几行、失败原因那一句
   仍旧出整段文字：它们本来就是句子，拆开没有意义。落在行里的那几句同理——
   一行只有一格，装着整句话，画它的那一头把它当整段文字折行。这样的行有八种：
   跳过、隔离、部分救回、过期副本、摊开、几何门底下那几句注解、`--per-page`
   那一种卷级判定，以及一页失败。

   **覆盖顶掉判定那一行是唯一的例外**：它成句的那一格之外，另占一格候选——
   卷表要照它写基准档那一列（P3 spec 第六条：「覆盖 4bit」），
   而那一个值不该靠回头认字符串取出来。代价见《后果》。

5. **抬头与末尾那两段仍返回 `String`。** 它们不进卷表：抬头那几行是「这一趟的前提」，
   一趟只说一次；末尾那几小结要看完整趟才给得出来。两者都不是一卷一行的东西。

6. **行与格不落成一个对外格式。** 它是进程内的一层，不是 JSON、不是 CSV，
   `Report` / `VolumeReport` / `PageReport` 那几个库里的类型一格不动
   （P3 spec 的《Out of Scope》）。

## 它推翻了 `p1-session` spec 的哪一句

推翻的是**「渲染也共用一套」那一句的那种读法**——「两头拿同一段文字」。

那一句同一段里的前半截**至今成立**，一个字都不改：事件流就是报告的增量，
命令行攒完一次性渲染，会话攒到哪儿画到哪儿，两者拿的是同一份数据。
真正作废的只有末一句里的**「一套」指的是什么**：

- **从前**：一套 = 同一段文字。措辞与排版是同一件事，两头共用。
- **从此**：一套 = 同一份措辞。排版两副——纯文本一副、表一副，
  而「一个判定该怎么说」仍旧只有一处。

那一句要防的事没有变，也没有松动：**措辞不该有两个版本**。本决定反而把它守得更紧——
从前会话要拿字段只能去认字符串，那才是第二个版本真正会长出来的地方。

## 后果

**好的：**

- **卷表、逐页表、上色、砍列有了地基。** 三样吃的都是格：取一列不必认字符串，
  上色不必猜这一行说的是什么。
- **措辞改动不再波及会话。** 改一句话只动 `render` 里的那一格或那一句，
  两副排版一个字都不用跟着改——那正是换词那一票（P3 的 03）要的东西。
- **「一行是什么行」成了可断言的东西。** 从前只能问「那段文字里有没有这几个字」，
  现在问得出种类与格数：跳过的卷少哪几格、失败的页是哪一种行。
- **命令行印出来的报告逐字不变，而且是钉住了的。** 落地这一步时屏上一处都没变，
  排版被抽出来这件事因此是可验证的，而不是「改完看着差不多」。钉住它的是两处：
  `render` 的 `mod tests`（二十多条问那段文字的用例，外加一条把四段逐段拼起来
  与一次性渲染逐字节比对的），以及 `session::draw` 那六张 `TestBackend` 快照——
  报告区画的正是这段文字。**不是黄金快照**：那一份由集成测试算出，链的是库那一侧，
  够不着 `render`（停车场 Q132）。

**要认的代价：**

- **`RowKind` 与 `Field` 是两张要跟着报告长的清单。** 报告上多一种行就要多一个变体，
  而纯文本那一副的 `match` 不留 `_`——多一种行必须当场决定它怎么摆。
  这是有意的：漏掉一种只会在屏上少一行，没有人会报错。
- **值在格里出现两次的地方有两处**：上包络那一行的基准档、覆盖顶掉判定那一行的候选，
  各自既在成句的那一格里，也单独占一格。表要的是那一个值，纯文本要的是整句话，
  而两者说的是同一个数——不这样，表就得回头去认字符串，那正是本决定要拆掉的东西。
  **只在表真要那一个值时才这么做**：摊开、隔离、部分救回那几句里的数没人另取，
  它们因此只有成句的那一格。
- **拼错了是恐慌，不是少印一行。** 纯文本那一副取一格取不到就当场恐慌：
  一种行该有哪几格由 `render` 那一侧定死，两处对不上必须响。
- **短期内两副排版只有一副。** 会话的报告区眼下走的还是纯文本那一副，
  表要等 P3 后面几张票。这一步在屏上看不出任何变化。

## 备选方案

- **让会话自己去解析那段文字**（切 `·`、认「基准档」那三个字）——改动最小，
  代价是措辞就此有了第二个出处，而且是个**不会报错**的出处：措辞一改，
  会话认错字段，屏上照样画得出一张看起来对的表。
- **在库里给 `VolumeReport` 加一组「给界面看的字段」**——省掉这一层，
  代价是把界面的排版需求推进对外 API：`VolumeReport` 的字段从此不能随手改
  （`p1-session` spec 已经认下这一条），而「表要哪几列」是会随版式改的东西。
- **让 `render` 直接出表**（列宽、砍列、上色都在里面）——两头看起来仍共用一套，
  代价是命令行那一路也跟着变成表，而 P3 spec 明写「命令行那一份除换词三处外一字不改」。
- **落成 JSON / CSV 之类的对外格式，两副排版都从它读**——顺手能给脚本一条路，
  代价是多一个要维护向后兼容的 seam，而眼下没有任何调用方要它。
  真有人要，那是一张独立的票，不该搭在这一层上。
- **只把卷表要的那四个字段抽出来，别的仍出文字**——改动更小，
  代价是同一份报告里两种模型并存，而「哪几行已经降到字段级」成了一件要记住的事。

## 不要做的「简化」

**「既然行与格都有了，那就让抬头和末尾那几小结也拆成格，全报告一个模型。」**

那几段是**句子**，不是记录。「非卷文件 3 个：发现走完之后没被任何卷收下，既没转也没拷……」
拆成格之后，格里剩下一个 `3`，而那句话会整个搬到排版那一层去——于是每加一副排版
就要抄一遍它，措辞的第二个出处从另一头长了出来。**拆的那一刀会把措辞挪走**，
这正是本决定要防的事。一行只有一格、装着整句话，就是它们在这个模型里正确的样子。
