# ADR 0004：输出以 PNG 为默认，AVIF 为显式可选

状态：已采纳（2026-08-25）

## 背景

输出要先能被打开。四台目标设备的自带阅读器官方支持的格式里没有 WebP，也没有 AVIF；
PNG 是三家口径的交集（见 measurements 的《设备支持的图片格式》）。含 WebP 的 CBZ 在 Kobo 上直接打不开。

PNG 同时把位深做成了显式字段（1/2/4/8）与调色板模式，本项目按卷选一档位深的机制在它上面附着得住。
AVIF 也有位深字段，机制同样附着得住——它的障碍在设备侧，不在格式能力。

第三方阅读器不受自带阅读器的格式表约束。因此 AVIF 有真实用途，只是不能当默认。

## 决定

1. **默认输出 PNG。** 不加参数时的行为只有这一种。
2. **`--codec=avif` 是显式可选项**，面向第三方阅读器。用户开它即表示自己负责可读性。
3. **编码器抽成接口。** 位深与抖动模式在接口以外，调色板模式在接口以内。
4. **判据层对编码器无知。** 候选仍是 (位深, 抖动模式)，编码器选择在判据外层。
5. **不实现 WebP。** 它既无位深字段，也不在任何一台目标设备的格式表里。

## 后果

**好的：**

- 默认输出在四台设备上开箱可读，不依赖用户装第三方阅读器。
- 判据分数与编码器无关（无损候选下同一候选的像素完全相同），**多一个编码器只增加试编码次数，不增加判据评估次数**。
- 阈值只需在一条质量-体积曲线上标定；接口以外的两维不因编码器而变形。

**要认的代价：**

- **中高质量区 AVIF 在体积与误差两轴上都优于 PNG**（见 measurements 的《编码器对比》）。
  默认走 PNG 就是主动放弃这段收益，换设备可读性——这笔交换对本决定不利，但它是真的。
- 开了 `--codec=avif` 的输出在四台设备自带阅读器上打不开，这条代价转嫁给了用户。
- ADR 0006 写进 PNG tEXt 区块的判定记录要为 AVIF 另找载体，各家格式的元数据能力不同，尚未调研。
- 接口只有 PNG 一个成熟实现，形状难免带 PNG 痕迹，接第二个编码器时多半要改一次。

## 备选方案

- **全面改用 AVIF**：三家自带阅读器都读不了，输出在目标设备上打不开。
- **改用 WebP lossless**：设备不支持，且没有位深字段，本项目的机制无处附着。
- **输出无损、把体积交给编码器**：PNG 8bit、WebP lossless、AVIF lossless 三者均为源的两倍半以上
  （见《编码器对比》），全都比输入还大。「无损换编码器」这条路是死的。
- **只做 PNG、不抽接口**：省一层间接，但「输出格式」这个决定会散进管线各处，位深逻辑与 PNG 编码细节纠缠。

## 不要做的「简化」

**「两个编码器都试编码，每页选体积小的那个」**——听起来是免费的收益，实则重新打开本文关掉的问题。

一是可读性不再确定：输出格式逐页漂移，同一卷里有些页设备打不开。
二是判据要跨编码器比较，而两条曲线形状不同，单一阈值比不了。
三是中高质量区 AVIF 稳定胜出，那批页会从位深的证据集里消失——而 PNG 不可替代的地方恰恰在另一端：
**2bit 及以下的极低码率区，AVIF 与 WebP 到不了**（见《编码器对比》）。规则一旦按体积选优，这个非对称就看不见了。
