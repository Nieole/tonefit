# ADR 0012：试算与执行之间续做

状态：已采纳（2026-08-26）；决定第 1～4 条修订（2026-08-26，开 spec 时）

## 背景

会话的核心回路是「配置 → 试算 → 看报告 → 满意 → 执行」。而 dry-run 走 `Retention::Account`：
缓存只记账、不留页。按下执行时，第一遍——解码、缩放、算判据——完整重算一遍，
而第二遍只是量化与编码。贵的那一遍白跑了两次。

判断「能不能省」的工具已经在手上：参数哈希收的是**会改变输出**的每一项，且**不收模式**。
试算与执行的参数哈希因此天生相同。

## 决定

1. **续做只在处理范围是单卷时成立。** 多卷时试算与执行各跑一趟，第一遍照付两遍的价。
   理由是内存，不是口味：缓存逐卷建、逐卷丢，峰值随单卷走（ADR 0005）。全量试算要续做，
   就得同时押住**全部卷**的参照，而缓存预算是**每卷**的——20 卷即 20 份预算，加溢写。
2. **试算与执行是同一次 `run` 调用。** `run` 在每一卷的「汇总之后、第二遍之前」
   向观察者要一次指令（ADR 0011：观察者是双向的）。答继续就往下做，答收尾就停在这儿。
   续做因此不跨调用——缓存从头到尾没出过那一次 `run`。
3. **等不等人是会话的策略，不是库的行为。** 库永远在那个点上问。会话在单卷时于此处把报告画出来
   并等用户拿主意；多卷时立刻放行，试算另走一次 `Mode::DryRun`。
4. **缓存的寿命仍是「一次运行」，不延长。** 决定第 2 条已经把续做关进一次调用里，
   跨趟共用那条规矩因此不需要，也就没有失效问题。
5. 单卷试算走 `Retention::Keep`。**那一条路上 dry-run 的承诺从「一个文件都不落盘」
   重述为「不写输出」**：越过预算的页仍建溢写临时文件，运行结束即收走。
   命令行的 `--dry-run` 不变，仍走 `Retention::Account`——它没有下一步可续，留着只是白占。

## 后果

**好的：**

- 「试算满意就执行」不再付两遍的价。这条回路是会话存在的理由，它必须便宜。
- 判定与报告在试算与执行之间**逐字相同**——它们本来就是同一次计算的结果，
  而不是「两次算出来碰巧一样」。

**要认的代价：**

- 峰值内存在「试算停住了、你还没拿主意」这段时间里一直占着**一卷**的量。人会看着报告去泡茶。
- **续做的好处只有单卷会话吃得到。** 批量跑多卷时那条回路仍付两遍的价，而这正是耗时最长的场景。
  能接受是因为用法不同：反复调参数时看的是一卷，批量跑 20 卷时没人盯着报告改参数。
- **两条路的 dry-run 不完全同形**（会话单卷那条留参照、建溢写文件，命令行那条不留），
  这是本决定最尖的一根刺。
- `run` 会在观察者那里**阻塞**。观察者的实现从此有了「可能很久不返回」这个性质，
  用例里的计数器不受影响，但任何持锁调用它的地方都不行。

## 备选方案

- **完全不续做**——改动为零、少一层状态，代价是把最常走的那条回路的成本翻了一倍。
  单卷限定之后，本决定的复杂度已经压到「库在一个点上问一句」，这个代价不再值得付。
- **试算能押多少卷就押多少，满了就不押**——最省时间，但「哪几卷会续做」变成用户预测不了的结果，
  而它直接决定要等多久。行为不可预测比慢更糟。
- **在库里开一个 `Session` 类型装这份状态**——续做与两级停都有明确的家，但多一个对外 seam；
  而决定第 2 条把状态关进一次调用之后，那个类型没有东西可装。
- **改任何参数都尽量复用缓存**（只有影响参照的参数才让缓存失效）——收益更大，
  但要在会话里维护「哪些参数脏了」的依赖图，而参数哈希是一个整体、给不出这个粒度。
  真要做，先给参数哈希分层。
- **续做时重新校验源哈希**——那要把源字节再读一遍，省下的当场还回去一大半。
  会话是秒到分钟级的，源在这期间被改动的概率与这笔开销不成比例。

## 不要做的「简化」

「既然缓存能跨趟活，那就让它跨会话活，下次打开 TUI 还在。」
缓存装的是整卷的参照，几百 MB 到几 GB。它一落盘就成了一份需要失效策略的构建缓存，
而 tonefit 的幂等依据随输出文件走、不需要任何旁路状态（ADR 0009）。不要给它开这个头。
