# ADR 0012：试算与执行之间续做

状态：已采纳（2026-08-26）

## 背景

会话的核心回路是「配置 → 试算 → 看报告 → 满意 → 执行」。而 dry-run 走 `Retention::Account`：
缓存只记账、不留页。按下执行时，第一遍——解码、缩放、算判据——完整重算一遍，
而第二遍只是量化与编码。贵的那一遍白跑了两次。

判断「能不能省」的工具已经在手上：参数哈希收的是**会改变输出**的每一项，且**不收模式**。
试算与执行的参数哈希因此天生相同。

## 决定

1. **续做**：会话里试算跑完，紧接着按执行，参照仍在缓存里，于是**只跑第二遍**。
2. 续做的条件比「参数哈希相同」严。只对**紧接着那一次**成立，且只对试算**真的跑完**的那些卷成立：
   中间跑过别的、改过任何参数、或试算被收尾/中止过——剩下的卷整趟重跑。
3. 会话里的试算改用 `Retention::Keep`。**dry-run 的承诺随之从「一个文件都不落盘」
   重述为「不写输出」**：越过缓存预算的页仍会建溢写临时文件，运行结束即收走。
4. 缓存的寿命从「一次运行」延到「会话里参数未变的相邻两趟」。

## 后果

**好的：**

- 「试算满意就执行」不再付两遍的价。这条回路是会话存在的理由，它必须便宜。
- 判定与报告在试算与执行之间**逐字相同**——它们本来就是同一次计算的结果，
  而不是「两次算出来碰巧一样」。

**要认的代价：**

- 峰值内存在「试算完了、你还没按执行」这段时间里一直占着。人会配置完就去泡茶。
- dry-run 会建临时文件了。命令行上的 `--dry-run` 仍走 `Retention::Account`——它没有下一趟可续，
  留着只是白占。**两条路的 dry-run 因此不完全同形**，这是本决定最尖的一根刺。
- 续做把「上一趟发生过什么」变成了会话的状态。状态一多就有失效问题，决定第 2 条那三句是它的边界。

## 备选方案

- **不续做，执行时重算**——改动为零，代价是把最常走的那条回路的成本翻了一倍。
- **改任何参数都尽量复用缓存**（只有影响参照的参数才让缓存失效）——收益更大，
  但要在会话里维护「哪些参数脏了」的依赖图，而参数哈希是一个整体、给不出这个粒度。
  真要做，先给参数哈希分层。
- **续做时重新校验源哈希**——那要把源字节再读一遍，省下的当场还回去一大半。
  会话是秒到分钟级的，源在这期间被改动的概率与这笔开销不成比例。

## 不要做的「简化」

「既然缓存能跨趟活，那就让它跨会话活，下次打开 TUI 还在。」
缓存装的是整卷的参照，几百 MB 到几 GB。它一落盘就成了一份需要失效策略的构建缓存，
而 tonefit 的幂等依据随输出文件走、不需要任何旁路状态（ADR 0009）。不要给它开这个头。
