# ADR 0017：会话的模式拆成两维

状态：已采纳（2026-09-05）

## 背景

会话「此刻在做什么」由**一个** `Mode` 说，六个取值：浏览 · 编辑一行 · 跑着 · 等答话 ·
展开着 · 预设栏 · 取值栏。六个取值答的却是**两个**问题：

- **这一趟走到哪儿了**——没跑过 / 跑着 / 停在决策点上等答话 / 收场了；
- **眼下在看什么**——左栏 / 摊着取值 / 编辑一行 / 报告区 / 展开着 / 预设栏。

挤成一维的代价是**两个问题里的每一对组合都得二选一**。三处后果：

1. **跑着的时候什么都不能看。** 跑着那个取值一占，展开、预设栏、取值栏就都不成立
   ——一趟几十分钟，想回头看第一卷的逐页得等它收场（停车场 Q72）。
2. **报告区没有自己的光标。** 光标是「浏览」那个取值带着的东西，归左栏；
   报告区因此只会跟着最新那一卷滚到底，翻不回去（停车场 Q64）。
3. **「哪些键在哪个状态下有效」那张表要按六选一查**，而它真正分岔的是两件事：
   按停与答话归第一维，`↑↓`／`⏎` 归第二维。一维里这两批键必须在每一个取值上重列一遍。

P3 的三张票压在这一点上：报告区的光标与跟随（本票）、展开的逐页表（`11`）、
覆盖层（`12`，`?` 那张键位表是第二维上的又一个取值）。

### 先前三次判过「不拆」

**`p1-session/10`**（范围层跟着冻住，停车场 Q69）：

> 拦住它的不是道理，是形状：会话此刻在做什么由**一个** `Mode` 说，
> 而「正跑着」与「正打字改一行」要同时成立的话，那个枚举得拆成两维。

> **范围层继续冻着，`Mode` 不拆两维。**……拆成两维的唯一用处是让范围层在跑着时
> 还能打字，而那件事本身不该做：改了看着像生效、其实没有，比按不动更坏。

**`p1-session/11`**（跑着的时候展不开，停车场 Q72）：

> 要让它按得动，`Mode` 就得拆成两维（「正跑着」与「正展开着」同时成立），
> 而那正是 `10` 在 Q69 上判过不拆的那件事。还有第二重代价：那一刻按得动的只有 `s`，
> 而展开态要吃掉上下左右与 `⇥`，按停那个键在一屏滚动键里会被挤没。

**`p1-session/14`**（决策点在会话里长什么样）：

> `Mode::Deciding(Instruction)`——一个**状态**，不是 `Mode::Running` 上的一个开关。
> 两处按得动的键是两套（跑着时只有 `s`，等答话时是 `x` 与 `s`），而「哪些键在哪个状态下
> 有效」那张表是 `session/state.rs` 唯一的产出；摆进同一个状态就要靠一个 flag 分岔。

三次的依据各不相同，但**共同的前提只有一条：本票不需要**。10 判的是「拆了只能用来做一件
不该做的事」，11 判的是「拆的代价现在换不来东西」，14 判的根本不是拆不拆——它判的是
**等答话不能退化成一个 flag**，而那一条本决定原样保住了。

## 决定

1. **`Mode` 拆成两维**：`Stage`（这一趟走到哪个阶段了）与 `Focus`（眼下在看什么）。

   | 维 | 取值 |
   |---|---|
   | `Stage` | 没跑过 · 跑着（带闩）· 等答话（带闩）· 收场了 |
   | `Focus` | 左栏 · 编辑一行 · 取值栏 · **报告区** · 展开着 · 预设栏 |

   `Focus` 多出来的那一个取值就是**报告区**：焦点落得上去的一块，`⇥` 在它与左栏之间切。
   覆盖层是这一维上的又一个取值（`12` 的事，本决定不画它）。

2. **「哪些键在哪个状态下有效」仍旧一处答完**（`Session::action`），只是那张表**按两维查**：
   先按焦点分岔，落到哪一块之后再按阶段分。**阶段那一维派得出的那几个键只有一处**
   （`stage_action`：按停、答话那三个、退出会话），焦点那一维上摆得下它的三块
   （左栏、报告区、展开着）都把自己不认的键交到那里。

3. **三层只读由阶段那一维说了算，与焦点在哪无关**（`Stage::read_only`）。
   「跑起来之后一个改动键都不派」因此是结构上成立的：那三块自己一个改动键都没有，
   而阶段那一处也没有。**焦点落到报告区不解锁任何一格。**

4. **按停与答话那三个键在焦点落在哪一块上都按得动**，两级语义一格不变：
   它们问的是「这一趟还走不走」「这一卷的第二遍还做不做」，与眼下在看什么无关。

5. **`⇥` 按状态分派，三个意思不冲突**：左栏 ⇄ 报告区切焦点；编辑一行时是逐层补全；
   展开着时是换下一卷。三处各是那个键在那个状态下最该做的事。

6. **跟随是卷表独有的状态**（`Follow`）。它记的**不是滚动量，是光标停在哪一卷上**——
   视口照旧由光标算出来（`CONTEXT.md` 的《视口》一个字不改）。跑着时默认跟着最新收摊的
   那一卷；光标一挪跟随就停，报告区那一格的抬头说一句「跟随停了」；`g` 交回给跟随。

7. **展开的索引从「报告上第几卷」改成一个认得出两处的取值**（`live::Volume`：
   收摊了的第几卷 / 决策点上攒着的那一份）。**这一改是 `p2-loose-ends/08` 那条硬约束
   （「不许摊开上一卷冒充它」）的解法**：决策点上那一卷停在攒着的那一份上、不在收摊了的
   那几卷里，一个下标根本指不到它——而它要进表、要停得住、也要展得开。

8. **两维不是笛卡儿积。** 取值栏、编辑一行、预设栏三个取值**只从左栏进得去**，
   而跑起来之后左栏一个改动键都不派——它们与跑着、等答话**结构上碰不到面**。
   这一条不靠代码守着，靠的是那三个状态的唯一入口在按键表上不存在。

## 它推翻了哪一条

推翻的是 **`p1-session/10` 与 `11` 那两次「不拆」的结论**，而**它们各自要防的那件事
一件都没有松动**：

- **10 要防的是「改了看着像生效、其实没有」。** 本决定把三层只读挂在阶段那一维上，
  比一维时守得更紧——从前「只读」是「跑着」那个取值顺带带着的，现在它是一个读法
  （`Stage::read_only`），焦点怎么切都改不动它。**范围层照旧冻着。**
- **11 要防的第二重代价是「按停那个键在一屏滚动键里被挤没」。** 那件事在两维下不成立：
  按停是 `s`，滚动走方向键，两批键不在同一个键位上。屏底那一行照旧按阶段摆出按停那一副
  ——展开着的时候它跟在展开那几个键后面，一个都不少。

`p1-session/14` 那一条**不在推翻之列**：等答话仍旧是**取值**，不是「跑着」上的一个 flag
——它只是换了一维待着。`CONTEXT.md` 的《会话》那句「等答话是一个状态，不是『跑着』上的
一个开关」因此一个字都不用改。

## 后果

**好的：**

- **跑着的时候读得了报告。** 几十分钟的一趟里回头看第一卷、展开它的逐页、翻回去，
  三件都按得动——而这正是停车场 Q64 与 Q72 记着的两个缺口。
- **决策点上那一卷进了表，也展得开。** `p2-loose-ends/08` 那条硬约束落到了实处：
  屏上给它一行、光标停得住、逐页那几行是它自己的，一格都没有拿上一卷冒充。
- **按键表的两批键各只有一处。** 从前跑着与等答话两个取值各列一遍那批「按不动的键」，
  现在阶段那一维一处答完；添一块新焦点（`12` 的覆盖层）不必再抄一遍按停与答话。
- **屏上「焦点在哪」有了唯一的载体**：反白那一行。焦点在左栏时它落在配置那一行上，
  切到报告区之后落在光标停着的那一卷上——屏上同一刻仍旧只有一处反白。

**要认的代价：**

- **一个状态变成两个字段，转场要一处一处交代。** 起一趟只动阶段那一维（外加把跟随扳回），
  收场了只动阶段——**焦点原样留着**（正在读的东西不该被搬走）。写错一处的后果是
  「切了个焦点，按停按到的那一级没了」，因此那几处各有一条用例钉着。
- **两维不是笛卡儿积，而那件事看不见。** 三个取值与两个阶段碰不到面靠的是入口，
  不是类型——类型上它们摆得出来。代价写在 `Session::action` 的文档里。
- **屏底那一行更长了。** 焦点那一块自己的键在前，阶段那几个跟在后面；窄终端上它折成
  两三行（`p2-loose-ends/07` 的折行照旧，`q 退出` 一行不让）。`?` 那张完整键位表要等 `12`。
- **卷表上的光标跳过没做成的那几卷。** 它们连一份卷报告都没有，逐页那几行无从谈起
  ——光标停上去没有第二步可走。表上它们照旧占一行、照旧红、照旧带着那句原因。
  这一笔记在停车场 Q159。

## 备选方案

- **留一维，给「跑着」那个取值加一个 flag（正展开着 / 焦点在报告区）**——改动最小，
  代价正是 `p1-session/14` 判过的那件事：屏底那一行要靠 flag 分岔，
  而「哪些键在哪个状态下有效」那张表就此有了第二个出处。
- **留一维，多添几个取值（「跑着且展开着」「等答话且焦点在报告区」……）**——
  不必碰两维，代价是取值个数是两维的**乘积**：四个阶段乘六块，添一块新焦点要添四个取值，
  而每一个都要在按键表上单列一支。
- **报告区的光标记成一个行号（滚动量），不记成一卷**——省掉 `Volume` 那个取值，
  代价是报告一长行号就不作数了（表上一卷可能占两行），而决策点上那一卷根本没有稳定的行号。
- **跟随做成视口上的一个开关，四处共用**——听起来更整齐，代价是把「记着滚到哪儿」
  泛化到别处去：`CONTEXT.md` 的《视口》明写着「滚动量是算出来的，不是记着的」，
  而别处的视口一处都不需要它。
- **等这几张票都要它了再拆**——那正是先前三次的判断，而本批三张票同时压在这一点上：
  再推一次的代价是 `11` 与 `12` 各自去发明一个绕过去的办法，而两个办法互不相认。

## 不要做的「简化」

**「既然拆成两维了，那就让三层在跑着的时候也编辑得动——反正焦点是分开的。」**

不行，而且这一条正是 `p1-session/10` 判过的那件事：`Request` 在起线程那一刻就是一份快照，
改了**不影响正跑的那一趟**。「看着改得动、其实没生效」比按不动更坏。两维改变的只有
「按不动的是谁说了算」——从前是那个取值顺带说的，现在由阶段那一维一处说死。
拆两维是为了让人**在跑着的时候看得见更多**，不是为了让人在跑着的时候**改得动更多**。
