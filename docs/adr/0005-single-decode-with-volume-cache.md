# ADR 0005：解码一次，缓存缩放后的图

状态：已采纳（2026-08-25）；决定第 1、3 条修订（2026-09-08，逐页那条路上第二遍退化成纯写出；2026-09-10，覆盖顶死的那一趟参照不进缓存）；**待修订**（2026-09-11，ADR 0018）——下面「档由逐页判定加段式迟滞定……回看长度是有界常数」那一句已不成立：段式迟滞退场，一页的档只取决于它自己，回看长度是 0。原文由 `two-pass-rework/11` 落地时改

## 背景

三个特性要求先看完整卷：跨页拆分的判定（用卷内尺寸众数定单页基准）、固定元素检测（各页对齐后逐像素取中位数）、
位深的卷级上包络（见 ADR 0006：位深按卷取上包络并加迟滞）。三者的成本相差三个数量级：
跨页判定只要图片尺寸，读 PNG 的 IHDR 或 JPEG 的 SOF 即可，零解码；固定元素只要 1/16 降采样图；
**只有位深上包络需要全尺寸的缩放后图像**。

这一项无法靠廉价预扫绕开。JPEG 可以在 DCT 域直接解成 1/8 尺寸（`scale_denom`），PNG 没有这个能力，必须完整解码——
「轻量第一遍」在 PNG 源上会退化成完整第一遍，两遍解码就是实打实的两遍。
所以要决定的不是「要不要先看一遍全卷」，而是「那一遍看过的像素留不留」。

## 决定

1. **第一遍**：读 → 解码 → 彩页识别 → 拆分/裁边 → 单次仿射（deskew + 预缩 + 残差重采样）→ 算判据曲线；
   同时缓存缩放到目标尺寸的 8 位灰度图，即判据用的那份**参照**。LZ4 压缩，内存优先，
   超出 `--cache-budget` 溢写临时文件。
   **逐页那条路上这一遍还要量化与编码**：一页的档定得下来的当场做完，那一格缓存
   从参照换成编好的 PNG 字节（2026-09-08 修订，见下面《第二遍在逐页那条路上退化成纯写出》）。
   **覆盖顶死的那一趟连参照都不缓存**：那一档开卷之前就定死了，量化与编码就地做完，
   那一格从头装的就是编好的 PNG（2026-09-10 修订，见下面《覆盖顶死的那一趟不必等到第二遍》）。
2. **汇总**：卷级 p95 上包络 + 迟滞 + 固定元素定位。**特例页识别排在上包络聚合之前。**
3. **第二遍**：从缓存读 → 量化（含可选抖动）→ 编码 → 写出，**不再碰源页**。
   逐页那条路上量化与编码已经在第一遍做完，这一遍**只写出**（2026-09-08 修订）；
   覆盖顶死的那一趟同样（2026-09-10 修订）。
4. **彩色 profile 下彩页走彩色分支，不进灰度缓存。** 黑白 profile 下彩页先转灰，再走与其它页相同的灰度路径。
   彩色分支的形态——彩色 profile 由什么定、彩页怎么识别出来、编好的字节何时写出——
   见 ADR 0010：彩页按 profile 分流。
5. 非图片文件（`ComicInfo.xml` 之类）由源层原样透传，既不进缓存，也与本 ADR 无关。
6. **缓存只活在一次运行之内。** 进程结束即释放内存、清理临时文件，不提供跨运行的持久缓存。

缓存体积按面板分辨率 1264×1680、每像素 1 字节估算为 2.1 MB/页。**这个数是 fit-inside 那条路上的上界**：
目标尺寸是 fit-inside 的结果，漫画页更瘦，实际必然更小。以高为准（ADR 0007 决定第 7 条）下宽可以溢出面板，
跨页因此越得过它——最宽的一页有多宽，见《适配方式：fit-inside 与以高为准》。
参照按目标像素数走，这个上界因此跟着**适配方式**变；越过 `--cache-budget` 的页照旧溢写（决定第 1 条），
预算那道闸不因此被绕开。LZ4 压缩与解压的开销相对解码接近于零。

## 第二遍在逐页那条路上退化成纯写出

修订于 2026-09-08（`two-pass-rework/12`）。原来那条「第一遍缓存参照、第二遍取回来量化编码」
**只有上包络需要**：基准档要看完整卷才定得下，参照因此得押到汇总之后。
`--per-page` 一关，档由逐页判定加段式迟滞定，而那一层的回看长度是**有界常数**
（`src/hysteresis.rs` 的 `Rolling`）——一页的档只要再看几页就定得下来。

那条路上因此改成：参照只在一个**滚动窗口**里活着，出了窗口当场量化、编码，
缓存那一格从参照换成编好的 PNG 字节，第二遍退化成把字节按阅读顺序写出去。
峰值内存从「整卷参照」降到「几页参照 + 整卷编好的字节」，而后者比前者小得多。
**彩色分支本来就是这条路**（ADR 0010 决定第 5 条），本次修订只是让灰度路径也走上去。

三样一格没动：

- **写出仍旧等全卷。** 一页失败整卷进隔离目录，而哪页失败要解过才知道；
  拆分加序号的成员名可能撞上卷里本来就有的成员，那一撞要在写出第一个字节之前拦下；
  更要紧的是「第二遍开始之前一个字节都没写」这条不变式被中止与决策点同时依赖着
  （ADR 0013、ADR 0012）。编好的字节进的是**缓存**，不是输出容器。
- **预算与溢写。** 编好的字节照旧过 `--cache-budget` 这道闸，装不下照旧溢写。
  参照换掉之后临时文件里那一段作废，文件不缩——限的是峰值内存，那一段死字节占的是盘。
- **上包络那条路。** 它照旧攒一整卷参照，与本次修订之前逐字节相同。

**覆盖项那一档答不出来时让位。** 「覆盖项裁到只剩一个候选」问的是其余页那一组的候选集，
而哪一组是其余页要等整卷判完几何门才知道（`src/lib.rs` 的 `pinned`）。两组给出同一个答案时
碰卷之前就答得出；一组裁到只剩一个、另一组没有时它要等整卷，滚动窗口于是不开，
那一卷照旧攒整卷参照。**答得出的那一趟窗口同样不开**，理由相反：判定已经定死，
一页都不必等后文——见下一节。

## 覆盖顶死的那一趟不必等到第二遍

修订于 2026-09-10（`two-pass-rework/06`）。上一节那条「答得出就不必等整卷」原先只用来
决定**滚动窗口开不开**，而它本身够得着更多：那一档开卷之前就定死了，判据说什么都不改结果，
第二遍要用的东西第一遍当场就做得完。缓存那一趟往返——存参照 → 取回来 → 换成字节
（`PageCache::replace`）——整个省掉，那一格从头装的就是编好的 PNG
（`PageCache::insert_encoded`）。参照因此**一张都不进缓存**。

**本条对候选是被哪一道裁剪裁到只剩一个的一视同仁**——判据说什么都不改结果这件事，
与裁剪来自哪一道无关。但四道裁剪够得着的维**不一样**，而这决定了哪些参数真能顶死：

| 维 | 裁得动它的 |
|---|---|
| 位深 | `--bit-depth`；**面板灰阶数**（ADR 0003 的硬上界，两级灰阶的面板上只剩 1bit） |
| 抖动 | `--dither`；**几何门**（ADR 0007，门不成立时只剩不抖） |

候选集是两维的全积，因此要成单例，两维都得被裁到 1。**位深那一维两条路都走得通**
（点名，或面板够窄）；**抖动那一维只有 `--dither` 走得通**——几何门是**页**的事实，
`pinned` 问的是碰卷之前，那时没有页可判，门成立那一组恒有两种抖动模式。
**因此每一趟顶死都点着 `--dither`。**几何门在这一问上的作用不是裁出那个单例，
而是决定门不成立那一组**在不在**：`--dither fs` 让它成为一条拒绝（上面 `Err` 那一支），
`--dither off` 让它与门成立那一组给出同一个答案。

**一个覆盖项都没点而候选只剩一个的那一种按设计不算顶死**——面板灰阶数裁到只剩 1bit、
又撞上一页门不成立，那一页的候选集确实只有一个。不算的理由有两条，缺一条都不够：
那一档仍是**判出来的**，不是被顶掉的，理由分得清报告才解释得了它（`src/decide.rs`）；
而且它的**理由**要等整卷汇总才定得下（`VolumeEnvelope` 或 `OutsideTheGate`，
取决于这一卷有没有一页门成立），碰卷之前答不出——理由写进 tEXt，
提前编码会写出与今天不同的字节。

**判据曲线照旧求。**「覆盖了判定也照求判据曲线」是有意的（试算要说得出你点的那一档判据
是多少），本次修订只收缓存那一趟往返，一格判据都没少求。

四样一格没动：

- **写出仍旧等全卷**，理由同上一节：编好的字节进的是**缓存**，不是输出容器。
  决策点上答收尾时那一卷照旧一个字节都没写。
- **预算与溢写。** 编好的字节照旧过 `--cache-budget` 这道闸。
- **判定与写出的字节。** 第一遍编字节用的那一档与 `summarize_volume` 定的那一份逐格相同
  （`src/lib.rs` 的 `pinned_verdicts` 加一条 `debug_assert!` 钉着），
  写出的字节因此与本次修订之前逐字节相同。
- **试算。** 那一趟没有第二遍，编出来的字节没有读者，缓存也只记账、不留页；
  顶死的试算因此照旧攒参照，与滚动窗口那一条界逐字相同。

**滚动窗口不是下面那个「32 页滞后窗口」。** 本节这一个是**判定**的窗口：
参照押到这一页的档定得下来为止，长度由迟滞的回看长度推出，只在逐页那条路上有。
下面那一个是**预算**的退路：整卷参照压不住时把处理范围切成恒定长度的窗口，
代价是卷级统计的作用域从全卷降到窗口。两者互不替代，也不互斥。

**预算撑不住时的退路是 32 页滞后窗口，不是把卷切块。** 窗口恒定内存、恒定滞后、不产生临时文件；切块会同时削弱
三项卷级统计，且合并不完全等价。这是本 ADR 明确的例外，不与 ADR 0006 冲突：那里禁止的是拿滑动窗口**替代**卷级上包络当常规路径。

## 后果

**好的：**

- PNG 源上不必付第二遍解码。
- 第二遍的输入是确定的像素缓冲：同一次运行内换阈值档位、开关抖动重跑不必重新解码。
- 三项卷级统计各按自己的真实成本取数据，不会因为「都是卷级」就一起按最贵的那项算。

**要认的代价：**

- **卷成为不可分割的处理单元。** 峰值内存与临时空间随卷大小线性增长。
  逐页那条路上涨的是**编好的字节**而不是参照（2026-09-08 修订），覆盖顶死的那一趟同样
  （2026-09-10 修订，而且那一趟连一张参照都不曾进过缓存），系数小了一截，**但仍是线性**。
- **缓存体积估算依赖尚未测量的压缩率。** 灰度图能压到多少，真实片源上**尚未测量**；2.1 MB/页 本身也是上界而非实测。
- 超大卷落到退化路径，卷级统计的作用域从全卷降到窗口，影响**尚未测量**。
- 多出一条溢写路径要维护：临时文件的位置、清理、中断后的残留。
- 参照的工作精度定死在 8 位灰度，8 位以上的源在进入判据前已被量化一次。

## 备选方案

- **真两遍、不缓存像素**：内存最低，但 PNG 源上接近两倍总耗时。
- **纯流式、放弃卷级统计**：吞吐最优、内存恒定，但同时推翻上述三个特性。
- **缓存未缩放的原始解码图**：保留汇总后重选缩放参数的自由度，但体积高出数倍，为无人要的自由度付这个价不划算。
- **把超大卷切块**：见决定第 6 条之后——切块削弱统计且合并不等价，退路取滞后窗口。

## 不要做的「简化」

**「第一遍只读尺寸和缩略图，第二遍再完整解码」**——三项统计里确实有两项只要尺寸和 1/16 降采样图，
内存立刻掉到几 MB，临时文件与 `--cache-budget` 一起消失。它漏掉第三项：位深上包络要全尺寸缩放后图像，
PNG 拿不到便宜的预扫，第二遍于是变成第二次完整解码——本 ADR 关掉的正是它。要重开这个口子，先证明手上的源不是 PNG。
