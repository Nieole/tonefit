# ADR 0014：点名的路径展开成一批卷

状态：已采纳（2026-09-03）；决定第 3 条的非卷文件**清单**尚未实现——
本版本只保证不是卷的东西不产出任何字节，那张表由 `volume-discovery/04` 挂到报告上

## 背景

模型里藏着一条从没写出来的恒等式：**点名的路径 = 一个卷**。`source::open` 照它实现——
是目录就整个当目录卷，是归档就当归档卷，没有第三种。

这条恒等式在真实漫画库上当场失效。点名一个 `_cbz` 目录，得到的是：

- 目录里直接躺着的 185 张 png——转了；
- 同一层的三个 `.cbz`——**原样拷进输出目录**，报告写着「0 页」。

报告说的是真话：`_cbz` 整个被当成**一个卷**，三个 cbz 在它眼里既不是页也不是卷，
于是按「非图片文件原样透传」搬了过去。而真实的库形状是
`网络资源/<作品>/<第N话>.cbz`——**两层**，恒等式够不着。

由此长出四类真问题：

1. **卷的边界只能是点名的那一层。** 一个作品目录装 56 话，用户要么点 56 次，
   要么点一次得到一个 56 卷合一的怪物——上包络按卷取，位深判定因此也错。
2. **说不出「什么没被转」。** 没被当成页的东西一律透传，产物里混着源库的杂物，
   而报告里没有一处列得出它们。
3. **「一页都没有的卷」是合法状态。** 一个字体包被当成卷，输出里就多一个空容器。
4. **一个坏文件挡住整个库。** 预扫发现有卷点不开就整趟拒绝，而库里混着一个坏 zip
   是常态。

## 决定

1. **发现两条规则。** 点名的每一个路径展开成一批卷：

   - 路径是**归档** → 一个卷，**内部结构照收**；
   - 路径是**目录** → 直接躺着页就**同时**是一个卷（**只收直接那一层**），
     并且**继续往下发现**。

   **卷与卷架不互斥**：同一个目录可以既是卷又装着卷。因此**不给「装卷的目录」造词条**
   ——它不是一种东西，只是目录的一面。

   这条是从孤立封面图倒推出来的。`N和S/` 里一张 `cover.jpg` 加 56 个 cbz：
   若「直接有页就整个子树归它」，56 个 cbz 又变回透传文件；若「混装当场拒绝」，
   一张 `folder.jpg` 就能让整个库跑不起来，而**源库只读**，tonefit 修不了它。
   不互斥是唯一不猜、不拒、也不靠名字表的走法：封面自成一个一页的卷，56 话各自成卷。

   **一页都不许被处理两遍**：目录卷只收直接那一层，子目录里的页只属于子目录自己那个卷；
   躺在目录里的归档是卷，不是这一卷的透传成员。

   发现**只在点名的路径底下走**。ADR 0009 关掉的三件事——全库扫描、索引、watch——
   一件都不回来。

2. **卷的边界：两种容器不同形。** 两者在**读取与输出**上同形（`source::Volume` 是收敛点），
   在**卷边界**上不同形。理由是一句能立住的原则：
   **归档的边界由打包者定死了，目录的边界可以再分。**
   一个 cbz 里 `第01话/001.png`、`第02话/001.png` 这样分目录装着是真实的打包习惯，
   归档若也只收顶层，整卷一页不剩。

3. **卷至少有一页。** 一页都没有的东西不是卷，归入**非卷文件**：字体包、源码包、空目录、
   纯粹的卷架都落在那一栏，**输出里一个字节都没有**。非卷文件**不是失败**，
   不影响退出码。

4. **输出镜像源的结构，基准点是点名路径的父目录**——点名路径自己的名字恒出现在输出根下。

   ```text
   点名 _samples\网络资源            → D:\test\网络资源\N和S\第10话.cbz
   点名 _samples\_cbz\改革之獸-Vol05 → D:\test\改革之獸-Vol05\CMR_05_000-1.png
   ```

   一套规则管两种点名。取「点名路径自己」当基准点的话，点名一个**卷**时页会直接撒进
   输出根，于是实际要两套规则。

5. **「点名的 / 发现的」只决定一件事——点不开时的处置。**

   - **点名的**卷点不开 → **整趟拒绝**（`CONTEXT.md` 的《失败》：拒绝执行。他明说了要处理它）；
   - **发现的**归档点不开 → 进非卷文件，**其余照做**，退出码一格不动。

   对推测出来的东西不用最重的处置。

## 后果

**好的：**

- 点一次名跑完 98 话，而不是点 98 次。触发这张票的那批 cbz 从「原样拷过去」
  变成「各自转换、各自重新打包」。
- 输出目录的结构与源目录一致，可以按原样拷进设备。
- 一个坏 zip 不再挡住几百卷；一张封面图不再让整个库跑不起来。
- 输出里**只有产物**：源库的杂物既不当页也不当透传文件，一个字节都不跟着进来。
- 卷边界那条不对称有了一句立得住的理由，两种容器的差别不再是实现的偶然。

**要认的代价：**

- **目录卷不再递归收页。** `某卷/特典/x.png` 从前归某卷，如今特典自己成卷，
  两边的上包络因此分家、位深判定可能不同。这不是回归，是本条决定买下的东西——
  「一页都不被处理两遍」与「递归收页」不能同时成立。
- **一个混装目录的输出去处，同时是它那些兄弟卷输出的父目录。** `out\N和S` 既是封面那一卷
  的目录，也装着 `out\N和S\第01话.cbz`。目录卷收尾时把最终位置**整个换掉**
  （`crate::sink` 的 `DirectorySink`，那是「不产出半成品」与「清掉陈旧产物」两条换来的），
  于是父卷真被重写的那一趟会先删掉整个 `out\N和S`——同一趟里兄弟卷随后照写，
  末了的盘是对的；但那一趟**中途停下或有兄弟卷失败**时，上一趟好好的兄弟产物就没了。
  源库一个字节没动，重跑一趟就全回来（见停车场 Q113）。
- **预扫的代价随库长。** 点名一个库要走一遍那棵树，慢盘上这要花时间。
  发现本身不碰像素、不占步，命令行那条转轮（ADR 0011）盖着这一段。
- 纯粹的卷架也会被开一次才知道它一页都没有——「什么算页」因此只在一处写着，
  代价是多开一次目录。
- 用户看不出「哪些东西没被转」，直到非卷文件那张清单落地（`volume-discovery/04`）。

## 备选方案

- **保留「点名的路径 = 一个卷」，让用户逐卷点名**——今天的做法。库大时这是真实负担，
  而它正是本 ADR 要解决的问题。
- **加一个 `--recursive` 开关**——发现是默认且唯一的行为，不留旧路。留旧路就要在
  两套卷边界上各测一遍，而旧的那一套已经被判定是错的。
- **目录卷「直接有页就整个子树归它」**——`N和S/` 里那 56 个 cbz 又变回透传文件，
  触发这张票的问题原样回来。
- **混装目录当场拒绝**——一张 `folder.jpg` 让整个库跑不起来，而源库只读。
- **靠名字表认「这是封面不是页」**——猜。名字表必然认漏，也必然误伤。
- **输出镜像的基准点取「点名路径自己」**——点名一个卷时页会直接撒进输出根，
  于是卷与卷架两种点名要两套规则。
- **发现出来的卷点不开也整趟拒绝**——库里混着一个坏 zip 是常态，
  那等于把几百卷押在最坏的那一个上。

## 不要做的「简化」

**「既然要走一遍目录树，顺手把结果存下来，下趟就不用再走了。」**
那是一份全库索引，而索引正是 ADR 0009 关掉的三件事之一。它跟着要断点续传来应付中途失败，
要监听来知道库变没变——一步一步走回库管理器。发现活在**一次运行之内**，不落盘。

**「一页都没有的卷就产出一个空容器好了，反正不占地方。」**
那是把一个字体包、一个源码包当成漫画卷交给用户，而输出目录本该「只有产物」。
不是卷的东西一个字节都不写，用户才敢把整个输出目录拷进设备。

**「目录卷也递归收页，只是把子目录里的 cbz 挑出来单独处理就好了。」**
那样一张页会同时属于两个卷——父目录那个和子目录那个——两边各转一遍、各写一份，
而两份的基准档还可能不同。「一页都不被处理两遍」是这条规则的硬边界，不是偏好。
