# ADR 0003：面板灰阶数是位深的硬上界

状态：已采纳（2026-08-25）

## 背景

面板 = 分辨率 + PPI + 灰阶数。灰阶数是显示属性，e-ink 恒 16；位深是编码属性，全集 {1,2,4,8}。
4 位编码的 16 个取值与 e-ink 的 16 个灰阶一一对应，8 位多出的那 240 级在显示端被截断，到不了眼睛，
只留下体积：《B 类位深实测》里 8bit 的字节数是 4bit 的两倍以上，换来的误差差额在 e-ink 上不可见。

这条论证依赖 ADR 0007 那道**几何门**：目标尺寸有一条边贴住面板，且输出不再被下游缩放。
一旦下游还要缩放，像素与灰阶不再对齐，截断的论证就断了。

判据以参照为准，参照是未经目标位深量化的 8 位灰度图，面板显示能力不在其中。
所以裁剪必须发生在判据之前——交给判据自己选，8bit 会以零误差稳赢。

## 决定

灰阶数是面板的字段，与分辨率、PPI 并列，同为 profile 主键的一部分。
候选按面板灰阶数裁剪，裁剪在判据求值之前：e-ink → {1,2,4}，LCD → 全集 {1,2,4,8}。
被裁掉的位深不进入候选，不参与上包络，也不进入仲裁。取值来源三条，优先级从低到高：

- 内置面板表，给出已知面板的灰阶数；
- `--gray-levels` 显式覆盖，未知面板与实测修正走这一条；
- `calibrate` 子命令输出灰阶阶梯图，在目标设备上直接看，数出实际可分辨的级数。

几何门不成立——输出仍会被下游缩放——时上界失效，不得套用，此时该用哪个位深集合尚未测量。
ADR 0007：抖动仅在目标尺寸未被下游缩放时启用 与本条共用同一道几何门，两者的判定必须同源，不许各写一份。

标定档位属于 profile，不属于面板。

## 后果

**好的：**
- e-ink 路径的位深全集由 4 个降到 3 个，候选数同比收缩，判据求值与试编码开销一并减少。
- 排除了一个判据自己排不掉的错误解：8bit 在参照口径下永远误差最小，却在 e-ink 上买不到可见收益。
- 灰阶数进入主键后，分辨率相同而灰阶不同的面板不再共用一份 profile。

**要认的代价：**
- 阶梯图数出的是感知可分辨级数，不等于物理灰阶数。两者不必相等，`--gray-levels` 填的是前者。
- 「多余精度没到过眼睛」的前提是显示固件不再自行抖动。固件抖动是否存在尚未查证，查证之前，
  这条论证只落在「e-ink 恒 16」这一既有事实上。
- 未知面板的灰阶数欠一次实测，进表之前一律要求显式 `--gray-levels`。
- LCD 无硬上界，且无设备可标定，相关 profile 必须标注「未经标定」。

## 备选方案

**不裁剪，让判据挑。** 参照里没有面板，8bit 恒以零误差胜出；要让判据看见面板就得把显示模型塞进判据，比一个字段贵得多。

**把灰阶数并进阈值档位。** 档位是标定出来的、可调的，硬上界不是。混在一起，一次阈值放宽就能把 8bit 放回 e-ink 候选集。

**运行时向设备查询灰阶数。** 目标阅读器都不提供这个接口，读不到仍要回落到面板表，等于白多一条路径。

## 不要做的「简化」

- 不要用「灰调级数」称呼面板灰阶数。前者是内容侧的量，后者是显示属性，混用会让裁剪读起来像内容自适应。
- 不要因为 e-ink 上界落在 4bit 就删掉 8bit 编码路径：LCD 走全集，那条路径必须留着。
- 不要在几何门不成立时沿用 {1,2,4}。上界的依据是像素与灰阶对齐，对齐消失就得重测，不是照抄。
- 不要把面板表铺成设备清单。设备只是面板的别名，多对一，型号到面板的映射属于标定文档。
