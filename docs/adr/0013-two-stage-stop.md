# ADR 0013：两级停——收尾与中止

状态：已采纳（2026-08-26）

## 背景

会话里 TUI 进 raw mode，Ctrl+C 归它管；而 `Request` 里一个取消的口子都没有。
长任务跑到一半发现参数错了，现在只有一条路：杀进程。

停在哪一道边界上不是纯技术问题，因为两种容器的写法不同：
归档卷先写 `partial` 再改名，中途死掉只留一个改不了名的临时文件；
目录卷逐页直写，中途死掉留下**半卷散页**——而那些页各自带着完全正确的元数据。

## 决定

1. **收尾**：按停的第一级。当前卷跑完才停。盘上只有完整的卷，下一趟幂等接着走。
2. **中止**：按停的第二级，再按一次。立刻停，并把当前卷的**半卷删掉**。
3. 收尾与中止是 `run` 的能力，不是 TUI 私有的：命令行那一路同样用得上。

## 后果

**好的：**

- 第一级对得上卷这个不可分割的处理单元（ADR 0005），也对得上幂等的作用域——
  停下来的结果是一份可以接着走的输出，不是一个需要清理的现场。
- 第二级给出了「我现在就要停」的答案，而不必让用户拿 Ctrl+C 去赌终端能不能恢复。

**要认的代价：**

- 中止**删用户输出目录里的东西**。这是 tonefit 唯一一处主动删除。范围严格限定在
  「本次运行、本卷、已经写出去的那些成员」，且只在中止这一条路上发生。
- 一个几千页的卷，收尾可能要等几分钟——而那几分钟里你已经知道参数错了。
- `run` 要在卷边界与页边界各留一个检查点。

## 备选方案

- **只做收尾**——模型最干净、零删除代码，但把「我现在就要停」这个需求原样退回给用户。
- **只做页边界取消，不删半卷**——半卷在文件管理器里与一本处理好的书没有分别。
  幂等那一道会因为「输出不齐」重做它，结果不会错；但它和《失败》里的「过期副本」是同一类陷阱，
  而这一个是我们自己留下的。
- **中止时把半卷改名到 `_aborted/`**——多一个要用户理解的目录，而它的内容一文不值：
  下一趟必然重做整卷。
- **不拦 Ctrl+C**——终端可能停在 raw mode 与 alternate screen 里。

## 不要做的「简化」

「中止既然要删，收尾也顺手把上一趟的过期副本删了吧。」
过期副本是**上一趟**的产物，它的去留由用户定（见 `CONTEXT.md` 的《失败》）。
中止删的只有**本次运行写出去的**那些成员。两者作用域不同，混在一起就成了
「这个工具会删我不知道的东西」。
