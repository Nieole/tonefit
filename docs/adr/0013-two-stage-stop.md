# ADR 0013：两级停——收尾与中止

状态：已采纳（2026-08-26）；决定第 2 条修订（2026-08-26，目录卷改成整目录重写之后）；
决定第 3 条修订（2026-09-07，命令行接上 `Ctrl-C` 之后）；
《后果》最后一条修订（2026-09-07，摊开一整卷那一段接上检查点之后）

## 背景

会话里 TUI 进 raw mode，Ctrl+C 归它管；而 `Request` 里一个取消的口子都没有。
长任务跑到一半发现参数错了，现在只有一条路：杀进程。

停在哪一道边界上要看两种容器怎么写。两支现在同形：各写一格 `partial`
（归档卷的是文件，目录卷的是目录），改名成功才算数。中途死掉留下的只是一个
改不了名的临时容器，它从不出现在最终位置。

## 决定

1. **收尾**：按停的第一级。当前卷跑完才停。盘上只有完整的卷，下一趟幂等接着走。
2. **中止**：按停的第二级，再按一次。立刻停，当前卷那格 `partial` **直接丢弃**——
   那一卷等于没做，最终位置上一个字节都没动过。
3. 收尾与中止是 `run` 的能力，不是 TUI 私有的：**两边都按得动**。会话里是 `s`
   ——按一次收尾、再按一次中止；命令行上是 `Ctrl-C`——同样按一次收尾、按两次中止。
   **两边落到同一条闩、撞的是同一对检查点**：那一条闩是 `run` 自己记的「观察者答过的
   最强那一级」，两边按下的字都从观察者那条回路流进它；命令行没有另立一套停法，
   停在哪一道边界上仍由上面那两条定。第三下与第二下一个待遇——两级停就是两级。

## 后果

**好的：**

- 第一级对得上卷这个不可分割的处理单元（ADR 0005），也对得上幂等的作用域——
  停下来的结果是一份可以接着走的输出，不是一个需要清理的现场。
- 第二级给出了「我现在就要停」的答案，而不必让用户拿 Ctrl+C 去赌终端能不能恢复。
- 中止不必去最终位置删任何东西：丢掉**它自己建的**那格 `partial` 就够了。
  「这个工具会删我不知道的东西」这种顾虑因此不存在。

**要认的代价：**

- **命令行上 `Ctrl-C` 从此不是硬杀。**按下去要等一个检查点：中止那一级停在页边界上，
  等的是一页的功夫；收尾那一级要等当前卷跑完，而那可能是几分钟——按下之后屏上因此
  得当场说出按到了哪一级，不说的话用户会当它没收到、再按一下，而再按一下当前卷就丢了。
  真要立刻弄死这个进程仍有办法（`SIGQUIT`、`kill`），而那时盘上留下的只是一个改不了名的
  临时容器，它从不出现在最终位置（见《背景》）。
- 中止仍是一处删除，只是范围缩到了**本次运行自己建的那格 `partial`**。
  最终位置上的东西一个都不碰——包括上一趟留下的过期副本，它的去留仍由用户定。
- 一个几千页的卷，收尾可能要等几分钟——而那几分钟里你已经知道参数错了。
- **检查点要留在卷边界与页边界上，而它们不都在 `run` 里**（2026-09-07 修订，
  `p4-parking-lot/13` 收停车场 Q121）。卷边界那个在 `run` 的逐卷循环里，页边界那个由
  `process_volume` 摆在它每一个逐成员的循环头上——**外加读取那一层**：
  `.7z` / `.rar` 开工前要整卷摊到临时目录（ADR 0015 决定第 3 条），几百兆的卷上那是分钟级的
  一段，而它排在卷边界那一道之后、第一个页边界之前。从前那一段里**按中止不会立刻停**，
  要等整卷解完才停得下来，其间一条事件都不报，进度条一动不动。

  **开的是同一个检查点，不是第三种停法**：`source::extract` 那两遍顺序扫在**成员边界**上
  问的仍是页边界那一级（`Instruction::Abort`），报出去的仍是既有的 `Event::Stepped`——
  一个成员一步。「一个成员」与「一页」是同一道边界：摊开那一遍走的正是这一卷的成员表。
  **要认的代价有两笔**：读取那一层从此认得进度与指令，多一条跨模块的依赖
  （`source::open` 收一个 `progress::Events`，只列成员那一条不收）；
  以及**这一段停下来时交出的是一份半摊开的卷**——成员表齐、临时目录里只有停之前落下的
  那几个，靠调用方紧接着再问一次闩来兜住（闩只升不降，答案恒同）。
  盘上那半份不必手动收：它活在卷上，卷一丢临时目录整棵跟着走，本决定第 2 条
  「最终位置上一个字节都没动过」因此一格没变。

## 备选方案

- **只做收尾**——模型最干净、零删除代码，但把「我现在就要停」这个需求原样退回给用户。
- **中止时把写了一半的那格 `partial` 留在原地不清**——省几行代码，代价是重跑时要么撞上残留、
  要么每一趟都得先清一次；而它的内容一文不值，下一趟必然重做整卷。
- **不拦 Ctrl+C**——终端可能停在 raw mode 与 alternate screen 里。

## 不要做的「简化」

**「中止既然要清 `partial`，收尾也顺手把上一趟的过期副本清了吧。」**
过期副本是**上一趟**的产物，它的去留由用户定（见 `CONTEXT.md` 的《失败》）。
中止清的只有**本次运行自己建的**那一格。两者作用域不同，混在一起就成了
「这个工具会删我不知道的东西」——而本决定修订之后，那种顾虑本来已经没有了。
