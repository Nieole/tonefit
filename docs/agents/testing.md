# 写用例的三条手法

绿着的用例证明不了它自称在证明的事——下面三条各堵一种。

## 守卫按反跑一次

一条守卫用例落地时，把它守的那道守卫**按反**跑一次，亲眼看见红，才算夹具咬住了。

几道守卫串在一起时，上游那道失效，下游那道照样挡住，用例照绿。覆盖率会说那一行走过了——
确实走过了，只是走进了下游那道守卫。绿色本身就是这个病的伪装，没有工具会替你看出来。

按反那一遍看见了什么，写进票据的《落地记录》。

## 屏上改掉一句假话，留一条反着钉的断言

正着断言「现在这句对」，防不住后来有人把那句假话写回来。改掉一句，就留一条断言说**这句不许再出现**。
屏上的措辞没有别的守卫。

## 用例点名取值，不借默认值

默认值是一个会移动的锚：借了它的用例，在默认值改动的那一天静默失效。

- 用例要的取值写出来，不写 `default()`；
- 「改成 X」那一族里的 X 不许等于当前默认值——等于的话那一格是空操作，照绿；
- 一条用例里同一个数只有一个出处。
