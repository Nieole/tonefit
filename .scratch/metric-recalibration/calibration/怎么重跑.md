# 怎么从零重跑这一批

中间产物（参照页、候选图、`tiles.npz`、逐页 dry-run 读数）**都不入库**——它们由源素材
重算得出，几百 MB，留着不如留重算的路。这一份记的就是那条路。

结论与数在 `docs/measurements.md` 的《四条真机结论在现有判据形状下互不相容》，
这一份只管「怎么再跑一遍」。

## 前提

```
export PKG_CONFIG_PATH="<vcpkg>/installed/x64-windows-static-md/lib/pkgconfig"
cargo build --release
```

见 `.cargo/config.toml` 的《本机的 dav1d》。下面 `tf` 指 `./target/release/tonefit.exe`，
`P` 指 `-p "kobo libra 2"`，`W` 是一个临时工作目录。

**素材一律一手**（`_samples/` 在仓库之外）：武器種族傳說 v01 原档、N和S 与 Bowing！的
一手 B 类发布版、哆啦A梦 v15 的一手 8K 源目录。**不要用成品库**，也**不要开纸白对齐**
（`--white-align-limit` 保持 0）——理由见 `README.md` 的《口径自检》。

## 一、参照 8bit 与候选

参照是判据的「参照」那一侧，未量化：

```
tf <哆啦A梦 v15 源目录> -o $W/doraemon_ref8 $P --gray-levels 256 --bit-depth 8 --dither off
tf <N和S 第23话.cbz>     -o $W/ns23_ref8     $P --gray-levels 256 --bit-depth 8 --dither off
```

武器原档与 B 类那几话的参照 8bit 已经在 `_samples/_实验-判据重标定/` 下（`原档/参照8bit/`、
`真机包/参照8bit/`），不必重渲。

把要用的页按组抽进 `$W/ref8/<组名>/`，共 18 页：

| 组 | 页 | 来自 |
|---|---|---|
| `B_武器白底` | MHZ01_088-2 / 089-1 / 089-2 / 090 | 武器原档参照8bit |
| `C_N和S_43` | 001 / 005 / 009 / 013 | 真机包/参照8bit/第43话.cbz |
| `C_Bowing_16` | 001 / 004 / 008 / 012 | 真机包/参照8bit/第16话.cbz |
| `G_哆啦A梦闸1` | 1004-冒险游戏书-01-1 / 1046-梦游盒-04-2 / 0969-列车粉笔-01 / 1000-报仇传票-05-1 | 上面渲的 |
| `Q_棋魂垫底` | QH-01_0060 / QH-01_0148 | 棋魂源两页各自渲一遍参照 |

**几何要对得上**：闸① 那四页渲出来该是 1208 / 1141 / 1380 / 1140 × 1680，
与 AB 交错本答案表逐页一致。对不上就先查口径，别往下走。

六档候选，都由 tonefit 渲（**不要用脚本自己量化**——少一层等价性风险）：

```
for d in 1 2 4; do for dt in off fs; do
  tf $W/ref8 -o $W/cand/${d}bit_${dt} $P --no-crop --no-split --bit-depth $d --dither $dt
done; done
```

逐页六档的判据读数：

```
tf $W/ref8 -o $W/dry_out $P --no-crop --no-split --per-page --dry-run > $W/dry.txt
```

`dry.txt` 是软折行的，解析成 `dry.json`：正则先把整份压成一条流，再抓
`dry_out\ref8\<组>\<页>.png … 判定 X（…） 判据 1bit … 4bit+FS …`。

## 二、逐块四原始量 ＋ 口径自检

```
python export_tiles.py $W/ref8 $W/cand $W/dry.json $W/tiles.npz
```

**这一步就是自检**：它拿今天那四个常数重算每一页每一档，与 `dry.json` 比。
18 页 × 6 档 = **108 格，最大偏差要小于 0.01**（判据只印到小数点后三位），
对不上就非零退出。**没过这一条，后面的结果一个都不作数。**

## 三、可行域与诊断

```
python feasible.py $W/tiles.npz          # 161 万组网格，四条约束逐条判（约 25 分钟）
python diagnose.py $W/tiles.npz          # 把读数拆成两项，看缺口缺在哪一项
```

`feasible.py` 满足不了时**以非零退出**——那是它的正常结论，不是失败。

## 四、真机材料

```
python build_flat_ladder.py <武器原档参照8bit.cbz> $W/ladder      # L 组十五格
python build_anchor.py       $W/ref8/G_哆啦A梦闸1  $W/anchor      # N 组锚点
```

两组各自渲 `2bit off/fs` 候选并跑一次 dry-run，把读数解析成各自目录下的 `读数.json`
（格式 `{页名: {判定, 读数}}`）；M 组另把 N和S 第 23 话里白底占页最高的四页抽进
`$W/ref8_ns23/`，渲 `2bit fs` 与 `4bit off` 到 `$W/ns23_cand/`。然后：

```
python pack_device_bundle.py $W/真机包04     # 编成三本交错 cbz ＋ 答案键
python verify_bundle.py      $W/真机包04 $W  # 逐页比字节自检编排
python ladder_calibrates_floor.py $W/ladder  # 印「真机翻转点 → 地板比例」对照表
```

**`verify_bundle.py` 必须过。**页上没有标注（有标注就不是盲测了），编排对不对只能靠它
——第五轮整批作废正是栽在这里。
