# 判据重标定：颗粒项覆盖到所有位深，掩蔽认得出连续灰调

Status: ready-for-agent

## Problem Statement

一套参数批量转一整个库，不同作品的观感差异很大——同样是 `kobo-libra-2`、同样开着抖动，
五星物語读起来很好，武器種族傳說满屏麻子。用户的诉求是**批量启发式自动定参**，
不是逐部作品调参，而现在做不到。

这不是参数没调对，是**判据在 2bit 及以上少了一项**：

颗粒项 `visible_grain = 候选grain − 参照grain − 地板` 里的地板是一个绝对值 55，
而 FS 颗粒的上界是格点间距的一半——1bit 上 127.5、2bit 上 42.5、4bit 上 8.5。
**地板卡在 1bit 与 2bit 之间，因此颗粒项只在 1bit 上生效，2bit 及以上恒读零**
（measurements 的《颗粒项只在 1bit 上生效》，算术 + 合成图 + 仓库自己的用例三重证据）。

判据在那些档上于是只剩低通项，而 ADR 0002 决定第 5 条明写着单靠低通项会**结构性地偏袒抖动**
——颗粒项本来就是为防这件事而设的，它防漏了。后果在真实素材上量得出来：
目标工况 4436 页里 **69.3% 的页 4bit 不抖判据更优，68.1% 却因两档都在阈值内、按体积被选成 2bit+FS**。

第二处更细：**判据在同一档内部给页排序是有效的（ρ=+0.539，p=0.017），跨档选谁却无效甚至反向
（ρ=−0.240）**，而跨档正是判定要做的事。跨档的错误不是均匀的，**全部落在连续灰调素材上**
——19 页里其余 14 页判据与判读逐页一致，连续灰调那 5 页判据 0/5 偏 4bit、判读 5/5 偏 4bit。
嫌疑落在掩蔽加权：它按块内活动度给误差打折，而那两个常数 `MASKING_FLOOR` 与 `MASKING_KNEE`
至今是未标定占位值。

## Solution

判据动两处，重标一次：

**A 地板跟着格点间距走。** 地板不再是绝对值，而是格点间距的一个比例。下界有闭式解——
`sqrt(u(s−u)) − u` 的最大值在 `u/s = (2−√2)/4` 处取到 `0.2071·s`，代进 1bit 得 52.81，
与 measurements 记的 52.8 吻合，现行的 55 就是它乘安全系数 1.0414。**下界因此不必新标定**，
乘同一个安全系数即得三档的值：1bit 55.0、2bit 18.3、4bit 3.7。

**B 掩蔽认得出连续灰调。** `MASKING_FLOOR` 与 `MASKING_KNEE` 重定，判据在连续灰调上不再偏袒抖动。
这一处**没有闭式解**，要真机盲测夹出。

**C 一次真机标定同时定四个数**：地板上界、掩蔽两个常数、阈值。地板与掩蔽一改，判据读数全变，
阈值 5.5 立刻不成立——三者本来就是同一批盲测夹出来的，重标也该一次付清。

## User Stories

1. As a 用户, I want 一套参数转一整个库、不同作品的观感不要差这么多, so that 我不必逐部作品调参
2. As a 用户, I want 判据在 2bit 那一档上也说得出话, so that 它选档时不是只凭低通项
3. As a 用户, I want 大面积平坦网点色块的页不要被判成抖动, so that 衣服和脸上不再满屏麻子
4. As a 用户, I want 连续灰调的页选得到 4bit, so that 渐变不塌成生硬色块
5. As a 用户, I want 换到 4bit 的体积代价看得见, so that 我知道自己为观感付了多少
6. As a 用户, I want 报告里印出的判据构成说得出地板是怎么来的, so that 我能判断它对手上这块面板成不成立
7. As a 用户, I want 重标之后旧的输出全部不命中幂等这件事被明确告知, so that 我知道下一趟为什么全库重跑
8. As a 用户, I want `--threshold` 覆盖项在新判据下仍然可用, so that 我能在自己那台设备上自己夹一个界
9. As a 用户, I want 4bit 上不再白付抖动那笔字节, so that 同样的观感少花 6~11 MB
10. As a 维护者, I want 地板的取值由算术推出而不是调出来, so that 换一个位深不必重标一次
11. As a 维护者, I want 地板下界那条不变量在三个位深上都被用例钉着, so that 谁把比例调低了当场会红
12. As a 维护者, I want 修完之后判据与判读的跨档相关性由负转正, so that 我知道这一改真的修好了那件事
13. As a 维护者, I want 验收不必再付一轮判读人力, so that 已经花掉的 95 格判读数据能再用一次
14. As a 维护者, I want 真机那一轮只回答剩下的那几个数, so that 最贵的资源花在只有它能答的问题上
15. As a 维护者, I want 连续灰调上判据与判读的反向被一次真机判读了结, so that measurements 里「连续调彩色源上 2bit+FS 更优」那一行的存废有个交代
16. As a 开发者, I want `Composition` 仍然只带一个数, so that 报告那一行不必因为位深多了就变长
17. As a 开发者, I want 判据仍然是那个纯函数 seam, so that 数值测试与标定工具照旧调得动它
18. As a 开发者, I want 改动落在既有 seam 上, so that 不为这件事新开一个测试入口
19. As a 开发者, I want 黄金快照的变化是显式接受的, so that 判定的改变不被顺手覆盖掉
20. As a 开发者, I want ADR 0002 里已经不成立的那半句被就地改掉, so that 后来的人不照着过期陈述做决定

## Implementation Decisions

### A 地板：`Composition` 存归一化比例

- `Composition` 从 `{ grain_floor: f32 }` 改成 `{ grain_ratio: f32 }`，**仍然只有一个数**。
  地板由它乘格点间距算出：`floor(n) = grain_ratio × 255/(2^n − 1)`。
- `grain_ratio` 的值 **0.2158**（= 0.2071 × 现行安全系数 1.0414）。这个数保证 1bit 上算出
  55.0——与现行值逐位一致，**1bit 那一档的行为一格不变**。
- 报告《判据构成》那一行从「颗粒超出 55.0 灰度级」改成「颗粒超出格点间距 21.6% 的那一部分」。
  措辞仍只有一处出处（ADR 0016）。
- **为什么不存三个位深的表**：地板的本质是格点间距的一个比例，三个数之间的算术关系存进表里就丢了；
  而且上界至今只有 1bit 上有真机数据，一个数比三个数更好标定。

### B 掩蔽：两个占位常数重定

- `MASKING_FLOOR`（现 0.5）与 `MASKING_KNEE`（现 8.0）重新标定。方向由实测指出：
  判据在**连续灰调**上偏袒抖动，而掩蔽正是按块内活动度给误差打折的那一层。
- 活动度的量法（块尺度 32 px、取局部均值而非块内均值）**不动**——那一条有 ADR 0002 的论证
  与 measurements 的《位深盲测》撑着，画集 040 与 056 的分界就是靠它拉开的。
- 掩蔽加权只由参照定、与候选无关这一条**不动**：它是每页每块只算一次的前提，动它要重估吞吐。

### C 一次真机标定定四个数

- 地板上界（现行 1bit 上是 60，2bit/4bit 无数据）、`MASKING_FLOOR`、`MASKING_KNEE`、阈值。
- 标定材料用**一手素材**，不用成品库——两者的判读读数差着一档
  （measurements 的《判读的可辨性依赖材料是不是一手的》）。
- 判读要**整页 1:1**，不用局部放大块：局部块判不出整页尺度的现象
  （《成品库上判不出阈值的原因是空间尺度》）。对比成品已备好五组。

### 顺带认下的两件事

- **4bit 上抖动白付**：4bit 不抖与 4bit+FS 在两批材料、八位判读者、45 格上无一格判出差别，
  而体积差 6~11 MB。真机确认之后，4bit 那一档可以只留不抖，**候选集少一个** ——
  判据占单页 32%~73%，少算一个候选是直接的吞吐收益。
- **全库重跑**：地板与阈值都是参数哈希的输入，一改则旧输出全部不命中幂等。这一条写进 ADR 的
  《后果》——不写下来，将来没人知道那次全库重跑是从哪来的。

## Testing Decisions

好的用例只测**外部行为**：`run` 交出来的报告、`score` 算出来的数、印出来的那几行字。
不测私有函数、不主张任何具体秒数。

**三个 seam 全是既有的，一个都不新开。**

- **`score(&Reference, &GrayImage) -> Score`**——判据的纯函数形态。A 的端到端断言落这里：
  同一页同一候选，2bit 上的读数在地板改比例之后**必须变**（现在它恒等于纯低通项）。
  `tests/metric.rs` 的性质测试就是先例。
- **`composition()`**——地板本身。`grain_ratio` 乘各位深的格点间距，1bit 上必须仍是 55.0。
  下界那条算术不变量（`src/metric.rs` 的 `the_grain_floor_stays_above_what_an_undithered_flat_tone_pays`）
  **要从只管 1bit 扩成三档都管**：谁把比例调到 0.2071 以下，三档里任何一档当场红。
- **`run(&Request) -> Report`**——判定分布的变化。既有的卷级档位一致性、逐页判定、隔离目录、
  幂等跳过都在这里，新增的断言是同一批夹具在新判据下落到哪一档。

**要跟着改的既有断言**（它们钉的是旧形状，不是 bug）：
`tests/metric.rs` 的 `grain_below_the_visibility_floor_is_not_charged_for`（现在断言
4bit+FS「读数贴着零」——改比例之后 4bit 的地板降到 3.7，这一条要重新表述）、
`src/render.rs` 里印「颗粒超出 {:.1} 灰度级」的那一处。

**黄金回归会动。** 判据一改判定就变，快照要显式接受，不能顺手覆盖。

**验收：跨档相关性由负转正。** 用**已有的 95 格判读数据**（19 页 × 5 位，
measurements 的《第四轮》），修完之后拿同一批 19 页重算判据读数，对判读结果求 Spearman：

> 现状 ρ = −0.240（p=0.32）→ **改完应显著为正**。

判读问的是「图好不好看」，与判据算出什么无关，因此**这批数据不会因为改判据而作废**，
验收不必再付一轮人力。同档内部那一个（现 ρ=+0.539，p=0.017）**不得变差**。

**真实素材冒烟**照旧 opt-in，不提交任何素材。

## Out of Scope

- **迟滞的去留**（`.scratch/非阻塞问题.md` 的 Q205）。它明写着要等地板修好、
  spec `two-pass-rework` 那三条账（54 次换档 / 30 页降配 / 135 页被抬档）重测之后才谈得上——
  那三条账是在颗粒项恒零的判据下量的。
- **素材分类器与任何形态的模型**。三、四轮判读证明结构测量用算法更好（可复现、零成本、每页可算），
  模型在运行时没有位置；它剩下的三个位置（研发期探特征、离线生成标注、长尾兜底）都在管线之外。
- **活动度的量法**、掩蔽只由参照定这两条，见 Implementation Decisions。
- **判据聚合那三个数**（块边长 32、上分位 p99、K=8）。K 是未标定占位值，但它与本 spec 要改的
  两处正交，混进来会让一次标定要同时夹五个数。
- **`two-pass-rework` 的四件事**（遍名语义化、白付清理、逐页默认、滑窗幂等）。本 spec 只改判据，
  不动管线形状。两者在 P-C 上有交集——那边翻默认要重测的三条账，正是本 spec 修完之后才作数的。
- **成品库那一类素材的行为**。它不是目标工况（measurements 的《全库扫描》口径），
  本 spec 不为它调参。

## Further Notes

### 两道闸

- **闸 ①：真机判读第 5 组（哆啦A梦）。** 那一组上判据 0/3 偏 4bit、模型判读 3/3 偏 4bit，
  完全反向，而 measurements 的《A 类位深实测》记着「连续调彩色源上 2bit+FS 更优」——
  **那一行是判据算出来的，不是人标的**。两者必有一错，B 的方向取决于它。
  体积上不构成障碍：连续灰调换 4bit 只贵 1.02×。
- **闸 ②：地板改比例之后 1bit 的行为逐位不变。** `grain_ratio × 255 = 55.0` 是这一改动的
  兼容性底线；1bit 上一动，《位深盲测》整批数据的可比性就没了。

### 已经付过的账，可以再用一次

- **95 格判读**（19 页 × 5 位，一手素材，五类素材分层）——验收跨档相关性用它，零新人力。
- **对比成品五组**（`_samples/_对比-整页/整页对比\`，含体积表与判读说明）——真机那一轮的材料已备好。
- **地板的闭式解**——三个位深的值都在 measurements 里，不必重算。

### 判据不是全坏的

n=19 上判据在**同一档内部给页排序**是显著有效的（ρ=+0.539，p=0.017）。坏的只有跨档比较。
这决定了修法的形状：**不是重做判据，是补上它缺的那一项、修掉那一处偏袒**。
验收因此有两条，一条要变好（跨档），一条不得变差（同档）。
