# 03: 真机判读——连续灰调上哪一档对（闸 ①）

**What to build:** 一次真机判读，了结判据与判读在连续灰调上完全反向这件事。判据在那一类素材上 0/3 偏 4bit，五位模型判读者 3/3 偏 4bit，而 `docs/measurements.md`《A 类位深实测》记着「连续调彩色源上 2bit+FS 更优」——**那一行是判据算出来的，不是人标的**。两者必有一错，而 04 的四个数全建在这个方向上。体积不构成障碍：连续灰调换 4bit 只贵 1.02×。

材料是 **`AB对比（先看这个）.cbz`**：12 对页交错编排，同一页的两个版本**相邻**，翻一页就是一次 A/B 切换。跨文件切换要几秒到几十秒，而视觉工作记忆撑不住那么久——那时比的不是两张图，是一张图和一段褪色的印象。顺序随机、页上无标注，判完再对答案。12 对覆盖五类素材，闸 ① 占最后四对；其余八对是顺带收获，可能提前答掉 04 的一部分。

**这张票不能派给 subagent**，哪怕它读上去像一次判读任务。两条实测挡着：《成品库上判不出阈值的原因是空间尺度》——局部放大块判不出整页尺度的现象，而模型看的永远是喂给它的裁切；以及《第四轮》里 `2bit+FS` 判读者之间 ρ 只有 `+0.194`（`4bit不抖` 是 `+0.713`），它落在感知边界上，加判读者只会更精确地测出「它是 50/50」。派 agent 去判会拿回一个看着有效、实际定不了阈值的结论。
