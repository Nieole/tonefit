# 01: 地板跟着格点间距走

**What to build:** 颗粒项的可见度地板不再是一个绝对值，而是**格点间距的一个比例**。跑完之后，同一页同一候选在 **2bit 上的判据读数会变**——颗粒项在那一档不再恒读零，判据不再退化成只剩低通项；而 **1bit 上的行为逐位不变**，`_samples` 那批盲测数据的可比性因此保住。报告《判据构成》那一行改成按比例说，读的人仍然一眼看得出这个数是怎么来的。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `Composition` 带的是**一个数**（占格点间距的比例，值 0.2158），不是三档的表；地板由它乘 `255/(2^n − 1)` 算出
- [ ] 1bit 上算出的地板**逐位仍是 55.0**——这是兼容性底线，一动《位深盲测》整批数据就不可比了
- [ ] 取一页真实素材，同一候选在改动前后：**2bit 上的判据读数不同**，1bit 上相同
- [ ] `src/metric.rs` 里那条算术下界不变量从**只管 1bit 扩成三档都管**：谁把比例调到 0.2071 以下，任一档当场红
- [ ] `tests/metric.rs` 与 `src/render.rs` 里钉着旧形状的那两处断言已跟着改（前者断言 4bit+FS「读数贴着零」，后者印「颗粒超出 {} 灰度级」）
- [ ] 黄金快照的差异**逐条审查后接受**，不是顺手覆盖——判定变了才是这张票成立的证据
- [ ] ADR 0002 就地说明：决定第 5 条设的颗粒项原来只覆盖 1bit；**全库重跑**（地板进参数哈希，旧输出全部不命中幂等）写进《后果》
- [ ] 闸门三条绿
