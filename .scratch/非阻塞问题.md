# 停车场：实现途中撞见、但没有为它停下来的东西

**状态：** 长期（本轮队列全部票据共用）
**路径：** `.scratch/非阻塞问题.md` — 每一份派活说明都要交出这个路径

---

## 这个文件是什么

落地票据会撞出票面没预料到、或者票面写错了的东西。**其中几乎没有一件该让队列停下来。**
它们落在这里：**记下来、绕过去、接着走、收尾时逐条了结。**

它不是产品的长期缺口清单（那是 `CONTEXT.md` 的《尚未确立》）：

| | 《尚未确立》 | 本文件 |
|---|---|---|
| 装的是 | **产品**本身的缺口 | **执行**中冒出的问题——票面写错、规格没说、两处文档互相打架 |
| 寿命 | 比这一轮队列长 | **收尾时应当清空**——每条要么就地了结、要么升进《尚未确立》、要么另立一张票 |
| 谁读 | 下一个动这个产品的人 | 收尾那一步，以及拍板的人 |

---

## 停线——只有这三种

停下来很贵：拍板的人要把整个上下文重新装回脑子。门槛：

1. **继续做下去会写出错的东西，而撤销它要伸手到这张票之外。**
   典型：票面的指示与上游一条仍然生效的决定相抵触。
2. **动作不可逆，而且不止一个方向说得通。**
   典型：删掉或改名一个被多处引用的东西——一个 id、一个字段、一个文件。
3. **前提根本不在，这张票无从下手。**
   典型：「在 X 之上做 Y」，而 X 不存在。

其余一律：记在这里，走最站得住的那条路，接着做。**包括**票面给的数与你量出来的对不上、
验收条读着含糊、票面没想到的第三种情形、路过发现的无关缺陷，以及你确实拿不准的单项。

> ⚠️ **绕过去要留下痕迹。** 条目记的是**你走了哪条路**，不是「当时有两条路」。
> 说不出自己做了什么的条目不算条目。

### Q40 — 「不得在持锁处调观察者」这条性质没有真正的闸门，靠人看加一条弱用例

- **From:** 票 `p1-session/02`
- **Kind:** 确实拿不准的单项
- **Where:** `src/progress.rs` 的模块文档；`src/lib.rs` 的 `process_volume`（拼卷报告之前
  先把缓存用量读回来那一行）与 `Compute::page`；`tests/events.rs` 的
  `a_slow_observer_does_not_wedge_the_pipeline`
- **Why it did not block:** 这条性质说的是「**没有**发生某件事」，而 Rust 这一侧没有现成的形式
  把它表达成断言——`MutexGuard` 活到哪儿是编译期的作用域问题，跑起来看不见。
  真要拦得住，得给缓存那把锁包一层「持锁期间调观察者就 panic」的哨兵（线程局部的计数器），
  那是一件独立的加固，且只在调试构建上成立。
- **What this ticket actually did:** 逐个调用点核了一遍——五处报到（幂等那一道、第一遍每张源页、
  第二遍每张输出页与每个透传成员、卷级两条）都在锁外；把最容易踩的那一处**改写成明式**：
  卷报告原先在结构体字面量里 `cache: lock(&cache).usage()`，那个 guard 要活到整条 `let` 结束，
  而下一句就要把报告交给观察者——改成先 `let cache = lock(&cache).usage();` 把它掐在自己那一句里。
  闩用的是原子量而不是锁（`progress::Standing`），报到这条路上因此一把锁都不抢。
  用例那一侧留了一条下限：观察者每条事件睡 1 毫秒，整趟照样跑得完。
  **锁之外还握着两样，本票认下来但没有动**：`Stepped` 与 `PageFailed` 是在一条 rayon 工作线程上、
  且手里还攥着读取层那张在途字节额度（`read::Read` 的 `_permit`）时被调到的。两样都不是锁、
  都不会死锁，但观察者久不返回会把读取层背压闸住——那多半正是想要的（消费不动就别再读），
  真要让它不闸住，得在报到之前先把 `bytes` 与额度交出去。
- **Whose call:** 下一张动并发或缓存的票（要不要那个哨兵；报到要不要先放掉额度）
- **处置：** 待处理。

### Q42 — 点名的每一个归档卷，整趟都占着一个打开的文件句柄

- **From:** 票 `p1-session/03`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/survey.rs` 的 `Survey::of`；`src/source.rs` 的
  `Reader::Archive(zip::ZipArchive<BufReader<File>>)`
- **Why it did not block:** 票面要「枚举结果交给管线复用，不扫两次」，而归档卷那次枚举**就是**
  `ZipArchive` 本身——中央目录读出来之后住在它里面，放掉它就等于要再读一遍。
  因此预扫打开的卷全部留到各自被处理时，点名 N 个归档卷即同时占着 N 个句柄
  （目录卷不占：它的读取端只是一个 `PathBuf`）。眼下不咬人：处理范围是用户点名的子集
  （ADR 0009），一次几十个卷，而 Windows 的句柄上限是百万级、Linux 默认软上限 1024。
  真要摘掉这笔代价，只有让枚举与「取字节的那一半」分家——那要改 `source::Volume` 的形状，
  是一件独立的事。内存那一侧同量级、更小：一份中央目录约每成员几十字节。
- **What this ticket actually did:** **认下这笔代价，写进 `src/survey.rs` 的模块文档**
  （《要认的代价》那一段），并说清它是「不扫两次」的必然结果而不是疏忽。
  没有引任何句柄池或惰性打开。
- **Whose call:** 拍板的人（点名上千个归档卷要不要支持）
- **处置：** 待处理。

### Q56 — `calibrate` 子命令读不到预设，而标定图挂在**设备层**上

- **From:** 票 `p1-session/07`
- **Kind:** 路过发现
- **Where:** `src/main.rs` 的 `Cli`（`args_conflicts_with_subcommands = true`）与
  `Command::Calibrate`；`CONTEXT.md` 的《会话》「设备层里还挂着标定图」那一段
- **Why it did not block:** `--preset` 是顶层参数，而 `args_conflicts_with_subcommands`
  让顶层参数与子命令互斥——`tonefit calibrate --preset 漫画` 因此解析不出来。
  眼下不咬人：`calibrate` 自己收 `-p` 与 `--gray-levels`，两项都填得出来，
  只是配好一份预设之后出标定图仍要把型号再敲一遍。要通，得给子命令自己加一个
  `--preset`（各自一份解析，两处都要说清读的是设备层那一半），或者把
  `args_conflicts_with_subcommands` 拆细——后者会动到处理卷那一路的必填项判定。
  `CONTEXT.md` 说「设备层里还挂着标定图」，而那句话的落点是**会话**（`13` 号票），
  不是命令行。
- **What this ticket actually did:** **没有碰 `calibrate`。**`--preset` 只作用于处理卷
  那一路，`calibrate` 的两项照旧自己填。
- **Whose call:** `13`（会话里出标定图）——它是第一个真要把预设与标定图接起来的地方
- **处置：** 待处理。

### Q57 — 《会话》的**口味层**词条列着六项，而口味层现在有十一项

- **From:** 票 `p1-session/07`
- **Kind:** 票面写错了 / 两处文档互相打架
- **Where:** `CONTEXT.md` 的《会话》，**口味层**那一行（「第二层：这一趟的立场——滤波器、
  位深、抖动、逐页、缓存预算、读取策略」）；`src/preset.rs` 的 `TasteLayer`
- **Why it did not block:** 页几何那一批给口味层添了五项（适配方式、裁边、拆分、拆分阈值、
  阅读方向），而那一行没跟着改。本票的派活说明明写着要把它们一并列上，`08`（会话骨架）
  的票面也这么写——那一行因此**已经落后于两张票**，不是本票造成的。
  它与 Q54 是同一类：一个说设备层少列一项，一个说口味层少列五项，改法也是同一个决定。
  **它还使一条论证站不住**：口味层不收 `--dry-run` 与 `--no-metadata` 这个判断，
  一度是靠「它们不在那张单子上」立的——而那张单子同时漏掉了五项已经落地的东西，
  当不了那个论据。
- **What this ticket actually did:** **没有动 `CONTEXT.md`**（改写已有词条是领域决定）。
  十一项按票面要求全部落地，那张清单连同「哪五项是页几何添的」写在 `preset::TasteLayer`
  的文档里。**把那条论证换掉了**：`--dry-run` 与 `--no-metadata` 不进口味层，
  按它们各自是什么判——一个是这一趟做到哪一步（`Mode`），一个是对这一批输出的处置——
  不再引用那张单子。
- **Whose call:** 拍板的人（那一行要不要补上页几何那五项）；`08` 是下一个会撞上它的票
- **处置：** 待处理。
