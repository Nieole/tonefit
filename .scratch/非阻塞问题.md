# 停车场：实现途中撞见、但没有为它停下来的东西

**状态：** 长期（本轮队列全部票据共用）
**路径：** `.scratch/非阻塞问题.md` — 每一份派活说明都要交出这个路径

---

## 这个文件是什么

落地票据会撞出票面没预料到、或者票面写错了的东西。**其中几乎没有一件该让队列停下来。**
它们落在这里：**记下来、绕过去、接着走、收尾时逐条了结。**

它不是产品的长期缺口清单（那是 `CONTEXT.md` 的《尚未确立》）：

| | 《尚未确立》 | 本文件 |
|---|---|---|
| 装的是 | **产品**本身的缺口 | **执行**中冒出的问题——票面写错、规格没说、两处文档互相打架 |
| 寿命 | 比这一轮队列长 | **收尾时应当清空**——每条要么就地了结、要么升进《尚未确立》、要么另立一张票 |
| 谁读 | 下一个动这个产品的人 | 收尾那一步，以及拍板的人 |

---

## 停线——只有这三种

停下来很贵：拍板的人要把整个上下文重新装回脑子。门槛：

1. **继续做下去会写出错的东西，而撤销它要伸手到这张票之外。**
   典型：票面的指示与上游一条仍然生效的决定相抵触。
2. **动作不可逆，而且不止一个方向说得通。**
   典型：删掉或改名一个被多处引用的东西——一个 id、一个字段、一个文件。
3. **前提根本不在，这张票无从下手。**
   典型：「在 X 之上做 Y」，而 X 不存在。

其余一律：记在这里，走最站得住的那条路，接着做。**包括**票面给的数与你量出来的对不上、
验收条读着含糊、票面没想到的第三种情形、路过发现的无关缺陷，以及你确实拿不准的单项。

> ⚠️ **绕过去要留下痕迹。** 条目记的是**你走了哪条路**，不是「当时有两条路」。
> 说不出自己做了什么的条目不算条目。

  （《展开》《折行》《砍列》《视口》），连同 `p3/12` 与 `p4/11` 后来按同一类并进去的几点；

### Q241 — 收编按**字面路径**认「同一个卷根」：大小写、`./`、软链，三种写法都折不到一起

- **From:** 票 `p4-parking-lot/15`（大小写那一半由评审补上）
- **Kind:** 本票造出来的新形状（收编的边界）
- **Where:** `src/discover.rs` 的 `Found` 那张 `HashMap<PathBuf, …>`；对照
  `src/lib.rs` 的 `collision_key`（撞名那一道按平台折大小写）
- **Why it did not block:** 收编按 `PathBuf` 本身查，而 `Path` 的相等**逐字节**比，
  在哪个平台上都一样。三种写法因此认不出是同一个卷根，Q111 那个形状原样回来
  ——同一卷做两遍、写两份，去处还不同，撞名那一道也拦不住（它比的是**去处**）：
  1. **大小写**（Windows／macOS 上最容易撞见的一种）：`tonefit --out D:\out D:\库 d:\库\作品`
     ——盘符大小写不同就够了，一个是手敲的、一个是补全或粘贴来的。
     `Path` 不折大小写，两边各展一遍。
  2. **`.` 与相对写法**：`tonefit 库 ./库`。
  3. **软链**：点名一条软链与它指向的那棵树。
  第 2、3 种要同一条命令行上把同一个库写成两种写法，场合很窄；**第 1 种不窄**——
  在不区分大小写的文件系统上，两种写法指的就是同一个文件。
- **What this ticket actually did:** **没有规范化。** 本票的派活说明写死了可动的文件
  （`src/discover.rs`、`src/survey.rs`、它们的用例、`tests/discovery.rs`，加两份 markdown），
  而这三种都要一把「文件系统认不认成同一个东西」的尺子，那把尺子已经在
  `src/lib.rs` 的 `collision_key` 上（撞名那一道用它，`normalises_an_extension`
  的文档明写「与比去处同一把尺子」）——在 `discover` 里另抄一把就是第二个出处，
  而把它开成 `pub(crate)` 要动 `src/lib.rs`，落在本票之外。
  **评审驳掉的一条理由记在这里**：本条初稿写的是「规范化会把报告里印的那条路径换掉」，
  那不成立——`at` 那张表的**键**可以取规范化过的形式，而 `Candidate::root`
  照旧留用户点的那一条。第 1 种（大小写）尤其便宜：`collision_key` 一个平台折叠就够，
  一次系统调用都不必付。第 2、3 种要 `crate::resolve`（`std::path::absolute` 加
  `canonicalize`），那是逐个候选一次系统调用，另一笔账。
- **Whose call:** 拍板的人（收编按哪把尺子认「同一个卷根」——字面、按平台折大小写、
  还是解析到规范路径）
- **处置：** 待处理。

### Q242 — 本轮撞见的三次假结果：一次假红、一次拼接出来的假红、一次跑了别人产物的假绿

- **From:** 票 `p4-parking-lot/15`
- **Kind:** 路过发现（工具链，不是产品）
- **Where:** `/tmp/tonefit-B` 上跑的 `cargo test` 与 `cargo xtask gate`
- **Why it did not block:** 成因是一条，记在 **Q244**；这一条只记撞见的**现象**，
  因为三次各自的样子不一样，下一个撞上的人要认得出来。
  1. **假红**：收编落地之后 `cargo test --lib` 全绿，而 `cargo test --test discovery` 红，
     新加的四条各报「同一个卷做了两遍」；不动一个字符再跑一次仍红，cargo 印的是
     `Finished`（判定全都新鲜、一行不重编）。改一行触发重编之后全绿，改回去再跑照旧全绿。
  2. **拼接出来的假红**：为了验红，`Found::absorb` 被临时改坏过两次——一次摘掉「点名的」
     那顶帽子（只该红 `a_named_path_swallowed_…`），一次改成按点名路径的前缀折
     （只该红 `a_junk_directory_named_on_its_own_…`）。两次各自跑完都把源恢复了
     （`md5sum` 核过逐字节相同），随后跑闸门——闸门 1 红，红的正是**那两条**。
     **没有任何一版源码同时带着这两个毛病**：跑起来的那个二进制是从两次实验的产物里拼出来的。
  3. **假绿**：加了 `flock`、又先 `touch` 过一遍源码的那一趟闸门，三条全绿——
     而闸门 2 把 `tests/discovery.rs` 报成 **12 个用例**（本树是 20 个）、lib 报成 **216**
     （本树是 213）。查 `.d` 文件才看出来：那个二进制是 `/tmp/tonefit-A` 编的。
     闸门 1 也是**混的**（lib 与 `discovery` 是本树的，`unittests src/main.rs`、`pipeline`、
     `events`、`exit_code`、`container` 是别的树的）。**绿在那种情况下什么都没证明。**
  **认它的办法只有一个**：查 `target/**/deps/<name>-<hash>.d` 的头一行，
  那里写着这个产物是哪棵树编出来的。
- **What this ticket actually did:** 前两次各重编一遍绕过去；第三次查出了根因，记进 **Q244**，
  并按拍板的人的决定**停下不再跑闸门**——本票的《数》因此写「待主仓闸门」。
- **Whose call:** 见 Q244（同一条决定）
- **处置：** 待处理（随 Q244 一起了结）。

### Q243 — 收编之后，几个点名路径之间的**卷序**随点名次序而变，而输出树不变

- **From:** 票 `p4-parking-lot/15`（评审撞见）
- **Kind:** 本票造出来的次序变化
- **Where:** `src/discover.rs` 的 `Found`（候选按**头一回被发现**的次序排队）
- **Why it did not block:** `tonefit 库/作品 库` 与 `tonefit 库 库/作品` 得到的输出树、卷数、
  非卷文件清单逐条相同（本票的验收要的就是这个），而**报告里的卷序**与进度条上卷的先后
  不同：前者先出 `库/作品` 底下那几卷、再出 `库` 底下别的卷，后者是纯粹的先序阅读顺序。
  `discover::of` 的文档说的是**一个点名路径**展开出来的那一批按先序深度优先排
  （「报告里的卷序因此与文件管理器里看到的一致」）——那一句仍成立；跨几个点名路径的次序
  从来是「用户点名的次序，各自内部按阅读顺序」，本票没有改这条，只是收编让一个卷可以
  被**里层**那个点名先占下座位。
- **What this ticket actually did:** **留在「头一回被发现就占座」这条上**，并把它写进
  `Found` 的文档。另一条路是收编到外层时把那一格连同它那一批**重排**成外层展开的次序——
  那要在收编时移动已经排好的候选，而「卷序」本身是次序的次序（点名次序 × 阅读顺序），
  重排哪一半是领域决定，不是实现细节。
- **Whose call:** 拍板的人（几个点名路径重叠时，卷序按点名次序还是按最外层那一棵的阅读顺序）

### Q244 — 几棵 worktree 在 cargo 眼里是**同一个包**：产物同名可互换，而 cargo 判它新鲜

- **From:** 票 `p4-parking-lot/15`
- **Kind:** 路过发现（并行方案的根因；本轮并行最值钱的一条）
- **Where:** `/tmp/tonefit-A/target`、`/tmp/tonefit-B/target` 都是软链，指向
  `/home/alex/workboox/tonefit/target` 那**同一个目录**；三条线同时在里面编、在里面跑
- **Why it did not block:** 两层，第二层才是根子。
  1. **cargo 的构建锁只盖编译、不盖跑测试。** 编译一结束锁就放了，测试二进制是锁外跑的：
     甲线正在跑测试的当口，乙线可以把同一个二进制重编覆盖掉。
  2. **三棵 worktree 在 cargo 眼里是同一个包**——单元哈希逐字相同
     （闸门 2 的 `discovery-5700301a8122a718` 在 A 树与 B 树上是同一个文件名），
     产物因此**同名、可互换**，而 cargo 判它「新鲜」、直接拿来跑。
  两条推论，都验过：
  - **`flock` 挡不住。** 锁只保证不同时跑，不保证跑的是**自己那棵树**编出来的东西。
    加锁跑出来的那一趟闸门照样混着别人的产物（现象见 Q242 第 3 条）。
    它**既造得出假红，也造得出假绿**，而假绿更贵——绿了就没人再查。
  - **`touch` 自己的源码也救不了。** 那些单元的 dep-info 记的是**另一棵树**的文件路径，
    touch 本树的文件对它没有任何影响。撞见的那一趟正是先
    `touch src/*.rs tests/*.rs tests/fixtures/*.rs` 再加锁跑的。
  要让 cargo 真去重编，只有让那几个单元失效：`cargo clean -p tonefit`
  （默认目录与两个闸门目录各一次），或者让本树的单元哈希与别人的不同。
  而 `clean` + 闸门意味着**每次闸门都整棵重编**（十几分钟）：余下三十张票各至少一次，
  合计五到七小时纯编译且全串行；在主仓串行跑则是增量，一两分钟一次、总计约一小时。
  **并行只要碰编译就是负收益。**
  这与 `docs/agents/gate.md`《为什么各用各的目录》记的不是一回事：那一节记的是
  **特性组合**来回切造出的假红，这一条是**几棵 worktree 共用一个 target**造出来的。
  也不是 Q118 那种计时抖动：撞见的用例都与时间无关，源码 md5 与好版本逐字节相同。
- **What this ticket actually did:** 查出根因、验过上面两条推论，并把它报给了拍板的人。
- **Whose call:** 已拍板（见处置）
- **处置：** **共用 target 的并行方案就此作废，改成「支线只写、主仓合流后跑闸门」。**

### Q364 — 记住的那一格是**一个进程一个**，不是一个挂载点一个

- **From:** 票 `p4-parking-lot/23`
- **Kind:** 落地时走的那条路（记住的粒度）
- **Where:** `src/session/complete.rs` 的 `remembered`（一个 `OnceLock<Case>`）
- **Why it did not block:** 大小写敏感性是**挂载点**的性质，不是进程的：
  ADR 0009 的决定第 2 条就站在旁边——它说的是介质探测「同一次运行里不同路径各自判定，互不影响」，管的是寻道惩罚与并发度、不是大小写，
  因此不是直接冲突；但那一条的**原则**（文件系统的性质按路径各判各的）与这一格的做法相左，记在这里。
  macOS 上可以挂一个大小写敏感的 APFS 卷，Linux 上也可以挂 ciopfs。
  一个会话里补全先打到 A 卷、后打到 B 卷时，B 卷拿到的是 A 卷那个答案。
  票面要的是「多探一次，把结果记住」，一格记住的东西是最小的那一种做法，落得下去。
- **What this ticket actually did:** 一个进程探一次、记一格，跨挂载点不重探。
- **Options:** ① 一格（照现在）；② 按目录或挂载点记一张表（`Mutex<HashMap>`），各答各的。
- **Recommend:** ①。这个模块的性质就是**记不住任何东西**（ADR 0009：不递归、不建索引、
  不缓存），一格 `bool` 是对那条性质最小的偏离，而 ②要引一张会长大的表和它的失效问题——
  正是 ADR 0009 关掉的那件事的小号版本。跨挂载点补全在会话里少见，
  而答错那一边的代价只是多列或少列几项候选，不写任何东西。
- **Whose call:** 拍板的人
- **处置：** 待处理。
