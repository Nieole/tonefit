# 停车场：实现途中撞见、但没有为它停下来的东西

**状态：** 长期（本轮队列全部票据共用）
**路径：** `.scratch/非阻塞问题.md` — 每一份派活说明都要交出这个路径

---

## 这个文件是什么

落地票据会撞出票面没预料到、或者票面写错了的东西。**其中几乎没有一件该让队列停下来。**
它们落在这里：**记下来、绕过去、接着走、收尾时逐条了结。**

它不是产品的长期缺口清单（那是 `CONTEXT.md` 的《尚未确立》）：

| | 《尚未确立》 | 本文件 |
|---|---|---|
| 装的是 | **产品**本身的缺口 | **执行**中冒出的问题——票面写错、规格没说、两处文档互相打架 |
| 寿命 | 比这一轮队列长 | **收尾时应当清空**——每条要么就地了结、要么升进《尚未确立》、要么另立一张票 |
| 谁读 | 下一个动这个产品的人 | 收尾那一步，以及拍板的人 |

---

## 停线——只有这三种

停下来很贵：拍板的人要把整个上下文重新装回脑子。门槛：

1. **继续做下去会写出错的东西，而撤销它要伸手到这张票之外。**
   典型：票面的指示与上游一条仍然生效的决定相抵触。
2. **动作不可逆，而且不止一个方向说得通。**
   典型：删掉或改名一个被多处引用的东西——一个 id、一个字段、一个文件。
3. **前提根本不在，这张票无从下手。**
   典型：「在 X 之上做 Y」，而 X 不存在。

其余一律：记在这里，走最站得住的那条路，接着做。**包括**票面给的数与你量出来的对不上、
验收条读着含糊、票面没想到的第三种情形、路过发现的无关缺陷，以及你确实拿不准的单项。

> ⚠️ **绕过去要留下痕迹。** 条目记的是**你走了哪条路**，不是「当时有两条路」。
> 说不出自己做了什么的条目不算条目。

> **拍过板的结论要进代码旁边。** 一条条目拍了板、而它约束着某处代码时，落地的人在那一处留一句注释、
> 指着条目号——后来读代码的人撞得到它，不必先知道停车场里有过这一条。

---

## 什么才值得记一条

一条条目是**你走过的一个岔口**，不是你做过的一件事。三道检验，三道都要过：

1. **另一条路也说得通。**写得出那条路，而且它不是稻草人。只有一条路说得通就没有岔口——
   做了什么写进提交，不写进这里。
2. **翻过来只在这张票之内。**拍板的人日后选另一条，代价是改几处，不是把落了地的东西拆回来。
   翻过来要伸手到这张票之外，那是**停线**，不是一条条目。
3. **你推荐得出一条。**走过那条路，你手上的上下文说得出哪条该留下。
   交出一个耸肩的条目，连你的上下文一起交出去了——而往后挪，图的就是那一批了结时读得便宜。

每条条目的字段，照这个文件一贯的写法：`### Q<n> — 一句话说岔口是什么`，下面
**From**（票 `<effort>/NN`，必填——编号里不带票）、**Kind**、**Where**（路径加行号或标识，点得过去）、
**Why it did not block**（差在停线三条的哪一条）、**What this ticket actually did**（必填）、
**Why it matters**、**Options**（两条以上）、**Recommend**（必填）、**Whose call**、**处置：** 待处理。

编号全文件一条序列。并行派活时每份派活说明分到一段编号，只用自己那一段；用不完留空号，不补。

- **What this ticket actually did:** 一个字没动它。`cargo xtask gate` 头一条红了就停，而 `cargo test` 在头一个红的测试二进制上

  闸门 3 走 `cargo xtask gate 3`。数记在票据的《数》里，红的那一条两头都点名。

- **Options:** ① 给 macOS 补第三种问法：`/dev/fd` 列出本进程的描述符，逐个 `fcntl(F_GETPATH)` 取路径
  （`libc` 已是 dev 依赖），按 `root` 过滤——阳性对照与主断言在这个平台上都恢复检出力；
  ② 两种问法都答不出的平台上，这一条**明写跳过**（走自带 harness 那样分得清「跳过」与「跑过了」），不再假装问过；
  ③ 只在 `docs/agents/gate.md` 写一句「macOS 上这一条已知红、闸门改用 `--no-fail-fast` 跑」。
- **Recommend:** ①。③ 等于承认闸门在这台机器上没有检出力；② 诚实但把这台机器上的检出力整个让掉，
  而这正是日常做票的那一台。
- **Whose call:** 拍板的人（归 `green-counts` 那一批，或另立一张票）

### Q997 — stdout 上几何与门两件照搬报告那几行：没裁白边的页不印裁前裁后，门那一句说「检查了 1 页灰度页」

- **What this ticket actually did:** 几何那一行是逐页几何那一行（`geometry_cells`）：裁白边那一格**只在真裁过时在场**——
  这是那一格的既有规矩（`Field::Crop`），没裁过的页因此不印裁前裁后。门那一行借的是卷级尺寸贴合检查那一行

- **Why it matters:** 读验收的人可能以为「裁前／裁后」每一叠都要印；而门那一句是卷级的口吻，一叠只有一页时读着略绕，

  ③ 只把裁白边那一格在样张上改成恒在，门那一句照搬。
- **Recommend:** ①。样张的每一页与报告里的一页同一个形状（`ProofPage::page` 就是 `PageReport`），
  同一件事两处说法不同才是要防的；「一格在不在场本身就是一句话」是报告那一侧已经立住的规矩。
- **Whose call:** 拍板的人（验收条是它写的）
- **处置：** 待处理。

  摊不下回 `Err` 时那一格也照写（`say-and-stop/07` 要没做成的卷带计时，摊开失败正是一种）。
  代价是 `(Events, &mut Duration)` 一对穿过 `open` → `OpenVolume` → `open_*` → `extract` 四层（`/code-review` 记作 Data Clumps）。
- **Why it matters:** `design-parity/13` 与 `say-and-stop/07` 都站在这条边界上；`process_volume` 的接口宽（Q1068）是另一刀，本票没碰。
- **Options:** ① 现状（交一格进去，开工与掐表挨着在 `extract`）；② 在 `process_volume` 里围着整句 `source::open` 报开工、掐表——
  要先知道这一卷摊不摊开（清点那一份或 `container_of` 再问一次），开归档头与列成员算进摊开，屏上「开卷」那一格在要摊开的卷上一闪都没有；

- **Recommend:** ①。②把「开卷」与「摊开」混成一段；③换来的只是 `process_volume` 里少一个出参，代价是 `source` 那一层的改写与一次多余的解头；④让 07 号票拿不到失败卷的摊开耗时。

### Q1100 — 「段外不再含摊开」钉成一条上界断言：段外那一截小于用例自己磨蹭掉的那一段

- **From:** 票 `say-and-stop/03`
- **Kind:** 用例手法的取舍
- **Where:** `tests/timing.rs` 的 `an_extracted_volume_times_its_extraction_and_nothing_of_it_falls_outside_the_segments`
- **Why it did not block:** 断言里的时长仍只是用例自己摆的那一段（`waits`，文件抬头的规矩），只是这一次它当上界用。
- **What this ticket actually did:** 观察者在摊开途中每步睡 100ms（三步，`waits` = 300ms），断言摊开那一段 ≥ `waits`、段外那一截 < `waits`。
  改之前按反跑过：段外是 243ms（那时 60ms 一步）、摊开那一格不存在；改之后本机量到段外 0.8ms。
  `waits` 由夹具交回的成员数乘出来，不另写一个成员数。
- **Why it matters:** 上界断言理论上会在极重的负载下误红——段外要装两遍列成员、查撞名、汇总这些零头，平时是亚毫秒到几十毫秒。
- **Options:** ① 现状；② 只留「摊开那一段 ≥ `waits`」一句——断言里再没有对机器快慢的上界，永远不会因负载误红；
  而「段外不含摊开」由它间接推出：段外是减出来的，摊开那一段装下了磨蹭的那一截，段外就没有它（前提是段不重叠，那条等式另钉着）。
- **Recommend:** ①。票面那一条验收说的就是段外，直接断言比推出来的好读；300ms 对亚毫秒的余量够宽。真在 CI 上误红过一次再退到 ②。
- **Whose call:** 协调人
- **处置：** 待处理。
