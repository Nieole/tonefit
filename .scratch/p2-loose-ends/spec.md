# p2-loose-ends — 停车场收口

**Status:** ready-for-agent

## Problem Statement

五十三张票落地之后，停车场攒下 34 条「记下了、没停下来」的条目。它们不是缺陷清单——
每一条都写着当时为什么走得过去——但其中二十条已经积成了四类真问题：

1. **闸门有洞。** `cargo test` 只走默认特性。会话那六十几条用例整个在 `tui` 后面，
   `--no-default-features` 那一趟一条都编译不到；`profiling` 那一半连编译都没人验。
   闸门盖不住的地方，后面每一批的绿都打折扣。
2. **同一件事在仓库里有几个说法。** 兜底上界那道线三处给出 24:1 / 12:1 / 16:1；
   互锁 ③ 的判定两处形态靠一句 `debug_assert!` 拴着。
3. **失败的口径与退出码对不上词汇表。** 卷根整个消失走页级失败→隔离（`2`），
   而它是「这一卷没做成」；输出根写不进去每卷各记一笔（`3`），而它是「这一趟的参数错了」（`1`）。
4. **会话上有一批用起来会咬人的毛边。** 中文长句在终端上一个空格都没有、因此不折行，
   窄屏上把「q 退出」整个挤出屏；预设存得进删不掉，覆盖一份要把手写注释丢掉；
   一趟跑着的时候展不开，而报告正是那时在长。

加上一件剖面量出来的：归档卷的幂等这一道占整趟 27%，几乎全是把源字节再串行 deflate 一遍。

## Solution

二十条按四段收口，闸门排头——闸门补齐之后，后面三段的红绿才真算数。

每一条的原文、当时为什么没停、以及「谁该拍这块板」都在 `.scratch/非阻塞问题.md`
的《待处理》里，票不复述，只写要做成什么样。

## User Stories

1. 作为改这个仓库的人，我希望 `cargo test` 一条命令能盖住关掉终端库那条路，这样我改状态机时不必记得多跑一遍。
2. 作为改这个仓库的人，我希望 `profiling` 那一半也有人编译，这样往 `Stage` 加一格时漏在别处会当场红。
3. 作为改这个仓库的人，我希望「不得在持锁处调观察者」这条性质有个哨兵，而不是靠下一个人再核一遍五个调用点。
4. 作为读文档的人，我希望兜底上界那道线只有一个说法，这样我不必猜 24 / 12 / 16 哪个对。
5. 作为读代码的人，我希望互锁 ③ 只有一处判定，而不是两处形态加一句 `debug_assert!`。
6. 作为跑一批卷的人，我希望「一卷点不开」与「一卷全是坏页」在退出码上分得开，这样脚本能按码分岔。
7. 作为跑一批卷的人，我希望 `--out` 指错时开工前就被拒（`1`），而不是每一卷各撞一次报同一句话。
8. 作为在 6 寸设备上用窄终端的人，我希望帮助与报告里的中文长句折行，而不是从行尾切掉。
9. 作为在窄终端上开会话的人，我希望屏底那一行不把「q 退出」挤没——不知道怎么退出是最难受的一种卡住。
10. 作为会话里试参数的人，我希望一趟跑着的时候也能展开某一卷的逐页，因为报告正是那时在长。
11. 作为攒了几份预设的人，我希望在会话里删得掉一份，而不是退出去手改 TOML。
12. 作为手写过 `presets.toml` 的人，我希望覆盖一份预设不会把我的注释与排版抹掉。
13. 作为在会话里改阈值的人，我希望屏上不写「命令行指定」——我明明是在会话里打的。
14. 作为在 Windows 上敲卷名的人，我希望逐层补全不因为大小写不同而筛掉本该匹配的那一项。
15. 作为跑归档卷的人，我希望幂等那一道不要占掉整趟四分之一的墙钟。
16. 作为一次点名上千个归档卷的人，我希望不因为句柄占满而跑不动——或者至少被明确告知这个上限。

## Implementation Decisions

### 缝

**不新开缝。** 三个既有的缝（`run(Request) -> Report`、`score(&Reference, &GrayImage) -> Score`、
`write_calibration_chart(&Profile, &Path)`）加上会话那个纯状态机
（`Session::action(key) -> Action`）够用：本 spec 二十条全部落在这四处之内或它们的下游。

### 闸门

闸门从一条命令变成**三条**：`cargo test`、`cargo test --no-default-features`、
`cargo check --features profiling`。第二条要求会话的**状态机**搬到 `tui` 之外
（它本来就不 `use` 任何终端库，搬出去是把这个事实变成结构），绘制与 crossterm 翻译留在 feature 后面。

### 退出码与失败口径

`CONTEXT.md`《失败》是这一段的判准，改的是实现不是词条：

- **卷根整个消失** → 卷级失败（`3`），不再走页级失败→隔离。判据是「一页都没成的卷不算做出来了」。
- **输出根写不进去** → 开工前探一次，拒绝执行（`1`）。`Sink::create` 逐卷那条路仍在
  （单卷权限不同、某一卷去处被占到得了那里），只是不再由它承担「参数错了」这一种。

### 会话

- **折行**：界面层出一套按显示宽度折行的工具，帮助、报告、屏底三处共用。屏底那一行改成可折。
- **`Mode` 拆两维**：跑没跑是一维，在看什么是另一维。`p1-session/10` 与 `11` 各自判过「不拆」，
  依据都是「本票不需要」；本 spec 需要，因此拆。
- **预设**：补一个删；写入端换成保住格式的那一种（`toml_edit`），覆盖不再重排整份文件。

### 性能

归档卷幂等那一道并行化，**要改一条领域决定**——`CONTEXT.md`《I/O 与并发》明写
「一个 ZipArchive 就是一个游标，读取恒串行，点名也改不了」。改法是把**幂等那一道**
排除在这条之外（同一个文件开几个独立句柄，各解各的成员，哈希那一端仍按成员序喂），
第一遍与第二遍照旧串行。这条改动要先拍板，票里单列。

## Testing Decisions

好的用例只问外部行为。这一批的外部行为是：**退出码**、**报告的字节**、**屏幕缓冲**、
**盘上的字节**、**闸门本身跑不跑得到**。

- 退出码那几条走 `tests/isolation.rs` 的现成形状（造一个坏卷，问整趟的码）。
- 屏幕那几条走 `src/session/draw.rs` 的快照，读回来用 `TestBackend` 自己的 `Display`
  （按 `cell_width` 跳过宽字符占住的那一格——`p1-session/09` 立的）。
- 折行要有**窄到放不下**那一档的快照，且断言「q 退出」在最窄那一档仍在屏上。
- 预设那两条比**盘上的字节**：手写注释在覆盖之后仍逐字节在原处。
- 并行化那一条比**产物的哈希**：与串行那一趟逐张相同，且黄金快照不变。
- 闸门那一条最特别：它验的是**另外两条命令跑得到什么**，因此断言写在 CI 脚本或
  `xtask` 上，不是写在用例里。

## Out of Scope

- 停车场剩下的 14 条（重复与内聚那八条、口径与交付记录那六条）。它们留在停车场，
  由本 spec 之后再判。
- 字号跳动的夹子：所有者已拍板「暂不加，先扩样本」，见 `CONTEXT.md`《尚未确立》。
- 命令行侧的按停（Q38）、`fast` 模式（Q80）——那是新能力，不是收口。
