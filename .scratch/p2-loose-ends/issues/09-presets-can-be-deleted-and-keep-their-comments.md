# 09 — 预设删得掉，覆盖不吃掉注释

**What to build:** 两件在预设那一栏上缺的事。

**删不掉**：会话里存得进一份预设、列得出、套得上，就是删不掉——攒错了一份要退出会话去手改 TOML。

**覆盖会重排**：覆盖一份同名预设要把整份文件按标准格式重排，手写的注释与排版留不下来。
存**新的**一份不吃这个亏（那一条是追加，原文一个字节不改），只有覆盖吃。
根子是写入端没有保住格式的能力。

收停车场的 **Q74**（删）与 **Q73**（覆盖重排）。Q73 的出路是换一个保住格式的写入端；
引不引那个依赖本票要判并说明。

**Blocked by:** 01 — 闸门盖住三种构建

**Status:** resolved

- [x] 预设那一栏上删得掉一份，且删之前要确认——这是不可逆的写盘动作
- [x] 删掉的是点名那一份，同一份文件里其余预设、注释、排版全部原样留着
- [x] 覆盖一份同名预设之后，**手写的注释仍逐字节在原处**——这条要比盘上的字节
- [x] 本版本读不懂的预设在删与覆盖之后都还在（不认识不等于可以丢）
- [x] 写盘仍是先写临时再改名，整份读不懂就一个字节都不写
- [x] 删到最后一份、以及对着一份不存在的预设按删，都说得清、不崩

> 第二、三条**打勾的范围**：按节写法——本模块写出去的、文档里教出去的那一种——逐字节成立。
> 剪不动的那几种同样合法的写法（点号键、内联表……）退回整份重排，注释仍留不下来；
> 那一条残留记在停车场 **Q108**，不在本票收。

## 落地记录

### 做成了什么

**删得掉了。** 预设那一栏上停着一份预设时 `d` 删掉它，而**要按两下**：第一下只在屏底问一句
（「真要删掉「X」吗：再按一次 d 删掉它。那一份从预设文件里没了，撤不回来；文件里其余几份
与手写的注释照旧留着」），第二下才动盘。问的是**哪一份**记在 `Picker::asked` 上，
而**屏底那句话一换，那一问就作废**——挪一行、按一个别的键、套用失败报出的那句错，
都把它清掉。那一问就摆在那句话里，而屏底只摆得下一句：闩不能比它活得长
（`Session::says` 是屏底那一句唯一的出口，清除就在那里）。
与撞名那一问「缓冲一改就作废」同一个形状（ADR 0013：再按一次）。
停在末尾那一行（＋ 存成一份新的）上 `d` 按不动，屏底那一行也就不摆它。

新添的是一支动作 `Action::Erase`，不是复用卷行那个 `Action::Remove`：两者不是一个量级
（那一条是这一趟屏上的一行，这一条是盘上长期存着的东西），而 `press` 那一层本来就写着
「四支各走各的函数，合起来就要留一支到不了的 `_`，而那正是新添一支动作会被静默吃掉的地方」。

**覆盖不再吃掉注释。** 写入端从「整份重排」换成**按节剪、按节接**（`preset::cut`）：
逐行找出那一份自己占的那几节——从它的表头那一行起，到下一个表头之前最后一行**有字**的行
为止，尾巴上的空行与注释不算它的（注释说的是紧跟它的那一节）——覆盖把那几段就地换掉，
删就地剪掉。文件里别的字节一个不动，位置也不动。

**算出来的那一份验过才作数**（`preset::keeps_faith`，从原来的 `appends_cleanly` 长出来）：
重新解析一遍，其余每一份的 `toml::Value` 逐个相等，点名的那一份如数读得回来
（删那一条是「它不在了」）。验不过、或者那份文件的写法根本剪不动（点号键、内联表、
多行字符串里冒出来的 `[`、转义过的名字、光秃秃一节 `[preset]`），就**退回整份重排**
（`preset::rewrite`）——那正是本票之前的行为，**安全的下限因此是从前的样子，
不是一种新的失败**。写盘仍是先写临时再改名（`Presets::put`，一个字节没改），
整份读不懂就一个字节都不写。

屏上与词汇表跟着改口：撞名那一句不再说「整个重排、注释留不下来」，改说那一份自己的去处
（「它原来的内容换成眼下这两层，撤不回来；那份文件里其余几份与手写的注释照旧留着」）；
`CONTEXT.md` 的《会话》那一段与**预设栏**词条一并订正。

### 引不引 `toml_edit`：**不引**

判据不是「少一棵依赖」——它的传递依赖（`indexmap`、`winnow`、`toml_datetime`、`serde_spanned`）
本来就在树里，真引只多 `toml_edit` 自己一棵；`THIRD-PARTY-NOTICES.md` 装的是**随程序分发的
第三方素材**，crate 依赖本来就不列在那里（`anyhow`、`ratatui` 一个都没有）。判据是
**它做不成本票要的那件事**：

- **实测过**（`toml_edit` 0.22.27，拿本票的验收样例跑了一遍）：
  `doc["preset"].as_table_mut().remove("漫画")` 与 `doc["preset"]["漫画"] = <新的那一份>`
  两条路，**都把紧挨在那一节上面的 `# 我手写的` 一起带走了**。一节前面的注释在以
  「装饰（decor）」记格式的编辑端里挂在**那一节自己**身上，删掉或换掉它，注释跟着走。
  要保住那一行仍得手工搬装饰，而那一行正是本票唯一要保的那个字节。
- **这份文件的形状本来就窄**：顶层 `deny_unknown_fields`，整份文件除了 `preset` 那张表
  一无所有。要保的字节因此只有**节与节之间**的注释与空行，而一刀切在节边界上就答得完——
  用不着一个通用的编辑端。
- **「算一份、验一遍、验不过退回重排」这条路子模块里本来就有**（`appends_cleanly`）：
  本票把它推广了一次，写出去的形状仍只有 `write` 一处出处。
- **退路恒在**：剪不动就重排，最坏是今天的行为。引一个依赖换来的那一半保证，
  这条路子自己给得出。

Q73 那句「要保住格式就得引 `toml_edit`」因此**判错了**——不是它做不到，是它一样要手工
管装饰，而管装饰的活比按节剪一刀更长。

### Q73 — 覆盖一份同名预设要把整份文件重排，手写的注释与排版留不下来

- **From:** 票 `p1-session/12`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/preset.rs` 的 `insert`（重排那一条）；`Cargo.toml` 的 `toml = "1.1.4"`
- **Why it did not block:** 存**新的**一份不吃这个代价——那一条是**追加**，原文一个字节都不改
  （注释、排版、连本模块读不懂的那几份预设全部原样留着，用例
  `saving_a_new_preset_leaves_every_byte_of_the_file_where_it_was` 逐字钉住）。
  只有**覆盖同名**那一条要重排：那一份要换掉，而 `toml` 1.1 没有保留格式的编辑端
  （`Spanned` 只给得出**键**的位置，`[preset."名字".device]` 那一节的正文范围它答不出来——
  本票实测过）。真要保住，得引 `toml_edit`，而那是一条**依赖面上的决定**，
  不是本票该顺手拿的（先例：Q65 判「要不要给 ratatui 开一个不稳定特性」是同一类）。
- **What this ticket actually did:** **两条路分开走，并把代价说在按下去之前。**
  新名字追加、原文不动；同名重排，而重排之后**每一份预设的内容都还在**
  （读不懂的那几份按不透明的 `toml::Value` 原样搬过去，用例
  `overwriting_one_preset_keeps_the_others_but_not_the_comments` 一并钉住注释**没有**留下——
  哪天格式保得住了，那条断言会反过来提醒人改这一段）。
  追加完还验一遍（读得回同一份、别的几份一个没变），验不过才退回重排——
  `preset` 那张表写成内联表时接不上一节，那一种就走重排。
  屏上那句在覆盖的**第一下**就说出口：「再按一次 ⏎ 覆盖它。覆盖会把那份预设文件整个
  照标准格式重排，手写的注释与排版留不下来」。
- **Whose call:** 拍板的人（要不要引 `toml_edit` 换一个保住格式的写入端）
- **处置：** **了结。** 换了写入端，但**没有引 `toml_edit`**：走的是「按节剪、按节接 +
  验一遍 + 验不过退回重排」（理由见上面《引不引 `toml_edit`》——实测那个包同样会把
  节前面的注释一起带走）。Q73 留的那条断言按它自己说的翻了面：
  `overwriting_one_preset_keeps_the_others_and_the_comments`，比的是盘上的字节。
  「哪天格式保得住了」就是今天。

### Q74 — 会话里存得进一份预设，却删不掉一份

- **From:** 票 `p1-session/12`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/session/state.rs` 的 `listing_action`（预设那一栏的按键表）
- **Why it did not block:** 票面三条动作写的是**存、列出、套用**，没有删。
  眼下不咬人的原因是有出路：那份文件的位置屏上刚说过（存完那一句里带着全路径），
  用编辑器删掉那一节就是了；而覆盖同名是有的——名字打错之后重存一份对的，
  错的那份留在清单上不影响任何一趟。
  真要加，`d` 那个键是现成的（范围层那一栏上它就是「删掉这一条」），
  但删一份预设与删一条卷不是一个量级：后者是这一趟的一行，前者是盘上一份长期存着的东西，
  按错一下没有撤销。那就得再来一次「按两下」，而屏底那一行已经摆着四组键了。
- **What this ticket actually did:** **没有加删。**`d` 在预设那一栏上派 `Action::Ignored`
  （`which_keys_do_what_in_which_state` 第八段逐个问过）——屏上也就不摆它。
- **Whose call:** 拍板的人（会话里要不要能删一份预设，要的话按几下）
- **处置：** **了结。** 加了删：`d` 在停着一份预设时派 `Action::Erase`，
  **按两下**（第一下只问一句，光标一挪就作废），停在末尾那一行上仍是 `Action::Ignored`。
  Q74 顾虑的「屏底那一行已经摆着四组键了」由 `p2-loose-ends/07` 的折行工具答掉——
  那一行现在折得开，`d 删掉` 挤不掉 `q 退出`。
