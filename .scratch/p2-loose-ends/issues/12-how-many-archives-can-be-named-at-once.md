# 12 — 一次点名多少个归档卷才到头

**What to build:** 预扫打开的归档卷全部留到各自被处理时——枚举结果**就是** `ZipArchive` 本身，
放掉它等于要再读一遍中央目录。于是点名 N 个归档卷即同时占着 N 个句柄。
眼下不咬人（一次几十个卷，而系统上限是千级到百万级），但那道上限现在没人说得出，
撞上去会是一个读起来莫名其妙的错。

要么给这笔代价划一道明确的线并在越过时说人话，要么让枚举与「取字节的那一半」分家。
本票要判走哪条，并把判的依据写下来。

`11` 会让同一卷同时开出更多句柄，所以这道线要在它之后重新算。

收停车场的 **Q42**。

**Blocked by:** 11 — 归档卷的幂等这一道不再串行（它改变每卷占几个句柄）

**Status:** ready-for-agent

- [ ] 一次点名很多归档卷时，要么跑得动，要么在开工前说清是句柄不够、以及能点多少
- [ ] 那道线的算法只有一处出处，并说明它随平台走
- [ ] 撞上去的错不是底层的原话，是说得出「点名太多了」的那一种
- [ ] 走「枚举与取字节分家」那条路的话，中央目录不许读第二遍——那是预扫存在的理由
- [ ] 目录卷不受影响（它的读取端只是一个路径，不占句柄）
- [ ] 判的依据写下来：为什么是划线而不是分家，或者反过来
