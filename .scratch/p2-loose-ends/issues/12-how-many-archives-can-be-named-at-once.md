# 12 — 一次点名多少个归档卷才到头

**What to build:** 归档卷的句柄这笔账现在没人算得出，撞上去会是一个读起来莫名其妙的错。
要么给它划一道明确的线并在越过时说人话，要么证明这道线已经不必划。本票要判走哪条，
并把判的依据写下来。

**前提已经变了两次，按现状读：**

- 原来是「预扫打开的归档卷全部留到各自被处理时，点名 N 个归档卷即同时占着 N 个句柄」。
  `volume-discovery/01`（预扫只数不留）已经把这一笔消掉——预扫数完就放掉整个卷，
  处理那一卷时按路径重开，一趟同时开着的从「点名几个就是几个」变成
  「正在处理的那一卷」。**点名的卷数不再是这道线的自变量。**
- `11`（归档卷的幂等不再串行）会让**同一卷**同时开出多个句柄。这道线因此要在它之后、
  按「一卷同时开几个 × 并发度」重新算。

**Blocked by:** 11 — 归档卷的幂等这一道不再串行（它改变每卷占几个句柄）

**Status:** ready-for-agent

- [ ] 一次点名很多归档卷时，要么跑得动，要么在开工前说清是句柄不够、以及能点多少
- [ ] 那道线的算法只有一处出处，并说明它随平台走
- [ ] 撞上去的错不是底层的原话，是说得出「点名太多了」的那一种
- [ ] 目录卷不受影响（它的读取端只是一个路径，不占句柄）
- [ ] 判的依据写下来：为什么是划线而不是不划，以及自变量到底是什么

**收停车场的 Q42。** 那一条的《处置》里记着 `volume-discovery/01` 把现状改成了什么样，
先读它再动手。
