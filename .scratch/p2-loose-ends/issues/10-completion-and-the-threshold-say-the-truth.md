# 10 — 补全认得出大小写，阈值不再说错来源

**What to build:** 两处会话上说错话或做错事的小地方。

**补全大小写敏感**：范围层逐层补全按前缀筛，而筛法区分大小写——Windows 的文件系统不区分。
敲 `d` 补不出 `Doraemon`。中文卷名上不咬人，英文卷名上咬。

**阈值说错来源**：在会话里改了阈值，屏上却写着「命令行指定」——那句话是命令行的措辞，
而阈值现在有三个入口（命令行、预设、会话）。三个入口同一个来源
（`p1-session/12` 判的：来源分的是**这个数怎么定出来的**，不是从哪个入口点的名），
所以要改的是**措辞**，不是再加一个来源。

收停车场的 **Q59** 与 **Q62**。Q62 那句改成什么，`p1-session/12` 已查明它不在黄金基线里，
改它不必重录黄金快照。

**Blocked by:** 01 — 闸门盖住三种构建；07 — 中文长句折行（本票改的措辞落在同几处屏上）

**Status:** resolved

- [x] 逐层补全在 Windows 上按平台的规矩筛前缀，敲小写补得出大写开头的卷
- [x] 区分大小写的平台上行为不变——不要为了 Windows 把别处也放宽
- [x] 阈值那一行不再声称是「命令行指定」，三个入口下印出来的话都对
- [x] 阈值的**来源**仍只有两种（标定的 / 点名的），没有为入口加第三种
- [x] 报告里印的是数值加标定来源，读的人仍能自己判断它对手上那块板成不成立
- [x] 黄金快照未变

## 落地记录

两件小事各改一处：补全那侧多了一个平台常量与两个私有函数，阈值那侧只动一句措辞。
三条闸门全绿，**黄金快照与会话那几张整屏快照一个字节没动**（`src/session/draw.rs` 未改）。

### 补全走的是 Q59 摆的哪条路

**第二条：按平台分支。** 依据一句话——第一条（一律 `to_lowercase` 再比）**做不到本票的验收**：
第二条验收明写「区分大小写的平台上行为不变」，而 `to_lowercase` 改的恰恰就是那些平台的行为
（Q59 自己写的「让 Linux 上两个只差大小写的目录互相污染」）。两条不是代价高低之争，
是一条做得到、一条做不到。

Q59 记的代价（「要在一个十行的模块里引一个 `cfg`」）**没有真的发生**：判据落成一个常量

```rust
const CASE_INSENSITIVE: bool = cfg!(windows);
```

——`cfg!` 是**表达式**不是属性，两支在所有平台上都编译得到，模块里因此一道 `#[cfg]` 的墙都没有，
读的人也不必在脑子里同时装两份代码。筛法收进两个私有函数：`matches_prefix` 按平台分岔，
认大小写那一支就是原来那句 `name.starts_with(prefix)`（**一字未动**），
不认的那一支走 `starts_with_folded`。

**逐字折，不整串折。** 两边按字各 `to_lowercase` 一次再比，不先把整串 `to_lowercase`
再 `starts_with`：一来那样每个候选都要新分配一个串，二来两者在「一个字折出好几个字」
的那种字上分岔（土耳其语的 `İ` 折成 `i` 加一个组合点），**逐字的那一种更严**——
敲 `i` 补不出 `İ`，而 Windows 自己那张表也是逐码点折的，不做多字折叠。

**补回来的是盘上那个写法。** `level` 拼的是「用户敲的那一截 + 盘上的那个名字」：
打到一半那一层**之前**的路径仍原样留着，只有最后那一截按盘上的大小写改写——
敲 `d:/comics/dor` 补出来是 `d:/comics/Doraemon 01/`。模块文档里那句「前缀原样留着」
因此改了半句：它当初成立，靠的正是筛法区分大小写。

**会话那侧一行没改。** `state::complete` 里那道闸（`common.len() > edit.buffer.len()`）
恰好还挡着新冒出来的一种情形：混大小写的两项（`Apple` 与 `apricot`）共同段只到上一层为止，
比缓冲还短，那道闸挡的正是「把用户已经打出来的一截截掉」。

**验收怎么钉的**（两条，都不挂 `cfg`，因此两条闸门上都编译得到）：

- `folding_lets_the_other_case_through_and_nothing_else` 问**折法本身**——
  `starts_with_folded` 不看平台常量，它在每个平台上都跑得到。
- `case_is_folded_only_where_the_file_system_folds_it` 问**平台那条规矩**：
  同一棵树（`Doraemon 01` 与 `doraemon 02`）上敲 `d`，不认大小写的平台该补出两个
  且其中带盘上的大写写法，认大小写的平台只该补出后一个。断言按 `CASE_INSENSITIVE` 分岔，
  两支的代码到处都编译。

### 阈值那句话改成了什么

`ThresholdSource::Pinned` 的 `Display` 从 **「命令行指定」** 改成 **「点名指定」**。
一句话，**不提入口**：报告里那一行现在读作 `阈值 2.000（点名指定）`。

- **来源仍只有两种**，没有为入口加第三个变体——`p1-session/12` 判的那条原样成立。
- **三个入口都经 `Profile::with_threshold`**（命令行、预设、会话共用 `main::target_profile`
  那一个函数），这件事写进了 `with_threshold` 与 `Pinned` 各自的文档：那一项分的是
  「这个数怎么定出来的」，不是「从哪个入口点的名」。
- **报告仍印数值加来源**：标定那一支一个字没动（`盲测标定于 boox-poke6，其余面板未复核`），
  点名那一支说的是「这个数是用户自己点的，不是内置标定值」——读的人要判断的
  「它对我手上这块板成不成立」，两支都答得出。

断言三处，三个入口各一处：

- **命令行**：`tests/pipeline.rs` 的 `the_threshold_says_where_it_came_from` 改字，
  并补一条**反面**断言（那句话里不许出现「命令行」）。
- **预设**：`src/main.rs` 新添 `a_threshold_from_a_preset_says_what_the_command_line_says`——
  同一个数从预设的设备层与从 `--threshold` 进来，印出来的必须**逐字相同**，且含「点名指定」。
- **会话**：`src/session/state.rs` 的 `the_threshold_row_prints_the_source_the_report_prints`
  续一段：在会话里点一个数，屏上那一行与库那一份**逐字相同**，且含「点名指定」。
  原来那条只问得到标定那一支。

### 快照

**黄金快照 `tests/golden-snapshot.txt` 一个字节没动、未重录。** 派活说明查实的那一条属实：
那一趟不点 `--threshold`，印的是标定那一句，「命令行指定」在那份基线里出现 **0** 次。

**会话那几张整屏快照也一行没变**，`src/session/draw.rs` 一个字没改。理由同上：

### 停车场结转

两条原文照抄，各带一句处置。

### Q59 — 逐层补全按前缀**大小写敏感**地筛，而 Windows 的文件系统不是

- **From:** 票 `p1-session/08`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/session/complete.rs` 的 `level`（`name.starts_with(prefix)`）
- **Why it did not block:** 中文卷名上不咬人——本仓库面向的库里卷名多是中文与数字。
  咬得上的是 `D:/Comics/` 里打 `d:/comics/c` 这种：路径本身 Windows 认，前缀那一截却筛不出
  `Comics`。改法有两条，各有代价：按 `to_lowercase` 比会让 Linux 上两个只差大小写的目录
  互相污染；按平台分支写两套则要在一个十行的模块里引一个 `cfg`。
- **What this ticket actually did:** **照大小写敏感做，并写进了模块文档**（列出来的东西
  按用户打的写法拼回去，前缀原样留着）。没有引平台分支。
- **Whose call:** 拍板的人（要不要按平台放宽大小写）
- **处置：** **了结。** 走**按平台分支**那一条，代价比原条目估的小：判据是一个常量
  `CASE_INSENSITIVE = cfg!(windows)`（表达式而非属性，两支到处都编译），筛法收进私有函数
  `matches`。另一条（一律 `to_lowercase`）被排除的理由不是代价，是**做不到本票第二条验收**
  ——那正是 Q59 自己写的「让 Linux 上两个只差大小写的目录互相污染」。
  模块文档里「前缀原样留着」那半句跟着改了：打到一半的最后那一截现在按**盘上的写法**还回来。
  macOS 那一档（APFS 默认也不认大小写，而 `cfg!(windows)` 判它为「认」）另立 **Q107**。

### Q62 — 在会话里改了阈值，屏上却写着「命令行指定」

- **From:** 票 `p1-session/08`
- **Kind:** 路过发现
- **Where:** `src/profile.rs` 的 `ThresholdSource::Pinned`（`Display` 里那句「命令行指定」）；
  `src/session/state.rs` 的 `threshold_shown`
- **Why it did not block:** 会话里那一行照 `Threshold` 自己的 `Display` 印，
  为的是**不另编一套说法**（spec 的 Further Notes）——而那一份里「用户点名的界」写作
  「命令行指定」。在会话里点的名不是从命令行来的，那半句因此读着不对。
  改法只有一条站得住：把库那一句换成不提入口的写法（例如「点名指定」）。
  那是**报告文字**的改动，会落到 `tests/golden.rs` 的黄金基线上——本票的硬约束是
  黄金快照不该变，而这一句与本票要做的事无关。
  眼下不咬人：命令行是唯一点得动阈值的入口，会话那一行只在用户自己刚打完那个数时露面。
- **What this ticket actually did:** **照库那一份原样印。**没有在会话里另写一句，
  也没有动库里那一句。`the_threshold_row_prints_the_source_the_report_prints` 钉住
  「两处逐字相同」——库那句改了，这一条不会红，但两处永远不会走散。
- **Whose call:** 拍板的人（那句「命令行指定」要不要换成不提入口的写法，
  连同重录一次黄金快照）
- **`12` 撞上之后：判成 `Pinned`，措辞那一半仍归拍板的人。**
  本票被点名回答「会话改出来的阈值算哪一种来源」，判**仍是 `Pinned`，不加第三个变体**：
  ① `ThresholdSource` 分的是**这个数怎么定出来的**——盲测标定的内置值，还是**用户点名**的界，
  而不是「从哪个入口点的名」。会话里打的那个数与命令行上敲的那个数是同一件事：
  都是用户在自己那台面板上量出来的（ADR 0002），判定也只看数值。
  `ThresholdSource::Pinned` 自己的文档第二句写的正是这个（「用户在自己那台设备上数出来的界
  走这一条」），代码一个字都不必改。
  ② 加一个 `Session` 变体会让同一个数**因为从哪个键进来而印出不同的话**，
  而读报告的人要判断的是「这个界对我手上这块面板成不成立」，入口对他没有用。
  ③ 本票又添了**第三个入口**：预设的设备层可以写 `threshold`，而它经
  `Profile::with_threshold` 同样成 `Pinned`——预设既不是命令行也不是会话。
  三个入口一个来源，这条判断因此更站得住，而那句「命令行指定」也更明确地错了。
  **没有改那句措辞**：本票的硬约束是「命令行那一路行为一字不变」，而报告里那一行
  正是命令行的输出。剩下要拍的只有一句话（例如换成「点名指定」），
  连同 `tests/pipeline.rs` 的 `the_threshold_says_where_it_came_from` 里那条断言。
  顺带更正原条目的一处：黄金基线 `tests/golden-snapshot.txt` 里**没有**这句话
  （那一趟不点 `--threshold`），改它不必重录黄金快照。
- **处置：** **了结。** 拍的就是 Q62 自己提的那句：`Display` 改成**「点名指定」**，不提入口；
  来源仍两种，`ThresholdSource` 一个变体没加。改了什么、断言落在哪三处，
  见上面《阈值那句话改成了什么》。
  《Why it did not block》里「会落到黄金基线上」那句**写下时就假**，本票复核为 0 次
  （`12` 已订正过一次，见《票面与停车场里写错的地方》）。

### 复审

两轴各跑一遍（Standards / Spec）。收了这几条：

- **`fn matches` 名字说不出比的是什么**（Standards，Mysterious Name；还与 `matches!` 撞脸）。
  收了：拆成 `matches_prefix`（按平台分岔）与 `starts_with_folded`（折一次再比前缀）。
- **两条平台用例形状逐句相同，且非 Windows 那条在本机一次也编译不到**
  （Standards 的 Duplicated Code 与 Spec 的验收②，同一个东西的两面）。
  收了，且收法把两条一起答掉：合成**一条**用例（同一棵树，断言按 `CASE_INSENSITIVE` 分岔，
  不挂 `cfg`，两支到处都编译），另加一条只问折法本身的用例——`starts_with_folded`
  不看平台常量，**每个平台上都跑得到**。
- **「三个入口都经 `with_threshold`」在 `src/profile.rs` 里写了三遍**（Standards，
  违反 `CLAUDE.md`《文档写作》第 4 条「单一出处」）。收了：入口那张单子只留在
  `with_threshold` 上，`Pinned` 与 `DEFAULT_THRESHOLD` 改成指过去。
  票据里同一条结论说两遍的那处也一并收了（Q62 的《处置》改成指回正文那一节）。
- **验收③「三个入口下印出来的话都对」，预设那个入口零断言；会话那条也没钉住新措辞**
  （Spec）。收了：`src/main.rs` 新添 `a_threshold_from_a_preset_says_what_the_command_line_says`
  （预设点的数与 `--threshold` 点的**逐字相同**），会话那条改成与库那一份逐字比、
  并断言含「点名指定」。
- **《票面与停车场里写错的地方》误引了 `issue-tracker.md`**（Spec）。原引的是
  「记录不因后来的工作而重写」，而那条的下半句正相反：订正一句**写下时就已经假**的话
  不算重写。改了措辞，并说清原文为什么仍照抄不动（存档是「原文 + 处置」两半）。
- **`starts_with_folded` 的文档把逐字折的理由说错了**（Spec）。原写「整串折完长度对不上、
  会错位」——这个函数只返 `bool`，还回去的名字取自盘上，不存在错位。真实差别是
  **逐字更严**（敲 `i` 补不出 `İ`）加上不必为每个候选各分配一个串，且更贴近 Windows
  自己那张逐码点的表。文档照实改了。

- **`.scratch/p2-loose-ends/issues/08-…md` 被改成 `Status: wontfix`，还多出一个未跟踪的
