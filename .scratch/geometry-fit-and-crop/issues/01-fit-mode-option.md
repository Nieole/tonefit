# 01 — 适配方式做成选项，新增「以高为准」

**Status:** ready-for-agent

**Blocked by:** None — can start immediately

## 要做到的

用户能点名这一趟按哪种方式适配到面板：

- **fit-inside**（现状）：整页塞进面板，长边定夺。
- **以高为准**：目标高恒等于面板高，宽按源宽高比算出，**允许超过面板宽**；比面板矮的页
  放大到面板高。超出的部分靠阅读器横向翻动。

面板宽高比 1.35、漫画页 1.43–1.53，**普通漫画页本来就受高度约束**，两种方式产出同一个尺寸——
实测棋魂完全版 230 页、N和S 24 页 100% 一致。分岔只发生在比面板更扁的页上，也就是跨页：
哆啦A梦 6048×4320 从 1072×766 变成 2027×1448，改革之獸 7162×3000 从 1072×449 变成 3457×1448。
数据见 measurements 的《适配方式：fit-inside 与以高为准》。

**跨页因此可读，而不必做拆分。** 附带的是几何门在这条路上恒成立：比面板矮的页放大到面板高，
抖动不再被整卷关掉。代价是体积——跨页卷 ×2.8 到 ×3.6，普通漫画卷不动。

## 验收

- [ ] 命令行能点名适配方式，两种都选得到，**默认仍是 fit-inside**
- [ ] 以高为准时目标高恒等于面板高，宽按源宽高比算出，**不设上限**
- [ ] 比面板矮的页放大到面板高；几何门在这条路上恒成立，抖动不再被整卷关掉
- [ ] 报告说得出这一趟用的是哪一种，以及哪些页的输出宽超过了面板
- [ ] 一条用例钉住「普通漫画页两种方式同尺寸」——那是受高度约束的直接后果，
      不是巧合，写下来后面改动才碰得响
- [ ] 预缩的总缩放比跟着适配方式走（以高为准时恒为 源高 ÷ 面板高）
- [ ] ADR：不变量由「目标尺寸 = fit-inside(面板分辨率)」改为随适配方式而定；
      ADR 0007（抖动挂在输出不被下游缩放上）与 ADR 0003（灰阶硬上界）挂在它上面的部分随之说明
- [ ] `CONTEXT.md`《尚未确立》的「几何门不成立时该用哪个位深集合」改写：
      那个状态在以高为准下不存在，该条只对 fit-inside 成立
- [ ] 黄金快照重录，差异逐条确认

## 不要做的

- **不要给宽度设上限。** 用户明确接受任意宽度的横向翻动，实测最宽 3.22 倍面板宽。
- **不要把它做进 profile。** 它是读法偏好，不是面板的物理事实——profile 的主键是面板。
- **不要顺手实现跨页拆分。** 以高为准之后跨页已经可读；拆分是另一件事、另一套代价。

## 要认的前提

比面板宽的输出要求阅读器以 100% 平移显示。缩放适配会把抖动连同 1 像素周期的结构一起抹平
（见《真机像素完整性》），而 tonefit 探不到阅读器的显示管线（ADR 0007 的备选方案）。
这一条写进文档，不在代码里绕。
