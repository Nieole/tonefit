### 形状放宽成了什么

第一遍产出的单位从「源页」换成**输出页**（`crate::OutputPage`：来自哪张源页 + 写到哪个成员 +
这一张的结局）。一张源页读一次、解一次、彩页识别一次，然后 `split` 把它切成一到多张图，
每一张各走各的分支、各占一个缓存序号、各占报告里的一格。同一源页切出来的那几张挨着排，
卷内输出页序因此仍是阅读顺序。第一遍**之后**的每一处序号——汇总、上包络的驱动页、
第二遍的写出、逐页报告——都指进输出页那个序列。

| 认这个形状的地方 | 从前 | 现在 |
|---|---|---|
| 成员命名 | `relative.with_extension("png")` | `output_name(relative, ordinal, count)`：一张时不改名，多张时接 `-1`/`-2` |
| 幂等依据 | `targets: Vec<PathBuf>` | `Vec<Vec<PathBuf>>`，一个源页一组，`can_skip` 每一张都要对上 |
| 进度步数 | 一个成员数 | `MemberCounts { source_pages, output_pages, extras }`，前两段按源、第二段按输出 |
| 缓存 | 一页一个序号 | 一张**输出页**一个序号（彩色分支与失败页照旧不进） |
| 每输出成员只对一个源成员 | 按源页与目标名等长 zip | 摊平成 (源成员, 输出成员) 对再查重 |
| 报告 | `page_count()` 一个数 | 加 `VolumeReport::source_pages`；`page_count()` 收窄为**输出**页数 |
| `VolumeTiming`（加固批 11 号票） | 三段都按成员 | 前两段源、第二段输出，段界不动 |
| `render` 四段（`p1-session/01`） | — | 四段照原样吃新形状，印出的文字一字未改 |

`OUTPUTS_PER_SOURCE_PAGE = 1` 是**预告**那一侧的唯一出处（输出成员名要在碰像素之前给得出来），
`split` 是**产出**那一侧。此刻两边都是这个常量。失败页另走 `OUTPUTS_PER_FAILED_PAGE`：
它没有像素可切，切不出第二张，而这一条与拆分与否无关。

### 报告新增的那一个数

`VolumeReport::source_pages`，源页数。它是这张票**唯一**外部可见的新增，不进渲染出的文字。
`page_count()` 与 `VolumeVerdict::Skipped { page_count }` 一并收窄成**输出**页数——
两者眼下与源页数相等，语义分开是为了 04 号票落地那天不必再动一次调用方。

### N=2 怎么测的

命令行造不出 N=2（此刻恒 1），因此在 `src/lib.rs` 的 `mod tests` 里直接喂一份 N=2 的
第一遍产物，八条用例分别问：成员命名、进度步数、撞名校验、卷内统一尺寸的众数、
汇总的序号、逐页报告的成员名、第二遍的写出与报到、以及幂等要对上每一张。
最后那一条做过变异检验：把 `can_skip` 的 `.flatten()` 换成只看头一张，它当场变红。

### 留给 04 号票的那一处

**幂等仍要在碰像素之前预告出全部输出成员名**，而 04 号票的 N 由内容决定，那条预告不成立。
出路与代价记在 `.scratch/非阻塞问题.md`，需所有者拍板。`process_volume` 在两个数都在手上的
那一处加了一句 `debug_assert_eq!`，好让这件事在 04 的测试里当场撞响，而不是变成
「报告照出、输出里少了成员」的静默错。
