# 05 — 各开关的互锁只写一处

**What to build:** 开关组合不成立时用户**当场知道**，而不是跑完拿到一份白做的产物。

这几个开关互相咬着，而规则命令行现在就要用、会话层将来也要用。写两份必然漂移，
因此只写一处。**不必等 TUI 就能验收**——规则与呈现分开。

**Blocked by:** 01、02、03、04

**Status:** resolved

- [x] 三条互锁表达在同一处，命令行照它说话：
  - 拆分开着、适配方式却是 fit-inside → 连续跨页仍被压扁，等于白开
  - 裁边关着 → 用户得留着阅读器的裁切，抖动会被抹平、字节白付
  - `--dither fs` 在以高为准下几乎打不着（没有页贴不住面板），它仍在 fit-inside 上活着，
    那条错误消息要提一句「换个适配方式也能解」
- [x] 规则与呈现分开：会话层将来照着接，不必复制一份
- [x] 每条互锁各有一条用例
- [x] 三条各自的处置**已定**，照此落地：
  - ① 拆分开着但适配是 fit-inside → **说清楚**，报告头部提一次。组合本身合理：可拆的拆了，
    不可拆的被压扁，那是部分收益不是荒谬，不该拦住用户
  - ② 裁边关着 → **只进文档与 `--help`，不进每趟报告**。关掉裁边完全合法，而抖动被抹平
    只在用户的阅读器会裁时才发生——tonefit 看不到那一层，逐卷提醒等于噪音
  - ③ `--dither fs` 撞上贴不住面板的页 → **维持拒绝**。覆盖项是显式指令，不该静默放弃

## 跨批次依赖

`p1-session/07`（预设）的口味层是**逐项列举**的，现在写死了「滤波器、位深、抖动、逐页、
缓存预算、读取策略」。本批的四个开关不会自动流进去。页几何先于会话落地，因此 07 与 08
写的时候把它们算进去即可，不必回头补。

**阅读方向按口味层放**，不留逐卷口子：用户一批一批处理，一批内同质。混批要跑两趟。

## 落地记录

新模块 `src/interlock.rs`，公开 `Interlock`（三条的全集）与 `Voice`（三条处置）。
它答两件事，别处一件都不重答：**这一趟咬上了哪几条**、**每一条在哪儿说话**。

### 规则与呈现怎么分的

| | 出处 | 谁读它 |
|---|---|---|
| 判定 | `Interlock::engaged`（只看开关的那些）、`Interlock::dither_outside_the_gate`（还要一页的那一条） | `Report::interlocks`、`nothing_left_error` |
| 处置 | `Interlock::voice` | `render::interlock_lines` 照它筛 |
| 措辞 | `Interlock` 的 `Display` | 报告抬头、`--help`、那条拒绝的错误 |
| 呈现 | `render::interlock_lines`（抬头挂「互锁」标签）、`main::interlock_help`（`--help` 排成一节） | — |

**措辞破例放在库里**，与 `render` 模块文档那句「措辞不进库」相抵，理由写在 `interlock.rs`
的模块文档里：同一句要从三张嘴里出来，其中一张（那条拒绝的错误）在库内——
放到界面层等于给库里那一份留第二个出处。`FitMode`、`SplitRule`、`InkRule` 的 `Display`
早已是这个形状，不是新开的例外。

**会话层怎么接**：跑完之后问 `Report::interlocks()`，跑之前问
`Interlock::engaged(fit, crop, split)`（关联函数，随 `Interlock` 一起导出，库外调得到），
两处拿到的是同一份判定；照 `voice()` 决定报告区说不说，措辞照 `Display` 取。
一行都不必复制，也不必等 TUI 才验得了——命令行上三条各自都验过了。

### 三条各自落在哪

**① 报告抬头提一次。**`render::header` 在四个开关那几行之后插一行 `互锁 …`，
筛的是 `Voice::Header`。默认那一套开关一条都不咬，抬头因此一个字不多。
`--fit inside` 且拆分开着时才出现，一趟一次，不逐卷不逐页。

**② 报告一个字都不说。**`Voice::Silent`。它只在 `--help` 末尾那一节里。
`--no-crop` 的帮助文本里那句「关掉本项就得把阅读器那一侧的裁切留着，抖动会被它抹平」
**搬走了**（02 号票预告过这一步），原地留的是一句指路。
抬头那一行仍照实说「裁边 关」——那是事实，与提醒不是一回事。

**③ 维持拒绝。**`Voice::Refusal`，咬上就没有报告可渲染。
错误措辞改成两段：规则那一句由 `Interlock` 自己说，出路那一句由 `dither_outside_the_gate_error`
**按适配方式**给——

- fit-inside 上仍指 `--fit height`，**但把例外一并说出来**：宽高比极端到会被
  兜底上界退回 fit-inside 的页，换过去仍是这条拒绝（自检第 2 条）；
- 以高为准上那句是**假话**（门在那条路上恒成立，走得到这里的只能是兜底上界退回 fit-inside
  的页，07 号票开的那个例外），改成说清这一页是怎么来的；
- 两条路共用同一个收口：不点 `--dither fs`（判据自己会替这一页把抖动关掉），
  或换一张宽高比没这么极端的源页。

`nothing_left_error` 现在收 `gate`，那一支加了 `debug_assert!(Interlock::dither_outside_the_gate(…))`
把「候选集被抖动那一维裁空」与「互锁 ③ 咬上」这两句话拴在一起（欠账记在 Q33）。

### `--help` 那一节

`after_long_help` 新增《开关互锁》，三条按 `Interlock::ALL` 逐条列出。
**三条都列，与处置无关**：处置说的是咬上之后这一趟怎么交代，这一节是说明书——
拒绝那一条要让人事先躲得开，一趟不吭声的那一条更是只剩这里说得到。
`--fit`、`--no-crop`、`--no-split`、`--dither` 四处各留一句指路，不留第二份说法。
只进 `--help`，不进 `-h`。

  ② 在两种适配方式 × 两种拆分下只看裁边；③ 的两项条件各自扫；三句措辞非空、互不相同、
  不含 markdown 强调。
- `src/render.rs`：① 抬头**只提一次**且拦不住任何东西；另外三种组合一个「互锁」都没有；
  ② 咬上了报告仍不提（而 `report.interlocks()` 确实数得出它）；
  露不露面**由 `voice` 说了算**——两条一起咬上的那一趟，一条在、一条不在。
- `src/main.rs`：`--help` 逐条列全（比的是 `after_long_help` 原文，不是渲染出来的整份帮助——
  渲染那一步会折行）；`Interlock::ALL` 加一条却忘了写进帮助就当场变红；短帮助不带那一节。
- `tests/pipeline.rs`：fit-inside 上那条拒绝照旧（并加了指路）；
  新增一条把**两种适配方式一起跑**的用例——夹具
  `DEGENERATE_STRIP_SMALLER_THAN_PANEL`（1000×20）以高为准算出 1.41 亿像素、
  退回 fit-inside 之后 1000×20 一条边都贴不住面板，两边都被拒：
  以高为准那一趟错误里**不再出现** `--fit height`，fit-inside 那一趟提了那个开关、
  但把「这张页是例外」一并说了。这一张页正是那句出路的反例，两条路因此写在同一条用例里。

### 自检（`/code-review`）改掉的六处

两轮并行复核（标准 / 票面）各报了一批，六处当场改掉，其余归档：

1. **互锁 ② 仍有两个出处——本票的靶心差点没打中**（两轮都报）。`--no-crop` 的帮助里
   「阅读器裁白边会改变页尺寸…抖动连同 1 像素周期的结构一起被抹平、字节白付」
   与 `Interlock::ReaderCropWipesTheDither` 的 `Display` 逐句同义；删掉的只是后面那句
   「关掉本项就得…」。那一整段机理已经去掉，`--no-crop` 只留「裁完之后阅读器那个开关变成
   空操作」加一句指路。
2. **处置 ③ 的假话从以高为准搬到了 fit-inside 那一侧**（Spec 轴）。fit-inside 上原本**无条件**
   劝人换 `--fit height`，而本票自己新加的那张夹具页（1000×20，两边都比面板小）
   换过去仍被拒——它在以高为准下会被兜底上界退回 fit-inside。这里判不出手上是哪一种页
   （错误在碰卷之前就备好），因此改成**把话说全**：仍指 `--fit height`，但把那道例外一并写出来。
   用例跟着扩成两条路一起跑：同一张页在 height 上不再提那个开关，在 inside 上提了、也说了例外。
3. **`Interlock::engaged` 库外够不着**（两轮都报）。`mod interlock` 是私有的，只 `pub use` 了
   两个类型；自由函数 `engaged` 因此谁都调不到，而票面明写会话层要在**跑之前**问同一份判定。
   挪进 `impl Interlock` 成了关联函数，随 `Interlock` 一起导出，`Report::interlocks` 也改走它。
4. **`render.rs` 模块文档那句「措辞不进库」变成了假话**（标准轴）。原地补了一段，
   点明那一处有理由的例外与理由所在，并说清本模块对它只做呈现。
5. **停车场两条新条目落错了位置**（标准轴）。它们被插在「以下条目**早于本模板**」那段引言
   下面，而它们恰恰是按模板写的。引言挪进《已了结》——早于模板的条目（Q1–Q20）本来就在那儿。
6. **变体文档与 `Display` 逐句同义**、以及「三条」这个数散在多处（标准轴）。
   变体文档改成只说「咬的是哪几项、为什么这么处置」，不复述那句话；
   `全集只有三条` 一类写法改成指向 `Interlock::ALL`，用例里那句 `assert_eq!(ALL.len(), 3)`
   删掉——数组类型本身已经钉着它。

**没有当场改的**，各自记进了停车场：`engaged` 的 `DitherOutsideTheGate => false` 那一支
与 `ALL` 的双重身份（改注释说清它逼着人当场答一句「开关答得出它吗」，不改结构）；
`(fit, crop, split)` 是个 Data Clump 而 `crop` 是裸 `bool`（`Request` 与 `Report` 上它们本来
就是三个并排字段，收成一个类型是另一件事）；`Voice` 三个变体不完全在同一根轴上。
③ 的判定仍是两处形态，那是 **Q33**。
