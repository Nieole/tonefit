# 05 — 各开关的互锁只写一处

**What to build:** 开关组合不成立时用户**当场知道**，而不是跑完拿到一份白做的产物。

这几个开关互相咬着，而规则命令行现在就要用、会话层将来也要用。写两份必然漂移，
因此只写一处。**不必等 TUI 就能验收**——规则与呈现分开。

**Blocked by:** 01、02、03、04

**Status:** ready-for-agent

- [ ] 三条互锁表达在同一处，命令行照它说话：
  - 拆分开着、适配方式却是 fit-inside → 连续跨页仍被压扁，等于白开
  - 裁边关着 → 用户得留着阅读器的裁切，抖动会被抹平、字节白付
  - `--dither fs` 在以高为准下几乎打不着（没有页贴不住面板），它仍在 fit-inside 上活着，
    那条错误消息要提一句「换个适配方式也能解」
- [ ] 规则与呈现分开：会话层将来照着接，不必复制一份
- [ ] 每条互锁各有一条用例
- [ ] 三条各自的处置**已定**，照此落地：
  - ① 拆分开着但适配是 fit-inside → **说清楚**，报告头部提一次。组合本身合理：可拆的拆了，
    不可拆的被压扁，那是部分收益不是荒谬，不该拦住用户
  - ② 裁边关着 → **只进文档与 `--help`，不进每趟报告**。关掉裁边完全合法，而抖动被抹平
    只在用户的阅读器会裁时才发生——tonefit 看不到那一层，逐卷提醒等于噪音
  - ③ `--dither fs` 撞上贴不住面板的页 → **维持拒绝**。覆盖项是显式指令，不该静默放弃

## 跨批次依赖

`p1-session/07`（预设）的口味层是**逐项列举**的，现在写死了「滤波器、位深、抖动、逐页、
缓存预算、读取策略」。本批的四个开关不会自动流进去。页几何先于会话落地，因此 07 与 08
写的时候把它们算进去即可，不必回头补。

**阅读方向按口味层放**，不留逐卷口子：用户一批一批处理，一批内同质。混批要跑两趟。
