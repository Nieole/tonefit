# 02 — 裁边

**What to build:** tonefit 自己裁掉页面白边，用户因此**可以关掉阅读器那一侧的裁切**。

那才是这张票的要点。阅读器的自动裁边在 6 寸屏上是刚需，但它裁掉白边就改变了页尺寸，
随后的适配于是不再是 1.0 倍——抖动连同 1 像素周期的结构一起被抹平。裁边收进来之后，
好处已经烤进产物，阅读器的裁切变成空操作，1:1 恢复。

收益不在分辨率上：漫画页受高度约束，裁掉左右白边不改变 fit-inside 的缩放比（实测 ×1.000–1.019）。
收益是白边消失本身，以及在以高为准下少翻一点。

默认打开。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 命令行能开关裁边，**默认打开**
- [ ] 裁法按**行列墨量占比**，孤立噪点不算内容
- [ ] 一条用例用「白边里带孤立噪点」的夹具钉住上一条：内容外接框会失败，本裁法不会
      （实测外接框那样量出来的中位增益是 0）
- [ ] 逐页各裁各的。页间字号会跳动（实测线性放大极差最大 0.112），**那是接受的形态**，
      用例把它写下来，免得后来的人当回归修掉
- [ ] 整页空白的页原样通过，不裁成零尺寸
- [ ] 报告逐页给出裁掉了多少
- [ ] 裁边发生在适配之前
- [ ] 幂等依据含裁边开关
- [ ] 黄金快照重录，差异逐条确认

## 不要做的

- 不取卷级裁切框。用户要的是更大的实际利用面积，卷级框会被留白最多的那一页拖住。
- 不做倾斜校正与扫描黑边。素材还没到手。
