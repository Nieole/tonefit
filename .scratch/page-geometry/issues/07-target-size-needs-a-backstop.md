# 07 — 目标尺寸要有一道兜底上界

**What to build:** 极端宽高比的源页不再把整趟处理弄崩。

`height` 适配方式下宽随源比例算出、不设上限，这是所有者定的（横向翻多少屏都接受）。
但那说的是**读得动读不动**，不是**跑得完跑不完**：一张 20000×100 的源页算出 289600×1448，
那块缓冲分配不下会**中止整趟**——不是变成失败页，是整趟死掉。一页坏内容毁掉一整趟处理，
而管线本来有隔离机制专门防这个（`p0-core-pipeline/12`）。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 目标尺寸有一道兜底上界；越界的页**退回 fit-inside**，不中止整趟
- [x] 退回这件事在报告里说得出来，逐页可指认——用户要知道哪几页没按点名的方式适配
- [x] 上界取值有依据，写进落地记录。它防的是分配不下，不是画质，因此该定在
      「肯定跑得完」那一侧，不该贴着真实素材的上沿去卡
- [x] 真实素材一页都不受影响：实测最宽的一页是面板宽的 3.22 倍（改革之獸 7162×3000），
      有用例钉住它仍走 `height`
- [x] 一条用例造出越界的页，断言整趟仍然跑完、那一页退回 fit-inside、其余页不受影响

## 与裁边那道守卫的关系

`page-geometry/02` 落地时自己加了第三条守卫：内容窗口的宽或高留不到原页一半就整页原样通过。
它挡的是同一类事情的另一个入口——棋魂 `QH-01_0211` 只印一行版权字，窗口 338×36，
裁完顶到面板高会放大 66.7 倍、输出宽 13595。

**两者不要各写一份。** 本票的兜底上界管的是「算出来的目标尺寸太大」，那条守卫管的是
「裁出来的窗口太小」，但后果是同一个。落地时把它们收在一处，或者说清为什么必须分开。
那条守卫的 0.5 同样未标定。

## 不要做的

- 不要把它做成用户可调的开关。这不是偏好，是防崩溃的兜底；可调等于把崩溃的责任交回用户。
- 不要改成「越界就当失败页」。那一页的像素是好的，退回 fit-inside 仍然读得了，
  变成白页反而丢了内容。

## 落地记录

目标尺寸有了一道兜底上界，落在 `FitMode::target` 里——**算目标尺寸的唯一入口**。
越界的页退回 fit-inside，整趟照常跑完；那一页**不是失败页**，它的像素是好的。

### 上界取多少，依据是什么

（取值与依据的出处是 `geometry::MAX_TARGET_PIXELS` 自己的文档；这里只记拍板时看的那几个数。）

`MAX_TARGET_PIXELS = 32 Mi 像素（33 554 432）`，由**解码那一侧的上界折算**而来：

```
MAX_TARGET_PIXELS = MAX_DECODED_BYTES / PEAK_BYTES_PER_TARGET_PIXEL
                  = 512 MiB / 16 字节
```

- **为什么是折算，不是另拍一个数。** 两侧各定一个数，就会出现「解码收得下、目标分配不下」，
  而后者中止的是整趟——正是本票要消灭的东西。`decode::MAX_DECODED_BYTES` 因此改成
  `pub(crate)`，折算的那一头引它、不抄它；一条用例钉住这个等式，改任一头另一头跟着走。
- **系数取 16，而照代码数出来的是 9**（彩色分支：三个平面缩放缓冲 3 + 交织 3 + 编码输出 ≤ 3）。
  取大了上界更小、更安全：取 9 会让目标那一侧的峰值正好顶在 512 MiB 上，与解码那一侧**齐平**，
  而齐平不是「肯定跑得完」。取 16 之后目标那一侧的峰值是 **302 MiB，严格低于**解码那一侧——
  「解得进来的页，缩出去必定也分配得下」这句话有了一个不等号，一条用例断言它。
  那个 9 本身是数出来的、不是量出来的，没有实测峰值内存背书，记在停车场 **Q22**。
- **它定在「肯定跑得完」那一侧。** 换成面板：在 1072×1448 上是 21.6 倍面板宽，
  在 1264×1680 上是 15.8 倍。换成源页的形状：宽高比要超过 **12:1** 才够得着，
  而实测最宽那一页是 2.4:1。按像素算，它（改革之獸 3457×1448）离这道线还有 **6 倍**——
  用例把这两句都钉住了。
- **它不是开关。** 命令行一个字都没加：这不是偏好，是防崩溃的兜底。

### ADR 0003 那笔账（本票自己要算的）

ADR 0007《后果》押着「任何改动目标尺寸的改动，都要同时对 ADR 0003 的硬上界负责」。
兜底改的正是目标尺寸，账当场算了，全文在 `geometry::MAX_TARGET_PIXELS` 的《ADR 0003 那笔账》
一节，三句话：判定仍同源（尺寸仍出自 `FitMode::target`，门仍只由 `GeometryGate::of` 判一次）；
门可能因此不成立，而那正是实情被如实报出来，那一页照 ADR 0007 决定第 2、3 条走；
兜底只会让门变严、不会让它变松。

### 退回，不是失败页

`fit_inside` 的结果恒不超过面板（源比面板小就原样返回，否则等比缩进面板），
面板本身远在上界之内——**退回这一步自己不会再越界**，一条扫描用例钉住它，
同一条顺带钉住 fit-inside 那条路一次都触发不到兜底。

一处随之而来的语义变化：**「以高为准下几何门每一页都成立」从此有了一个例外**。
退回去的页是一张 fit-inside 的页，门照 fit-inside 那条判，源两边都比面板小时会不成立。
代码那一侧（`GeometryGate::Broken`、`GeometryGate::of` 的文档、那条扫描用例的名字与断言）
已照实际行为写全；ADR 0007 与 `page-geometry/05` 票面上那两句归 06 号票，
记在停车场 **Q21**。

### 报告

两处说话，都只在真发生时说：

- **逐页那一行**末尾一小截「· 兜底退回 fit-inside」——「哪一页」翻得到，靠的是它。
- **末尾一小结**「兜底上界 N 页：…越过 67108864 像素…」，点名头几页，上界那个数原样印出
  （与裁法那两个数同一条规矩：数摆出来，读的人自己判断）。抬头一个字不提——
  用户没得选的东西不该每趟都提醒（与 05 号票处置 ② 同一个待遇）。

API 那一侧：`Report::backstopped()` 给全部退回页，`PageReport::backstop()` 逐页问。
它与 `Report::wider_than_the_panel()` **不重叠**——退回之后的页恒在面板宽以内。

### 与裁边那道守卫：**分开，不合并**

票面要求「收在一处，或者说清为什么必须分开」。**分开**。三条理由的全文在
`crop::MIN_KEPT` 的文档里（那是它的出处，这里不复述）：问的时刻不同（守卫问的时候面板还
没进来）、退法不同且各自的退法只对各自那一张有用、两个数标定的东西不同（画质对跑得完）。

**作用区间也不重叠，而且量得出来**（`crop` 里那条同名用例，面板取实测的 boox-poke6）：

| 那一张 | 谁接得住 | 数 |
|---|---|---|
| 棋魂 `QH-01_0211`（窗口 338×36） | 只有守卫 | 裁下去算出 13595×1448 = **1968 万像素**，仍在兜底上界（3355 万）之内——兜底接不住 |
| 四边顶着墨的长条（3500×100） | 只有兜底 | 每一行每一列都是墨，守卫一个像素都拿不走 |

顺带得到一条界：留下的宽高各不少于原页一半，**裁边至多把目标宽放大 2 倍**，
越过兜底上界的必定是源页本身的形状。

### Q7 — 以高为准让目标尺寸没有了上界，极端瘦长的源页会把输出缓冲撑到分配不下

  `page-geometry/01` 明确不给宽度设上限（票面的《不要做的》：用户接受任意宽度的横向翻动），
  实测最宽只有 3.22 倍面板宽。但目标宽 = 源宽 × 面板高 ÷ 源高，一张 20000×100 的长条
  （解码那一侧只有 2 MB，`MAX_DECODED_BYTES` 拦不住）在 1448 高的面板上算出的目标是
  289600×1448 ——那块缓冲分配不下，`Image::new` 那一步会直接中止整趟，
  而不是像别的坏页那样变成一个失败页（`CONTEXT.md` 的《失败》）。
  fit-inside 上这件事不可能发生：目标尺寸恒不超过面板。
  不当场处理：出路是「给目标像素数一道与 `MAX_DECODED_BYTES` 对称的上界，越界记为失败页」，
  但那等于给宽度加了一道上限，与本票明确定下的「不设上限」正面相撞——该由所有者拍板。

  **处置**：所有者立了 `page-geometry/07`，已落地——上界与取值依据见
  `src/geometry.rs` 的 `MAX_TARGET_PIXELS`，落地的账见那张票的《落地记录》。
  与本条的猜测差在两处：**不记为失败页**（那一页的像素是好的，退回 fit-inside 仍读得了，
  变白页反而丢内容），且「不设上限」被读成**阅读上**不设上限——兜底管的是跑得完跑不完，
  不是读得动读不动，因此不是用户可调的开关。
