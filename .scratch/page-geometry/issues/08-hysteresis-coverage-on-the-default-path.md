# 08 — 迟滞升档在默认适配方式上要有端到端覆盖

**What to build:** 迟滞升档这条行为在**默认**路径上也有用例守着。

`page-geometry/01` 把默认适配方式改成 `height` 之后，三个长卷夹具留在了 `inside` 组——
迟滞升档因此在默认路径上**一条端到端用例都没有**。迟滞是 ADR 0006 的核心行为
（相邻两页不该在翻页处换档），默认路径上没覆盖等于裸奔。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 迟滞升档在 `height` 上有端到端用例，黄金快照里看得出「迟滞升档 N 页」
- [x] 卷级夹具的两个占位取值重新定出来，依据写进落地记录——
      `p0-hardening/07` 当初推过一次：上包络取 p95 时，要让升上去的那几页不被自己的秩圈进去，
      需 `ceil(0.95n) ≤ n-3`，解得 **n ≥ 60**。适配方式换了之后这个推导要重走一遍，
      不要直接抄那个数
- [x] 变异检验：把迟滞页数常量改掉，这条用例要红（`p0-hardening/07` 当初正是靠这个
      发现旧夹具对迟滞完全不敏感的）
- [x] `inside` 那一侧的既有覆盖不动

## 不要做的

- 不要为了省事把长卷夹具整组搬回 `height` 就算完——`inside` 那一侧的覆盖也要留着，
  两条路的行为不同。

## 落地记录

默认路径上补了两处覆盖。**`inside` 那一侧的行为一点没动，名字与共用体有改**——
`NEEDS_FOUR_BITS` 改名、造卷体抽成 `levels_with_a_run_of`、`run_with_a_run_of` 改名
`run_with_a_run_of_fitted_inside`、`FAR_OUTSIDE` 的文档跟着改名订正、
`a_sustained_run_raises_the_depth_but_one_page_short_of_it_does_not` 体内加了两行注释。
断言与判定一条都没改：

- `tests/pipeline.rs` 的 `a_sustained_run_raises_that_stretch_on_the_default_fit_but_one_page_short_does_not`——
  与 `inside` 那一条同形的一对卷（段长 3 与 2），跑在默认适配方式上。
- `tests/golden.rs` 的 `envelope-hysteresis-gate-holds`——60 页的长卷，只进 `height` 那一组。
  快照那一行：`基准档 2bit · 驱动页 060.png · 主体 60 页 · 离群 0 页 · 迟滞升档 3 页`。

页尺寸是 `fixtures::NARROW_PASSES_THROUGH`（64×1680）：与 `PASSES_THROUGH` 同一条性质——
两种适配方式下都恒等通过——但窄到只够铺开两块判据分块（32×32），一卷 60 页约 1.2 秒。
`TINY` 用不了：以高为准会把每一页放大到面板高。

### 两个占位取值：重推之后没有变，改的是名字

**几何门在这条路上每一页都成立**（ADR 0007 决定第 1 条），候选集因此是六个那一套。
在 64×1680 的纯色页上逐档量出来的判据（界是 5.5，离群线是 3 倍即 16.5）：

| 纯色取值 | 1bit | 1bit+FS | 2bit | 2bit+FS | 4bit | 4bit+FS | 逐页判定 |
|---|---|---|---|---|---|---|---|
| 85 | 85.000 | 71.429 | **0.000** | 0.000 | 0.000 | 0.000 | `2bit` |
| 96 | 96.000 | 81.431 | 11.000 | **3.693** | 6.000 | 0.743 | `2bit+FS` |

- **85 留原值。** 它正落在 2bit 的格点上，而 1bit+FS 在这一档灰调上颗粒读 71.4、
  照样过不了界——门成立与否，第一个在界内的都是 `2bit`。名字 `NEEDS_TWO_BITS` 仍是实话。
- **96 留原值，名字从 `NEEDS_FOUR_BITS` 改成 `ONE_STEP_ABOVE_TWO_BITS`。** 它要的那个
  位置没变——基准档过不了它的界（2bit 上 11.000 > 5.5），又够不上离群（11.000 ≤ 16.5）。
  但**两条路把它送上去的机制不是同一套**：门成立时 `2bit+FS` 读 3.693 在界内，走的是
  「界以内最低的一档」；门不成立时候选只有三个、读数 96.000 / 11.000 / **6.000**，
  一档都不在界内，判定走 `decide` 的兜底取候选上界 `4bit`，迟滞那一段同样由
  `envelope::lowest_for` 的兜底抬上去。旧名字把后一条读成了「它要 4bit」，
  新名字只承诺「落在 2bit 之上」——**这也意味着 fit-inside 那一侧对 96 这个具体取值不敏感**，
  界外任何取值都会走同一条兜底。
- **纯色页在门成立的候选集上根本升不到 4bit。** `2bit+FS` 的颗粒是 `sqrt(d(85-d))`，
  上限 42.5，压在可见度地板（55）以下，颗粒项因此恒为零，只剩低通残差 2.3~4.5——
  永远在界内。这不是取值没选好，是这套候选集的结构：位深那一维的升档在默认路径上
  换个夹具也测不出来（记在停车场 Q25）。

两个取值连同上面这批读数落在 `tests/fixtures/mod.rs`，**出处只此一个**：黄金回归与
`tests/pipeline.rs` 是两个 crate，各写一份必然各自漂。

### 卷长 60：推导重走，结论不变

`ceil(0.95n) ≤ n-3`，解得 **n ≥ 60**——与 `p0-hardening/07` 同一个数，但不是抄的：
这条不等式数的是**页在 `by_demand` 序列上的名次**，与那一档是位深还是抖动无关。
适配方式换了只换掉候选集，换不掉名次。核对了一遍：60 页里 57 页判 `2bit`、3 页判 `2bit+FS`，
p95 的秩 57 落在最后一张填充页（060.png）上，基准档因此是 `2bit`，那三页留在秩之外。
立脚点那一层同样核过：秩 `ceil(0.75×59)=45` 站在填充页上，那三页在 `2bit` 上读 11.000，
够不上 16.5，一页都没被当成离群页摘走（快照那一行的「离群 0 页」）。

### 变异检验

改 `src/envelope.rs` 的 `HYSTERESIS_PAGES`，跑
`cargo test --test pipeline a_sustained_run_raises` 与 `cargo test --test golden`，复跑得出来：

- **3 → 8**：两条用例与快照那一行都红——新用例断言 `raised_pages` 得 0、要 3；
  快照里 `envelope-hysteresis-gate-holds` 与 `envelope-hysteresis` 两行的「迟滞升档 3 页」
  双双变 0 页。
- **3 → 2**：同样红——那一对卷里段长 2 的那个升了 2 页，`raised_pages` 得 2、要 0。

**两个方向都碰得响**，且默认路径与 `inside` 两侧各自红一次。留不下可重放的痕迹：
变异的是一个常量，复核只能照上面重做一遍。

### 代价

两处各多跑 60 页的卷（`pipeline` 那一条是一对，段长 3 与 2），这是买覆盖的价钱。
落地机上 `tests/pipeline.rs` 从 62.6 秒到 69.4 秒，多出的两卷单独计时各约 1.2 秒，
其余是并行下与别的用例抢核。**绝对秒数随机器与负载走**（同一份 `tests/golden.rs`
在两台上量到 101 与 130.8 秒），因此这里只报得出「一卷约 1.2 秒」这个可比的数；
`tests/golden.rs` 改动前的时间没有量，那个二进制的差额报不出来。
