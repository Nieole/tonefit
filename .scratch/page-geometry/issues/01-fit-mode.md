# 01 — 适配方式：新增以高为准

**What to build:** 用户能点名这一趟怎么把页适配到面板。`fit-inside`（现状）之外多一种
**以高为准**：目标高恒等于面板高，宽按源宽高比算出、**允许超过面板宽**，超出的部分靠阅读器
横向平移。跨页因此从压扁状态变得可读——哆啦A梦最宽一页从 1072×766 变成 2027×1448。

默认是以高为准。这是有意的行为变化：跨页卷体积涨到约三倍，比面板小的卷会被放大到面板高。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 命令行能点名适配方式，两种都选得到，**默认以高为准**
- [ ] 以高为准时目标高恒等于面板高，宽按源宽高比算出，**不设上限**（实测最宽 3.22 倍面板宽）
- [ ] 比面板矮的页放大到面板高
- [ ] 几何门在这条路上**每一页**都成立，抖动不再被关掉
- [ ] 报告说得出这一趟用的哪一种，以及哪些页的输出宽超过了面板
- [ ] 一条用例钉住**普通漫画页两种方式产出同尺寸**——那是「页比面板更瘦长、受高度约束」的
      直接后果，不是巧合，写下来后面改动才碰得响
- [ ] 预缩的总缩放比跟着适配方式走
- [ ] 幂等依据含适配方式：换了它，这一卷要重做
- [ ] 黄金快照重录，差异逐条确认

## 要认的

**留边与溢出对阅读器的要求不是同一个。** 留边只要求阅读器填背景不重采样；溢出要求它
平移不缩放，后者更强。以高为准把留边换成了溢出，实现时容易当成一件事。

ADR 0007《决定》第 7 条现在写着「目标尺寸只有一个来源：fit-inside 结果，不得为别的收益改动」，
本票直接与它冲突。文档收口在 06 号票。

## 不要做的

- 不给宽度设上限。用户明确接受任意宽度的横向翻动。
- 不做进 profile。它是读法偏好，不是面板的物理事实——profile 的主键是面板。
