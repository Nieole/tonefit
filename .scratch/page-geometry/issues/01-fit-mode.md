# 01 — 适配方式：新增以高为准

**What to build:** 用户能点名这一趟怎么把页适配到面板。`fit-inside`（现状）之外多一种
**以高为准**：目标高恒等于面板高，宽按源宽高比算出、**允许超过面板宽**，超出的部分靠阅读器
横向平移。跨页因此从压扁状态变得可读——哆啦A梦最宽一页从 1072×766 变成 2027×1448。

默认是以高为准。这是有意的行为变化：跨页卷体积涨到约三倍，比面板小的卷会被放大到面板高。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 命令行能点名适配方式，两种都选得到，**默认以高为准**
- [x] 以高为准时目标高恒等于面板高，宽按源宽高比算出，**不设上限**（实测最宽 3.22 倍面板宽）
- [x] 比面板矮的页放大到面板高
- [x] 几何门在这条路上**每一页**都成立，抖动不再被关掉
- [x] 报告说得出这一趟用的哪一种，以及哪些页的输出宽超过了面板
- [x] 一条用例钉住**普通漫画页两种方式产出同尺寸**——那是「页比面板更瘦长、受高度约束」的
      直接后果，不是巧合，写下来后面改动才碰得响
- [x] 预缩的总缩放比跟着适配方式走
- [x] 幂等依据含适配方式：换了它，这一卷要重做
- [x] 黄金快照重录，差异逐条确认

## 要认的

**留边与溢出对阅读器的要求不是同一个。** 留边只要求阅读器填背景不重采样；溢出要求它
平移不缩放，后者更强。以高为准把留边换成了溢出，实现时容易当成一件事。

ADR 0007《决定》第 7 条现在写着「目标尺寸只有一个来源：fit-inside 结果，不得为别的收益改动」，
本票直接与它冲突。文档收口在 06 号票。

## 不要做的

- 不给宽度设上限。用户明确接受任意宽度的横向翻动。
- 不做进 profile。它是读法偏好，不是面板的物理事实——profile 的主键是面板。

## 落地记录

命令行多了 `--fit`，两种适配方式都点得到，**不点名就是以高为准**。
目标尺寸从此只有一个入口：`FitMode::target(源尺寸, 面板分辨率)`。

### 开关长什么样

```
--fit <方式>   height（默认，以高为准）| inside（fit-inside）
```

名字解析照 `--filter` 那一套：大小写不论、两边空白不算，`fit-height`/`fit-inside`
是各自的别名，规范名是 `height` 与 `inside`（参数哈希拿规范名当稳定写法）。
认不出的名字在拼 `Request` 之前就被挡下，错误把两者的差别一并说出来。

库那一侧是 `Request::fit`。它**不进 profile**——profile 的主键是面板，而适配方式是读法偏好。

| 这一趟走哪条 | 目标尺寸 | 几何门 | 宽 |
|---|---|---|---|
| `height`（默认） | 高恒等于面板高，宽 = 源宽 × 面板高 ÷ 源高 | **每一页**都成立 | 不设上限，可溢出面板 |
| `inside` | 等比缩进面板，源比面板小时不放大 | 逐页判，比面板小的页不成立 | 恒不超过面板 |

### 「几何门恒成立」说的是每一页

门仍是**逐页**判的（ADR 0007 决定第 1 条），`GeometryGate::of` 一个字没改：
以高为准让高那条边每一页都贴着面板，于是「不成立」那一支成了空集。
那套逐页机制不白做——换回 `--fit inside` 它照旧有效，本批把它整套行为
（抖动关闭、跟着基准档的位深走、一页成立的都没有时门不成立的页就是主体、
`--dither fs` 撞上门当场被拒）留在了 fit-inside 那条路上，黄金快照与用例都在那里钉着。

### 留边与溢出不是一件事

门问的是「tonefit 交出去的像素与面板像素对不对得上」，两种情形下答案都是「对得上」，
**读数因此不变**。变的是对阅读器的要求：留边只要它填背景、不重采样；溢出要它平移、不缩放，
后者更强。那一层是**像素完整性**，门够不着（`CONTEXT.md`），只有标定图问得出来。
两句话分别落在 `GeometryGate::of` 与 `FitMode` 的文档里，报告末尾那一小结也照这条说话。

### 普通漫画页两种方式同尺寸怎么钉的

两处，一处证性质、一处证行为：

- `src/geometry.rs` 的 `the_two_fit_modes_agree_on_every_page_that_is_height_constrained`：
  三块面板 × 宽高比 1.43–1.53 × 面板高到四倍面板高的高度，逐个断言两条路产出同一个 `Size`。
  前提两条写在用例里、也在扫描里带着：**受高度约束**（源宽 × 面板高 ≤ 面板宽 × 源高）
  且**不比面板矮**。缺一条就该分岔，扫描把那些点跳过。
- `tests/pipeline.rs` 的 `an_ordinary_comic_page_comes_out_the_same_size_either_way`：
  同一卷跑两趟，逐页比**尺寸、判定候选与写出的像素**。比像素不比文件字节——
  适配方式进了参数哈希，两趟的 tEXt 本来就不同，而那正是幂等要的。

实测复核：棋魂完全版 Vol.01 的 230 页，两条路上目标尺寸**逐页一致**（boox-poke6 面板）。

### 幂等

参数哈希新增一行 `fit`，规范名写进去。换了适配方式，这一卷每一页的尺寸、几何门、
判据参照与判定都要重算，上一趟的输出一张都不能留——`tests/idempotency.rs` 的
`a_changed_parameter_redoes_the_volume` 多了一格。

### 缩放

`Scaling::plan` 一个字没改：它算的是「源高 ÷ 目标高」，目标高一换，三个数自己跟着走。
以高为准下比面板矮的页缩放比**小于 1**（放大），预缩自然退化为恒等；
`the_total_ratio_follows_the_fit_mode` 拿同一卷两条路各断言一遍五个档位。

### 报告

- 抬头多一行 `适配方式 …`：两种方式在普通漫画页上产出同一个尺寸，光看页尺寸分不出走的是哪一条。
- 末尾多一小结**输出宽超过面板 N 页**：最宽多少、是面板宽的几倍、点名头三页、
  出路（换 `--fit inside`）与代价一并说出。一页都没有就一个字都不说，
  与部分救回、隔离那两小结同一条规矩；点名复用 `first_few_names`，不另起一份。
- 库那一侧是 `Report::fit` 与 `Report::wider_than_the_panel()`。后者按
  `PageReport::size` 问，**失败页也算**——那张占位页真有那么宽，翻起来真要平移。

### 真实语料上变成了什么样（boox-poke6，1072×1448）

三卷各跑了两趟，**数落在 `docs/measurements.md` 的《适配方式：fit-inside 与以高为准》**
（那一节多了一张「实际字节」表）——实测数字只有那一个出处。这里只说这一趟看到的形态：

- **棋魂完全版 Vol.01（普通漫画卷）**：两条路上 230 页**逐页同尺寸**，0 页溢出面板。
  性质那一条在真实语料上的复核就是它。
- **哆啦A梦 8K Vol.15（跨页卷）**：413 页里 376 页（91%）溢出，最宽 2027×1448 = 1.89 倍面板宽；
  几何门 413/413 成立。体积涨到 2.51 倍，与票面说的「约三倍」同一量级。
- **Bowing！第1话（比面板小的卷）**：几何门从 **62/66 页不成立**变成 **0 页不成立**，
  60 页由 836×1200 放大到 1009×1448，3 页溢出到 2016×1448。
  **体积不涨反降 16%**——那 62 页从不抖的兜底档回到 2bit+FS，省下的比放大付出的多。
  「比面板小的卷会被放大」是真的，「因此更大」不是。这是本票最值得记下来的一条。

### 黄金快照

快照的卷行加了适配方式：`[型号 适配方式] 卷名`。夹具分成两组跑：

- **默认（height）组**：除三个长卷之外的全部黑白夹具，加彩色面板那一卷。
- **fit-inside 组**：几何上真会分岔的三个（`spread`、`undersized`、`mixed-size`）
  在两组里各出现一次；三个长卷（`envelope-outlier`、`-heavy`、`envelope-hysteresis`）
  **只在这一组**——它们考的是上包络、离群与迟滞，用的是 `fixtures::TINY` 小页，
  而小页只在 fit-inside 上还是小页。

差异逐条：

| 变动 | 为什么 |
|---|---|
| 每个卷行加 ` height` / ` inside` | 快照现在覆盖两条路，卷行要分得开 |
| `spread` 1264×420 → **5056×1680**，44307 → 606399 字节 | 跨页不再被长边压扁。这个夹具是面板宽的 4 倍，比实测最极端的 3.22 倍还夸张 |
| `undersized` 800×1000 → **1344×1680**，门 1 页不成立 → 0 页，基准档 4bit → **2bit+FS**，2364 → 213578 字节 | 放大到面板高，门跟着成立，抖动那一维回到候选集。字节涨 90 倍是合成夹具的极端：4bit 不抖的平滑渐变几乎全是长游程，换成抖过的 2bit 就成了高熵 |
| `mixed-size` 001.png 同上；主体 4 页 → **5 页** | 那张封面不再被摘出去，进了上包络 |
| 三个长卷从 height 组挪到 inside 组 | 见上。**三行数字一个字没变**（基准档 1bit、驱动页 019/018/060、主体 19/18/60、离群 1/2/0、迟滞升档 0/0/3），确认过是原样搬家、不是重算 |
| 其余全部卷 | 只有卷行那一处变动。它们的页比面板更瘦长、也比面板高，两条路上产出同一个尺寸——那正是上面那条性质在快照里的现场 |

三个长卷要是留在默认那条路上，`envelope-hysteresis` 会从「迟滞升档 3 页」变成
「离群 3 页、迟滞升档 0 页」——门一成立候选集多了抖动那一维，同一批读数排出的次序变了。
那不是回归，但**迟滞那条路径会在快照里整个消失**，所以那一卷跟着另外两卷一起留在 fit-inside 上。

### 用例侧的连带改动

三类，各有各的理由：

1. **门不成立是被测对象的**，点名 `--fit inside`：`tests/pipeline.rs` 七条、
   `tests/concurrency.rs` 两条。以高为准下那一支是空集，不点名就什么都没钉住。
2. **只要一张「不经缩放」的页的**，改用新夹具 `fixtures::PASSES_THROUGH`（800×1680，
   高已经等于面板高，**两种适配方式下都恒等通过**）：解码、转灰、透明区、调色板那几条，
   加 `tests/container.rs` 两条。断言里的「输出与源逐字节相同」因此仍写得下来。
   `tests/concurrency.rs` 的 `TOUCHING` 由 1264×200 改成 200×1680，同一个理由。
3. **拿小页图快的卷级用例**，走新助手 `fixtures::run_volume_fitted_inside`：
   上包络、离群、迟滞、覆盖那几条。它们与几何无关，改走 fit-inside 是为了让小页还是小页。

新增用例：几何那一层 7 条（同尺寸性质、实测两页的极值、放大到面板高、门每一页成立、
取整不压成 0、名字解析与默认、错误清单），`run` 这个 seam 上 4 条（默认这条路的目标尺寸、
放大到面板高、两种方式同尺寸、总缩放比跟着适配方式走），命令行 2 条，报告渲染 1 条，幂等 1 格。

### 自检（`/code-review`）改掉的四处

两轮并行复核（标准 / 票面）各报了一批，四处当场改掉，其余归档：

1. **`--dither fs` 那条拒绝的措辞变成了假话。** 它原写「几何门动不了——它是页的几何事实，
   不是一个可以放宽的档位」。门确实放宽不了，但**几何动得了**：`--fit height` 把那一页
   放大到面板高，门跟着成立。措辞补了这一句出路，用例跟着断言它。
   （spec 的《Further Notes》本来把这句话记在 05 号票名下，但落地之后那半句在**默认路径上
   就是错的**，不能等。05 号票那张互锁表照旧归它。）
2. **那条同尺寸性质的前提守卫是死代码。** 扫的宽高比 1.43–1.53 全部比三块面板更瘦长，
   那句 `continue` 一次都没走到，而文档写着「缺一条就该分岔，扫描把那些点跳过」。
   扫描补了三条：**恰好等于面板宽高比**（`fit_inside` 正好顶在 `.min(面板宽)` 那道夹子上，
   两条路要差一个像素只会差在这里）、以及两条比面板更扁的。末尾两句断言钉住
   「前提内外都真的走到过」，那句 `continue` 从此不会再悄悄变成死代码。
3. **`src/resample.rs` 的残差比不变量只扫了 fit-inside 的目标。** 以高为准带来了一支
   从前不存在的情形——**总缩放比小于 1**（放大）。那条扫描现在两种适配方式各跑一遍；
   「预缩之后不小于目标」加了一道守卫：没预缩过的页没有「缩过头」可谈。
4. **溢出那一小结把 markdown 强调印进了终端文字。** `**平移**` 去掉——
   报告里别处一处都没有。

实测字节表挪进了 `docs/measurements.md`（`CLAUDE.md`：实测数字的来源只有那一个）。
本记录里那几处 `measurements 的《适配方式》` 补成了完整小节标题（稳定引用）。

**归档没改的**：`CONTEXT.md` 与 ADR 0007 的矛盾（本票明令不改，归 06——但 06
`Blocked by: 01、02、03、04、05`，词汇表要一直假到那四张票落地，值得所有者看一眼）；
二三十处仍拿 `SMALLER_THAN_TARGET` 当便宜页的夹具；迟滞升档在默认路径上没有端到端覆盖。
后两条与下面这一条一起记在《非阻塞问题》。

### 留给所有者的两处

以高为准让目标尺寸**没有了上界**（票面明确要求不设上限），于是一张极端瘦长的源页
（例如 20000×100，解码那一侧只有 2 MB）算出的目标是 289600×1448，那块缓冲分配不下、
会中止整趟，而不是变成一个失败页。fit-inside 上这件事不可能发生。已记进《非阻塞问题》。

**迟滞升档在默认那条路上一处端到端覆盖都没有了。** 三个长卷与那条迟滞用例都留在了
`--fit inside` 上（小页只在那条路上还是小页），`src/envelope.rs` 的单元用例不碰几何、
覆盖没丢，丢的是「默认这一趟真跑一遍」。补回来要给卷级夹具换尺寸并**重定两个占位取值**，
那是改上包络那批用例的立论基础。已记进《非阻塞问题》。
