# 页几何：裁边、跨页拆分、适配方式

Status: ready-for-agent

## Problem Statement

三件事在真实素材与真机上撞在了一起。

**跨页读不了。** 五卷 A 类里三卷以跨页为主（哆啦A梦 91%、改革之獸 99%）。目标尺寸恒等于
fit-inside(面板分辨率)，跨页因此被长边压扁：哆啦A梦最宽一页从 6048×4320 压到 1072×766，
改革之獸从 7162×3000 压到 1072×449。那个尺寸下字认不出来。

**阅读器的白边裁切把抖动抹平。** 6 寸屏上自动裁边是刚需，用户实测开不开差别很大。但裁掉白边
就改变了页尺寸，随后的适配于是不再是 1.0 倍——像素完整性测试在开着裁切的 KOReader 上
糊成一片，1 像素周期光栅无纹理。**抖动要 1:1、裁边必然改尺寸，两者在阅读器那一侧结构性对立。**

**混排卷。** 同一卷里常有些页已经拆成单页、有些还是连页，尺寸判定要能分得开。

## Solution

三个开关，默认全开。

- **裁边**：tonefit 自己裁掉白边。好处烤进产物，用户因此可以关掉阅读器那一侧的裁切，
  1:1 恢复，抖动活下来。
- **跨页拆分**：可调阈值挑出候选，装订沟定切点。没有装订沟的是**连续跨页**——一幅画横跨两页，
  不切。
- **适配方式**：`fit-inside`（现状）之外新增**以高为准**，目标高恒等于面板高，宽随源比例、
  允许超出面板宽，靠阅读器横向平移。连续跨页与拆不动的页落在这一条上。

顺序是**裁边 → 判跨页 → 拆分 → 每半再裁 → 适配**。先裁再判，因为白边过宽的单页在裁之前
宽高比会像跨页。

## User Stories

1. 作为读 8K 跨页扫描的用户，我要跨页被拆成两页，这样每半页都能用满面板高度而不必横向翻动。
2. 作为读跨页的用户，我要拆点落在装订沟上而不是正中，这样画面不被切进去——实测沟中心在
   0.441–0.507 之间，按正中盲切最偏一页错 340 像素。
3. 作为读日式漫画的用户，我要拆开后右半页在先，这样阅读顺序不被翻转。
4. 作为读国漫或西方漫画的用户，我要能把阅读方向改成左开。
5. 作为遇到整幅跨页的用户，我要它**不被切开**，这样为视觉效果画满两页的画面保持完整。
6. 作为遇到整幅跨页的用户，我要它以高为准输出，这样即使要横向翻动也看得清。
7. 作为处理混排卷的用户，我要拆分阈值可调，这样已经拆好的单页不被误拆、还没拆的连页不被漏掉。
8. 作为 6 寸屏用户，我要 tonefit 自己裁掉白边，这样我可以关掉阅读器的裁切而不损失任何东西。
9. 作为开着抖动的用户，我要输出在阅读器里 1:1 贴上，这样抖动不被抹平、字节不白付。
10. 作为扫描件用户，我要裁边认得出孤立噪点不是内容，这样边缘一个墨点不会让裁边整个失效。
11. 作为用户，我接受页间字号跳动，我要的是更大的实际利用面积。
12. 作为用户，我要空白页在裁边下原样通过，这样它不会被裁成零尺寸。
13. 作为用户，我要报告说得出每一页裁掉了多少、拆没拆、用的哪种适配方式。
14. 作为用户，我要报告点得出哪些页的输出宽超过了面板，这样我知道哪几页需要横向翻动。
15. 作为不想改变现有产物的用户，我要能把三项各自关掉，退回原来的行为。
16. 作为处理普通漫画卷的用户，我要两种适配方式产出同一个尺寸，这样开关不该起作用的地方它不起作用。
17. 作为处理比面板小的卷的用户，我要页被放大到面板高，这样几何门成立、抖动不再被关掉。
18. 作为用户，我要幂等在开关变了之后重做这一卷，这样换了设置不会拿到上一趟的产物。
19. 作为用户，我要拆出来的两半有可预期的成员名，这样阅读顺序与幂等都站得住。
20. 作为用户，我要彩页与失败页在这三项下有明确行为，这样卷内不出现两套规矩。
21. 作为用户，我要 `--dither fs` 在以高为准下仍然说得清它为什么被拒或为什么不被拒。
22. 作为用户，我要知道以高为准会让体积涨多少，这样我不会被跨页卷的产物吓到。

## Implementation Decisions

**新术语进词汇表。** 装订沟：跨页正中附近贯穿全高的空白列。连续跨页：没有装订沟的跨页，
一幅画横跨两页。适配方式：目标尺寸怎么由源尺寸与面板算出。阅读方向：拆开后两半的先后。

**不变量改口径。** ADR 0007《决定》第 7 条现在是「目标尺寸只有一个来源：面板分辨率的
fit-inside 结果，不得为别的收益改动」。以高为准直接违反它，该条要改成「随适配方式而定」。
`CONTEXT.md`《几何》里「漫画页更瘦，目标尺寸的宽必然小于面板宽」当场变假。

**留边与溢出对阅读器的要求不同，不能当成一件事。** 留边只要求阅读器填背景不重采样；
溢出要求它平移不缩放，后者更强。以高为准把留边换成了溢出。

**几何门在以高为准下恒成立**——每一页都成立，不是「卷级恒成立」（门是逐页判的）。
`CONTEXT.md`《尚未确立》里「几何门不成立时该用哪个位深集合」那个洞**还在**，
只是这条适配路上没有页掉进去；换回 fit-inside 就又有了。

**裁边按行列墨量占比**，不用内容外接框。外接框边缘沾一个墨点就退回整页，实测那样量出来的
中位增益是 0。逐页各裁各的，不取卷级裁切框——卷级框会被留白最多的那一页拖住。

**拆分是两级判定。** 阈值挑候选（宽高比与面板比，可调），装订沟在候选里定切点；找不到沟就是
连续跨页，不切，退回以高为准。两级都不看内容语义，只看几何与墨量分布。

**默认三项全开。** 代价要写在显眼处：跨页卷体积涨到约三倍（哆啦A梦按像素折算 58.9 → 166 MB），
比面板小的卷会被放大。拆分与横向平移在像素数上等价，省不掉——那是用满面板高的必然结果。

**`Request` 增四个字段**：裁边开关、拆分开关与阈值、适配方式、阅读方向。CLI 各给一个开关。

**幂等依据要含这四项**，否则换了设置拿到的是上一趟的产物。

## Testing Decisions

**Seam 只用 `run(Request) -> Report` 这一个。** 三个开关都是 `Request` 字段，效果全部落在
`Report` 与写出的文件上：页尺寸、页数、成员名、逐页的裁切量与适配方式。不新开公开 seam——
装订沟检测虽然是个有误报率的检测器，但它的误报特征要在真实素材上才量得准，而那条路已经有
`tests/smoke.rs` 与 `TONEFIT_SAMPLES`。

**好的用例只断言外部可见的事实**，与 `tests/pipeline.rs` 现有的一致：不断言中间步骤，
不断言具体像素值，断言性质。

要钉住的性质：

- 普通漫画页两种适配方式产出同尺寸——那是「页比面板更瘦长、受高度约束」的直接后果，
  不是巧合，写下来后面改动才碰得响
- 白边里带孤立噪点的夹具：外接框会失败，本裁法不会
- 装订沟不在正中的夹具：切点跟着沟走，不落在正中
- 没有装订沟的宽页：不被切开，走以高为准
- 页间字号跳动是接受的形态，不是回归
- 空白页裁不出内容时原样通过
- 阅读方向反过来时两半的成员名顺序跟着反
- 四种开关组合都跑得通

**真实素材冒烟**（`tests/smoke.rs`）多担一件事：装订沟检测在单页卷上的误报率。
现有实测基线：哆啦A梦 15/16、改革之獸 16/16 找得到；棋魂 2/16、画集 1/16 误报，
而误报的沟宽 21–24%，真装订沟窄得多。

**黄金快照会整片变红**，默认三项全开是有意的行为变化，差异要逐条确认，不是回归。

## Out of Scope

- 倾斜校正（deskew）与扫描黑边。素材还没到手。
- 装订沟的语义判断。tonefit 只看几何与墨量，不判断「这幅画该不该切」。
- 读 ComicInfo.xml 取阅读方向。八卷素材里出现 0 次，为它引入 XML 解析不划算。
- 卷级裁切框。用户明确要更大的实际利用面积，不要页间一致。
- 横向平移的阅读器配置。tonefit 看不到阅读器的显示管线（ADR 0007），这条进文档不进代码。

## Further Notes

三个开关默认全开是用户的明确决定，理由是他是目前唯一的用户、要开箱即用。升级的人会看到
输出明显变样，这一条必须写在票面与文档里。

`--dither fs` 那条拒绝路径在以高为准下几乎打不着了——没有页贴不住面板。它仍在 fit-inside 上
活着，但错误消息该提一句「换个适配方式也能解」。

ADR 与 `CONTEXT.md` 那半边由 tonefit-0a 负责，等实现落地照实际行为写。
