# 11 — 幂等与 tEXt 元数据

**What to build:** 判定与理由写进输出 PNG 的 tEXt 区块，同一批字段兼作幂等依据：参数或源变了就重跑，没变就跳过。重跑一个已处理且参数未变的卷时不重复工作，`Report` 把它标为 `Skipped`。

记录随文件走，不依赖外部状态库——文件被移动、改名、重新打包都不会丢。

**Blocked by:** 08 — 卷级上包络与迟滞

**Status:** resolved

- [x] tEXt 写入工具版本、profile 名、参数哈希、源哈希、判定位深与理由
- [x] 重跑时参数与源均未变的卷被跳过，`Report` 标为 `Skipped`
- [x] 参数变更触发重做
- [x] 源文件变更触发重做
- [x] 输出被移动或改名后，幂等判定仍然成立
- [x] `--no-metadata` 关闭元数据写入，此时不再具备幂等能力，行为在帮助文本里说明

## Comments

**源哈希取卷级，不逐页；跳过的单位也是卷。**这是 ADR 0006 决定第 3 条的直接后件，
论证与代价一并写进了那一篇的《决定》末段——本票只是落地它。

**代价是源字节多读一遍**，这一遍在第一遍解码之前。ADR 0006 认下的正是它（「不是零：要算源哈希、
读回 tEXt 比对」）。换不掉：彩页在第一遍就编好并写进 tEXt（ADR 0010），那一刻卷级哈希必须已经齐了。
`--no-metadata` 连这一遍都不读。

**指纹四项里有三项管像素，型号名那一项不管。**同一块面板的两个别名（`kobo-libra-2` 与
`kobo-libra-h2o`）输出逐字节相同，参数哈希因此**不收型号名**——它收的是面板四项、阈值、
残差段滤波器与三个覆盖项。型号名单独占指纹的一项，也单独比：记录要说得出「这批输出该拿去
哪台设备看」，那是 `Report::profile` 存在的同一个理由，说错了型号的记录就是过期的记录。
换别名会重做一遍，是明知故犯的交换。两件事分在两个字段上，各自的作用才说得清；
合成一个就得在「别名换了要不要重做」上二选一，而两边都有道理。

其余不收的几项各有理由——`--cache-budget` 限的是峰值内存、不动写出的像素（ADR 0005），
收了它，改一次预算就要整库重做；`--dry-run` 一个文件都不写；输入路径与输出根目录收了之后，
输出一搬家记录就全部失效，而「记录随文件走」要的正是反面。喂进哈希的是一段按名写死的文本，
不是 `Debug`——那串字节要落进文件、几个月后还要比对，而 `Debug` 的写法没有稳定承诺，
它一变全库的输出会静默地一起过期。

**跳过要问两件事：每页的指纹对不对得上，透传文件还在不在。**指纹只随页走，透传文件不带记录——
只比指纹的话，有人从输出里删掉 ComicInfo.xml 之后这一卷会永远跳过，那个文件再也补不回来。

**`Skipped` 落在 `VolumeVerdict`，不在 `Reason`。**spec 把它列在判定理由里，而幂等命中是**整卷**的
结果：那一趟一页都没重做，也就没有逐页的理由可给。`VolumeReport` 因此有两处跟着改——
`gate` 变成 `Option`（门是算出来的，那一趟一页都没算），`pages` 是空的而页数走
`page_count()`（页数是源那一侧的事实，不做工作也数得出来）。摆一个 `GeometryGate::Holds`
上去是编的，报告不该有编出来的字段。

**dry-run 也走幂等这一道。**它预告的是照做时会发生的事，而照做时会发生的正是「跳过」
（spec 的 story 6 与 story 8 在这里交汇）。

**一页读不出记录就整卷重做，不逐页续做**（同上，ADR 0006）。一页都没有的卷则永远不命中——
记录随页走，没有页就没有地方放它。

**「输出被移动或改名后幂等判定仍然成立」钉的是「记录不丢」，不是「还找得到」。**
输出去处按源卷名算（`Volume::output_path`），改了输出容器的名字，下一趟会在原来的名字上
重写一份——那不是判成了过期，是压根不在它看的地方。记录本身毫发无损：
`the_record_survives_moving_renaming_and_repacking_the_page` 把页搬走、改名、重新打包进
另一个归档，六个字段一字不差。搬**整个输出根**并把它交给 `--out` 则照旧跳过，
那一条是 `moving_the_output_elsewhere_keeps_the_judgment`。

**tEXt 的取值是 Latin-1，中文写不进去。**判定理由因此有两份写法：报告那一侧是中文
（`Reason` 的 `Display`），记录这一侧是钉死的英文，上包络那条照 ADR 0006 的原话写成
`volume-p95, driven by page 087`。两份不互相替代——一份给人当场读，一份给几个月后
打开这个文件的人读。

**一处已有用例跟着改了口径。**`the_filter_changes_the_residual_step_and_never_the_prescale`
比的是两次输出的字节。参数哈希收滤波器，留着记录的话两次输出必然逐字节不同，
那几条 `assert_ne!` 会因为几行 tEXt 而通过、与像素有没有变毫无关系。该用例改为
关掉元数据再比——比字节这才是在比重采样。

**留给 12 号票：`VolumeReport` 该拆成「处理过 / 跳过」两支。**「跳过」这件事现在由三处一起
编码——`verdict` 是 `Skipped`、`gate` 为空、`pages` 为空——读的那一端要自己认其中一处。
本票只做到「只有一个来源」：`VolumeReport::skipped()` 与 `page_count()` 各是唯一的入口，
`gate_line` 那个 `expect` 也挪到了与它的守卫同一个函数里。真正的修法是照 `PageBranch`
的样子（10 号票：两条分支的产物不是同一套，因此是一个枚举而不是几个各自可空的字段）
把 `gate`/`cache`/`decodes`/`pages` 收进一个 `Processed` 里。没在本票做，因为那要改约七十处
读取点、全在测试里，与幂等无关。12 号票要给卷加上「有失败页 / 隔离目录」这第三种状态，
那时是第二个理由，一起拆最划算。
