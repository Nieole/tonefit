# 02 — Profile 与面板表

**What to build:** 用 `--profile` 指定目标设备，目标尺寸由该设备的面板算出，不再写死。内置面板表覆盖 Kobo、BOOX、Kindle 主力型号，型号名到面板是多对一的别名表。`--gray-levels` 可覆盖面板灰阶数。

面板只含分辨率、PPI、灰阶数三项；阈值档位属于 profile，不属于面板。同一面板可以有多个 profile。

**Blocked by:** 01 — 骨架：单页贯通与合成夹具

**Status:** resolved

- [x] `--profile` 接受型号名，经别名表解析到面板
- [x] 目标尺寸 = fit-inside(面板分辨率)，随源页宽高比逐页算出
- [x] 面板表用少量面板 + 型号别名表达，新增型号只需加一行别名
- [x] `--gray-levels` 覆盖面板灰阶数
- [x] 未知型号给出可操作的错误，并提示 `--gray-levels` 与内置型号清单
- [x] `Report` 标明本次使用的 profile 与面板

## Comments

面板表在 `src/profile.rs`：9 块面板是 `const`，`DEVICES` 是型号别名表，27 个型号一行一个。
`PANEL_RESOLUTION` 随本票退场。

本票内定下、还没有 ADR 承接的几件事：

- **`--profile` 必填，没有默认设备。** 输出是给一块具体面板的，默认挑一台设备会静默产出
  尺寸不对的副本，而错在哪儿从输出上看不出来。
- **型号名归一后再查表**：大小写与分隔符不计，`Kobo Libra 2`、`KOBO_LIBRA_2`、`kobo-libra-2`
  是同一个型号。表里存规范名，`Report` 也回显规范名。
- **`--gray-levels` 在 CLI 层折进 profile**，`run` 只收解析好的 profile。它不是 spec 里那组
  「覆盖项」——覆盖项是判定的旁路，这一条改的是面板本身。上界 256，即 8bit 输出的表达极限。
- **`Report` 加了 profile 字段，`spec.md` 的 `Report` 形状同步改了。** 本票的验收要求它；
  `--gray-levels` 覆盖之后，「本次到底用的哪块面板」只有报告能回答。
- **换代换过面板的产品线，型号名必须带代次**：`kindle-paperwhite-11`（6.8 英寸）与
  `kindle-paperwhite-12`（7 英寸）分列，`kindle-oasis-2/3` 同理。不带代次的名字走未知型号那条路——
  蒙一个代次就是静默给出错的目标尺寸，而那正是这张表要挡掉的事。
- **面板参数取各家公布的规格，不是实测。** `docs/measurements.md` 只收实测数字，
  它《B 类素材普查》那一节的三块面板都在本表内。只收黑白 e-ink 型号，
  Kaleido 彩色面板不在 P0 范围内。
- **公开面仍是 `run` 一个 seam。** 面板表不对外暴露枚举接口，表的完整性在 `src/profile.rs`
  里就地断言；`tests/profile.rs` 只测型号解析与错误这些用户看得见的事。

ADR 0003 的「不要做的简化」里说型号到面板的映射属于标定文档。那一条要防的是把面板表铺成设备清单；
本票交出的正是它要的形状——少量面板 + 多对一别名，新增型号只加一行，不新增面板。

未知型号的错误把内置清单按面板分组端出来（按尺寸排序），并给出兜底办法：挑一个面板相同的型号，
再按实测用 `--gray-levels` 覆盖灰阶数。灰阶数是挑替身时唯一挑不出来的那项。

灰阶数当前只进 `Report`，还没有消费者——按面板灰阶数裁剪候选位深是 06 号票的事（ADR 0003）。
`--gray-levels` 收下的级数不必是 2 的幂：它是阶梯图上数出来的可分辨级数，怎么映射到候选位深
归 06 号票。阈值档位同理，随判据落地（04 号票），此刻 profile 只有面板。

**本票没解决的**：面板本身不在表里的设备（分辨率或 PPI 都对不上）没有入口，只能挑一个面板相近的
型号顶上。story 32 要的「面板灰阶数可覆盖」已经兑现，分辨率覆盖 spec 里没有，本票不擅自加。
