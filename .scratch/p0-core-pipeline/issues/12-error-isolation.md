# 12 — 错误处理与隔离目录

**What to build:** 一张坏图不再毁掉整卷。单页失败时仍强制统一尺寸以保证卷内一致，该卷被标记并输出到隔离目录，失败页与原因进 `Report`。问题因此可见且有界——可以选择忽略，但它不会藏起来。

**Blocked by:** 08 — 卷级上包络与迟滞

**Status:** resolved

- [x] 截断的图片只要能解出完整尺寸就使用，解不出尺寸才算失败
- [x] 单页失败时该页仍以目标尺寸产出，卷内尺寸保持一致
- [x] 含失败页的卷输出到隔离目录并被标记
- [x] `Report` 列出每一个失败页与原因
- [x] 零字节文件、非图片文件、超大尺寸页均不导致进程中止
- [x] 退出码能区分「全部成功」与「有卷被隔离」

## Comments

**界线画在「出不出得来一张对的页」上，而尺寸是其中的大头。**票面头一条与第二条
其实是同一条：尺寸解得出来的页有自己的几何，
它照常缩放、照常过几何门、照常进判据与上包络，与好页毫无二致；解不出尺寸的页连几何都没有，
只能借卷内统一尺寸。把截断页也算作失败反而更糟——那会用一个卷内统一尺寸顶掉一个**本来就正确**的
尺寸，还平白把整卷送进隔离目录。

救回那一段落在 `decode::salvage`：整解失败之后按文件头里的尺寸建好缓冲，解到哪一行算哪一行，
没解到的地方留纸白（与转灰对透明区的处理同一条：漫画页上没有内容的地方就是纸）。
`image` 只在 `DynamicImage::from_decoder` 里做这件装配，而那一个遇错就整张丢掉，
因此这里自己装一遍。PNG 要靠它、JPEG 多半不必，以及救不回来的那一侧长什么样，
见 measurements 的《截断页的解码容忍度》。

**「失败页」是三种页，不是两种。**票面第一条的字面（「解不出尺寸才算失败」）不够用：
尺寸解得出来而像素缓冲分配不下的页同样算失败，那正是票面第五条点名的「超大尺寸页」。
`CONTEXT.md` 的《失败》按三条判据写，代码与用例照它。

**超大尺寸页排在救回之前被拒。**`image` 自带 512 MiB 的分配上界，整解那一侧本来就会拒掉它；
救回这一侧要照**同一个数**再拒一次，否则会出现「整解嫌大拒了，救回却去分配 4 GiB」这种事。
常数因此显式写在 `decode` 里，两条路径共用。尺寸解得出来仍算失败，是刻意的：
分配不出缓冲的页救不回任何像素，「解得出尺寸」在它身上买不到任何东西。

**卷的去处到第一遍走完才定得下来。**输出容器原先在第一遍之前就建，现在挪到了第一遍之后——
写出全在第二遍，早建一步只会让隔离的卷在干净的去处留下一个空壳。同一个改动顺带让
「dry-run 不写输出」少绕一个 `Option<Sink>`。

**失败页在 `pages` 里占着自己那一格，不另立一个失败页数组。**几何门的 `Broken { page }` 与上包络的
`driver` 都是**指进 `pages` 的序号**；把失败页摘到另一个数组里，这两个序号就要跟着重新映射一次，
而那正是本仓库反复警告过的那类静默错位（见 `Branch::Gray` 的 `slot` 那条注）。
spec 形状里的「失败页集」因此是 `Report::failures()`——从同一处过滤出来，不是第二个出处。
**这是对 spec 那个「故在此固定」的形状的一处偏离**：它落成了方法而不是字段。
偏离的收益是上面那两个序号不必重映射，代价是读 spec 的人得多跳一步才找得到它。

**`PageReport` 拆成了两层。**`PageOutcome::{Processed, Failed}` 在外，`PageBranch::{Gray, Color}` 在内。
两层问的不是同一件事：外层问「这一页解出来了吗」，内层问「解出来之后它走了哪条路」。
合成一个枚举就得回答「失败页走的是哪条分支」，而那个问题没有答案——分支是解码之后才分的。
`scaling` 与 `color` 跟着沉进 `Processed`：失败页两样都没有，摆一个 `PageColor::Gray` 上去是编的
（11 号票立的那条规矩：报告不该有编出来的字段）。`size` 留在外层，因为它对失败页也是**真的**——
那就是占位页实际写出去的尺寸。

**卷内统一尺寸取众数，不取最大值也不取第一页。**取最大值会让一张跨页把整卷的占位页撑宽，
取第一页会被卷首的封面或彩页带偏。并列时留先出现的那个。一页好页都没有的卷退到面板分辨率——
卷内没有可参照的尺寸了，那就照这块面板的满幅出。

**占位页是纸白，不是别的什么。**它顶住页序与尺寸，但不冒充内容，也不该往页上添一笔本来没有的墨。
它认得出来的地方在别处，而且有三处：卷在隔离目录里、页里的记录写着 `tonefit:verdict = failed`、
报告里逐条列着原因。记录那一句照 `Record::color` 的样子钉死成英文——
tEXt 只装得下 Latin-1，而报告那一侧的原因里有成员名与中文。

**隔离的卷每一趟都重做，不被幂等跳过。**`can_skip` 只认干净的那个去处，而隔离的卷从来不写到那里，
于是自动落空——没有为此加一行代码。这是有意的：那不是一份做完了的输出，
而「`Report` 列出每一个失败页与原因」要求那份清单每一趟都重新给得出来，跳过就等于把它弄丢。
代价是有坏页的卷每趟都重做一遍，直到坏页被修好。

**源哈希那一遍也得放坏成员过去。**指纹排在第一遍之前，而它把每个成员的字节都读一遍——
拦在那里，一个坏成员照样毁掉整卷，正是本票要拆掉的那件事。`SourceHasher::unreadable` 因此
把读不出的成员记成一个固定记号（长度前缀写成 `u64::MAX`，真实字节串到不了那个长度）。
**不能干脆跳过它**：跳过的话，把一个坏成员从卷里删掉之后哈希纹丝不动，那一卷会被静默跳过，
而它明明少了一页。

**退出码三个数各说一件事：**做完了（0）、做完了但有卷带着坏页（2）、没做成（1，`run` 返回 `Err`）。
`exit_code` 出的是 `u8` 而不是 `ExitCode`，因为后者不可比较、这条规则也就测不了。

**透传文件读不出来仍然是卷级的失败。**它没有失败页那条出路：页可以留一张白页顶位，
而透传文件是逐字节照搬的，编一份空的 ComicInfo.xml 顶上去只会让阅读器读到假的书籍元信息。
第二遍里出的错同理不再降级成失败页——那些不是坏图，是磁盘、内存与输出容器出了事，
换一页重试也躲不过去。

**11 号票留的三个用例按它预告的换了触发方式。**`an_archive_that_fails_partway_leaves_no_half_written_output`
与 `a_run_that_fails_leaves_the_previous_output_archive_intact` 原先靠一张坏图在写到一半时失败，
坏图现在被隔离、不再中止整卷；两者改用**读不出字节的透传文件**——它排在页之后写，
页因此已经进了临时归档，那一刻失败才真的是「写到一半」。要钉住的性质没变：归档要么完整、要么不存在。
`a_member_whose_bytes_are_corrupt_is_named_in_the_error` 改名成
`a_pass_through_file_whose_bytes_are_corrupt_is_named_in_the_error`，页那一侧的同一条性质
搬去了 `isolation.rs`。

**11 号票提的 `VolumeReport` 拆分没有做。**它当时的预判是「12 号票要给卷加上『有失败页/隔离目录』
这第三种状态，一起拆最划算」。落下来看不是这样：隔离的卷是一个**处理过**的卷——
几何门、卷级判定、缓存用量、逐页结果一样不少，只是其中几页失败了。
它不是 `Processed` 之外的第三支，`isolated()` 只是从 `pages` 里过滤出来的一个问句。
「跳过 / 处理过」那条拆分的理由原样还在，但它与本票无关，也就没有理由挤进本票的 diff。

**占位页按 1bit 编，不跟卷级基准档走。**它不是一个判定——没进过候选集、没求过判据，
而卷级那一档说的是「这一卷的内容要几档灰」，这一页没有内容。位深是编码属性（`CONTEXT.md`），
整页只有一个取值时 1bit 恰好装得下；换个更宽的档也写不出别的字节，
编码器那一层照旧会挑最窄的（ADR 0004）。

**隔离这套机制自己造了一个坑，本票把它填上了一半。**卷的去处随「有没有失败页」在
`out/卷名` 与 `out/_isolated/卷名` 之间跳，而这一趟写不到的那一份不会被覆盖、也不会被删。
坏的那个方向是：上一趟被隔离、这一趟修好了——隔离目录里留着的是**一整卷白页**，
摆在文件管理器里与一本正经的书没有分别。

填的那一半是**说出来**：`VolumeReport::superseded` 指着另一处那一份，报告里单占一行。
没填的那一半是**不删它**——那是用户手上真实存在的一份输出，而 tonefit 在别处一律不做
破坏性动作。删不删由用户定，工具负责让他知道有这么一份。词表里叫「过期副本」。

**一处认下的代价，不在票面之内，记在这里：文件头完好、像素一行都救不回来的页会静默出成一张白页。**
它满足「尺寸解得出来」这条判据，因此不算失败页、也不隔离，报告里与一张好页毫无二致。
要把它标出来，得给报告加上「救回过」这第三种页状态——本票的六条里没有这一条，没有顺手加。
`decode::salvage` 知道每一次救回都伴着一个错误，只是不知道救回了多少，
真要做的话那是它该出的一个数。
