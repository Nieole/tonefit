# 06 — 位深决策：逐页判定与灰阶上界

**What to build:** 输出不再固定 8bit。面板灰阶数先把候选位深裁掉一轮，再由判据逐页选出最低可用档，PNG 以该位深写出。`Report` 给出每页的判定与理由。

裁剪顺序见 ADR 0003：面板灰阶数是位深的硬上界——先裁集合，再在集合内选。位深取值全集是 {1,2,4,8}，e-ink 面板上裁成 {1,2,4}。

编码时灰度与调色板两种颜色类型都试，取体积较小者（见 ADR 0004：输出以 PNG 为默认，AVIF 为显式可选）。

**Blocked by:** 04 — 判据与 `score` seam

**Status:** resolved

- [x] 候选位深在判据之前按面板灰阶数裁剪，e-ink profile 上 8bit 不参与选择
- [x] 逐页选出满足阈值的最低位深
- [x] PNG 支持 1/2/4/8 位的灰度与调色板两种颜色类型，按体积取小者
- [x] `--bit-depth` 可覆盖自动判定
- [x] 阈值当前是未标定的保守占位值，`Report` 与文档均显式标注这一点
- [x] `Report` 逐页给出判定位深与理由

## Comments

第一条 checkbox「候选位深在判据之前按面板灰阶数裁剪」已由 04 号票落地
（`BitDepth::candidates`，ADR 0003 要的顺序在那里成立）。本票从「在裁剪后的集合里选一档」开始。

选档落在 `src/decide.rs`：`decide(候选判据值, 阈值, 覆盖) -> Verdict`，纯函数，
`Verdict { 位深, 理由 }` 挂在 `PageReport.verdict` 上。理由三种——阈值内最低的一档、
无一档达标时取候选上界兜底、`--bit-depth` 覆盖。spec 固定的那四种理由是卷级的形状，
随 08、11 号票落地。

阈值是 profile 的字段（`Threshold`），不是面板的。占位值取 **8.5 = 4bit 量化步长的一半**：
4bit 是与 e-ink 灰阶数对齐的那一档，量化到它的格点逐像素误差不超过半个步长，低通、分块
与掩蔽加权都只会把这个数往下压——界放在这里意味着「不比 4bit 更差就算过关」，e-ink 的
候选上界因此恒过关，往下走必须由判据说了算。保守指的是这个偏向，数值本身**未经标定**，
`Threshold` 的 `Display` 把这句话写在数值旁边，报告头一行因此自带标注。

`--bit-depth` 覆盖的是自动判定，不是灰阶硬上界：e-ink profile 上 `--bit-depth 8` 当场被拒，
错误信息指向 `--gray-levels`（ADR 0003 给的就是这一条路）。

编码两路都编、取体积小者。真正买到东西的是位宽：色板只收页面用到的取值，一页只有两个
灰度取值时，判定 4bit 也能装进 1 位而像素一个不动。判定说的是**量化格点**，文件里那个
位深可能更低——ADR 0004 把调色板留在编码器接口以内，这就是它买的东西。

处理模式现在也求判据（此前只有 dry-run 求）：判据决定输出，两种模式因此给出同一个判定，
dry-run 预告的就是照做时写出的那一档。覆盖了判定也照求，`--dry-run --bit-depth 2` 才说得清
「你要的这一档判据是多少」。代价是每页多几次判据求值，缓存与两遍管线是 07 号票。

原先量重采样、解码、转灰的那几个用例改走 `run_volume_at_eight_bits`：输出钉在 8bit，
量化成了恒等。它们说的都不是量化，混进来就分不清一处差异出自哪一步。
