# 14 — `calibrate` 子命令

**What to build:** 生成一张灰阶阶梯标定图，按目标 profile 的面板分辨率排布，供在真实设备上显示并目视数出从哪一档开始出现肉眼可分的台阶。

这是唯一能自证面板灰阶上界的路径。本票只负责产出标定图，反推阈值是标定完成后的独立工作。

**Blocked by:** 02 — Profile 与面板表

**Status:** resolved

- [x] 生成的标定图尺寸匹配目标面板，可 1:1 显示
- [x] 图中并排给出各候选位深的阶梯，每档可分别辨认
- [x] 图内含判读说明，脱离文档也能用
- [x] 标定图本身不经过位深判定，以无损方式写出
- [x] 帮助文本说明目视数出的是感知可分辨级数，不等于面板物理灰阶数

## Comments

**阶梯排的是候选位深，不是位深全集。**`BitDepth::candidates(gray_levels)` 与判定用的是同一个函数
（ADR 0003：灰阶数是位深的硬上界），因此 e-ink 上是 {1,2,4} 三条，`--gray-levels 256` 上是四条。
图上出现的每一条都是这台设备**真会用到**的那一档——排上一条它永远不会选的，量出来的数也指导不了判定。

**每一档的灰取自编码器的格点，不是随手取的等距灰。**为此在 `quantize` 里补了 `grid_level`，
它是 `grid_index` 的逆，两侧对得上有用例钉着。阶梯要预告得了输出，格点就必须与编码器同源。

**图不经过位深判定，但仍走同一个 PNG 出口**（`encode::png` + `BitDepth::Eight`）。
「不经过判定」说的是判据、上包络、抖动一概不碰它，不是「另写一条编码路径」。
8 位是工作精度而不是判定结果，编码器在灰度与调色板之间取小者，两种编法写出的像素完全相同。
无损这一条的用例断言的是**解回来逐字节相同**，不是「颜色类型是灰度」——后者是编码器的自由。

**判读说明是印在图上的大写 ASCII，随程序带了一份 5×7 点阵字模。**中文字模按 16×16 算，
一句话就是几十个字形，手写不出也验不了；而说明必须在图内（票面第三条），不能指望目标设备上有字体。
字模表一行一个字形、`#` 是点亮的那一格，`#[rustfmt::skip]` 挡着——rustfmt 会把它拆成七行一个字形，
那样改一个字形得在脑子里重新拼一遍。这是本票唯一一处**没能照票面做到底**的地方：
「脱离文档也能用」在图上是英文成立的，中文那一份只在 `--help` 里。

**说明要点名数哪一条阶梯。**几条阶梯就有几个数，只说「在每条阶梯里数」，回填给
`--gray-levels` 的会是随便哪一个。改成「数最右那条」——阶梯按候选位深由小到大排开，
最细的恒在最右边，其余几条只作对照。只剩一条时（`--gray-levels 2`）那句对照的话不印。

**「档」留给位深与阈值档位，阶梯上的一格叫「级」。**`CONTEXT.md` 里「档」已经归了
「对齐的那一档」「基准档」，而阶梯上数的是灰度级，与「灰阶数」「级数」同一个词根。
票面写的是「每档可分别辨认」，那是词汇表定稿前的写法。

**级号只在放得下时印，放不下就整条都不印。**16 级的阶梯每级几十像素，号印得下；
`--gray-levels 256` 那条 8bit 阶梯每级四五像素，印不下——那时整条不印，
而不是隔几级印一个：半数带号半数不带，数起来比全不带还难。不印号的阶梯仍数得出来，
靠的是各级的灰本身两两不同（那条断言不认版式，逐列扫过去找接连走过全部格点的那一列）。

**版式里的 u32 减法没有一处兜底，靠的是「内置表撑得住」。**这不是推断出来的：
33 个型号 × 10 个灰阶数取值各画一张，330 张全画得出来。唯一加了 `saturating_sub` 的是
抬头居中那一处——`fitting_scale` 的下限是 1，栏窄到连 1 号字都放不下时它仍返回 1，
那一步宁可让抬头出栏，也不该变成一次恐慌。

**`clap` 那一层踩到一个坑：`subcommand_negates_reqs` 只放行解析，放行不了派生。**
它让 `tonefit calibrate …` 不必再交出 `--out`/`--profile`，但派生出的 `Cli` 结构里
`out: PathBuf` 是非 `Option`，`from_arg_matches` 造不出这个结构体，报的仍是
`MissingRequiredArgument`。把字段改成 `Option` 并显式写 `required = true`：
必填这道关留在 clap（错在哪、该怎么敲，它说得比手写的检查好），字段只负责容得下「没有」。
另有一条用例钉着「处理卷那一路的必填项一项都没松」——类型放松了，那道关不许跟着放松。

**`calibrate` 只收型号、灰阶数覆盖、去处三项。**处理卷要的那一整排参数它一个都不收：
标定图不读源、不落进输出根，缩放、位深、抖动、缓存、并发在它身上一件都不发生。
它也没有「有卷被隔离」那种结局——写成了是 0，写不成是 `Err`。
两路共用 `target_profile`，不然标定图量的是一块面板、判定用的是另一块。

`--gray-levels` 超出票面，是有意留的：ADR 0003 那条回路要重测（数出 12 → 回填 → 再画一张看
剩下哪几条阶梯），而 8bit 那条阶梯只有覆盖到 256 才露得出来。两处的 `--gray-levels`
帮助文本说的不是同一件事（处理卷那侧是「表里没收录的设备」，这侧是「上一趟数出来的级数」），
因此没有合并成一个 `#[command(flatten)]`——合并会逼它们共用一份说法。

**那句「不等于物理灰阶数」进了 `about` 的头一行。**`-h` 只印头一行，而它正是最容易被误读的一条：
不说出来，用户会拿数出的 12 去质疑「厂商标的明明是 16」，然后什么都不填。用例两份帮助各查一遍。
