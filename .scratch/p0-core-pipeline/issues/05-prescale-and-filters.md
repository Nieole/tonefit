# 05 — 预缩与滤波器选择

**What to build:** 总缩放比 ≥ 2 时先做整数倍 box 预缩再走残差段 Lanczos3；比值 < 2 时预缩退化为恒等，单次 Lanczos3。`--filter` 暴露全套常见滤波器，只作用于残差段。

依据见 ADR 0001：重采样滤波器的选择比位深更能决定输出体积。box/area 只是预缩那一级，不是主重采样器。

**Blocked by:** 02 — Profile 与面板表

**Status:** resolved

- [x] 总缩放比 ≥ 2 时触发整数倍 box 预缩，预缩后残差比 < 2
- [x] 比值 < 2 时不做预缩，直接单次重采样
- [x] `--filter` 只改残差段，不改预缩级
- [x] 二值网点夹具在高缩放比下经预缩后灰调级数受控（对照 measurements 的《滤波器与灰调级数》给出的机理）
- [x] `Report` 标明每页实际的总缩放比、是否触发预缩、残差比

## Comments

两级都落在 `src/resample.rs`。预缩倍数取总缩放比的整数部分：`比 ÷ ⌊比⌋` 恒落在 [1, 2)，
一步就把残差比压进不变量。整数倍除不尽时向上取整，末尾那个不满的块按实际像素数平均——
裁掉余数会动到几何，那是 09 号票的事。残差比因此按预缩后的实际像素高算，不是 `比 ÷ 倍数`。

预缩那一级是手写的块平均，没有交给 `fast_image_resize`：ADR 0001 要的是**等权完整窗口**平均，
而卷积实现在整数比除不尽时会给出加权的部分窗口，正好把这一级要买的性质弄丢。

`Filter` 与 `Profile` 一样在库里按名字解析（`Filter::resolve`），CLI 只递字符串：
`--filter` 的取值集合不进 clap 的类型，库这一侧对 CLI 无知。`box` 与 `area` 是同一个滤波器，
`bicubic` 是 Catmull-Rom。

`Scaling` 从 crate 根公开，`PageReport.scaling` 带着它。dry-run 与处理模式都给这三个量——
预缩这条路径在现有全部实测素材上从不触发（见 measurements 的《B 类素材普查》），
报告里这一行是它在真实片源上唯一的现场证据。

网点夹具按两条路径各有一个用例：比值 1.219 的那页断言解析出连续灰调，比值 2.000 的那页
断言级数落在 2²+1 以内。后者量的是预缩这一级本身——那一页的残差段恰好是恒等，
输出全部来自 box。比值非整数时残差段会把级数重新推上去，那是 ADR 0001 要的分工。

n²+1 这条机理只对**完整**窗口成立。边长除不尽时末行末列按自己的像素数平均，分母不是 n²，
会另添几个集外取值（`the_last_partial_block_averages_over_its_own_pixel_count` 钉住了这一点）。
让窗口全都完整就得裁掉余数，那是动几何，不在本票。
