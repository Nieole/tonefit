# 04 — 判据与 `score` seam

**What to build:** 把判据实现出来并暴露为纯函数 `score(参照, 候选) -> Score`，供数值与性质测试直接调用。`--dry-run` 的报告里出现每页的判据值，但此时还不据此改变输出。

判据形态见 ADR 0002：判据建立在低通后的局部均值上——低通核由面板 PPI 推出，分块取上分位而非均值，带对比度掩蔽加权。参照是缩放到目标尺寸后、未经目标位深量化的图，工作精度 8 位灰度。

**Blocked by:** 02 — Profile 与面板表

**Status:** resolved

- [x] `score` 是公开纯函数，不依赖文件系统与全局状态
- [x] 低通核尺寸由面板 PPI 推出，不是硬编码常数
- [x] 分块聚合取上分位，一页里大面积留白不会稀释局部劣化
- [x] 对比度掩蔽加权：平坦低对比区收紧、高频纹理区放宽
- [x] 性质测试：渐变夹具上，抖动候选的判据优于不抖动候选（逐像素度量给出相反排序，见 measurements 的《抖动》）
- [x] 性质测试：位深越高判据误差不增
- [x] `--dry-run` 报告逐页给出判据值，且不写任何文件

## Comments

判据落在 `src/metric.rs`，`score(&Reference, &GrayImage) -> Score` 从 crate 根公开；
候选的像素形态由 `quantize` 给出（不抖动那一种，抖动是 09 号票）。

按面板灰阶数裁剪候选位深（`BitDepth::candidates`）一并落在这张票里：ADR 0003 要求裁剪
发生在**判据求值之前**，而本票正是引入判据求值的那一张，不裁就会在 e-ink profile 上
对 8bit 求值并把 `8bit 0.000` 打进 dry-run 报告。06 号票的同名 checkbox 由此已经满足，
那边只剩「选出最低可用档」与按位深写 PNG。

掩蔽加权的地板与拐点、以及低通核的视角常数都是未标定的占位值，代码里各自标注了。
