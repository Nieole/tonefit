# 10 — 彩页识别与彩色分支

**What to build:** 彩页在第一遍就被识别出来并按 profile 分流。彩色 profile 下彩页只做缩放、第一遍即写出、不进灰度缓存；黑白 profile 下彩页先转灰，再作为普通灰度页参与判定——转灰后它多半仍落在离群侧。

**Blocked by:** 08 — 卷级上包络与迟滞

**Status:** resolved

- [x] 彩页识别发生在第一遍，早于上包络聚合
- [x] 彩色 profile 下彩页不进灰度缓存；「第一遍即写出」按 ADR 0010 决定第 5 条修订为
      「第一遍完成缩放与编码，写出与灰度页同一遍按阅读顺序落位」——理由见下
- [x] 黑白 profile 下彩页转灰后走灰度路径
- [x] 彩页不污染灰度页的卷级上包络
- [x] 彩页夹具与灰度夹具混排时，两条路径各自产出正确
- [x] `Report` 区分彩页与灰度页

## Comments

**本票开工前请示过一次，结论是越过 spec 的 Out of Scope。**六条勾选项里有两条
（「彩色 profile 下彩页第一遍即写出」「彩页不污染灰度页的卷级上包络」）需要存在一个彩色 profile，
而 P0 里没有：面板的主键是三项，没有地方放彩色；`profile.rs` 的表注写着「P0 不在范围内」；
spec 的 Out of Scope 写着「Kaleido 彩色面板的专属分支」。项目所有者当场选了「把彩色分支做实」。
决定与代价记在 **ADR 0010：彩页按 profile 分流，彩色是面板的第四项**，spec 的 Out of Scope
随之收窄到 Kaleido **真正专属**的那些（彩色分辨率折半、CFA 感知的锐化、色域映射、彩色判据与彩色位深）——
那几件一件都没做。

**彩色进面板主键，不折进灰阶数。**同分辨率同 PPI 的 Kaleido 与纯黑白 e-ink 是两块面板：
同一卷在它们上面输出不同。内置表加了六个 Kaleido 型号（Kobo Clara/Libra Colour、
BOOX Go Color 7 / Note Air3 C / Tab Ultra C、Kindle Colorsoft），分辨率与 PPI 填**黑白那一层**的规格，
灰阶数仍是 16。折进灰阶数是最像捷径的那条歧路，ADR 0010 的《不要做的「简化」》说的就是它：
折过去之后灰度页会在彩色面板上被裁出 8bit 候选，而那一档在黑白层上根本显示不出来。

**识别不看颜色类型，看像素。**「97% 近灰度」的 B 类素材整批是 RGB 编码的有损 AVIF
（《B 类素材普查》）：照颜色类型判，那 97% 会整批被判成彩页。判据两维——单像素**色度幅度**
（sRGB 三分量极差）过一道地板，过地板的像素占到一个**比例**——两个数都是未标定占位值。
《B 类素材普查》的「97% 近灰度，3% 彩色」是**分布**不是判据形态，那一节没给出它是怎么数出来的，
这两个数因此不能说成是从它标定来的，记进了 `CONTEXT.md` 的《尚未确立》。
透明区的颜色不算数：全透明的红合到纸白上是消色的，转灰那一侧本来就这么做，
识别这一侧给出同一个答案（`色度 × alpha`，是近似，方向对了就够）。

**识别对每一页都做，与 profile 无关；分流才看 profile。**`PageReport` 因此有两个字段而不是一个：
`color` 是**页的事实**，`branch` 是**它走了哪条路**。黑白 profile 下 `color == Color` 而
`branch == Gray`，报告里渲染成「彩页转灰 · 判定 …」——不区分这两件事，
「这台设备为什么没留住颜色」就答不出来（spec 的 story 15、16）。
`branch` 是枚举而不是几个可空字段：彩色分支上没有判据曲线也没有判定，说「判定为空」会读成「判定丢了」。

**彩页不参与几何门，这是本票新加的一条决定（ADR 0010 决定第 4 条）。**门撑的是抖动与面板灰阶
那道硬上界（ADR 0007、ADR 0003），两者只作用在灰度路径上；彩页既不量化也不抖动，
它的几何事实对那两件事没有说话的资格。让一张源比目标小的彩页关掉整卷的抖动，
就是让一条不受影响的路径去削掉另一条路径的收益。门因此是**分支的函数**，不是页的常量：
同一张彩页在黑白 profile 下转灰走灰度路径，它的几何这时就说了算。
用例 `a_color_page_smaller_than_the_panel_does_not_close_the_geometry_gate` 把两边并排钉住。

**写出的时刻改了，ADR 0005 决定第 4 条的「第一遍即写出」由 ADR 0010 决定第 5 条修订。**
那一句要保的是彩页**离开灰度管线的时刻**——不进缓存、不求判据、不进上包络，三条原样成立，
第一遍完成解码、识别、缩放与编码。写出的时刻另有一条约束压着它：归档卷的成员按**写入顺序**排，
而页名的字典序与阅读顺序本来就对不上（`1` `2` `10`，`tests/container.rs` 早有一条用例钉着）。
彩页在第一遍就写进归档，混排卷的成员顺序会变成「先全部彩页、再全部灰度页」，
按归档顺序翻页的阅读器于是跳着读。归档成员顺序是产品的**正确性**，等在内存里的那些字节是**效率**，
正确性优先。代价认下并写进 ADR：编好的 PNG 字节要等到写出那一遍，且不受 `--cache-budget` 约束。
按容器分情形——`Sink::Directory` 没有顺序约束，目录卷本可第一遍就落盘——能把目录那一侧的内存拿回来，
但那会让峰值内存随容器形态而变，而报告里没有一个字解释得了这个差别；
ADR 0010 的《备选方案》记着它与不选的理由。真要拿回这块内存，该做的是让缓存收字节块。

**驱动页那个序号要换算。**上包络在**灰度页**的序列上取分位，`Envelope::driver` 却指进
`VolumeReport::pages`。卷内混着彩页时两者不重合，漏掉这一步，报告会指着另一页说「就是它定的档」——
甚至指到一张彩页上。`color_pages_stay_out_of_the_envelope_of_the_gray_pages` 钉的正是它：
同一批灰度页混进彩页前后，基准档、逐页判定、驱动页所指的那一张全都不变，
而驱动页的**序号**必须变（用例里有一条 `assert_ne!` 保证夹具真把序号推开了，否则它什么都没钉住）。
去掉换算跑一遍，这条用例给出 `left: 18, right: 14`。

**缓存序号从此不由页序推出来。**07 号票在 `ScoredPage` 上留的那条注说的就是这一天：
彩页不进灰度缓存，页序与缓存序就此分家，重新数出来的序号会静默地把另一页的像素写到这一页的位置上。
序号现在跟着 `Branch::Gray` 走。

**彩色分支只做缩放。**缩放**分平面**跑，逐通道各走一遍灰度那条路径：预缩是等权块平均、
残差段是卷积重采样，两级都逐通道独立，分平面与交织逐字节相同。这不是近似，
是把灰度那条路径原样用过来——彩色分支不必另写一份缩放，两条路径也不会各自漂移。
编码取真彩色与调色板中体积较小者，与灰度那一侧同一条规则（ADR 0004：调色板在编码器接口以内）；
颜色超过 256 种时调色板那一路直接给 `None`，数到第 257 种就停。
色板排序在彩色这一侧买不到「索引单调、行滤波器差分小」——三个分量上没有共同的序——
排序只为**定死次序**，同一页跑两遍要编出同一个文件（11 号票的幂等靠这一条）。

**dry-run 下彩色分支连编码都省。**灰度路径在 dry-run 里照求判据，因为那是要预告的东西；
彩色分支没有判据可预告，编出来的字节也没人要。要预告的只有几何，那照旧算。

**留下的洞，三个：**彩色分支的内存不受 `--cache-budget` 约束（要纳入得让缓存收字节块而不只是收参照，
是另一次改动）；Kaleido 的彩色分辨率折半等数值一律未测；彩页识别的两个数未标定。
三条都在 ADR 0010 的《后果》与 `CONTEXT.md` 的《尚未确立》里。
