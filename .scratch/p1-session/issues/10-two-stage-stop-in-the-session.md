# 10 — 会话：两级停按键与跑起来时的只读

**What to build:** 跑起来之后按一次停是**收尾**（当前卷跑完才停），
再按一次是**中止**（立刻停，当前卷那格 `partial` 丢掉）。停下来之后会话不退出，
回到可以改配置的状态。

同时：一趟跑起来之后**设备层与口味层只读**。卷与卷之间换参数，
报告顶上那行 `profile` 就开始撒谎。

**Blocked by:** 04 — 中止；09 — 会话主区。

**Status:** resolved

- [x] 按一次停 = 收尾：当前卷跑完才停，屏上说清它在等什么
- [x] 再按一次 = 中止：立刻停，当前卷在最终位置上没有留下任何痕迹
- [x] 停下来之后会话不退出，回到可改配置的状态
- [x] 跑起来之后设备层与口味层只读，范围层同样锁住
- [x] 只读状态在屏上看得出来，不是按了没反应
- [x] 收尾与中止之后的退出码与命令行那一路一致

## 落地记录

两级停的**语义**在 ADR 0013 上早就定死了，库那一侧（`02`／`04`）也早就做完了：
`Instruction` 只升不降，检查点在卷边界与页边界各一个。本票做的只有一件事——
**把它接到键上**，并把「跑起来之后只读」这件事从「按了没反应」改成「屏上看得出来」。

### 一个键，按两次

`s`。按一次收尾，再按一次中止，第三次起没有意义。

**不是两个键**，理由在 ADR 0013 与 `CONTEXT.md` 的《进度》里都写着：中止是
「**再按一次**」，而再按一次退不回上一级。分成 `S`／`A` 两个键的话，「按了中止之后
再按收尾仍然是中止」就得靠某处代码守着；同一个键按两次，那条性质是键盘的形状本身——
**升到中止之后 `s` 派的是 `Action::Ignored`**，回收尾的那个键根本不存在。

```
Mode::Running(Continue) --s--> Running(Finish) --s--> Running(Abort) --s--> （没有意义）
```

闩落在两处，各有一份、各有寿命：

| 谁 | 记的是 | 在哪 | 寿命 |
|---|---|---|---|
| `Session::stopping()` | **用户按到了哪一级**——屏上那两行照它写 | `Mode::Running(Instruction)` | 一趟一份（`run_started` 归零） |
| `run::Latch` | 观察者下一条事件**回哪个字** | `Running::latch`，`AtomicU8` | 一趟一份（`start` 换一个新的） |

出处只有状态机那一份：`session::press` 让状态机升完一级，再把升到的那一级
交给 `Running::stop` 送到计算线程上——**状态机不碰线程，起线程那一层不认键**。
两份都是一趟一份，理由与库把它自己那个闩放在 `run` 的栈上是同一条：
上一趟按下的停不该漏到下一趟去（`a_second_run_does_not_inherit_the_stop_pressed_in_the_first`）。

`Latch` 用 `fetch_max`，与库内那个闩同一条性质；那一份是 `pub(crate)` 的，
二进制 crate 够不着，因此这里有第二份编码（停车场 Q70）。

### 按下去之后屏上说什么

屏底两行，**一行说键、一行说它在等什么**：

| 按到 | 第一行（按得动的键） | 第二行（在等什么） |
|---|---|---|
| 没按过 | `跑着…… · s 停（按一次收尾，再按一次中止）· Ctrl-C 退出会话（当前卷中止，盘上不留半卷）` | （空） |
| 收尾 | `收尾中…… · 再按一次 s 中止 · Ctrl-C 退出会话` | `收尾：等当前卷跑完就停，剩下的卷一个都不开工；盘上只留完整的卷，下一趟幂等接着走` |
| 中止 | `中止中…… · Ctrl-C 退出会话` | `中止：当前卷停在这一页上，它那格 partial 丢掉——那一卷等于没做，最终位置上一个字节都没动过` |

第二行非有不可：按下收尾之后进度条照旧往前走，几千页的卷还要跑几分钟——
不说清「在等当前卷跑完」，看上去就是那一下没按上。
中止那一行说的是**盘上会剩下什么**，那是这一级唯一会让人犹豫的事。

到了中止就不再提 `s`：闩到了顶，**屏上不摆按不动的键**——那正是「按了没反应」的来源。

收场之后那一句照旧走 `render::outcome`（「按停（收尾）：当前卷跑完就停了……」），
与命令行那一路同一个出处；本票没有另编一句收场的说法。

### 跑起来之后只读，而且看得出来

拦住按键的仍旧是 `running_action`——它一个改动键都不派，连光标都不动。
本票加的是**说出来**那一半：

- 左栏抬头从「配置」改成「**配置 · 跑着，三层都只读**」；
- 光标那一行**不再反白**（反白说的是「就在这一行上动手」，而这时按不动），各行压暗；
- 屏底不提任何一个改一行的键。

**范围层也在里面**，而这是本票拿的主意（停车场 Q69）：spec 的《会话：布局与交互》
只写了前两层，本票的验收把范围层一并算进来。两层错的方式不同——设备层与口味层错在
**撒谎**（报告顶上那行 `profile` 跟着不作数），范围层错在**没用**（`Request` 在起线程
那一刻就是一份快照，改了也不影响正跑的那一趟）。`CONTEXT.md` 的《会话》照这个改了口。
`Mode` 因此**没有拆成两维**：拆的唯一用处是让范围层在跑着时还能打字，而那件事本身不该做。

### 退出码

**两级都不改退出码**，因此都与命令行那一路一致：`0` / `2` / `3` 走 `crate::exit_code`
（有卷被隔离取 `2`、有卷没做成取 `3`），`1` 仍旧只留给**拒绝执行**。

理由是 ADR 0013 的定位：按停是**用户自己的决定，不是失败**。`crate::exit_code` 的文档
本来就写着「按停停下来的那一趟不在这里露面」，而「这一趟被按停过」落在**收场**上
（`Report::outcome`），不落在退出码上。两级之间也没有分别可言——收尾与中止的差别是
**当前卷算不算做完**，而那件事已经反映在报告里了（中止掉的那一卷不进报告），
再给它们两个不同的数就是把同一件事说两遍，且脚本会当成两种失败。

`a_run_that_was_stopped_exits_with_the_code_its_report_earns` 把这一条钉死：
两级各跑一遍「干净」与「有卷被隔离」，四次都断言 `live.exit_code() == crate::exit_code(&report)`
——不是「恒为零」，是**与命令行那一路同一段代码算出来的那个数**。

### 停下来之后会话不退出

原样走 `09` 铺好的那条路：那条线程回来了 → `reap()` → `Session::run_finished()` →
回到 `Mode::Browsing`，配置又改得动，闩跟着那一趟一起走掉。按停那一下自己
**不改会话开不开着**（`press(Key::Char('s')) == Exit::Stay`）。

### `q` 与 `Esc` 跑着时仍然按不动

这是本票拿的第二个主意（停车场 Q63 点名要它定）。退出会话要连着把当前卷丢掉——
那是中止那一级的事，而中止现在有专门的键，按两次 `s` 就到。让最容易手滑的两个键
一下子挂上最重的后果，换来的只是省一步。`Ctrl-C` 照旧在**每一个**状态下都是退出
（`08` 立下的性质），它走的仍是中止那一级，只是不经过键盘：`Running::leave` 直接把闩
推到中止再 `join`——这一路因此与 `s s` 合流成同一个闩，不再是一个单独的 `leaving` 布尔。

### 决策点上的收尾要让路

**这是本票最容易踩反的一处**，`src/progress.rs` 逐字预告过它，而第一版实现照样踩了
（`/code-review` 的 Spec 轴逮住的）：会话的观察者原先对**每一条**事件都回闩记着的那一级，
其中包括续做的决策点——而库那一侧只有那一条事件的答复**当场作数**。
于是第一遍里按一次 `s`，库读到 `Finish` 就跳过第二遍，当前卷等于走了一次试算：
报告照出、盘上一个字节都没写。而收尾说好的是「当前卷跑完才停」。

规矩因此单摆一处（`run::answer`）：

| 事件 | 闩记着 | 回什么 | 为什么 |
|---|---|---|---|
| 决策点 | 收尾 | **继续** | 决策点问的是「这一卷的第二遍还做不做」，不是「这一趟还走不走」 |
| 决策点 | 中止 | 中止 | 那一级要的就是当前卷等于没做，与页边界上一个待遇 |
| 其余 | 任何 | 原样 | 那几处的答复只进闩，停在哪一道边界上是管线的事 |

**让掉的那一下不会丢**：答复照样进库那一侧的闩，而那是个 `fetch_max`——
记一个更弱的字不作数，闩仍是收尾，当前卷跑完之后卷边界那个检查点照样停。

**这里不等人**：单卷试算完了停下来问用户归 `14`，本票只管那一下按停不要把当前卷吃掉。

### 库那一侧一行没动

`src/lib.rs`、`src/progress.rs`、`src/render.rs`、`src/main.rs` 一个字节都没改。
两级停停出来的现场对不对是那一侧的事，`tests/events.rs` 的两个检查点那一批
（`finishing_up_after_the_second_volume_leaves_two_whole_volumes`、
`aborting_at_a_page_boundary_throws_the_partial_container_away`、
`the_two_checkpoints_stop_at_two_different_boundaries`）早就钉着，
而它们不开线程也不掐表。**命令行那一路因此行为一字未变，黄金快照未变、未重录。**

第二遍之前那个决策点也一个字没动：它回的仍是**当场那个字**、不是闩
（`06` 落地时定的那一条）。会话这一侧照着让路，见上一节。

### review 之后改的

`/code-review` 两轴各出了几条，收了这些：

- **决策点上的收尾把当前卷吃掉了**（Spec 轴，阻断性）。观察者原先对每一条事件都回闩，
  而决策点的答复当场作数。让路那条规矩单摆成 `run::answer`，两条用例钉住——
  一条钉那张表，一条走真观察者跑完一整趟（见上一节）。
- **键→线程那一段没有断言**（Spec 轴）。补
  `session::pressing_stop_reaches_the_run_that_is_going`：`press` 收的是
  `&mut Session` 与 `&mut Running`，一个终端都不碰，接头处因此测得动。
- **按停那条端到端用例是在跟线程抢**（Spec 轴，与 spec 的「取消的用例不需要开线程，
  也不需要掐表」相左）。换掉了：套一层替身在「一卷开工」那条事件上按下去，
  `tonefit::run` 同步跑完，时机由用例定死。
- **屏底那两行是两个函数、对同一个取值各 `match` 一次**（Standards 轴，Repeated Switches）
  → 收成一张表 `running_lines`。顺带把 `09` 那句「Ctrl-C 退出会话：当前卷中止，
  盘上不留半卷」补回了没按过时那一行——本票原先把它漏掉了。
- **范围层那段理由抄了四遍**（Standards 轴，《文档写作》第 4 条：单一出处）。
  留在 `CONTEXT.md` 的《会话》一处，`Mode::Running`、`READ_ONLY_TITLE`、`config` 改成引它。
- **`Latch` 的文档说库那份「同名」**（Standards 轴，Mysterious Name），而 `Standing`
  与 `Latch` 并不同名——改口说「同性质」，并点明「闩」这个说法出自
  `CONTEXT.md` 的《进度》（「按停是个闩」），不是本票新造的词。

一条没收，理由在下面 Q70：`Latch` 与库内 `Standing` 那三行编码逐字相同。
合成一份要把「一个原子的 `Instruction`」导出成公共 API，那是 API 面上的决定。

### 没做的

- **`11`（逐页展开与左栏收起）、`12`（预设存取）、`13`（标定图）、`14`（单卷续做接上决策点）**

## 停车场结转

### Q63 — 退出会话时那条还在写盘的线程要有人收，而按停那两个键还没有

- **From:** 票 `p1-session/09`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/session/run.rs` 的 `Running::leave` 与 `Watch::observe`；
  `src/session/state.rs` 的 `running_action`
- **Why it did not block:** `09` 把 `run` 放到另一条线程上（不然「跑起来时主区实时更新」
  只剩一句话）。那条线程正往盘上写字节，而 `Ctrl-C` 在**每一个**状态下都是退出
  （`08` 立下的性质）——`main` 一返回它就被连根拔掉，盘上留下一格写了一半的 `partial`。
  收尾与中止那两个**键**归本票，`09` 一个都不占，于是只剩两条路：退出时干等那一趟跑完
  （几十分钟），或者让观察者回一次 `Instruction::Abort`。
- **What this ticket actually did:** `09` 走了中止那一级但没有加键（一个 `leaving` 布尔）。
  **本票把那个布尔换成了闩**（`run::Latch`，`AtomicU8` + `fetch_max`）：`s` 那个键与
  「退出会话」推的是同一格，`Running::leave` 只是直接推到中止。两条路因此合流，
  「按过 `s` 之后再退出仍是中止」不必另有一条规矩。
- **Whose call:** `10`（两级停）
- **处置：** 由本票了结。**退出会话仍走中止那一级**，理由与 `09` 当初的一样：收尾要等
  当前卷跑完，那可能是几十分钟，而用户按的是「退出」。
  **`q` 与 `Esc` 跑着时仍然按不动**：退出会话要连着把当前卷丢掉，那是中止那一级的事，
  而中止现在有专门的键（按两次 `s`）；让最容易手滑的两个键一下子挂上最重的后果，
  换来的只是省一步。`Ctrl-C` 照旧在每一个状态下都是退出。
  用例 `leaving_the_session_aborts_whatever_is_running` 与 `the_latch_only_ever_goes_up`
  分别钉住「退出走哪一级」与「闩只升不降」。

### Q69 — 跑起来之后连范围层一起冻住了，spec 只要求前两层只读

- **From:** 票 `p1-session/09`
- **Kind:** 路过发现
- **Where:** `src/session/state.rs` 的 `running_action` 与 `Mode`
- **Why it did not block:** spec 的《会话：布局与交互》写的是「跑起来之后**设备层与口味层**
  只读：卷与卷之间换参数，报告顶上那行 `profile` 就开始撒谎」——范围层它没说。
  照字面放开范围层，用户就能在这一趟跑着的时候把下一趟的卷先打进去，而**改了也不影响
  正跑的那一趟**（`Request` 在起线程那一刻就是一份快照）。
  拦住它的不是道理，是形状：会话此刻在做什么由**一个** `Mode` 说，
  而「正跑着」与「正打字改一行」要同时成立的话，那个枚举得拆成两维。
- **What this ticket actually did:** `09` 一起冻住，并且只冻、不假装。
- **Whose call:** `10`（两级停）
- **处置：** 由本票了结。**范围层继续冻着，`Mode` 不拆两维。** 本票的验收原话就是
  「跑起来之后设备层与口味层只读，范围层同样锁住」——票面自己把这一条判了。
  拆成两维的唯一用处是让范围层在跑着时还能打字，而那件事本身不该做：改了看着像生效、
  其实没有，比按不动更坏。`CONTEXT.md` 的《会话》跟着改口成「三层都只读」，
  并把两层各自错在哪儿分开写（撒谎 / 没用）——那不是改写词条的含义，
  是把票面判下来的那一条落到出处上。
  屏上的交代由本票补齐（抬头说「只读」、光标不反白），
  用例 `a_run_in_progress_says_on_screen_that_the_three_layers_are_read_only` 钉住。
