# 02 — 事件流：观察者收事件、回指令，卷级事件带报告

**What to build:** 库向外报的从三个方法变成一条**事件流**：非穷尽枚举加单个回调，
而回调**回一个指令**（继续 / 收尾 / 中止）。

一卷跑完的那条事件**带着那一卷的报告**，调用方因此边跑边把整份报告攒出来——
命令行攒完在最后一次性渲染，会话攒到哪儿画到哪儿，两者拿的是同一份数据，不是两套。

**收尾**在卷边界生效：答收尾，当前卷跑完就停，盘上只有完整的卷，下一趟幂等接着走。

依据：ADR 0011（进度是事件流，开工前先预扫）。

**Blocked by:** 01 — 报告渲染搬出 CLI 主文件。

**Status:** resolved

- [x] 记录型观察者把事件收下来，攒出的报告与主入口的返回值等价
- [x] 事件说得出这几件事：这一趟开始了（带卷数）、一卷开始了（带步数）、走完一步、
      在走哪一遍、一页失败了（带原因）、一卷跑完了（带那一卷的报告）、这一趟完了
- [x] 枚举非穷尽：以后加变体不破坏任何实现方
- [x] 观察者在第 2 卷之后答收尾 → 只有 2 卷的输出，报告只有 2 卷，退出码 0
- [x] 命令行的进度条改接事件流，画出来的东西与之前一致
- [x] 没有观察者时一步都不报（现有性质不变）
- [x] 观察者可能很久不返回——实现里不得在持锁处调它

## 落地记录

`Progress` 从三个方法收成**一个**：`fn observe(&self, event: Event<'_>) -> Instruction`。
三个实现方（CLI 的进度条、`tests/` 里的记账本、`src/lib.rs` 第二遍那条用例）各改一处，此后
多报一件事只加一个变体。

### 事件：七条，非穷尽两层

| 变体 | 带什么 | 谁在等它 |
|---|---|---|
| `RunStarted` | `volumes: usize` | `03` 往这里加全局总步数 |
| `VolumeStarted` | `volume: &Path`、`steps: u64`（上界） | 当前卷条 |
| `PassStarted` | `pass: Pass`（`Fingerprint`/`First`/`Second`） | 「在走哪一遍」；`Second` 那一条就是 `06` 的决策点 |
| `Stepped` | — | 进度条；从计算线程上报出来，页序不作数 |
| `PageFailed` | `page: &Path`、`reason: &str` | `09` 的主区，不等整卷跑完 |
| `VolumeFinished` | `report: &VolumeReport` | 边跑边攒的那份报告 |
| `RunFinished` | — | 收场 |

**非穷尽做了两层**：枚举自己，加**每一个**变体自己——不带字段的 `Stepped` 与 `RunFinished`
也写成 `Stepped {}` / `RunFinished {}` 并标上。第二层是照后面的票画的：`03` 要往 `RunStarted`
里塞全局总步数，`RunFinished` 迟早要说得出这一趟是怎么收的场（停车场 Q39），
而**往已有变体里加一个字段**在只标了第一层时照样是破坏性改动。
库外的 `match` 因此一律带 `..` 与 `_`，`src/main.rs` 与三个测试 crate 现在都是这个样子。

事件带的是**借用**。要留下来的观察者自己克隆（`tests/events.rs` 的 `Recorder` 就克隆
`VolumeReport`），只画一条横条的那个不必为一份转手就扔的报告付克隆的价。

### 指令：三个字，是个闩

`Instruction::{Continue, Finish, Abort}`，序即力度。库记的是**至今为止收到过的最强的那一个**
（`progress::Standing`，`AtomicU8` + `fetch_max`），因此按停只升不降——
手指离开键盘之后下一条事件答「继续」，抹不掉已经按下的那一下。

**收尾在卷边界生效**：`run` 的循环每卷开工前问一次闩，不是继续就 `break`。
盘上因此只有完整的卷；验收那条用例跑三卷、第 2 卷之后答收尾，得到两卷输出、两卷报告、
`any_isolated()` 为假（命令行退出码 0 就是这两条拼出来的），再跑一趟三卷 `[跳过, 跳过, 做]`。

### 为什么这个形状容得下 `03`/`04`/`06`/`09`

- **`03`（预扫）**：全局总步数是 `RunStarted` 上多一个字段，而那条变体已经非穷尽。
  它排在开工前那几道检查**之后**——「一条点不开的路径整趟被拒，且发生在任何卷级事件之前」
  因此天然成立。
- **`04`（中止）**：`Abort` 这个字已经认下、闩已经在原子量里，缺的只是**页边界**那个检查点
  与丢弃 `partial`。眼下它在卷边界上与收尾同样停（`aborting_stops_at_least_as_early_as_finishing_up`
  钉着），`04` 要加的是「更早停」，不是「让它开始起作用」。
- **`06`（续做）**：决策点就是 `PassStarted { pass: Pass::Second }` 报出去的那一刻——
  代码里它排在 `summarize_volume` 之后、`timed(second_pass)` 之前，逐字对上 ADR 0012 决定第 2 条
  的「汇总之后、第二遍之前」。`06` 落地的是「答收尾就停在这儿」，事件本身不必改形状。
- **`09`（会话主区）**：`VolumeFinished` 带整份 `VolumeReport`，接的正是 `01` 切出来的
  `render::volume` 与 `render::pages`。攒出来的那份与 `run` 的返回值**逐字相同**——
  `what_the_observer_collects_is_the_report_the_entry_point_returns` 比的是整份 `Debug`，
  不是几个挑出来的字段：漏一项就等于给那一项开了漂移的口子。

### 命令行：一个字节都没变

**它仍然渲染 `run` 的返回值，没有改成从事件流攒。** 票面那句「命令行攒完在最后一次性渲染」
今天还攒不出来：抬头那几项（profile、适配方式、裁边、拆分、整趟耗时）挂在 `Report` 上，
事件流只带 `VolumeReport`——从流里拼不出一份完整的 `Report`。而两者装的是同一份数据，
`what_the_observer_collects_is_the_report_the_entry_point_returns` 逐字比过；改成从流里攒
是纯粹的搅动，还撞上「命令行一字不变」那条硬约束。`09` 真要边跑边画时按 `01` 号票记的办法
自己拼一份攒到一半的 `Report`（它手上有 `Request`，那几项都知道）。

`Bar` 改吃事件，只认三条（开卷起一条、走一步进一格、跑完抹掉），恒回 `Continue`。
黄金回归全绿且未重录。唯一的时序差别：抹掉进度条从「第二遍收尾之后」挪到「卷报告拼好之后」——
中间隔着一次 `zip`，屏上看不出来。命令行还没有按停的键，见停车场 Q38。

### 观察者可能很久不返回

五处报到全在锁外。最容易踩的那一处改写成明式：卷报告原先在结构体字面量里
`cache: lock(&cache).usage()`，那个 guard 要活到整条 `let` 语句结束，而下一句就要把报告交给
观察者——改成先 `let cache = lock(&cache).usage();`。闩本身用原子量而不是锁，报到这条路上
一把锁都不抢。这条性质没有真闸门（停车场 Q40），用例那侧留了条下限：
每条事件睡 1 毫秒，整趟照样跑得完。

### review 之后改的

Standards 那一侧：单元用例的断言由「挑几个字 `contains`」换成六条事件**整份比对**
（`Debug` 串），并补齐中文断言消息；`Events::pass` 改名 `pass_started` 与事件名对齐；
新开 `OutputPage::failure()`，`failed()` 改问它——「失败了吗」与「为什么失败」只留一个出处。

Spec 那一侧：`Events::report` 的文档原先说检查点「在 `run` 与 `process_volume` 里各自明写」，
而 `process_volume` 里一个都没有——改成明说眼下只有卷边界那一个，另两个属 `04` 与 `06`；
两个单元变体补上非穷尽（见上）；`CONTEXT.md` 那句「指令只升不降」补上它的出处
（ADR 0013 决定第 2 条的「**再按一次**」——再按一次退不回上一级，闩不是新决定）。
另外两件记进了停车场：观察者花掉的时间算在 `VolumeTiming` 里（Q41，`06` 的地界），
以及报到时手里虽没有锁、却攥着 rayon 工作线程与读取层那张在途字节额度（并进 Q40）。
