# 13 — 会话：设备层里一键写出标定图

**What to build:** 光标停在设备层时按一个键，按当前 profile 写出**标定图**。

设备层里最重要的那个数——感知可分辨级数——的获得方式是出一张图、拷进真机、
目视数出来再填回去。这条路现在完全在会话之外：用户得退出会话、敲另一条命令、
找到文件、拷设备、回来再填。

标定仍是**量具**：不读源、不走管线、不判定、无损写出。会话只是调用库里那个写出接口。

**Blocked by:** 08 — 会话骨架；`p0-hardening/12 — 标定图的落盘移进库`；`calibration-chart/01 — 标定图一并回答像素完整性`。

要的是移进库之后的那个写入口，**加上** C01 改过的图内容——否则一键写出来的还是只答一半的旧图。
**外部依赖：** `p0-hardening` 的 12 号票（标定图的落盘移进库）。
在那张票落地之前，界面层是唯一自己碰文件系统产出产物的地方，本票没有可调的库接口。

**Status:** resolved

- [x] 光标停在设备层时按一个键，按当前 profile 写出标定图
- [x] 会话调库里那个写出接口，界面层不自己建目录、不自己写文件
- [x] 屏上说清此刻要做对的那一件事：拷进设备、以**原尺寸**打开（关掉缩放，也关掉适配屏幕）
- [x] 怎么数**不在屏上重抄一遍**——图内已印，`calibrate --help` 里也写着
- [x] 写出失败（父目录建不了、盘满）在会话里说得清，不崩掉会话
- [x] 标定图仍不走管线：不判定、不量化、无损写出、不带自描述元数据

## 落地记录

**一格像素都不是这一票画的。** 图的内容归 `calibration-chart/01`，落盘归 `p0-hardening/12`
（`tonefit::write_calibration_chart`，库的第三个 seam）。本票做的是四件界面的事：
一个键、一条落点、屏上两行话、以及写不出去时那条路。

### `c`，只在设备层那三行上

`Action::Chart`，`Session::browsing_action` 里唯一一支**认层**的键：

```rust
Key::Char('c') if self.focus().layer() == Layer::Device => Action::Chart,
```

停在口味层或范围层上按它是 `Action::Ignored`，跑着时、展开着时、预设那一栏开着时也是
（那三种状态的按键表里根本没有它）。认层而不是「哪一行上都行」，理由是它出的那个数
——感知可分辨级数——正是设备层唯一填不出来的一格，键与那一格挨着才说得出它干什么用。
`which_keys_do_what_in_which_state` 十段里有六段问过它（一、二、三、六、七、八）。

**它不往 `Session` 上加状态**：一按就完，屏底说一句就是全部结果，会话此刻在做什么一格没变
（`assert_eq!(session.mode(), &Mode::Browsing)`）。这与 `e`／`p` 不同——那两个各带一个状态。

### 落点：会话是从哪儿敲起来的那个目录

```
<当前目录>/tonefit-calibration-<型号>-<灰阶数>-levels.png
```

**不问路径，一按就写。** 票面写的是「按一个键」，而不是「按一个键再打一个路径进来」；
命令行那一路的 `--out` 是必填，会话这一头没有那样一格可摆，也不该为它添一行。

**不落在输出根下面**：那是被处理的页的去处，标定图是量具，两者走的不是同一条路
（`lib.rs` 的第三个 seam）；何况按 `c` 那一刻输出根多半还空着，
而「先填一个输出根才出得了标定图」等于把设备层的事拴在了范围层上。

**名字里带型号与灰阶数**，因为图跟着这两项变（灰阶数决定排几条阶梯）：换一台设备出的是
另一张图，不该盖掉上一张。同一个 profile 再按一次写的是**同样的字节**——标定图不带记录、
不带时间戳，重写一遍等于没变。**全 ASCII**：这张图是要拷进设备看的，
那一头认不认得中文文件名说不准（图内留着英文说明也是这个理由）。

那个目录由 `enter` **一次问出来**（`std::env::current_dir()`）并一路传到 `press`：
一趟会话里当前目录不会变，按一次问一次只会让两张图落在两个地方。
它同时是这条路唯一的注入点——用例把临时目录交进去，因此写得出「写不出去」那一条，
也不会往跑用例的那个目录里扔文件。

### 界面层不碰文件系统，是结构上的

`Action::Chart` 与预设那三支同一条分法：状态机（`session/state.rs`）碰不到盘，
`session::press` 把它接走，调 `write_chart`：

```rust
let written = session.chart_profile().and_then(|profile| {
    let out = chart_file(here, &profile);
    tonefit::write_calibration_chart(&profile, &out).map(|()| out)
});
```

这一层建的不是目录、写的不是文件，只是**点了个名**——`create_dir_all` 与 `write` 都在
`crate::calibrate::write_chart` 里，那正是 `p0-hardening/12` 移进去的东西。
用例 `the_chart_key_hands_the_device_layer_to_the_library_seam` 把它钉死：
会话写出来的那份字节**与库直接写的逐字节相同**——会话若自己拼过一格像素，两份就分得开。

`chart_profile()` 走的是命令行与 `calibrate` 子命令共用的 `crate::target_profile`
（三处解析出来的必须是同一块面板），**阈值恒传 `None`**：标定图不经判定。
同一份设备层拼出的 `Request` 带着那个阈值，两个出口因此分得开
（`the_chart_is_drawn_for_the_panel_and_carries_no_threshold`）。

### 屏上两行，只说此刻要做对的那一件事

```
标定图 C:\…\tonefit-calibration-boox-poke6-16-levels.png
拷进设备，以原尺寸打开：关掉缩放、适配屏幕与白边裁切——图被缩过一次，它答的两件事一件都不作数了
```

那一句与命令行印的那几行**共用同一个常量**（`render::OPEN_IT_AT_NATIVE_SIZE`）：
同一件事从两张嘴里出来，措辞只能有一处出处。命令行那一路的输出**一字未变**
（连字节都比过：只有路径不同）。

**怎么数不在屏上**：图内中英两份都印着，`calibrate --help` 里也写着；屏底那一格
连指路那一行都不摆——三行的格子里多说一行就少一行按键提示，而此刻非说不可的只有
「以原尺寸打开」。它在别处已经来不及：图一旦被缩着显示过，抖动块与光栅先糊掉、
阶梯也跟着被重采样，它答的两件事一件都不作数了，而用户正是在这一刻决定怎么打开它。

两行而不是一行，是因为屏底那一格**不折行**：一条绝对路径接上那句话必被切掉，
而路径就是「图在哪儿」的全部内容。`footer` 因此改成「说的话有几行，上面那几行就让出几行」
（与 `listed` 同一条规矩）——说一行时这一格与从前逐格相同，只有出标定图那两行让掉一行。

### 写不出去：说一句，会话照开

库那一侧回 `Err`（父目录建不了、盘满都在里面），这一层 `format!("{error:#}")` 端到屏底，
返回 `Exit::Stay`——与套一份读不懂的预设同一条待遇，不另编一份措辞。
用例把图该落的那个目录的位置摆一个**文件**，`create_dir_all` 当场失败：
屏上说得出是哪一步、在哪条路径上出的事，三层一格没动，下一个键照按。
盘满那一种走的是同一条回路，在用例里造不出来，也不必造第二遍。

### 顺带

`render::failing_pages` 的文档说它是「本模块唯一挂着特性开关的一个」，而 `outcome` 早就
也挂着，本票又添了 `calibration_notice`——那句话改成点名三个。

## review 改了什么

- **Standards：用例里那个「按一个不出标定图的键」的助手，注释说的事不成立。**
  收了。它原本把 `Path::new("这一条不出图")` 当去处，而那是**相对路径**——真有人往那几条
  用例里加一下 `c`，图会落在跑用例的那个目录（仓库根）里，挡住它的只是「这几条不按 `c`」
  这条约定，结构上一格都没挡。改成点在那份预设文件的上一层，也就是临时目录里。
- **Standards：`browsing_keys` 里两支恒为空的插值。** 收了。`Shape::Path` 与
  `Shape::Volume` 只落得到范围层上，那两支的 `{chart}` 永远是空的；而 `Path` 那支
  真点着火的话，`·` 前后的空格还是反的。两支不再插它，理由写在旁边。
- **Standards：`chart_profile` 与既有的 `calibrated_profile` 是近亲。** 没有合并，
  但把两者的分别写进了文档：后者给左栏印阈值那一行用，**要**阈值、拼不出来吞成 `None`；
  前者反过来——阈值一格不带，拼不出来要说得出口。
- **Standards：`press` 的参数在攒成一堆（`presets` 与 `here` 都是外面那个世界的注入点）。**
  没动：两项还不贵，第三项进来时再给它一个类型。
- **Standards：`footer` 对超过三行的那句话是静默截断的。** 没动：今天只有出标定图那两行，
  而屏底那一格本来就不折行，多说的那一行摆不下就等于没说——这件事写在那个函数的文档里。
- **Spec：`enter` 里 `current_dir()` 答不出话时，屏上那条路径退成一个裸文件名。**
  收了注释——原话说「少说了一截」，实际少的是整个目录。行为没改：图仍旧落在同一处
  （进程的当前目录，只是这一头叫不出它的名字），仍旧写、仍旧说，
  因为另一条路是一个键按下去什么都不做；而 `current_dir` 答不出话的机器上，
  别的路径也一样叫不出名字。
- **Spec：`{chart}` 插进了两支恒为空的分支。** 与 Standards 那条是同一处，一并收了。
- **Spec：三处数字与事实对不上。** 收了：`which_keys_do_what_in_which_state` 问过它的是
  **六段**不是五段；左栏一个卷都没打进来时是**十六行**不是十七行；那条快照切掉的是
  `预设 · q 退出`，`p` 本身是完整的。
- **Spec：Q56 挪进《已了结》，而它记的那条命令行缺口代码里原样还在。** 收了措辞——
  改成**就地了结**并说清为什么它不成其为缺口（见下面《停车场结转》）：
  条目记的是「配好预设之后出标定图还要再敲一遍型号」，那件事现在有正路；
  命令行上剩下的只是多敲一个 `-p 型号`。不另立票、不升进《尚未确立》。

## 停车场结转

### Q56 — `calibrate` 子命令读不到预设，而标定图挂在**设备层**上

- **From:** 票 `p1-session/07`
- **Kind:** 路过发现
- **Where:** `src/main.rs` 的 `Cli`（`args_conflicts_with_subcommands = true`）与
  `Command::Calibrate`；`CONTEXT.md` 的《会话》「设备层里还挂着标定图」那一段
- **Why it did not block:** `--preset` 是顶层参数，而 `args_conflicts_with_subcommands`
  让顶层参数与子命令互斥——`tonefit calibrate --preset 漫画` 因此解析不出来。
  眼下不咬人：`calibrate` 自己收 `-p` 与 `--gray-levels`，两项都填得出来，
  只是配好一份预设之后出标定图仍要把型号再敲一遍。要通，得给子命令自己加一个
  `--preset`（各自一份解析，两处都要说清读的是设备层那一半），或者把
  `args_conflicts_with_subcommands` 拆细——后者会动到处理卷那一路的必填项判定。
- **What this ticket actually did:** **没有碰 `calibrate`，并且判定它不必再碰。**
  这条的动机原文写着：「配好一份预设之后出标定图仍要把型号再敲一遍」。
  本票落地之后那件事在会话里是**三个键**——`p` 套一份预设把设备层填齐，
  光标停在设备层上，`c` 出图，一次型号都不必敲，而这条路根本不经过 `calibrate`
  的命令行解析。原条目点名让 `13` 拍板，拍的就是这一下。
  仍然不给 `calibrate` 加 `--preset`，两条理由：
  一是**往命令行上添一条新语法**，而本票的硬约束是命令行那一路行为一字不变；
  二是那会给「一份预设怎么读」开出**第二条解析路径**（顶层一份、子命令一份），
  而两处都得各自说清读的是设备层那一半——为一个已经有正路的场景付这个代价不值。
  拆 `args_conflicts_with_subcommands` 更会动到处理卷那一路的必填项判定。
- **Whose call:** `13`（会话里出标定图）——它是第一个真要把预设与标定图接起来的地方
- **处置：** 由本票**就地了结**——不是留着，是判它不成其为缺口。
  `tonefit calibrate --preset 漫画` 仍解析不出来，而这条停车场条目记的不是那句语法，
  是它背后那件事：「配好一份预设之后出标定图还要把型号再敲一遍」。
  那件事现在有一条完整的正路（会话里 `p` 再 `c`），命令行上剩下的只是**多敲一个
  `-p 型号`**——一个短参数，不是一道过不去的坎。
  因此**不另立一张票，也不升进 `CONTEXT.md` 的《尚未确立》**：那里装的是产品的缺口，
  而这里没有缺口，只有一个拍过板的取舍（不给子命令开第二条预设解析路径）。
  往后真有人要它，那是一张新需求，不是本轮欠下的债。
