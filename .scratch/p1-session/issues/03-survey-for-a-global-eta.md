# 03 — 预扫：全局总步数与 ETA

**What to build:** 开工之前把点名的卷全**预扫**一遍，算出这一趟的全局总步数，
随「这一趟开始了」那条事件发出去。长任务因此给得出真正的剩余时间——
那是几十卷跑下来唯一有人真想知道的数。

预扫只列成员、不碰像素（目录卷走目录遍历，归档卷读中央目录），
而且**枚举结果交给管线复用，不扫两次**。

它顺带把「一卷点不开」提前到一页都没做之前：预扫阶段发现的坏路径**整趟拒绝**、逐条列出。
理由与「处理范围为空是错误」同一条——范围层错了可能写到别人的目录里。

依据：ADR 0011。

**Blocked by:** 02 — 事件流。

**Status:** resolved

- [x] 首个事件里的全局总步数等于各卷步数之和
- [x] 预扫只列成员，不解码任何像素
- [x] 管线复用预扫的枚举结果，同一个卷不被枚举两次
- [x] 命令行进度条给得出全局进度与剩余时间
- [x] 一条点不开的路径让整趟当场被拒，且发生在**任何卷级事件之前**，输出根下一个文件都没有
- [x] 幂等命中的卷提前收摊时，全局条不卡死在某个百分比上（预告的是**上界**，不是承诺）
- [x] 预扫本身在慢盘上的等待对用户有交代，不是静默的空白

## 落地记录

新开一个模块 `src/survey.rs`。`run` 的形状变成：开工前那几道检查 → **预扫** →
`RunStarted { volumes, steps }` → 逐卷。`process_volume` 不再收一个路径，收一个
**预扫过的卷**。

### 预扫读了什么，花多少

`Survey::of` 对点名的每一个输入调一次 `source::open`——**与从前完全同一个调用**，
只是从「处理那一卷时」挪到了「开工之前」。因此**这一趟的 I/O 次数一次都没有增加**，
预扫不是一笔新账，是同一笔账换了个付的时刻。

| 卷形态 | 预扫读什么 | 系统调用量级 |
|---|---|---|
| 目录卷 | 一遍 `WalkDir` 遍历 | 每个子目录一次 readdir + 每个成员一次 stat（Windows 上大小取自 `FindNextFile` 的记录，不额外 stat） |
| 归档卷 | 打开文件 + 读中央目录 | 常数次 seek/read，**与成员数无关** |

本机（固态盘、热缓存）实测量级：20 个目录卷 × 200 成员共 4000 个成员，遍历加 stat 约
**70 ms**；20 个归档卷 × 200 成员读中央目录约 **9 ms**。即目录卷每成员十几微秒、
归档卷每成员两微秒上下。慢盘上主导项是寻道而非成员数——几十个目录卷是亚秒到数秒。

### ETA 怎么算的

`Surveyed::steps` 一卷一个，由既有的 `volume_steps` 算（三段：幂等读全部源成员、
第一遍走每张源页、第二遍写全部输出成员，各段自己可能不在）。`Survey::steps` 是它们的
**和**——不是另算一遍，所以「全局总步数等于各卷步数之和」是构造出来的，不是要靠人守的约定；
开卷那条事件报的也是同一个 `Surveyed::steps`。

它在两处仍只是**上界**，而两处都不该由预扫去修：

- **幂等命中**：这一卷会不会命中，要读回上一趟写在输出里的记录才知道，那是幂等那一道自己的
  I/O；预扫只列成员，判不出来。
- **跨页拆分**（`CONTEXT.md` 的《进度》：预告的步数是上界，两处各出一次）：一张源页产出几张
  要解了像素才知道，预扫按 `MAX_OUTPUTS_PER_SOURCE_PAGE` 取上界。

上界之所以还站得住，是因为差额由画进度的那一层**在一卷收摊时结清**：CLI 的
`Bar::finish_volume` 从那一卷自己那条横条上读 `len - pos` 补进全局条，因此每一卷无论走了几步，
最终都往全局条上贡献满它预告的那些步——跑完恰好收在 100%。取下界会让条冲过头，
而「预告是上界」这条规矩本来就在（`CONTEXT.md` 的《进度》）。

### 命令行：报告一个字没变，屏上多两条

`render::report` 一行未动，黄金快照未重录、未改。变的只有 stderr 上那几条横条：

- `Bar::new(named)` 在 `run` **之前**就摆出一条转轮「预扫 N 个卷，列成员……」。
  它只能长在这一层——预扫排在 `RunStarted` 之前，库那时还没有话说。
  转轮由 `Drop for Bar` 兜底收掉：预扫拒绝整趟时 `run` 直接返回 `Err`，收场那条事件不来。
- `RunStarted` 到达时收掉转轮、摆上**整趟**那一条（全局进度 + `{eta}`）。
- 当前卷那一条照旧，只是几条一起画要走 `MultiProgress`，不然它们互相抹掉。

### 卷计时：枚举那一截跟着卷走

`VolumeTiming::elapsed` 的定义是「从打开卷到这份卷报告成型」，而
`outside_the_segments` 的文档明说「少掉的那一截恰恰是枚举」。枚举挪到预扫里并没有变便宜，
所以 `Surveyed::enumerating` 把那一截带给 `process_volume`，加进 `elapsed`。
`tests/timing.rs` 四条一行未改、全绿（`accounted_for == elapsed` 那条等式照旧成立）。

### 坏路径

`Survey::of` **收齐了再报**：点名十个卷写错三个，一次说清三条。`refuse` 照
`ensure_no_two_volumes_share_an_output` 的样子办——先说有几个 / 共点名几个，
再逐条缩进列出（路径一行、错误链一行），超过 5 条截断并说还剩多少。

到得了预扫的是「路径像个卷、打开才知道不是」这一类（损坏的归档、遍历不动的目录）。
「路径不在」「既不是目录也不是 .cbz」两种更早就被撞名校验挡下了，那一条仍是一次报一条——
记进停车场 Q43。两条路都在**任何卷级事件之前**返回 `Err`，验收那一条因此照样成立。

### 04 / 05 / 06 的地界一步没进

页边界检查点与丢弃 `partial`（`04`）、退出码（`05`）、决策点上停下来等人（`06`）
一件都没做。`05` 要的那个「预扫之后」的时刻现在存在了——`RunStarted` 报出去的那一刻——
形状仍留给它自己定。

### review 之后改的

Spec 那一侧点出**验收 #2 没有用例**：原先靠两条既有用例「合起来算证据」，而那两条在
「预扫把每页都解一遍」的世界里同样会通过，一条都不构成判别。补了
`the_survey_lists_members_without_reading_a_single_pixel`，判别式与「不扫两次」那条同一个
——收到开工事件的那一刻把一张好页改写成坏字节：预扫要是读过它，手上就是改写之前那份好像素，
这一页会照常出来；它其实一个字节都没读，于是这一页失败，**那一页失败正是证据**。

同一侧还点出**验收 #7 的文案早说了一步**：转轮在 `run` 之前就起来，而它盖住的那一段里
还有开工前那几道去处校验——只写「预扫」的话，被那几道拒掉的一趟屏上就写着一件没发生的事。
措辞改成「点名 N 个卷：查去处、预扫成员……」，并补
`something_is_on_screen_before_the_run_even_starts` 钉住「`run` 之前屏上就有东西、
开工事件一到就换成整趟那一条」。

另外两条按「说清楚而不是补测」处理：验收 #1 那条用例确实近乎恒真——两个数取自同一个
`Surveyed::steps`，那正是本票要的形状——用例文档因此改成明说它钉的是**接线**，
并指出算术在哪两处验；验收 #3 只测了目录卷，文档说明 `source::open` 在 crate 里只剩
一个调用点，会让它红的那种改动两种容器形态一起红。

Standards 那一侧点出**单一出处**：「上界 → 要结清」这套话在六处各说了一遍。
现在一条链：`CONTEXT.md` 的《进度》说为什么是上界与不结清会怎样，
`Event::RunStarted` 的 `steps` 说这是对实现方的要求，`Bar::finish_volume` 只说怎么做，
用例与停车场各自指过去。「不扫两次值多少」同样收到 `survey` 的模块文档一处。
另两条判断：`refuse` 与撞名校验那处的截断清单形状确有重复，但三处的条目各不相同——
照既有形状写了第三处，记进停车场 Q45；`volume_steps` / `MemberCounts` 没有搬进 `survey`
（`MemberCounts` 还要喂 `process_volume` 的区间断言，而搬家要在 crate 里造第二份
`Request` 夹具）。

还修了一处纯噪声：本票据文件被写成了 CRLF，而仓库其余文件都是 LF——改回 LF，
整份文件的假改动随之消失。
