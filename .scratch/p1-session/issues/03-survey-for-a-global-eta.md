# 03 — 预扫：全局总步数与 ETA

**What to build:** 开工之前把点名的卷全**预扫**一遍，算出这一趟的全局总步数，
随「这一趟开始了」那条事件发出去。长任务因此给得出真正的剩余时间——
那是几十卷跑下来唯一有人真想知道的数。

预扫只列成员、不碰像素（目录卷走目录遍历，归档卷读中央目录），
而且**枚举结果交给管线复用，不扫两次**。

它顺带把「一卷点不开」提前到一页都没做之前：预扫阶段发现的坏路径**整趟拒绝**、逐条列出。
理由与「处理范围为空是错误」同一条——范围层错了可能写到别人的目录里。

依据：ADR 0011。

**Blocked by:** 02 — 事件流。

**Status:** ready-for-agent

- [ ] 首个事件里的全局总步数等于各卷步数之和
- [ ] 预扫只列成员，不解码任何像素
- [ ] 管线复用预扫的枚举结果，同一个卷不被枚举两次
- [ ] 命令行进度条给得出全局进度与剩余时间
- [ ] 一条点不开的路径让整趟当场被拒，且发生在**任何卷级事件之前**，输出根下一个文件都没有
- [ ] 幂等命中的卷提前收摊时，全局条不卡死在某个百分比上（预告的是**上界**，不是承诺）
- [ ] 预扫本身在慢盘上的等待对用户有交代，不是静默的空白
