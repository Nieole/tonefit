# 05 — 卷级失败与第四个退出码

**What to build:** 预扫**之后**才点不开的卷（文件被删、盘拔了、权限变了）不再毁掉整趟。

现在一个卷开不了，整趟当场失败：前 27 卷的输出还在盘上，但那份报告全丢，退出码 1。
几十卷的长任务里，这是最难受的一种结局。

改成记为**卷级失败**：其余卷照做，报告照出。退出码从三个变四个，
脚本因此分得开「有卷带着坏页」与「有卷根本没做成」——那是两个不同的决定。

**Blocked by:** 03 — 预扫（它定义了「预扫之后」这个时刻）。

**Status:** ready-for-agent

- [ ] 报告容得下「没打开过的卷」，并说得出它为什么没打开
- [ ] 预扫之后一卷点不开 → 其余卷照常处理，报告完整，已做完的卷不受影响
- [ ] 退出码四个：`0` 全部成功、`2` 做完了但有卷被隔离、`3` 有卷没做成、`1` 这一趟没做成
- [ ] `2` 与 `3` 同时成立时取 `3`
- [ ] 卷级失败在事件流里也说得出来，不是只在最终报告里
- [ ] 透传文件搬不动仍是卷级的失败，走同一条路
