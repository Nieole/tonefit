# 05 — 卷级失败与第四个退出码

**What to build:** 预扫**之后**才点不开的卷（文件被删、盘拔了、权限变了）不再毁掉整趟。

现在一个卷开不了，整趟当场失败：前 27 卷的输出还在盘上，但那份报告全丢，退出码 1。
几十卷的长任务里，这是最难受的一种结局。

改成记为**卷级失败**：其余卷照做，报告照出。退出码从三个变四个，
脚本因此分得开「有卷带着坏页」与「有卷根本没做成」——那是两个不同的决定。

**Blocked by:** 03 — 预扫（它定义了「预扫之后」这个时刻）。

**Status:** resolved

- [x] 报告容得下「没打开过的卷」，并说得出它为什么没打开
- [x] 预扫之后一卷点不开 → 其余卷照常处理，报告完整，已做完的卷不受影响
- [x] 退出码四个：`0` 全部成功、`2` 做完了但有卷被隔离、`3` 有卷没做成、`1` 这一趟没做成
- [x] `2` 与 `3` 同时成立时取 `3`
- [x] 卷级失败在事件流里也说得出来，不是只在最终报告里
- [x] 透传文件搬不动仍是卷级的失败，走同一条路

## 落地记录

分岔只有一处：`run` 的逐卷循环从 `process_volume(...)?` 换成一个 `match`。
`Ok(Some)` 进报告、`Ok(None)` 是中止（照旧 `break`）、`Err` 记一笔卷级失败接着做下一卷。
**没有第二处判断**——「这一卷做不成」在管线里有十来个出口（撞名、指纹那一道读不出字节、
第一遍读不出源、建不出输出容器、透传文件搬不动），逐个去认就等于把那份清单抄第二遍。

### 失败与拒绝，分在哪里

`process_volume` 的 `Err` 里混着两种东西，而两者的处置正相反：

| | 卷级失败 | 拒绝执行 |
|---|---|---|
| 错在 | **这一卷**上 | **这一趟的参数**上，换一卷不会变好 |
| 处置 | 记一笔，其余卷照做 | 整趟当场停，`run` 返回那个错误 |
| 退出码 | `3` | `1` |

分辨它们的是一个标记类型 `Refusal`（`src/lib.rs`，私有），`run` 用 `downcast_ref` 认它。
**眼下只有一处戴它**：覆盖项把候选集裁空（`nothing_left_error`）。其中互锁 ③
（`--dither fs` 撞上一页贴不住面板）的处置明写着「维持拒绝」（页几何批 05 号票），
而它撞得上的时机在第一遍里、一页一页地判——真跟着走卷级失败那条路，
「拒绝」就悄悄降级成了「这一卷没做成」，而用户点的那个开关对每一卷都错。
`Candidates::for_gate` 每页重说一遍那句话时也戴着标记（`anyhow::Error` 复制不了，
那一句本来就要重造）。

撞名走的是**卷级失败**：`001.jpg` 与 `001.png` 都要写到 `001.png` 上，那是**那一卷内容**
的性质，换一卷根本不成立。这件事词条里没列，记在停车场 Q48。

**这条线没画满，两处缺口都记了下来**：卷根**整个消失**走不到卷级失败——页读不出来是
12 号票定死的页级失败，整卷进隔离目录、退出码 `2`（Q50）；`--out` 写不进去本该是拒绝执行，
而它由 `Sink::create` 逐卷各撞一次，于是每卷各记一笔、退出码 `3`（Q51）。
两处都要动本票之外的口径（前者是 12 号票的页级失败，后者是一道一直不在的开工前检查）。

### 报告与事件

- `Report::failed_volumes: Vec<VolumeFailure>`——`{ volume, reason }`，按点名顺序。
  与 `volumes` **并列而不并进去**：那一列的每一项都以「这一卷做出了东西」为前提
  （去处、页数、判定、计时），混进去就得给每一项编一个缺省值。
- `Event::VolumeFailed { volume, reason }`——与 `VolumeFinished` **二选一**：
  一条开卷之后到得了的只有其中一条，两条都没有的只剩中止那一种。
- `Report::outcome` / `Event::RunFinished { outcome }`——`RunOutcome`：走到头、
  被按停停在半路（带着按下的是哪一级）、拒绝执行。它一并了结了停车场 Q39 与 Q46，
  两条的处置见下面的《停车场结转》。
- 渲染多一小结，**压在整份报告的最末尾**（`render::failed_volume_tail`）：逐条列出路径与原因，
  多于五条只列前五并说还有多少（形状照预扫那条拒绝办）。没做成的卷在正文里一行都没有——
  正文逐卷那几段来自 `Report::volumes`，这一小结是它们在报告里唯一的位置。

`events.volume_started` 挪到了 `process_volume` 的第一件事之前（原先排在撞名校验之后）：
这样每一条出口——跑完、没做成、中止——都在开卷之后，画进度的那一层不必分
「这一卷开过头没有」两种情形。命令行那一侧因此只加了一个 `match` 分支：
`VolumeFailed` 与 `VolumeFinished` 走同一句 `finish_volume()`——一卷开过头就一定要收摊，
不然那条横条留在屏上不走，整趟那条也少了它预告的那几步、永远走不到头。

### 退出码

`FAILED_VOLUME_EXIT = 3`，**压过** `ISOLATED_EXIT`。既有三个数的含义一个字未动。
两者分开的理由与当初把「有卷被隔离」从「拒绝执行」里分出来是同一条：脚本要分得开——
隔离过的卷交出来了、只是带着坏页，修好重跑就行；没做成的卷一个字节都没交出来，
该去查的是文件还在不在、盘还挂着没有。按停停下来的那一趟**不在退出码上露面**：
那是用户自己的决定，不是失败。

### 用例

| 用例 | 钉的是 |
|---|---|
| `isolation.rs::a_volume_that_fails_after_the_survey_leaves_the_rest_of_the_run_alone` | 三个卷、坏的夹在中间：做完的两卷有报告也有输出，坏的那一卷指得出自己与原因，后面那一卷照做，输出根下没有它 |
| `events.rs::a_volume_that_never_got_done_is_reported_the_moment_it_fails` | 卷级失败**当场**报出去，排在下一卷开工之前；那一卷没有配对的 `VolumeFinished`；事件与报告说的是同一句 |
| `events.rs::the_last_event_says_how_the_run_ended` | 走到头 / 收尾 / 中止三种收场，事件与 `Report::outcome` 比同一个值 |
| `events.rs::a_refusal_after_the_run_started_still_says_the_run_is_over` | 拒绝执行照报收场（Q39），且没有降级成卷级失败 |
| `exit_code.rs`（真进程） | 四个数各说一件事，且 `2` 与 `3` 同时成立时取 `3` |
| `render.rs::the_report_names_every_volume_that_never_got_done_and_why` | 报告里那一小结说得出是哪一卷、为什么、这一趟没因此停下；退出码是 `3` |
| `render.rs`（隔离那一条尾巴上） | 同一份报告再添一卷没做成的，退出码让给 `3` |

抽走源里透传文件的那个观察者提进了 `tests/fixtures`（`RemoveOnceTheSurveyIsDone`）：
`container.rs` 原先那一份 `RemoveAtStart` 与本票在 `isolation.rs` 要用的是同一个东西，
抽走的时机一并改按**开工那条事件**——预扫排在它之前，「预扫时打得开」因此是这个夹具自己说的。

`tests/container.rs` 那四条「透传文件搬不动」从 `expect_err` 改成读
`report.failed_volumes[0].reason`，`tests/pipeline.rs` 的撞名那一条同理
（改名为 `two_pages_that_would_share_one_output_take_only_their_own_volume_down`）——
**它们要钉的东西一件没变**（指名是哪个成员、不留半成品、不毁掉上一趟的成品、
撞名不静默覆盖），变的只是那一趟不再整个失败。

### Q39 — `run` 返回 `Err` 时不发「这一趟完了」，异常收场没有自己的那一条事件

- **From:** 票 `p1-session/02`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/lib.rs` 的 `run`（`events.run_finished()` 排在 `?` 之后）；
  `src/progress.rs` 的 `Event::RunFinished`
- **Why it did not block:** 票面点名的七件事里，「这一趟完了」没有说异常收场算不算。
  眼下走的是**不算**：`process_volume` 返回 `Err` 时 `?` 直接把错误交出去，
  一条收尾事件都不发——调用方拿到的是那个 `Err` 本身，信息不少一条。
  另一条路是让它照发（或者给它带上「怎么收的场」），那要决定事件里装不装错误，
  而 `Report` 那一侧至今没有装过失败的位置。这是 `05`（卷级失败与退出码）的地界：
  那张票要重画的正是「一卷点不开算整趟失败还是算这一卷失败」。
- **What this ticket actually did:** **只发正常收场那一条**，并把这件事写进
  `Event::RunFinished` 的文档：`Err` 时不报，收尾停下来的那一趟照报（它是正常收场的一种）。
  会话那一头因此要自己认 `run` 的返回值，不能只等事件——这一句同样写在那份文档里。
- **Whose call:** `05`（卷级失败与退出码）
- **处置：** 由本票了结。**给它带上了「怎么收的场」。**`Event::RunFinished` 多了一格
  `outcome`（`RunOutcome`），三种：走到头、被按停停在半路（带着按下的是哪一级）、拒绝执行。
  规矩因此从「只发正常收场那一条」翻成了 **「报过开工，就一定报得到收场」**——
  拒绝执行的那一趟照发，只是收场说的是「拒绝执行」，紧接着 `run` 才把错误交出去：
  事件说了「完了」，返回值说了「为什么」，信息一条不少。
  事件里**不装错误**——那是当初拿不准的那一件，答案是不装：错误由返回值带，
  事件只说这一趟结束了、以哪种方式结束。
  开工那条事件**之前**被拒的那几种仍是一条事件都不发（那一趟连开工都没有）。
  本票同时把「一卷点不开算整趟失败还是算这一卷失败」定死了：算这一卷的
  （见《失败与拒绝，分在哪里》），因此除拒绝执行外，`run` 已经不会在开工之后返回 `Err`。
- **State:** settled

### Q46 — 中止掉的那一卷只有开卷那一条事件，`run` 的返回值也说不出这一趟是被中止的

- **From:** 票 `p1-session/04`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/lib.rs` 的 `run`（中止那一支 `break` 掉，不 `push` 报告）与 `process_volume`
  （回 `None`）；`src/progress.rs` 的 `Event::VolumeFinished`、`Event::RunFinished`
- **Why it did not block:** 中止掉的那一卷**等于没做**，因此它既不进 `Report::volumes`，
  也不报 `VolumeFinished`——这两条本身是对的（ADR 0013 决定第 2 条）。露出来的是另一件事：
  **「这一趟被中止过」在库的出口上没有形式。** 事件流那一侧看得见一条没有配对的
  `VolumeStarted`，会话的当前卷条因此要自己认这个形状才收得了摊；返回值那一侧更彻底——
  中止掉的卷与「压根没点名它」在 `Report` 上一模一样。
  真要给它一个形式，是往 `RunFinished` 里塞「这一趟是怎么收的场」（**那正是 Q39**），
  或者给 `Report` 加一格。两条都是往事件流/报告上加形状，而本票没有第二个消费方
  可以拿来验证那个形状对不对——`10`（会话按停）与 `05`（退出码）才是它的消费方。
- **What this ticket actually did:** **没有加形状。**把这两件事写进文档，让下一个实现方
  一眼看得见：`Event::VolumeFinished` 上明写「被中止掉的那一卷不报这一条」，
  并点出「流上一条没有配对的开卷」就是中止在事件流上的样子；`Instruction::Abort` 上明写
  「它因此不进报告」；`CONTEXT.md` 的《会话》补一句「中止掉的那一卷不进报告」。
  退出码一字未动——中止仍回 `Ok`，走的是既有的那套判定（`05` 的地界，本票不碰）。
- **Whose call:** `05`（退出码）与 `10`（会话按停）——两者合起来才知道要不要那格形式，
  以及它该长在事件上还是报告上（与 Q39 是同一个问题的两面）
- **处置：** 由本票了结。**加了那格形状，两处都加。**事件那一侧是
  `Event::RunFinished { outcome }`（Q39 的那一格），报告那一侧是 `Report::outcome`——
  同一个值，`run` 里算一次、两处各带一份。中止掉的那一卷仍不进报告、仍不报
  `VolumeFinished`（ADR 0013 决定第 2 条一字未动），而「这一趟被中止过」现在有了形式：
  `RunOutcome::Stopped(Instruction::Abort)`。收尾与中止分得开——`Stopped` 带着按下的
  那一级，两者停下来的现场不同（前者盘上留着完整的卷，后者连当前那一卷都丢了）。
  验证那个形状对不对的第二个消费方本票就有了一个：退出码。**它不看收场**——
  按停是用户自己的决定，不是失败，退出码照旧（`10` 因此不必回头改退出码的含义）。
  用例是 `tests/events.rs` 的 `the_last_event_says_how_the_run_ended`：三种一起断言，
  事件与报告比同一个值。
- **State:** settled
