# 03: 页事实、资源上界与几何进入 domain

**What to build:** 页的尺寸、灰度像素、救回事实和共用资源上界成为 tonefit-domain 的独立领域能力。几何、裁白边与拆分跨页无需认识解码实现，也能使用相同事实；原调用者继续使用同一类型而非副本。

**Blocked by:** 01「完整 workspace 闸门与外置测试装配」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：2、3、4、15、16、18、36、78。

- [ ] 新增 domain 并迁入尺寸、几何适配、灰度像素与救回事实；只公开真实跨 crate 生产协作需要的 interface，不批量公开原私有 module。
- [ ] 将几何与解码共用的资源上界放在最低共同拥有者，保持目标像素上界与解码限制的原计算关系及数值单一出处；处理侧引用领域事实，domain 不反向引用解码、根程序或 processing。
- [ ] 用同类型临时重导出适配现有调用者，不复制类型或算法；无论 processing 编译拥有权迁移是否已完成，都保持该票可独立落地并通过验证。
- [ ] 同步外置所属测试、测试专用实现和辅助；纯像素夹具不依赖 processing，私有断言仍通过所属测试子模块访问，保留真实公共构造契约。
- [ ] 验证尺寸边界、几何兜底、像素完整性、救回事实及跨 crate 类型互通；按性质索引说明所有替换或删除的断言。
- [ ] 新包加入时同步更新实际包选择、源码扫描、许可与版本检查及当时架构事实；反运行相关守卫后复绿，运行聚焦检查、cargo xtask gate、cargo xtask polish。

## 不做会怎样

领域能力仍经解码器取得事实与限制，拆 crate 后将出现反向依赖、重复常量或类型副本，无法由编译器维护单向依赖。
