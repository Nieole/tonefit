# 02: processing 接管编译拥有权，保留临时根门面

**What to build:** 原有处理、报告和量具能力由 tonefit-processing 的唯一实现提供，根程序与原库调用者仍可运行。先切换编译拥有权，保留源码位置暂存，避免一次搬迁整棵实现；本票不是最终目录结构，也不借机深化页处理或复用策略。

**Blocked by:** 01「完整 workspace 闸门与外置测试装配」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：3、5、7、8、9、11、12、73、74、75、76、78。

- [ ] 让 processing 单独编译原处理库实现，根库仅以临时门面重导出同一类型和实现；不重复编译两套领域／处理类型，不形成 processing 到根程序的依赖，不新增 common、contracts 或夹具 crate。
- [ ] 保持 run、score、write_calibration_chart、write_proof 的现有能力与根程序启动行为；源码位置暂存由 11 结束，根库门面由 24 在所有调用者迁移后删除。
- [ ] 同步适配依赖、平台依赖与 feature 转发；profiling 留在处理侧包裹领域调用，tui 仅控制实际终端，开发用编码／压缩特性不进入 release。
- [ ] 审计编译包名、版本、manifest 位置及相关环境值的消费者，固定产品仍为 tonefit，保持应用版本来源、记录、参数哈希和夹具定位；内部包版本与产品版本一致性须有守卫。
- [ ] 新包加入时即修正闸门覆盖、平台证明选择、交付包图和内部包许可证文本读取，验证仓库内真实许可来源，不留到最终验收再补。
- [ ] 对编译归属变化执行现有真实产物、事件、记录和量具回归；本票涉及的测试实现外置并按性质索引记录替换，不为测试批量公开原私有 module。
- [ ] 更新当时已成立的架构与 module spec，记录必要 ADR 及暂存设施退出条件；运行聚焦检查、cargo xtask gate、cargo xtask polish 和受影响交付脚本测试。

## 不做会怎样

直接全量搬目录会把编译归属、类型身份与处理行为混在一次变化里；只改包名还可能静默改变记录中的产品身份和许可清单。
