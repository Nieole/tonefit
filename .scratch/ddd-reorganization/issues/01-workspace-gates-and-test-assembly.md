# 01: 完整 workspace 闸门与外置测试装配

**What to build:** 维护者沿用现有闸门即可知道每个实际运行时包的测试是否执行；新增包、测试外置和输出次序变化不能让漏测冒充通过。本票先建立后续迁移可复用的测试装配与性质覆盖索引，不预先迁移领域实现。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：12、17、18、19、20、21、22、73、75、78。

- [ ] 核对开工提交、工作树与并行工作归属，记录三构建、polish、设计及交付检查的真实基线；区分既有失败、缺少真实素材与改动引入的问题，不重录黄金产物或快照。
- [ ] 将闸门与 polish 的测试、检查选择及汇总改为识别实际 workspace 包和 target；维持既有命令、locked 依赖及三构建各自的 target 隔离，不再按返回次序猜测 lib/bin，也不把 xtask 加进运行时依赖。
- [ ] 为乱序、多包、零测试、缺失测试结果和失败传播增加外置工具测试；分别报告应执行与实际执行的目标，不能把被选中的正常零测试目标和意外漏跑混为一谈。
- [ ] 建立就近外置私有测试、受限 sibling 辅助及共享测试源码的装配方式；共享源码区分纯领域与真实读写依赖，不新增夹具 crate，不扩大生产 interface。
- [ ] 扩展源码守卫识别实际自有 Rust 源码根、新运行时包和共享测试源码；区分测试装配与测试实现，不统一跳过外置测试或误扫 vendor。对守卫执行反运行，确认因目标断言变红而非编译失败或零测试。
- [ ] 建立可逐票更新的“旧性质／断言—新 interface 覆盖—删除理由—feature”索引；索引记录证据而非强求测试数量不变。
- [ ] 将本票测试实现外置，更新实际闸门与测试组织文档；运行聚焦检查、cargo xtask gate 与 cargo xtask polish，记录未执行项目及原因。

## 不做会怎样

后续拆包可能只编译而不测试依赖包，或把外置测试移到守卫盲区；局部全绿将无法说明验证范围是否完整。
