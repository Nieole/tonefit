# 19: 运行事实改为统一只读快照

**What to build:** 会话交互与绘屏读取同一份只读运行快照，清点、进度、确认、卷状态与报告由运行投影拥有；编辑、视图、焦点、光标和搜索仍由交互状态拥有。新旧运行和确认变更不会读到过期事实，也不必持可变投影锁绘屏。

**Blocked by:** 01「完整 workspace 闸门与外置测试装配」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：53、54、55、56、57、60、61、78。

- [ ] 沿既有快照能力建立统一只读、拥有型运行事实访问；运行投影保留清点、确认、卷状态、摘要与报告，交互状态不复制第二套事实，不把编辑与视图数据塞进运行投影。
- [ ] 让交互与绘屏消费快照而非可变投影守卫；运行事件与明确运行操作管理写入，运行身份变化及答完确认后及时刷新快照。
- [ ] 保持确认更新、释放锁与唤醒次序；锁内不等待确认、不 join、不读写预设、不调用量具、不绘屏，不以延迟快照掩盖状态变化。
- [ ] 验证旧运行回调不污染新运行、过期确认不残留；零卷清点明确区分完成与中途停止，保持备注、问题跳转和自动滚动。
- [ ] 用完整会话协作、只读访问、持锁哨兵及既有设计快照验证事实一致性和锁外工作，不增加生产测试后门；保持屏中文字、样式和命中区域。
- [ ] 同步外置／替换运行投影与协调测试、专用 impl 和辅助，按性质索引记录覆盖，更新实际 owning spec 与守卫。
- [ ] 运行默认／无默认特性的会话聚焦检查、cargo xtask gate 与 cargo xtask polish；本票可在原根库或处理库已迁移的状态下落地，不因无关拆包增加 blocker。

## 不做会怎样

交互与绘屏继续持有可变运行守卫，或在各自状态里复制运行真相；身份切换、确认答话和慢读写都会成为过期显示或死锁的来源。
