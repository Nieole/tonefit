# 08: 输入、发现与路径身份归位

**What to build:** 处理范围、发现、源读取、介质探测和同一处判断集中归入 processing 的实际源码组织。用户点名路径仍只读、仍按既有卷规则展开，Windows 真实路径守卫证明随迁移继续有效。

**Blocked by:** 02「processing 接管编译拥有权，保留临时根门面」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：2、5、10、75、78。

- [ ] 机械迁移源读取、发现、清点、路径身份与介质探测，不增加全库扫描或索引，不改变归档、分卷序列、目录卷及自动跳过／无法访问分类。
- [ ] 保持源库只读、成员阅读顺序、透传、同一处判断及源／输出两侧不同的探测保守策略，不借移动改变路径规整政策。
- [ ] 同步外置所属测试、平台 fixture 与测试辅助，保留真实临时目录和归档；按性质索引记录替换覆盖。
- [ ] 同票适配 Windows 路径前缀证明的包选择、真实源码位置和完整测试名及证明脚本自身测试；仍修改真实守卫、观察目标断言失败、按原字节恢复后复绿，不能以编译失败或零测试充数。
- [ ] 同步更新源码扫描、交付路径消费者、适用平台证明和实际 owning spec；不得等 25 才修迁移引入的验证失效。
- [ ] 运行输入、发现、路径与受影响交付脚本聚焦检查、cargo xtask gate 与 cargo xtask polish；Windows 证据注明真实平台，未执行不得冒称通过。

## 不做会怎样

输入规则仍与根程序位置纠缠，平台证明还可能指向旧位置而静默失效；本机全绿无法证明真实 Windows 守卫仍被测试。
