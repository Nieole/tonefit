# 05: 纯页变换进入 domain

**What to build:** 页的颜色事实、裁白边、拆分跨页、缩放与纸色提白按领域能力归入 domain。转换仍得到同样的输出页顺序、尺寸和像素，而这些纯规则不认识文件、运行报告或确认等待。

**Blocked by:** 03「页事实、资源上界与几何进入 domain」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：2、4、11、18、33、35、36、78。

- [ ] 迁移纯颜色、裁切拆分、缩放与提白计算，引用共用救回事实和资源限制，不复制算法、常量或引入领域到 processing 的依赖。
- [ ] 保持裁白边、判跨页、拆分、每半再裁及适配的既有顺序，保持阅读方向、连续跨页、残缺页与几何兜底语义。
- [ ] 保持提白关闭、纸白量测和颜色分支的既有用途差异，不借搬迁重标定阈值或升级依赖。
- [ ] 就近外置所属测试、辅助与夹具；纯领域夹具不得导入处理编排，按性质索引记录同步替换或删除的断言。
- [ ] 经现有纯变换性质、真实 run 产物、跨页页序、像素与窄计数器验证迁移；不重录黄金产物。
- [ ] 同步更新实际调用、源码扫描、路径消费者及 owning spec；临时同类型重导出由 24 收口，运行聚焦检查、cargo xtask gate 与 cargo xtask polish。

## 不做会怎样

页变换仍与运行协作混放，定位一个几何或像素问题需要跨处理代码追踪，后续共用页求值也无法取得干净的领域计算依赖。
