# 14: 候选纯规则统一拥有可行集与覆盖顶死事实

**What to build:** 转换与样张消费 domain 的同一套候选纯规则，得到可行候选、覆盖后候选、结构化裁空原因与真正覆盖顶死事实；processing 只补路径、拒绝时机和文案，调用者无需重新拼候选政策。

**Blocked by:** 02「processing 接管编译拥有权，保留临时根门面」、04「设备、画质分与量化协同进入 domain」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：23、24、27、28、36、78。

- [ ] 以面板、尺寸贴合、覆盖与必要页分组事实作为领域输入，统一产出可行集、覆盖集、裁空原因和顶死事实；domain 不接收 Request、路径、报告或拒绝文案。
- [ ] 同票接入当前转换与样张的真实调用，移除被替代的重复候选知识；样张展示全部可行候选，覆盖只裁判定候选。
- [ ] 保持“自然仅剩一个不等于用户覆盖顶死”，以及默认逐页、整卷统一灰阶和开卷前顶死各自时点；不以集合长度代替完整判据。
- [ ] 保持面板硬上界、尺寸贴合检查、位深与抖动覆盖组合、裁空诊断及其首错／路径上下文，不把处理侧错误规则推进 domain。
- [ ] 通过 run、write_proof 和必要领域 interface 验证组合与性质，同步外置／替换所属测试，按性质索引记录覆盖去向，不新增 helper 专用生产端口。
- [ ] 同步更新调用、单一出处扫描与 owning spec，运行聚焦检查、cargo xtask gate 与 cargo xtask polish；物理迁移先后只影响合并定位，不构成额外语义 blocker。

## 不做会怎样

转换、样张和不同判定路径会继续各自重建候选，容易混淆展示与判定，或把偶然单例误报为覆盖顶死。
