# 07: 请求、报告、事件与运行契约归位

**What to build:** 调用者从 processing 取得请求、报告、进度事件及运行控制契约，运行与领域计算的拥有关系在源码组织中可直接导航。本票只完成这一批实体迁移，不改变事件、控制或计时政策。

**Blocked by:** 02「processing 接管编译拥有权，保留临时根门面」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：2、5、7、8、11、74、78。

- [ ] 将请求、报告、事件、进度、确认协调与阶段计时实现迁入 processing 的实际源码组织，保留类型身份；domain 不接收整个 Request，也不依赖这些运行契约。
- [ ] 保持 Mode 的两个既有用途，不增加 Proof；拒绝、卷失败、无法访问及报告数据继续由处理侧区分，进程退出映射不搬入 processing。
- [ ] 保持事件顺序、两级停止、确认协调及卷级／阶段计时口径，profiling 仍由处理侧包裹领域调用。
- [ ] 同步外置所属用例、测试专用 impl、辅助与夹具，包含散落在用例模块之外的测试能力；按性质索引说明旧断言的新覆盖。
- [ ] 同步更新真实模块引用、源码扫描、完整测试名、路径消费者与 owning spec；过渡装配由 11、24 分别结束，不能成为长期薄转发层。
- [ ] 运行事件、报告与运行控制聚焦检查、cargo xtask gate 与 cargo xtask polish；确认迁移后测试实际由 processing 执行。

## 不做会怎样

编译所属包虽已改变，运行契约仍藏在根源码组织中，维护者无法从职责找到实现，也容易误把报告和事件推入 domain。
