# 15: 共用页求值贯通逐页处理与纯 DryRun

**What to build:** processing 的一个页处理 module 拥有从源字节、解码、识色、几何到参照和评估的完整次序，先让默认逐页、开卷前顶死和纯 CLI DryRun 消费同一生产 interface。调用者得到按阅读顺序的页事实及拥有型产物，不再自行拼步骤。

**Blocked by:** 05「纯页变换进入 domain」、14「候选纯规则统一拥有可行集与覆盖顶死事实」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：25、29、31、33、34、35、36、78。

- [ ] 建立唯一共用页求值与用途相关物化实现，贯通默认逐页、开卷前顶死及纯 DryRun；一次源页解码产出按阅读顺序的输出页，跨环节产物明确拥有资源。
- [ ] 默认逐页及开卷前顶死判完当场编码、缓存装字节，参照不入缓存；纯 CLI DryRun 不为输出编码，也不做没有消费者的彩色缩放。
- [ ] 保持提白关闭时量测用途差异、彩色分支、残缺页、跨页、尺寸贴合与落格；源哈希作用域由真实转换依赖决定，不由 DryRun 暂存策略推导。
- [ ] 卷级汇总、输出位置、坏页占位、记录、缓存槽和报告组装保留各自拥有者，不下沉为 domain 页规则；确认前不得写出正式产物。
- [ ] 允许 16、17 尚未迁移的旧调用通过窄适配继续工作，但不能复制新的页引擎或算法；本票只收敛本票调用者，后续两票分别删除其旧编排。
- [ ] 经 run 的像素、字节、报告、阅读顺序和窄计数器验证一次解码、必要工作及参照缓存语义；同步外置并替换相关测试，按性质索引记录旧断言去向。
- [ ] 同步更新单一出处守卫、路径消费者及实际 page-transform／processing spec，运行聚焦检查、cargo xtask gate 与 cargo xtask polish。

## 不做会怎样

调用者仍掌握完整评估次序，提取零散纯 helper 不会改善 locality；统一接口若强迫所有用途编码，还会悄悄增加 DryRun 的工作量。
