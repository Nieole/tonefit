# 04: 设备、画质分与量化协同进入 domain

**What to build:** 面板与 Profile、画质分和量化作为协同的领域计算由 domain 提供。调用者使用相同的领域值和数值规则，不再依赖处理编排才能量分或量化；相互引用的一组计算在同一可验证批次迁移。

**Blocked by:** 03「页事实、资源上界与几何进入 domain」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：2、4、7、8、11、15、18、36、78。

- [ ] 协同迁移设备与 Profile、画质分、量化及其相互依赖的领域值，保持类型身份、计算顺序、浮点运算和数值出处；不为拆环复制 Score、候选或量化图。
- [ ] domain 提供 score 产品 seam 及必要计算 interface，不接收 Request、报告、路径、事件或终端类型；profiling 由处理侧在调用协作处包裹，不反向进入领域计算。
- [ ] 同步外置用例、夹具与测试专用 impl；依附类型的私有测试能力留在拥有类型的测试装配中，不在另一 crate 为外来类型补 inherent impl，不扩大生产可见性。
- [ ] 以现有分值性质、Profile 校验、量化格点和数值证据验证迁移，保持 doctest 可用；逐项记录旧断言的新覆盖，不以数量代替等价。
- [ ] 同步修正实际调用、文档示例、源码守卫、依赖特性及版本／许可消费者，更新当时 owning spec；临时重导出由 24 收口。
- [ ] 运行聚焦领域检查、cargo xtask gate 与 cargo xtask polish，确认实际执行 domain 测试且纯领域夹具无处理侧反向依赖。

## 不做会怎样

把相互依赖的类型分别复制或公开整片内部实现，会让计算知识分散到调用者，并把测试权限问题误解成需要更大的生产 interface。
