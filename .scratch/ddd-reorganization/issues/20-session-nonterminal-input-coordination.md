# 20: 完整输入协调脱离终端 adapter

**What to build:** 给定输入、时刻、窗口尺寸、当前目录及明确的运行／预设依赖，就能驱动完整会话动作，不需要真实终端。起跑、两级停止、确认、预设、量具、搜索和导航在无 tui 构建中同样编译和受验；终端 adapter 只负责真正终端职责。

**Blocked by:** 19「运行事实改为统一只读快照」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：6、49、50、51、52、54、55、56、58、59、60、61、78。

- [ ] 将完整输入分派及具体动作放入非终端交互 module，直接协调 Running、Presets 等明确依赖，接收给定输入／时刻／窗口与目录，不引入通用动作／结果协议。
- [ ] 覆盖起跑、两级停止、确认／取消、同次运行继续写出、预设选择／保存／删除、灰阶测试图、搜索、导航与编辑；不把任何业务动作测试只留在 tui 构建。
- [ ] 消费统一只读运行快照，在运行或确认改变后刷新；等待、join、预设读写、量具和绘屏保持锁外，编辑／焦点状态不复制运行事实。
- [ ] terminal 只保留生命周期、原始事件与键码翻译、输入读取／批处理、取尺寸、调用交互、绘屏与命中反馈；按键表、措辞、布局规则和场景仍保持单一出处。
- [ ] 用真实临时目录、给定时刻、受控运行及完整非终端输入链验证行为，再用既有 TestBackend／设计快照逐格验证文字、样式、命中区域、自动滚动和批处理；不声称这些有读写和线程的动作是纯函数。
- [ ] 同步外置／替换所改测试、专用 impl 与 fixture，记录旧断言覆盖；设置可使用当时有效的共同调用，13 与本票互不虚设 blocker，后完成者适配实际现状。
- [ ] 更新源码守卫与实际会话 spec，运行无默认特性的完整交互测试及默认特性设计验证、cargo xtask gate、cargo xtask polish，不改快照接受行为变化。

## 不做会怎样

无默认特性只能验证部分状态方法，真正业务协调仍藏在终端 adapter；入口瘦身会停留在搬函数，而不是形成可独立受验的交互 seam。
