# 09: 输出、缓存、记录与编解码归位

**What to build:** 输出容器、当趟缓存、记录及编解码实现归入 processing 的实际源码组织，继续提供相同输出字节、提交安全与内存预算行为。本票不重写幂等复用，也不改变记录格式或算法。

**Blocked by:** 02「processing 接管编译拥有权，保留临时根门面」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：2、5、10、11、35、72、76、78。

- [ ] 机械迁移输出容器、缓存、记录、解码与 PNG 编码；domain 提供共用页事实和限制时使用同一出处，不复制类型或常量。
- [ ] 保持目录／归档临时产物、借住范围、陈旧成员清理、透传及最终提交规则；不趁搬迁修复独立领域问题，不改变源库只读。
- [ ] 保持缓存预算、记账、溢写与析构；缓存仅拥有当趟分析产物，不接管上一趟输出句柄。
- [ ] 保持记录格式、产品身份、版本来源、参数哈希与源哈希作用域；坏页、残缺页及写出错误分类不变，旧输出比较策略留待 18 深化。
- [ ] 同步外置所属测试、测试专用 impl、辅助与真实归档夹具，按性质索引记录替换；核查开发用编码／归档写入特性不泄漏 release，PNG 保持唯一输出编码器。
- [ ] 同步更新源码扫描、依赖图、许可、路径消费者与 owning spec；运行输出、缓存、记录、编码字节及受影响交付脚本检查、cargo xtask gate、cargo xtask polish。

## 不做会怎样

真实读写与资源生命周期仍无法按职责定位，搬迁还可能改变记录身份、引入开发依赖或让缓存和上一趟输出混为一体。
