# 12: 中立共用设置贯通转换 CLI 与库调用

**What to build:** 转换 CLI 与直接库调用者首先使用 processing 的同一套中立可选设置、默认与校验解析。可保存值保留“没说”，有效值才补默认；既有预设和会话可通过临时适配继续工作，但不能另留一套默认权威来源。

**Blocked by:** 02「processing 接管编译拥有权，保留临时根门面」。

**Status:** ready-for-agent

**规格覆盖：** task-ddd-reorganization；用户故事：37、38、39、40、41、44、46、47、78。

- [ ] 提供不含 clap、TOML 或终端类型的可选设备／处理设置与按用途解析；转换 CLI 和直接库调用贯通这套生产 interface，而非只增加无人消费的新 module。
- [ ] 保留未指定、显式默认、false、提白 0 和字段覆盖的差别；路径、输出、运行模式、metadata、进度及报告折叠不进入可保存设置。
- [ ] 将默认与共用校验集中到 processing；对未迁移的预设／会话调用者使用窄临时适配，不复制解析实现。13 完成其余入口迁移，24 清除已无调用者的过渡设施。
- [ ] 保持转换 CLI 的显式参数优先于已校验预设、再优先于默认，以及多个非法输入时的既有首错顺序；允许分阶段校验，不先全量解析改变诊断时机。
- [ ] 同步外置和替换本票测试，使用明确非默认 fixture 值；经真实 CLI 进程与直接库 interface 验证设置组合、stdout/stderr、首错及无参分派不变，按性质索引记录覆盖。
- [ ] 同步更新相关源码守卫、文档与实际职责 spec，运行聚焦设置／CLI 检查、cargo xtask gate 与 cargo xtask polish。

## 不做会怎样

共用规则仍寄居某个 adapter，库调用者不得不重建默认和请求装配；单独新增设置类型而没有真实消费者也不会产生 leverage。
