# 全项目 DDD 重组：三 crate 与六项职责深化

Status: ready-for-agent

## Problem Statement

维护 tonefit 的一项能力，往往需要跨平铺的文件、入口私有规则、处理管线与会话状态追踪同一条知识。生产文件混有测试、夹具和测试专用辅助实现；现有文档上的职责划分未充分变成编译依赖与可见性约束。只缩短 main 或移动目录，不能消除这些维护负担。

用户需要在不改变漫画适配结果和使用方式的前提下，对全项目进行领域驱动的结构调整：测试实现严格分文件，领域能力可导航，共用页处理、设置、会话交互与幂等复用形成具有 depth 的 module。六个方向全部属于本规格，不是候选菜单。

## Solution

以现有领域语言组织恰好三个运行时 crate：领域计算、处理编排与真实读写、命令行与会话所在的根程序。用单向依赖与窄 interface 约束协作，保持既有四道产品 seam，而不为每个 module 新造测试端口。

测试与生产实现独立文件、就近装配；共享夹具只复用测试源码。结构深化与测试替换同步进行，逐项说明旧断言的新覆盖。CLI、报告、预设、输出页、记录与幂等行为保持；公共 Rust 调用允许重整。

## User Stories

### 全项目结构与兼容

1. 作为项目维护者，我希望六个方向全部完成，以便这次重组不退化成仅清理 main。
2. 作为项目维护者，我希望按页、判定、设备、卷处理等领域能力导航，以便从业务问题直接找到拥有该规则的 module。
3. 作为项目维护者，我希望运行时代码分为三个 crate，以便依赖方向由编译器约束而非只靠约定。
4. 作为领域规则维护者，我希望领域计算不依赖终端、运行报告或读写编排，以便规则可独立理解和验证。
5. 作为处理编排维护者，我希望真实读写与卷生命周期有明确拥有者，以便领域规则无需认识磁盘与确认等待。
6. 作为界面维护者，我希望 CLI 与会话是同级 adapter，以便任一端都不依赖另一端的入口实现。
7. 作为库调用者，我希望既有四道产品 seam 的能力仍然可用，以便内部拆包不取消处理、画质分和两件量具。
8. 作为库调用者，我接受公共 Rust 调用的调整，希望新的 interface 显式表达领域能力，以便不再学习平铺的内部细节。
9. 作为命令行使用者，我希望程序名、参数、无参数启动和退出方式不变，以便已有使用习惯与脚本继续有效。
10. 作为漫画库持有者，我希望源库继续只读，以便结构调整不增加源文件风险。
11. 作为输出使用者，我希望输出页的像素、编码字节和记录保持既有规则，以便适配效果与上一趟依据不因搬迁变化。
12. 作为项目维护者，我希望构建与验收命令保持有效，以便拆 crate 不要求另学一套日常入口。

### 生产与测试分离

13. 作为代码阅读者，我希望生产文件中没有测试用例实现，以便定位实际处理逻辑时不被长断言淹没。
14. 作为代码阅读者，我希望测试专用 impl、辅助函数与夹具也外置，以便分离不只是移动测试标记。
15. 作为测试维护者，我希望私有测试继续访问所属 module 的私有实现，以便无需为测试扩大生产 interface。
16. 作为测试维护者，我希望跨 sibling 的测试辅助只在测试构建中受限可见，以便测试装配不变成运行时能力。
17. 作为测试维护者，我希望跨 crate 公共夹具只共享测试源码，以便既保持单一出处又不增加夹具 crate。
18. 作为领域测试维护者，我希望纯像素夹具不依赖处理编排，以便测试也不制造反向依赖。
19. 作为重构执行者，我希望同步迁移并替换测试，以便新 module 的 interface 成为实际测试表面。
20. 作为审查者，我希望每条被替换或删除的旧断言都有新覆盖或明确理由，以便测试全绿不能掩盖失去的守卫。
21. 作为审查者，我希望测试数量可以合理变化但性质覆盖不缩水，以便不为保住数字留下重复的实现细节测试。
22. 作为规则维护者，我希望新 crate 与共享测试源码仍被相应单一出处守卫检查，以便移动目录不能躲过重复规则检测。

### 共用页处理与候选规则

23. 作为领域维护者，我希望面板与尺寸贴合检查共同决定的可行候选只有一个出处，以便硬约束不在转换与样张之间漂移。
24. 作为领域维护者，我希望覆盖裁剪与覆盖顶死事实归领域 module，以便纯判断不夹带路径和错误文案。
25. 作为转换使用者，我希望页处理拥有解码、几何、参照和评估的完整次序，以便入口不能误拼步骤。
26. 作为样张使用者，我希望样张与转换消费同一评估实现，以便样张确实反映转换会写出的页。
27. 作为样张使用者，我希望仍能看到全部可行候选，以便覆盖项只影响判定而不隐藏比较对象。
28. 作为领域维护者，我希望单页候选恰剩一项不自动被解释成覆盖顶死，以便判定理由保持真实。
29. 作为默认逐页处理使用者，我希望每页判完当场编码且参照不入缓存，以便保持现有工作量与缓存语义。
30. 作为整卷统一灰阶使用者，我希望需要整卷判定的参照保留到汇总以后，以便统一档位仍依据全卷事实。
31. 作为命令行预览使用者，我希望预览不为输出编码、也不做没有消费者的彩色缩放，以便不引入无用工作。
32. 作为样张使用者，我希望全部候选编好后才开始落盘，以便前置拒绝不会留下半叠新样张。
33. 作为跨页素材使用者，我希望源页只解码一次、输出页按阅读顺序交付，以便重组不改变页序或重复昂贵工作。
34. 作为处理维护者，我希望页结果拥有跨环节需要的产物，以便确认等待不会借用已失效的解码缓冲。
35. 作为坏页素材使用者，我希望坏页占位、残缺页处理与隔离仍由既有卷规则决定，以便统一页处理不抹平这些差别。
36. 作为画质维护者，我希望落格、几何贴合与提白关闭时的用途差异保持，以便结构调整不改变既有画质决定。

### 共用设置与结果

37. 作为 CLI、预设与会话维护者，我希望共用设置由独立 module 拥有，以便任一 adapter 都不是其他端的规则仓库。
38. 作为直接库调用者，我希望使用相同的默认与校验解析，以便不用重写一套请求组装规则。
39. 作为预设使用者，我希望“没说”与“显式指定默认值”继续有别，以便将来默认值改变时预设含义不漂移。
40. 作为预设使用者，我希望 false、提白 0 与显式覆盖被完整保留，以便关闭功能不会被当成未指定。
41. 作为命令行使用者，我希望显式参数优先于预设、预设优先于默认，以便已有参数组合仍得到同一设置。
42. 作为预设使用者，我希望只有显式点名时 CLI 才读取预设，以便未点名的配置不会暗中影响处理。
43. 作为预设使用者，我希望点名预设中的非法值仍被校验，即使稍后被覆盖，以便坏预设不会被悄悄接受。
44. 作为命令行使用者，我希望多个输入同时非法时首先看到的错误与原来一致，以便共享校验不改变诊断先后。
45. 作为量具使用者，我希望灰阶测试图与样张只消费各自所需设置，以便无关卷选项不被错误地带进量具行为。
46. 作为处理使用者，我希望路径、输出和每趟运行控制继续不进入可保存设置，以便预设不会写入另一趟的位置。
47. 作为会话维护者，我希望共用 Profile 解析与退出规则不再寄居 main，以便会话不回调入口私有实现。
48. 作为脚本使用者，我希望拒绝、隔离、卷失败及无法访问的退出优先级保持，以便脚本继续分得清结果。

### 会话交互与终端 adapter

49. 作为会话维护者，我希望完整输入编排在不带 tui 的构建中仍受验，以便终端特性不遮住业务交互。
50. 作为会话测试维护者，我希望给定输入、时刻与窗口尺寸即可驱动交互，以便复现场景不依赖真实终端。
51. 作为会话使用者，我希望起跑、两级停止和确认仍经同一运行协调，以便拆 module 不改变控制语义。
52. 作为会话使用者，我希望预览后接着写出仍是同一次运行，以便缓存和分析结果不用重做。
53. 作为会话维护者，我希望运行投影拥有清点、确认、卷状态与报告事实，以便界面不复制另一套运行真相。
54. 作为会话维护者，我希望交互状态只拥有视图、焦点、光标、编辑和搜索状态，以便阶段与焦点两维保持清楚。
55. 作为交互维护者，我希望交互读取只读运行快照，以便绘屏和导航不攥住可变投影锁。
56. 作为会话使用者，我希望开始新一趟或答完确认后读取正确的新状态，以便快照不显示上一趟或过期确认。
57. 作为会话使用者，我希望清点零卷仍能区分已完成与中途停止，以便备注和问题跳转不丢失。
58. 作为交互维护者，我希望交互直接协调明确的运行与预设依赖，以便不必再维护通用动作协议。
59. 作为会话使用者，我希望预设读写、量具、搜索与导航仍可正常执行，以便终端瘦身不删掉现有能力。
60. 作为会话使用者，我希望等待确认、线程收尾、磁盘动作与绘屏都不占用投影锁，以便界面不因重构挂住。
61. 作为会话使用者，我希望整屏文字、样式、命中区域与输入批处理行为保持，以便结构变化不改变交互表现。

### 幂等复用与旧输出

62. 作为重复转换使用者，我希望幂等复用拥有比较规则与旧输出资源，以便命中结论和可读产物保持一致。
63. 作为卷编排维护者，我希望只消费整卷命中、按页复用或不复用及其理由，以便不自行重建跨页一族。
64. 作为重复转换使用者，我希望页级与卷级源哈希作用域继续互斥，以便另一种依据不能错误地命中。
65. 作为跨页素材使用者，我希望留下与重做仍按完整一族决定，以便不会只保留跨页的一半。
66. 作为大卷使用者，我希望比较时不提前读取全部留下页负载，以便句柄管理调整不变成全量内存加载。
67. 作为重复转换使用者，我希望留下的页在写出时原样搬运，以便像素、记录和编码字节不被重新生成。
68. 作为 Windows 使用者，我希望旧输出句柄在最终提交前释放，以便已经写好的临时产物能正常替换旧输出。
69. 作为处理维护者，我希望失败、取消与停止路径也正确释放旧输出，以便资源安全不只成立于正常结束。
70. 作为重复转换使用者，我希望无法打开旧输出可视为不命中、写出留下页失败仍是卷失败，以便重构不偷偷改变错误分类。
71. 作为混装目录使用者，我希望借住的卷、陈旧成员与多余成员检查保持，以便复用不会覆盖别卷或留下错误产物。
72. 作为缓存维护者，我希望上一趟输出与本趟缓存寿命分开，以便复用不会破坏内存预算与溢写规则。

### 构建、证明与交付

73. 作为项目维护者，我希望三个运行时 crate 的测试都真正执行，以便根测试全绿不掩盖依赖包漏测。
74. 作为剖面工具使用者，我希望 profiling 的阶段口径保持且不反向进入 domain，以便拆包不混淆卷计时、阶段计时与窄计数器。
75. 作为规则维护者，我希望源码位置变化同步更新守卫与真实平台证明，以便搬迁不能让验证静默失效。
76. 作为交付维护者，我希望许可、版本、依赖特性和最终归档验证仍覆盖正确包图，以便拆 crate 不改变产物可信度。
77. 作为跨平台使用者，我希望四个平台都完成实际质量与归档运行验证，以便本机通过不冒充其他平台可用。
78. 作为后续执行 agent，我希望现行架构与 module spec 随实现同步更新，以便下一次修改不重新推导已经确定的拥有关系。

## Implementation Decisions

### 全局约束与依赖

1. 六项全部交付：全仓生产／测试分离、领域组织、页处理深化、共用设置与结果、非终端会话交互、幂等复用深化。目录搬迁或薄转发不单独构成完成；module 的 depth 必须表现为调用者不再掌握其内部协作知识。
2. 恰好三个运行时 crate：根程序 tonefit、tonefit-processing、tonefit-domain。根程序依赖 processing，processing 依赖 domain；根程序可直接使用 domain 的领域值。禁止反向依赖与新增 common、contracts 或夹具 crate。xtask 与交付工具不进入运行时依赖。
3. domain 拥有像素与尺寸、页变换、量化、候选纯规则、画质分、逐页／整卷判定、面板与 Profile、标定纯绘制。processing 拥有解码调用、页评估协作、卷编排、范围清点、读写、缓存、记录、复用、设置解析、报告事件及量具写出。根程序拥有两种 adapter、预设持久化、退出规则和呈现。
4. 只按真实生产协作公开跨 crate interface，不把原私有 module 批量公开。domain 不接收整个 Request，不依赖运行报告、事件、终端或文件系统。救回事实和几何／解码共用限制由最低共同拥有者提供，常量只有一个出处。
5. 四道产品 seam 的能力保持：domain 导出 score；processing 导出 run、write_calibration_chart、write_proof。必要的跨 crate 计算 interface 不是新增产品入口。原公共 Rust 导出形式不要求兼容。
6. 保持程序名、CLI、预设格式、报告与退出语义、源库只读、PNG 唯一输出、输出页及记录的既有字节规则。拆包不改变应用版本来源、参数哈希或源哈希作用域，不借结构调整升级算法或依赖。

### 测试组织

7. 全仓自有 Rust 生产文件仅保留必要测试装配声明；测试用例、测试专用 impl、辅助函数与夹具全部外置。私有测试作为所属 module 的测试子模块装配；跨 sibling 辅助仅在测试构建受限可见。真实公共构造能力不因测试使用就被错误删除。
8. 跨 crate 公共夹具共享测试源码，不新增夹具 crate。纯领域夹具不得依赖 processing；文件、归档和运行夹具按依赖分开。场景数据与快照仍来自既有单一出处。
9. 按 Q11 同步深化并替换测试，不采用“先完整保留所有旧测试、以后再精简”的策略。每项改写或删除说明原断言的新覆盖或删除理由，不能用通过数量代替等价证据。

### 页处理与候选

10. domain 接收面板、尺寸贴合、覆盖和必要页分组事实，给出可行候选、覆盖后候选、裁空原因和顶死事实；processing 补路径、拒绝标记、诊断文案与执行时机。默认逐页和整卷统一灰阶的顶死时点不合并。
11. processing 的页处理 module 拥有从源字节到解码、识色、几何、参照与评估的完整次序。转换和样张按用途消费同一评估及物化能力，不各自拼流程；结果为按阅读顺序的页事实与拥有型暂存产物，不跨确认点借用已失效缓冲。
12. 保持真实工作计划：默认逐页与开卷前顶死当场编码、缓存存字节；需要等整卷的路径缓存参照、汇总后编码。命令行 DryRun 不为输出编码、无消费者的彩色缩放不做。会话中可接着写出的预览仍按既有同次运行与确认机制处理，不能与纯 DryRun 混为一条储存策略。
13. 样张评估全部可行候选，覆盖只裁判定候选；全部编好才开始建目录和写出。不要给 Mode 新增 Proof。提白关闭时的量测用途差异、源哈希的实际转换依赖、单次解码及落格保持。
14. domain 页规则不拥有输出位置、缓存槽、坏页占位、记录或报告组装。卷级汇总与生命周期由处理编排拥有；确认点报告和最终报告共享同一拼装规则。

### 共用设置与结果

15. processing 的共用设置 module 接收不含 clap、TOML 或终端类型的中立可选设置，统一解析默认与校验，供 CLI、会话、预设适配与直接库调用者使用。可保存值保留未指定，只有按用途解析有效值时填默认。
16. CLI 解释显式参数与启动分派，预设 adapter 解释格式和持久化，会话编辑设置。优先级保持显式 CLI > 已校验预设 > 默认；保留 false、0 和显式默认。路径、输出、mode、metadata、进度和报告折叠不因此进入可保存设置。
17. 无参分流、退场开关、clap 冲突、样张卷级参数拒绝、预设读取及首错次序保持。仅显式点名才读预设，点名预设整份校验先于覆盖；随后按用途消费设置，不错误验证该用途不消费的无关有效选项。面板位深拒绝与逐页抖动撞门拒绝不提前合并。
18. 根程序的共用结果 module 拥有报告到进程退出码的映射，CLI 与会话共用。processing 保留拒绝与卷失败分类，不替根程序决定进程退出。main 只负责启动装配，不再寄居共用 Profile 与结果规则。

### 会话交互

19. 非终端交互 module 接收明确的运行与预设依赖，以及给定输入、时刻、窗口尺寸与当前目录，直接协调动作；不新增通用动作／结果协议。完整输入链在无默认特性下编译与受验。
20. 运行投影拥有清点、进度、确认、卷状态、摘要与报告；交互状态拥有编辑值、视图、焦点、光标和搜索。交互与绘屏读取统一只读快照，不复制运行事实，不持有可变投影守卫；运行身份或确认改变后刷新快照。
21. 运行事件与明确运行操作管理投影写入。等待确认、join、预设读写、量具调用与绘屏均不持投影锁；保持确认更新、释放锁及唤醒顺序。终端 adapter 只负责终端生命周期、原始输入与键码、尺寸、交互调用、绘屏及命中区域回填。
22. 两个视图、阶段与焦点两维、按键表与措辞单一出处、清点完成的显式事实、输入批处理、自动滚动和设计快照契约保持，不借深化重新设计界面。

### 幂等复用

23. 复用 module 同时拥有比较策略、跨页一族、留下页与旧输出访问，私有持有句柄；对编排给出整卷命中、按页复用或不命中、理由、重做位置和留下页尺寸／长度，不暴露旧容器资源。
24. 比较只取必要依据与长度，写出时才读留下页负载并交给输出容器。正常结束以拥有型结束操作释放旧输出后再提交；失败、停止和取消也由明确拥有权与析构保证释放，不依赖正常路径手动 drop。
25. 记录 module 保留格式、哈希与记录解析；输出容器保留临时产物、字节写入、借住范围、陈旧成员清理和最终提交；缓存保留本趟预算、记账与溢写；卷编排只管环节次序。旧输出不可读可不命中，写出留下页失败仍是卷失败，不能回退重算。

### 构建与文档

26. 根构建及 gate/polish 入口保持，测试执行显式覆盖三个运行时 crate，不再假定测试结果按 lib/bin 次序返回。三构建仍隔离 target；tui 只控制真实终端，profiling 转发 processing 并包裹领域调用，dev 编码特性不泄漏到 release。
27. 源码扫描、完整测试名、Windows 真实守卫证明、交付包图、许可、版本与路径消费者在对应迁移切片同步适配。文档改为新的真实职责与依赖，记录必要 ADR；不把尚未迁移的目标写成已经实现，也不搭便车改写领域词义。

## Testing Decisions

### 已确认的高层 seam

1. 处理、几何、页工作计划、幂等复用、失败与资源生命周期优先经 run 的输入、报告、事件和真实产物观察，不直接断言内部 helper 的调用组合。
2. score 保留数值与性质 seam；write_proof 以 run 的产物作字节神谕；write_calibration_chart 验证量具产物与其独立职责。四道 seam 有不同用途，不强并成一个入口，也不为每个新 module 增加测试端口。
3. CLI 经真实子进程验证参数、无参分流、错误先后、stdout/stderr 与退出码。会话经完整非终端输入链验证协调，再以设计快照逐格验证绘屏；不让业务交互覆盖只存在于 tui 构建。
4. crate 依赖、feature、测试实现隔离和单一出处以编译、目标清单与源码守卫验证；这类结构契约不能仅凭产物行为证明。仅高层不可观察的“工作没有发生”与资源约束，沿用窄计数器、持锁哨兵及真实平台守卫，不造新生产测试后门。

### 好测试与替换规则

5. 测试通过所属 module 的生产 interface 断言可观察行为；夹具点名取值，不借移动的默认值。迁移旧测试时按 Q11 同步替换，逐项记录旧性质与新覆盖，不要求数量固定，不靠删守卫或排除新目录变绿。
6. 守卫按反运行并确认确由目标断言变红，编译失败或零测试不算守卫命中。Windows 证明继续修改真实守卫、观察真实断言失败、按原字节恢复后复绿；模拟 adapter 不能冒充真实平台证据。
7. 输出等价涵盖逐页 PNG、像素、记录、判定与预设语义；实际耗时不冻结。输出归档已有时间戳不可复现的限制不在本次修复，不要求两趟整个归档逐字节一致。不得重录黄金产物或改设计快照来接受实现差异。
8. 聚焦测试覆盖逐页／整卷、灰度／彩色、完整／残缺／坏页、跨页、覆盖、纯 DryRun、可确认后续写出及样张；覆盖整卷命中、按页复用、零留下页、跨页一族、多余成员、借住目录、读取失败与取消。资源测试验证延迟负载读取和提交前释放，不只看返回枚举。
9. 设置测试覆盖未指定、显式默认、false、0、字段覆盖、被覆盖的非法预设、用途选择和多个非法输入首错。交互测试覆盖新旧运行身份、确认更新、零卷清点、两级停止、预设与量具、搜索导航、只读快照及锁外等待。

### 既有先例与全量验收

10. 既有先例：`tests/pipeline.rs`、`tests/proof.rs`、`tests/golden.rs` 提供运行行为、落格及字节神谕；`tests/idempotency.rs`、`tests/resume.rs`、`tests/events.rs`、`tests/stop.rs` 提供复用、确认、事件与停止；`tests/preset.rs`、`tests/exit_code.rs`、`tests/session.rs` 提供进程与设置行为。沿用这些性质，不绑定迁移后的文件布局。
11. 会话已有场景数据、设计快照、交互期望屏及 TestBackend 逐格比对是呈现先例；单一出处扫描和 Windows 证明是结构与平台先例。纯像素与真实文件夹具继续使用，临时目录与给定时刻替代真实终端，线程／读写动作不伪称纯函数。
12. 每个独立迁移切片运行聚焦验收，收尾执行 `cargo xtask gate` 与 `cargo xtask polish`；三运行时 crate 的测试和无默认特性交互测试须实际列入。最终执行设计导出一致性、JS 与交付 Python 测试、四平台质量及最终归档真实运行验证。未提供真实素材按原机制明示缺测，不能算实测通过。

## Out of Scope

- 仅修 main、仅搬目录或只完成六项中的部分。
- 新功能、新输出编码器、算法与阈值重标定、画质政策、跨页／裁切规则或幂等语义变化。
- 为 DDD 强造实体、聚合根、Repository、可插拔编码器或通用文件系统 trait；PNG 唯一实现保持。
- 第四个运行时 crate、公共 contracts/common 包、夹具 crate或通用会话动作协议。
- 改变 CLI、报告措辞、预设格式、退出语义、两个视图与既有交互设计。
- 维持旧公共 Rust 导出路径和调用形式的兼容承诺。
- 为测试扩大生产可见性、添加生产后门、统一忽略测试源码或跳过既有守卫。
- 修复已知的跨运行归档时间戳不可复现、临时目录硬杀清理、混装目录非事务收尾等独立领域问题。
- 无关依赖升级、交付策略重做、vendor 整理或其他并行工作的接管。
- 本轮创建实施 tickets 或开始代码迁移；后续由 to-tickets 根据本规格拆票。
