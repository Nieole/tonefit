# 全项目 DDD 重组：六项设计收敛稿

## 状态与依据

已获用户最终确认，六项 grill 完成，尚未授权或开始源码实施。用户已定约束见 [grill.md《已确认的全局约束》及《设计树》](grill.md)。本稿给出这些约束下的技术方案，不把候选类型名、目录名或函数形状当成新增领域术语。

现行行为依据仍是 `GLOSSARY.md`、`architecture.md`、`src/specs/` 与相关 ADR；本稿不改变算法、模式含义、错误处置或产物格式。本稿已综合为 [spec.md](spec.md)，后续 to-tickets 以规格为需求与决定出处；本稿保留为设计来源，不另维护第二份规格。旧 HTML 报告仅供候选探索。

## 01 生产与测试文件分离

### interface 与组织

- 生产文件只保留必要的测试装配声明。测试用例、共享夹具、测试专用 impl 和辅助函数放独立文件。
- 外置私有测试仍作为所属 module 的子模块编译；跨 sibling 的测试辅助只在测试构建中受限导出，不扩大生产 interface。
- 共享测试源码按依赖拆分：纯像素与领域值夹具不能依赖 processing；真实目录、归档与运行夹具可以依赖 processing。场景数据与设计快照保持原有权威来源。
- 已属公共构造契约的 `Score::from_value`、`Salvage::from_share` 不因被测试使用就自动判成测试后门；是否保留按真实生产 interface 判断。

### 验收

测试与结构同步迁移、同步替换（Q11）。逐项列出旧断言、新覆盖和删除理由；不要求数量恒定，但字节神谕、落格、窄计数器、停止与确认、幂等、设计验收等性质不得失守。

单一出处扫描逐条区分生产出处与测试源码，不统一排除测试文件。新 crate 与共享测试源码必须进入对应规则的扫描范围。

## 02 三个运行时 crate 与领域能力

### 依赖图

- 根程序 `tonefit` 调用 `tonefit-processing`，也可直接使用 `tonefit-domain` 的领域值。
- `tonefit-processing` 依赖 `tonefit-domain`。
- domain 不反向依赖 processing、根程序、报告或运行事件；processing 不依赖 CLI、TOML 预设表示或终端。
- xtask、交付脚本与 vendor 不进入该运行时依赖图。不新建 common、contracts 或夹具 crate。

### 技术归属

- domain 按页变换、判定、设备能力组织：像素与尺寸、裁切拆分、缩放提白、量化、候选纯规则、画质分、逐页与整卷判定、面板与 Profile，以及标定图纯绘制。
- processing 拥有解码器调用、完整页评估协作、卷编排、范围清点、读写、缓存、记录、复用、设置解析、报告事件及量具写出。
- 根程序拥有命令行适配、预设持久化、进程退出规则、报告呈现和会话。

解码调用留在 processing 是实现选址，不把解码错误、工作用途与报告依赖推进 domain。现有 `crop/spread` 使用的救回事实可归 domain；几何与解码共用的内存上界仅保留一个出处，processing 引用它，不能复制数值或形成反向依赖。

`Request`、运行 `Mode`、`Report`、`Event`、`Instruction`、`ProgressSink`、`Proof`、`CacheBudget`、`IoPlan` 属于 processing。`GeometryGate` 属于 domain。domain 函数不接收整个 `Request`。

### interface 与验收

四道产品 seam 保持：domain 的 `score`；processing 的 `run`、`write_calibration_chart`、`write_proof`。跨 crate 必需的生产计算操作显式公开，但不将整个原私有 module 无差别公开，不承诺原平铺导出形式兼容。

根 build 与既有 gate/polish 命令保持；验证明确覆盖三个运行时 crate，而不只测根程序。根 `profiling` 转发 processing，掐表包裹 domain 调用；`tui` 不影响非终端交互。版本来源、参数哈希与 dev 编码特性不因拆包悄悄变化。

## 03 页处理：一个顺序，按用途消费

### domain interface

输入为面板能力、尺寸贴合事实、候选覆盖及必要页分组事实；输出为可行候选、覆盖后候选、结构化裁空原因、覆盖顶死事实。

纯规则不带路径、拒绝标记、建议文案、运行报告或 I/O。样张展示候选与判定候选有别；单页集合恰为单例不自动等于覆盖顶死。默认逐页与整卷统一灰阶的顶死时点不合并。

### processing interface

一个页处理 module 拥有解码到评估的完整次序；调用者给有效页设置、源字节、用途与明确计数依赖，得到按阅读顺序的页事实与拥有型暂存产物。

用途区分转换与样张；转换继续使用现有模式，不给 `Mode` 新增 Proof。用途控制必要工作，不强迫所有用途统一编码：

- 默认逐页与开卷前顶死：判完当场编码，缓存存字节。
- 整卷统一灰阶且未提前顶死：缓存存参照，卷判定后编码。
- 预览：不为输出编码；彩色分支不做没有消费者的缩放；缓存沿既有记账语义。
- 样张：评估全部可行候选，覆盖只影响判定；全部编好再建目录写出。

提白关闭时量不量纸白仍按用途决定；源哈希作用域由真实转换依赖决定，不能从预览的缓存计划推导。

暂存结果不借用已经释放的解码缓冲。处理策略、记录上下文及候选产物物化在页 module 的 interface 内协作；转换和样张不再各自重排步骤。卷级汇总、输出位置、坏页占位、记录和报告组装不下沉为 domain 页规则。

### 验收

覆盖两种判定路径、预览、覆盖顶死、彩色与灰度、残缺页和跨页。转换与样张共享评估；既有逐字节神谕、单次解码、落格、参照缓存计数及确认前不写出继续成立。

## 04 共用设置与结果规则

### settings interface

processing 的共用设置 module 接收中立可选设置，不含 clap、TOML 或终端类型。可保存设置保留“没说”；有效设置才填默认。直接库调用者与两个 adapter 使用同一套解析与校验。

预设 adapter 负责格式和文件；CLI adapter 负责显式参数及启动分派；会话负责编辑。路径、输出、进度、metadata、运行模式和报告折叠不因本次重组混入可保存设置。

### 错误与用途

- 无参数分流仍先于 clap；退场开关、clap 冲突和样张不接受的卷级参数按既有顺序处理。
- 仅显式点名才读取预设；点名的预设整份先校验，不能因某字段被 CLI 覆盖而忽略其中非法值。
- 优先级保持显式 CLI > 已校验预设 > 默认，保留 `Some(false)`、提白 0 和显式默认值。
- 解析接口允许分阶段校验，保住现有首错顺序；不能先批量解析所有字段而改变用户首先看到的错误。
- 有效设置按用途解析，灰阶测试图不消费无关页选项，样张不消费无关卷设置。面板位深拒绝与真实页几何上的抖动拒绝不合并时机。

根程序的共用结果 module 拥有退出常量与报告到进程退出码的映射；CLI 与会话共用。processing 仍区分拒绝与卷失败，但不替程序决定进程退出。

### 验收

以设置组合、非法输入组合与错误先后验证同源解析；预设格式、往返、显式默认值、无参启动和退出码优先级保持。main 不再充当共用规则的拥有者。

## 05 会话：交互协调不在终端 adapter

### interface 与拥有关系

交互 module 接收给定输入、时刻、窗口尺寸、当前目录、运行和预设依赖，直接协调具体动作；不增加通用动作／结果协议。

运行投影拥有清点、进度、确认、卷状态、摘要和报告事实；交互状态拥有编辑值、视图、焦点、光标、搜索与显示状态。两者不复制同一份运行事实。

建议沿现有 `Glimpse` 提供只读快照，交互与绘屏不持有可变投影守卫。起跑或答话导致运行改变后刷新快照；不以延迟快照掩盖确认状态或运行身份变化。

写投影仍由运行事件与明确运行操作管理；锁内不等确认、不 join、不读写预设、不调用量具、不绘屏。确认更新与唤醒维持正确顺序。

终端 adapter 仅负责终端生命周期、原始输入读取与键码翻译、取尺寸、调用交互、绘屏及命中区域回填。

### 验收

完整非终端输入链在无默认特性下编译与受验，包括线程、停止、确认、预设、量具、搜索与导航；使用真实临时目录和受控运行，不声称所有动作是纯函数。

整屏与样式逐格验证保持；零卷清点、确认等待、运行身份变更、自动滚动、输入批处理与锁外绘屏继续有守卫。

## 06 幂等复用：规则和资源共同拥有

### interface 与生命周期

复用 module 私有持有旧输出访问与句柄。对调用者给出整卷命中、按页复用或不复用的结论，以及理由、重做位置、留下页的尺寸与长度；不交出旧容器内部资源。

比较时只读必要依据与长度，整页字节留到写出时才读取。写出留下页时，由复用 module 从旧输出读取并交给输出容器，不要求卷编排重复识别成员与来路。

写出结束后以拥有型结束操作释放旧输出，再允许最终提交。比较失败、取消和错误路径也须正确析构；不是只在正常路径手动 drop。

### 与其他 module 的分工

- 记录 module：格式、参数与源哈希的表示和计算、记录解析；复用 module 使用这些事实决定是否命中，不复制格式实现。
- 输出容器 module：临时容器、字节写入、借住范围、陈旧成员清理与提交机制；不重新决定幂等命中。
- 缓存 module：本趟分析产物的预算、记账与溢写；不接管上一趟输出句柄。
- 卷编排：决定比较、分析、确认、写出与提交的顺序，不管理旧输出内部句柄。

### 验收

整卷与页级作用域互斥、跨页一族完整性、留下页原样字节、零留下页、多余成员与借住目录均保留覆盖。

旧输出或依据不可读取可以不命中；已决定留下的页在写出时读失败是卷失败，不偷偷重新计算。Windows 最终改名前释放句柄须通过真实平台守卫，不能用本机模拟冒充。

## 共同完成标准

- 六项必须全部完成；拆 crate 和搬文件不能代替 depth 提升。
- domain 不需要运行配置与副作用知识；转换与样张不需要重拼页顺序；卷编排不需要旧输出资源细节；终端不需要交互编排知识。
- 每项 interface 都有对应行为测试，测试覆盖去向明确。
- 现有源码扫描与 Windows 证明路径在对应切片同步适配，不留到最终才修；新目录不得成为守卫盲区。
- 架构图、owning spec 与必要 ADR 在方案批准后按事实归属更新，不提前把尚未实施的结构写成已成立事实。
