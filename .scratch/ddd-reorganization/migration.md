# 全项目 DDD 重组：迁移与验收计划

## 适用范围

用户后续按 to-spec → to-tickets 流程推进。本文件是基于已确认 [design.md](design.md) 的参考拆解，用户选择记录在 [grill.md](grill.md)；它不是已批准的 spec、tickets 或执行计划，不授权或执行源码迁移。正式范围、验收与拆票由后续流程确定。

下列是有序切片，不承诺每片只有一个提交。实现时再按可独立构建、独立验证的最小增量拆提交。每片同步迁移或替换所属测试（Q11），而非最后统一清理；不把拆包、深化、改算法和依赖升级混成一次变化。

## 通用规则

- 开工先确认当前提交、工作树及并行任务归属，不沿用先前的脏改动判断；不回退别处的工作。
- 每个测试替换列明旧断言、新覆盖、删除理由及所测 feature。外部素材缺失如实报告，不记成通过。
- 每次移动同步改对应源码扫描、测试名、证明脚本、路径消费者与文档引用；不等最终才修。
- 每个切片先跑聚焦测试，收尾跑 `cargo xtask gate` 与 `cargo xtask polish`，目标目录仍按现行闸门约定。
- 原有架构 spec 按实际迁移范围更新，不提前宣称三个 crate 已全部落地。架构决定在首次实施切片记录 ADR，行为不变量不重开。

## A 建立当前基线与测试覆盖映射

范围：当前运行、测试、三构建闸门、设计验收与交付命令。

- 记录当前 HEAD、应用版本与工作树归属，保存实际可执行的验证命令与测试清单。
- 建立六项验收索引：旧断言 → 新的所属 module／interface → 保留的性质。索引随每片替换更新。
- 保存黄金快照、样张字节神谕、记录参数与版本来源、预设格式及设计快照的现行证据；不重录快照来接受差异。
- 先准备外置测试的装配与扫描识别方式。扫描规则分别处理生产与测试源码，不统一忽略测试文件。

通过条件：三构建与 polish 的真实状态已知；设计与交付验收的实际状态已知。任何失败须区分既有问题与改动引入，不能静默跳过。

## B 抽出领域能力与候选纯规则

范围：新 domain crate、页事实、几何、变换、量化、画质分、判定、面板与标定纯绘制。

- 先迁共用值与页限制，解除几何／裁切对解码器实现的反向依赖，再逐能力迁移算法与测试。
- 提取候选可行性、覆盖裁剪与顶死事实；processing 暂时所在的原根库继续承担拒绝路径与措辞。
- 按必要生产调用公开 interface；禁止批量把原私有 module 整体公开。
- 移动时保持计算顺序、浮点运算、默认与数值出处不变；无依据不改算法或升级依赖。

通过条件：领域测试、画质分性质、Profile、几何贴合、落格与样张神谕保持。domain 无根程序／processing 依赖，无文件系统或终端依赖。

## C 抽出 processing 并保住完整验证范围

范围：现根库的卷编排、解码调用、范围、读写、记录、缓存、报告、事件与量具写出；根包变为程序。

- 先迁职责，不借搬迁重排运行顺序；四道产品 seam 分别归 domain 与 processing。
- 同一可验证切片调整 workspace、锁文件、feature 转发与 xtask 包选择，确保三个运行时 crate 的单元测试确实执行。
- 解除测试汇总对“先 lib 后 bin”的次序假设；保留三种构建各自的 target 目录。
- 同步调整交付 helper 对包图、许可依赖、版本与源码位置的读取；移动 Place 时同步 exact 名字及真实守卫证明路径。
- 过渡根导出只在迁移期间存在，记录其后续删除位置，不建立长期空转发 module。

通过条件：根 `cargo build`、三闸门与 polish 均覆盖正确目标；`tui`、`profiling`、dev 编码特性没有泄漏或丢失。原事件、停止、确认、幂等、隔离与计时验收保持。

## D 统一共用设置并让 main 退回装配

范围：processing 设置 module、CLI 参数适配、预设模型、会话请求组装、根结果规则。

- 引入中立可选设置与按用途解析，保留“没说”、显式默认、false 与 0。
- 先使一条入口走新规则并验证，再迁移其他入口；过渡期间不形成第二份默认或校验权威来源。
- 预设读写仍在根程序；整份预设校验、覆盖顺序、按用途消费及首错顺序保持。
- 共用进程退出规则脱离 main；不把进程退出语义推进 processing。

通过条件：CLI、会话、预设及直接库调用同源解析；非法输入组合的首错、无参数分流、样张／标定用途及退出优先级不变。

## E 深化共用页处理

范围：processing 页评估、domain 候选规则调用、转换与样张消费者。

- 用一个 module 收拢完整评估次序及用途差异；调用端不再重排步骤。
- 暂存产物拥有其资源；默认逐页当场编码、整卷统一灰阶留参照、预览不编码、样张编全再落盘。
- 报告组装、坏页占位与卷级汇总留在对应拥有者，不用统一页模型抹平不同模式。
- 以 interface 行为测试替换内部拼接测试，记录覆盖去向。

通过条件：转换与样张逐字节神谕、单次解码、落格、提白关闭时用途差异、缓存窄计数器和确认前不写输出全部受验。

## F 深化幂等复用与旧输出资源拥有权

范围：复用比较、跨页一族、留下页、旧输出访问及与 sink 的协作。

- 复用 module 私有拥有旧容器，把结论、理由、重做位置和留下页事实交给编排。
- 保持延迟读取负载；写出时由复用 module 读留下页并交给 sink，不提前搬入全部字节。
- 以消费式结束和析构覆盖正常、失败与停止路径，确保最终提交前释放旧输出。
- 记录格式、容器提交、缓存溢写各保留原拥有者；不新增 Repository 或文件系统 trait。

通过条件：两种源哈希作用域、跨页一族完整性、零留下页、原样字节、多余成员、借住目录、读取失败分类均有测试。Windows 句柄释放由真实平台守卫证明。

## G 深化非终端会话交互与投影访问

范围：完整输入分派、运行协调、预设与量具动作、Live 只读访问、终端 adapter。

- 先提供受控只读投影访问，再迁完整非终端交互，不在交互状态复制运行事实。
- 交互直接协调明确依赖；不新增通用动作协议。运行变化后刷新快照，保留运行身份及确认状态一致性。
- 迁移相应测试并使其在无默认特性下实际运行；临时目录、给定时刻和受控运行代替真实终端。
- terminal 只保留终端生命周期、输入翻译、尺寸、调用交互与绘屏；绘屏的设计快照验收继续存在。

通过条件：起跑、两级停止、确认、预设、量具、搜索与导航均不依赖 tui；零卷清点、锁外等待／绘屏、输入批处理及逐格样式受验。

## H 全仓收尾、工具与交付验收

范围：尚未处理的内嵌测试、临时适配、spec 归属、构建与交付。

- 按 A 的覆盖映射确认所有自有 Rust 测试实现外置；共享源码没有把 processing 依赖反向带入 domain 测试。
- 删除已无调用者的临时转发与旧配置模型，检查公开 interface 没有因测试而膨胀。
- owning spec 贴近领域能力，移除旧单库拓扑与过时路径；词汇表只增加确实确定的新领域概念，不重写既有含义。
- 检查所有扫描、脚本、许可收集、包版本与证明脚本已覆盖新的源码与包图。

通过条件：三构建、polish、设计导出一致性与 JS 测试、交付 Python 测试均运行；四平台质量与最终归档真实运行完成。不能用本机检查代替平台证据，也不把未设置真实素材所得的跳过算成实测。

## 六项完成落点

- 01 测试分离：A 定覆盖，B–G 随切片迁移和替换，H 核对全仓。
- 02 领域组织与三个 crate：B、C 建立依赖方向，H 清理过渡与文档。
- 03 页处理深化：B 定纯规则，E 收拢协作与产物生命周期。
- 04 共用设置与结果：D 完成。
- 05 会话交互：G 完成。
- 06 幂等复用：F 完成。
