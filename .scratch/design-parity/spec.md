# design-parity — 设计稿说了算：新界面与设计稿还对不上的那三十来处，一次改齐

**Status:** ready-for-agent

## Problem Statement

`session-redesign` 把会话换成了新界面，验收是机械的：设计稿导出的整屏快照与交互期望屏，实现画出来要逐格相等。
可是那一批落地途中撞见的**设计稿与实现对不上**，大半没有收——停车场 Q206–Q994 那一轮 `/settle` 之后，
它们在 `/grill-with-docs` 里被拷问过一遍，结论是这一批（条目原文在各票的《停车场结转》）。
眼下用户与维护者碰到的是：

1. **逐格比对在五处不是逐格。**比对器上长出四副「打折但仍是断言」的手法（抹掉一段、一格换成右邻、一段往右推、
   整行换掉），各自挂在一条停车场条目上。「快照是验收标准」在这五处打了折，而那四副手法本身就是设计稿与实现
   对不上逃出来的。
2. **屏上摆着按不动的键，按得动的键又没摆。**改一项设置的值、给预设起名时屏底写着 `Tab → 补全`，按下去什么都不发生；
   光标停在预设栏末行上时摆着 `dd → 删除`；清点中输出目录那一行写着 `i → 修改`，那一刻 `i` 派不出去。
   反过来，搜索那一行上 `C-w` 按得动，屏上却不说。
3. **设计稿有、实现没有的几样行为。**在展开着的目录行上按 `⏎` 收不起来；确认点上答了「不写出」的那一卷，
   卷列表上与做完写出的卷长得一样、总览把它数进「完成」，而盘上没有它；「全部按键」那一张比一屏长，
   滚轮滚不动它，补全框上也滚不动；`←`／`→` 按下去什么都不做，对不熟 vim 的人那是第一反应。
4. **设计稿自己的缺陷挡着验收。**补全候选的次序是手写的，两串序列因此只能不比屏；不是归档的文件也标「压缩包」；
   前缀一个都对不上时那句回话被输入行盖住、根本看不见；覆盖层底下按 `gt` 换了视图；「添加路径」那一景按键到不了；
   设计稿里预设文件那条路径是写死的、没导进场景数据；同名覆盖要按两下这件事设计稿里没有，那一句问话没有一份快照钉着；
   「整卷统一灰阶 + 等待确认」那一屏没有一景导得出，确认条上「差异大的页」那一截与「需留意几页」的数一格断言都没有；
   型号不进预设，而词汇表说预设装设备设置——9 月 20 日已拍板「词汇表赢」，至今没改。
5. **屏上说不出两件事。**按页跳过时留下了几页，每页结果上看不出来；一卷跑得慢，展开它也看不出慢在哪个环节。
6. **屏上提到键的那几句是手抄的。**每页结果、搜索提示、确认条上的键字面各写各的，而拦手抄的那条文件扫描
   随旧界面一起删掉了——换一次键位，这几句不会跟着变，也没有东西会红。
7. **三条会话 bug。**退出会话时印到 stdout 的报告，正文里的不许断空格没换回普通空格，从报告里抄出来的命令敲不通；
   灰阶测试图那句回话从行尾截断，截掉的正是文件名；分卷序列的头一份在屏上叫 `第01卷.part1`，而卷名是序列的名字。

`session-redesign/18`（人坐在真终端前与设计稿并排看一遍）排在这一批之后：先不改，人看到的屏上有三十来处接下来就要变。

## Solution

**照 ADR 0019 决定第 13 条办：设计稿是权威。**每一处对不上，归两类之一：

- **实现跟设计稿**：设计稿的行为是对的，实现还没做到——实现补上。
- **先改设计稿、重新导出，再改实现**：设计稿自己错了或缺一块——先把设计稿改对，`npm run export` 重导，
  实现照新导出的快照走。

改完之后比对器上那四副打折手法一副都不剩，每一串都比整屏；屏上不再摆按不动的键，按得动的键都摆；
屏上每一个键字面都从按键表来；三条 bug 修掉。命令行那一路的输出一个字节不变。

## User Stories

1. 作为会话用户，我想要在展开着的目录行上按 `⏎` 就把它收起，以便 `⏎` 在目录行上是开关，与设计稿一致。
2. 作为会话用户，我想要双击一个展开着的目录行也把它收起，以便双击与 `⏎` 始终是同一件事。
3. 作为会话用户，我想要 `l` 在目录行上照旧只展开，以便想展开时不会误把它收起。
4. 作为会话用户，我想要确认点上答了「不写出」的那一卷在卷列表上认得出来，行尾写「已分析，未写出」，
   以便不把它当成已经写到盘上的卷。
5. 作为会话用户，我想要总览上的「完成」不数那几卷，以便「完成 N 卷」里的每一卷盘上都真有。
6. 作为会话用户，我想要那一卷照样展得开、看得到每页结果，以便预览完了能回头看它的判定。
7. 作为会话用户，我想要在「全部按键」那一张上滚滚轮就能往下看，以便触控板上不必改用 `j`／`k`。
8. 作为会话用户，我想要补全框开着时滚轮挪的是候选，以便候选多时滚着挑。
9. 作为会话用户，我想要 `←`／`→` 与 `h`／`l` 做同一件事，以便不熟 vim 键位也能用方向键前进后退。
10. 作为会话用户，我想要屏底不因为方向键而多出一种写法，以便屏底仍是一行、照旧是设计稿那一副。
11. 作为会话用户，我想要存一份预设时连型号一起存、套一份预设时型号跟着换，以便一份预设就是一整套设备设置与处理选项。
12. 作为会话用户，我想要套一份没写型号的预设时型号回到「没说」、屏上照现成那一句叫我先挑型号，
    以便「预设没说的那一项回到没说」这条规矩对型号也成立。
13. 作为会话用户，我想要预设栏上「包含 N 项设置」、行尾的 `*`、顶上「改动了 N 项」三处都把型号数进去，
    以便三处数的是同一份单子。
14. 作为会话用户，我想要改一项设置的值、给预设起名时屏底不摆 `Tab → 补全`，以便屏上不摆按不动的键。
15. 作为会话用户，我想要添加与修改处理路径、改输出目录时 `Tab` 照旧摆着，以便需要补全的地方看得见它。
16. 作为会话用户，我想要搜索那一行上屏底也写着 `C-w`，以便按得动的键屏上都说。
17. 作为会话用户，我想要光标停在预设栏末行「＋ 把当前设置保存为预设」上时屏底不摆 `dd → 删除`，以便不对着一个删不了的东西摆删除键。
18. 作为会话用户，我想要清点中输出目录那一行不写 `i → 修改`，以便这一刻改不了的东西不摆修改键。
19. 作为会话用户，我想要在补全框里看到的候选按名字排，以便每次打开同一层看到的次序都一样。
20. 作为会话用户，我想要补全框里只有归档旁边标「压缩包」，以便 `答案.txt` 这种文件不被说成压缩包。
21. 作为会话用户，我想要打了一个一条都对不上的前缀再按 `Tab` 时，屏上看得见那一句「这里没有以……开头的项」，以便知道不是程序没反应。
22. 作为会话用户，我想要覆盖层掀着时 `gt`／`gT` 不在它底下偷偷换视图，以便关掉覆盖层时回到的还是原来那一屏。
23. 作为会话用户，我想要在补全框里用 `↓`／`↑` 挑候选，而不是一套设计稿里有、按键表上没有的 `C-n`／`C-p`，以便全部按键那一张列的就是全部。
24. 作为会话用户，我想要在搜索那一行上按 `C-w` 删掉一段之后，匹配处的下划线与框底边跟着变，以便屏上说的就是此刻在搜的那一句。
25. 作为会话用户，我想要给预设起一个已经有的名字时，第一下只在预设栏里问一句「再按一次 ⏎ 覆盖」，第二下才盖，

26. 作为会话用户，我想要确认条上「差异大的页」那一截与卷列表上那一格说的是同一个词、同一个数，以便上下两块不打架。
27. 作为会话用户，我想要确认条上「需留意几页」与每页结果抬头报的是同一个数（代表页也数进去），以便同一句话只有一个答案。
28. 作为会话用户，我想要掀着覆盖层答话时屏底照样说那一句回话，以便答了什么看得见，与按停止一个待遇。

## Implementation Decisions

### 裁决规则

- **设计稿是权威**（ADR 0019 决定第 13 条）。本批每一处都先归类：实现跟设计稿，或先改设计稿、重新导出、再改实现。
  归类已在拷问里定下（见下两节），实现途中再撞见新的对不上，照旧记停车场，不在本批里顺手判。
- **先追上，再逐项改。**头一张只改设计稿里**实现本来就对了**的那几处，重导之后四副打折手法当场删得掉、闸门照旧绿；
  其余每一项在自己那张票里一条路走完：改设计稿、重导、改实现、补用例——一次重导整批的话，实现还没追上的那几处当场红，
  那张票收不了尾。每一次重导之后 `npm run check` 绿，提交进仓库的快照、场景数据、交互期望屏与设计稿逐字节一致。
- **四副打折手法退场**：抹掉一段、一格换成右邻、一段往右推、整行换掉——四个都删掉，用到它们的那几串改成比整屏。
  **不收成一副统一的豁免记法**（2026-09-20 拍板：根治是让它们没有存在的理由）。

### 先改设计稿、重新导出，再改实现

- **清点中输出目录那一行**：设计稿按阶段分一档，跑起来之后不摆 `i → 修改`；重导清点中那两屏与 `survey-s` 那一串（Q807）。
- **环节横条**：设计稿横条的分子取屏上印的那个整数页数，不取连续时间的原值；重导「整卷统一灰阶」那两屏（Q844）。
- **总进度的步数**：导出时步数与屏上一样向下取整；重导 `deciding-x-advance`（Q899）。
- **折行**：设计稿的折行照《折行》带悬挂缩进——行首缩进跟着折下来的每一行走；重导 `ended-nonvolume-Enter`（Q845）。
- **灰阶测试图那句回话**：设计稿不再说「原型不写文件」，照实现说出写到了哪里（点一条假路径出来）；
  路径长时**从中间省略**，目录的头与文件名两头都在；「拷进设备，用原始尺寸打开」那半句不上屏底
  （命令行那一路照旧印它）。重导 `config-c`（Q890、Q968）。
- **型号进预设**：设计稿存预设与套预设两支都收型号；重导 `config-p-save-named`、`config-p-j-Enter`；
  实现那一侧存出去的单子包括型号，行尾的 `*`、「改动了 N 项」、「包含 N 项设置」三处读同一份单子（Q891，2026-09-20 已拍板）。
- **补全候选按名字排**：设计稿的假盘列一层时按名字排；重导 `add.*`、`add-F1*`、`add-narrow-*`、`fresh-o-Tab*`，
  那两串从此比整屏（Q790）。
- **「添加路径」那一景**：设计稿那一景走真的补全动作，缓冲换成头一个候选；与上一条同一次重导，夹具不再把缓冲改回去（Q797）。
- **只有归档标「压缩包」**：设计稿补全框按扩展名标（假盘里 `字体包.zip` 标，`答案.txt`、`README.md` 不标）（Q791）。
- **对不上的前缀那一句**：设计稿把「这里没有以……开头的项」画在输入行右端那几件的位置，实现跟着（Q792）。
- **覆盖层上的连击键**：设计稿的连击键分支排在覆盖层分支之后，覆盖层上只认 `gg`（Q793）。
- **`C-n`／`C-p`**：设计稿去掉，补全框只认 `↓`／`↑`（Q798）。
- **搜索那一行上的 `C-w`**：设计稿删一段之后同步「此刻搜的是哪一句」，与打字、退格两支一样（Q866）。
- **预设文件那条路径**：导出进场景数据，夹具照它摆（Q824）。
- **同名覆盖按两下**：设计稿补上这一问——第一下在预设栏里问「再按一次 ⏎ 覆盖「X」：覆盖后无法恢复，其他预设不受影响」，
  输入行与名字留着，第二下才盖，重开起名那一行就作废（措辞取实现今天那一句）；导出一串新的期望屏（Q894）。
- **预设栏末行**：设计稿的屏底按光标停在哪一行摆，末行上不摆 `dd`；末行上按 `dd` 设计稿也不再抛错（Q893）。
- **「整卷统一灰阶 + 等待确认」那一景**：设计稿导出一景，钉住确认条上「差异大的页」那一截与卷行那一列（Q900）。
- **「需留意几页」一种数法**：设计稿确认条与每页结果抬头同一种数法，代表页也数进去（照《需留意的页》）（Q902）。
- **掀着覆盖层答话**：设计稿覆盖层那一支答话之后也说那一句回话，与按停止一个待遇（Q903）。
- **隔离那一卷的去处**：设计稿带上处理路径自己那一级（`…/_isolated/漫画库/集英社/…`），只动场景数据（Q765）。
- **`parentHint`**：设计稿改成真正的父目录，导出直接读它，导出自己算根的那一段去掉（Q738）。
- **灰阶档位那一环**：设计稿列四格（1bit · 2bit · 4bit · 8bit），说明改成说清 8bit 那一格在电子墨水屏上派不上用场
  （灰阶硬上界，ADR 0003），实现照旧由穷尽的取值生成那一环（Q730）。
- **「差异大的页」一个叫法**：总览、确认条、分区与目录行的汇总一律用词汇表的名字（Q731）。
- **详情栏长说明带上取值的写法**：「`height`（按高度铺满）：……」，称呼与取值那一格同源（Q732）。

### 实现跟设计稿

- **`⏎` 在目录行上是开关**：按键表给目录行上的 `⏎` 派一件自己的事——展开着就收起，收着就展开；`l` 照旧只展开、`h` 照旧收起；
  双击等于 `⏎`，跟着变。`ended-h-Enter-Enter` 那一串接上、比整屏（Q806、Q853）。
- **《预览过 (Trialed)》**：卷状态多一档。确认点上答了「不写出」、分析做完而写出环节一步没走的那一卷，收摊时落在这一档，
  判的依据是这一卷写没写（`Live` 按卷已有的那一格）。行首记号照设计稿（与完成同一套：有需留意的是 `!`，没有是 `✓`），
  行尾写「已分析，未写出」；展得开；**总览上的「完成」不数它**（Q769、Q674）。
- **滚轮**：按键表上滚轮那一行放宽到「全部按键」那一张与补全框——覆盖层上滚它，输入行开着时挪补全框里的候选（Q979）。
- **方向键**：终端层把 `←`／`→` 翻成 `h`／`l`（设计稿在键的归一化上就是这么做的）；按键表不添行，屏底与全部按键
  不多一种写法。`⇧⇥` 照旧不翻（Q967）。

### 按键表：输入行的用途

- 按键表多一维「输入行的用途」：`Tab` 补全只在添加与修改处理路径、改输出目录那几种用途上派得出；
  `C-w` 删一段在每一种上都派得出，搜索那一行也是。
- 屏底右端那几件从表上一路派下来，**不再有手摆的岔路**（今天为搜索那一行摆两件的那道岔路删掉）。
  设计稿右端那几件按用途摆，与表一致（Q794、Q827、Q868、Q893 的 `Tab` 那一半）。

### 屏上提到的键出自按键表

- 屏上凡是在句子里提到一个键的地方，键的写法一律取按键表那个「不问阶段与块」的写法（它已经在）：
  每页结果框底边的 `a → …`、跳过的卷那一句末尾的 `h → 回卷列表`、一页都不需留意那一句末尾的 `a → 全部页`、
  搜索提示的 `n N`、确认条上的四个键（Q874、Q896）。
- **确认条那四句是它自己的措辞**，与屏底那几句回话一样，不从按键表取、按键表不为它添列。
  《确认条》词条里 `v` 那一句照设计稿改成「查看每页结果」（Q896）。
- 补回一条文件扫描：屏上的句子里不许手抄键；家是按键表那个模块，读者是画法那几个模块，
  记号取新界面屏上真出现过的几句（如「再按一次 ⏎ 覆盖」「再按一次 dd 删除」）（Q963）。

### 屏上多说两件（设计稿先行）

- **留下的页**：按页跳过的卷，每页结果上说出留下了几页（《留下的页》不进逐页结果，屏上只报个数）；位置与措辞由设计稿定（Q682）。
- **各环节耗时**：展开一卷时给出它各环节花了多久，数取卷级计时那几段；位置与措辞由设计稿定（Q624）。

### 摊开这个环节在屏上

- 要摊开的卷，屏上的环节名显示「摊开」——当前卷那一行、横条、`?` 那张表里的环节一节，三处逐字相同；
  它的种类色由设计稿给一色；不摊开的卷屏上照旧三个环节。
- **依赖 `say-and-stop`**：库里的 `Pass` 多出摊开那一个取值、卷级计时多出那一段，是那一批的活；
  本批这一项等它落地之后再做（拷问结论 1、2）。

### 三条会话 bug

- **退出时的 stdout**：会话退出时印到 stdout 的整份报告，先过命令行那一路同一道「印出去之前把不许断的空格换回普通空格」
  （字形约定），不折行——stdout 可能是一个文件，折到多宽另有一笔账（Q584）。
- **灰阶测试图那句回话**：路径从中间省略（原样那一档的规矩），见上《先改设计稿》那一条（Q968）。
- **分卷序列的卷名**：屏上的卷名取卷清单上那一卷的卷名，分卷序列因此不带 `.partN`（Q849）。

### 库：卷清单上带卷名（Q849）

- 《清点摘要》多一格**卷名**：清点时库本来就读过归档头认「这一份是不是另一份的续」，卷名（分卷序列取序列的名字）
  在那一刻算出来，随卷清单进开工那一条事件。会话写卷名一律读它，不再从卷根按名字猜。
- 这是本批**唯一**一处库的对外形状变化；命令行报告的字节不变（报告里的卷名不经这一格）。

### 词条随票落地

`CONTEXT.md` 的这几处改动**跟着实现它的那张票一起落地**，在那之前词汇表照旧写当前成立的事实（拷问结论《词条的落地时机》）：

- 《卷状态》多一档《预览过 (Trialed)》；
- 《确认条》里 `v` 那一句改成「查看每页结果」；
- 《输入行》右端那几件按用途摆（`⇥` 只在路径那几种上）；
- 《清点摘要》多一格卷名；
- 《环节》多出摊开那一个——由 `say-and-stop` 那一批改，本批只让屏上跟着。

## Testing Decisions

### 什么是好测试

只断言外部行为：**整屏**（每一格的字、前景色、修饰）、**喂一串输入之后的整屏**、**事件流**、**印出去的字节**。
不断言焦点是哪个枚举取值、按键表内部怎么查、卷状态里存了什么中间量——那些换一种实现就该能换，快照不变。

### 设计快照与交互期望屏（主力）

- 设计稿先改、`npm run export` 重导、`npm run check` 绿，再动实现。快照对实现只读。
- 经终端层喂键或鼠标，走完比交互期望屏；每一串都比整屏，本批落地之后比对器上没有一处打折。
- 补导的景与序列：「整卷统一灰阶 + 等待确认」那一景；同名覆盖按两下那一串；有一卷正在摊开的那一屏（等 `say-and-stop`）；
  答了「不写出」那一卷在卷列表与总览上的样子；每页结果上的「留下 N 页」与各环节耗时；
  `⏎` 收起展开着的目录行、双击收起；「全部按键」那一张与补全框上的滚轮；方向键；预设栏末行的屏底；
  输入行各种用途的屏底右端；搜索那一行 `C-w` 之后的屏。
- 先例：`session-redesign` 立下的那一整套——终端层的交互序列用例、夹具读场景数据摆状态、`TestBackend` 逐格比对。

### 按键表的单一出处

- 「屏底每一件都是按键表的一行」「全部按键与屏底出自同一张表」那两条既有用例扩上「输入行的用途」这一维：
  每一种用途上，屏底右端摆的恰好是那一种上派得出的键。
- `tests/single_source.rs` 补回「屏上提到键的句子不许手抄」那条扫描（先例是它从前那一条，以及同一篇里另外三条单一出处的扫描）。

### 库那一侧（只为 Q849）

- 事件流用例，与现有事件流用例同一个接缝（给 `run` 装一个观察者）：开工那一条带的卷清单上，目录卷、归档卷、
  分卷序列头一份各有卷名，分卷序列那一个不带 `.partN`，续的那几份不在清单上。

### 印出去的字节（只为 Q584）

- 会话退出时交给 stdout 的那一份，由命令行那一路同一个「印出去之前换回普通空格」的纯函数出；
  在 `render` 那几条问「stdout 上留下的命令敲得通」的既有用例旁边断言，覆盖报告正文，不只是那句拒绝。

### 闸门

- 三条闸门跑满：按键表、卷状态、输入行的用途在 `--no-default-features` 那一趟也编也测；画法与终端层在默认那一趟；
  `profiling` 那一趟编得过。
- 黄金快照原样过——命令行报告一个字节不变。
