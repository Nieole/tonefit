# 02 — AVIF 的页内元数据载体调研

**What to build:** ADR 0009 新写下那道闸——「**一个编码器进不了这个项目，除非它有页内元数据载体**」
——在 AVIF 上到底过不过得去，要有一个**写下来的答案**。

《记录》随文件走：它就在页里，文件被移动、改名、重新打包都不会丢，幂等因此不需要全库索引。
PNG 那一侧靠 tEXt 承载它。ADR 0004 自己认下的代价里就有这一条：
「写进 PNG tEXt 区块的判定记录要为 AVIF 另找载体，各家格式的元数据能力不同，**尚未调研**」。
这张票把那句「尚未调研」了结掉。

**口径是这条链，不是格式规范。**问的不是「AVIF 规范支不支持 XMP／Exif」，
是「**我们手上这套依赖，编得进去、读得回来吗**」。

**结论无论正反都写下来**——查出来不行，下一个人就不必再查一遍。

**Blocked by:** 无——可以立刻开始

**Status:** resolved

- [x] 答出四问：①写得进去吗；②读出来与写进去的**逐字节相同**吗；③`--no-metadata` 那条路照旧关得掉吗（能写就能不写）；④取值受不受 Latin-1 那一类约束（《记录》今天「取值一律 ASCII」正是被 tEXt 逼的）
- [x] 口径写明是**这条链**：用到的编码器与解码器**各自的名字与版本**写进结论
- [x] 结论落进 `docs/research/`，与既有那两篇同一个位置、同一个形状
- [x] 结论里说清它对 ADR 0009 那道闸意味着什么——AVIF 过不过得去，以及过不去的话卡在四问里的哪一问
- [x] **不碰生产代码**，不加任何运行时依赖

### 口径

问的不是「AVIF／HEIF 规范支不支持 Exif 与 XMP」（支持，查一遍就有），
是「**`Cargo.lock` 锁着的这几个包，编得进去、读得回来吗**」。**两问的答案不一致**，
而不一致的那一处就是这张票的全部产出。

链上各方与版本（全部取自 `Cargo.lock`，基线 `5d406be`）：
**编码**侧 `image` 0.25.10（`avif` 特性，**只在 `[dev-dependencies]`**）→ `ravif` 0.13.0
→ `avif-serialize` 0.8.9，AV1 由 `rav1e` 0.8.1（`asm` 关着）；
**解码**侧 `image` 0.25.10（`avif-native`，`[dependencies]`）→ `mp4parse` 0.17.0
＋ `dav1d` 绑定 0.11.1 → 系统 dav1d **1.4.1**。对照组 `png` 0.18.1。
本机 `g++ 13.3.0`、`rustc 1.98.1`。

### 四问的答案

| # | 问 | 答 | 怎么来的 |
|---|---|---|---|
| ① | 写得进去吗 | **写得进。**`AvifEncoder::set_exif_metadata` → `ravif::with_exif` → `Aviffy::set_exif`，写出标准的 `infe`(`Exif`)＋`iloc`＋`cdsc` 三件套。但**编码器只在 dev 侧**，且整条链**只有 Exif 项一个装任意字节的口子** | 📖＋🔬 |
| ② | 读回来逐字节相同吗 | **拆成两半，答案相反。字节逐字节在文件里**（自己走 ISOBMFF 取回来，剥掉 HEIF 那 4 字节头后与载荷逐字节相同，空与 64 KiB 两端都对）；**这条链取不回来**（`image` 的 `AvifDecoder` 只实现 `icc_profile()`，`mp4parse 0.17.0` 的 `AvifContext` 一个 Exif／XMP 访问器都没有） | 📖＋🔬 |
| ③ | `--no-metadata` 关得掉吗 | **关得掉。**不调就一个字节不落（295 vs 458 字节），两张解出来的像素逐字节相同 | 📖＋🔬 |
| ④ | 受不受 Latin-1 约束 | **不受。**三层都是裸 `Vec<u8>`，UTF-8、内嵌 NUL、`0x80~0xFF` 全部原样收下。那个约束是 PNG `tEXt` 的 | 📖＋🔬 |

**那 4 字节不是恒定的。**`exif_extents` 有两支：载荷本身已经像一个框好的 HEIF Exif 项时
（头 4 字节当大端偏移读、跳过去正好是 TIFF 头）写成**一段、原样**，取回来不多那 4 字节；
否则才写成两段。**本轮四种载荷全部落在第二支，第一支只读了源码、没有实测。**
接 AVIF 的人要知道：**「剥不剥头 4 字节」取决于写进去的那段字节本身，不是定值。**

**最要紧的一句：写侧只会 Exif，读侧只会 ICC，两头不相交。**
（`AvifEncoder` 的 `set_icc_profile` 恒 `Err`，`avif-serialize`／`ravif` 里 `icc` 零命中；
反过来 `AvifDecoder` 只读得回 ICC。）

**第二要紧的一句：读不回来不报错。**四个访问器在五种文件上共二十格回话**逐字相同**，
全是 `Ok(None)`——挂着 64 KiB 记录的页与一个记录都没挂的页，在这条链的 API 上分不开（Q957）。

### 给 `04` 号票的一段

`04` 走「AVIF 保得住落格」那一支时，要把两道闸写进 ADR 0004 的《后果》，
元数据那一道**引本票**。引过去之前要知道：**本票的结论是有条件的**。

ADR 0009 那句「一个编码器进不了这个项目，除非它有页内元数据载体」里，
**「载体」要求的是哪一格，今天没有一处拆开写过**——而 AVIF 第一次把两件事分开了：

- 读作**「字节挂得住、我们自己读得回」** → **AVIF 过得去**。代价是接 AVIF 的那张票要自带
  一份 ISOBMFF 走箱（约 40 行，本票探针里那一段是现成的形状），并认下 Q957 那个哑巴 `None`
  ——幂等那一道从此问不出「这张页有没有记录」，`Ok(None)` 同时意味着
  「没挂」「挂了但读不回来」「这不是我们写的页」，而 PNG 那一侧靠
  `PageRecord::read` 的「共用三项缺一项就是 `None`」把三者收成一档的那条路，在 AVIF 上迈不出第一步。
- 读作**「链上现成 API 读得回」** → **AVIF 过不去**，而且这一条不在我们手上：
  要等 `mp4parse` 补访问器，或换一个 AVIF 解析器。

**这一格是 `04` 真正缺的那一样**，它是领域决定不是实现细节，记在 **Q958**，归拍板的人。
ADR 0004《要认的代价》里那句「为 AVIF 另找载体……**尚未调研**」——调研完了，
**但把那句话改成什么，取决于上面那一格怎么定**。

**另外两条与 `04` 不相干、但顺手量到的**：`encode.rs` 那处写 tEXt 的 `?` 永远不会触发（Q959）；
`CONTEXT.md`《记录》那两句都是 PNG 专属的说法（Q960）。

### 评审

`/code-review` 提了 15 条，**14 条照收改了**，1 条部分收。值得记下的三条实质错误：

1. **「取回来恒比载荷多 4 字节」写成了无条件的**，而 `exif_extents` 有两支——
   本轮四种载荷碰巧全落在加 4 字节那一支，🔬 从没走到另一支。
   已改成两支并列，并点明**「剥不剥那 4 字节」不是定值**。这一条要是漏了，
   下一个照本篇写读回来的人会在另一支上剥错。
2. **「内嵌 NUL 在 PNG `tEXt` 里根本不可能出现」是错的**，而且没验过：
   `u8::try_from(0u32)` 是 `Ok(0)`，`png` 0.18.1 **不拒绝 NUL**；
   本轮载荷 ② 把 NUL 与中文混在一起，那个 `Err` 出自中文。已删掉这句，改记进《没验到的》。
3. **开头那句免责声明是从既有两篇抄来的**（「本文只记录仓库之外的现状与来源」），
   而本篇做不到——票面把口径钉死在「我们手上这套依赖」，回答它就必须点出锁了哪几个版本。
   已改写成如实的说法，并点名本篇里关于本仓的**只有三处**。

其余：三档判据只有一半小节在用（已重铸成「够用／只够一半／不够用」，四问都套得上）；
少了「一眼看完」那张表、《没查到的》位置不对（已按既有两篇的次序摆好）；
`decoder.rs:46`→`45`、`encoder.rs:46`→`53` 两处行号错（Q957 里那一份同步改了）；
「文档只有一句」其实是两句；「理由写在 `src/metadata.rs`」——那里写的是 Latin-1 的理由，
不是收窄到 ASCII 的理由（已改措辞）；探针三处（`iinf`／`meta` 的 FullBox version
没断言就按 v0 解析、空载荷那一行印出误导人的 `false`）已修。

**部分收的那一条**：探针的耗时数字重复在两处。**已从调研那一篇删掉**、只留在探针
`README.md`（重跑的人在那里）；但**没有**按评审建议挪进 `docs/measurements.md`——
