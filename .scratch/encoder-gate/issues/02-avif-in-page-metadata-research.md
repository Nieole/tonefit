# 02 — AVIF 的页内元数据载体调研

**What to build:** ADR 0009 新写下那道闸——「**一个编码器进不了这个项目，除非它有页内元数据载体**」
——在 AVIF 上到底过不过得去，要有一个**写下来的答案**。

《记录》随文件走：它就在页里，文件被移动、改名、重新打包都不会丢，幂等因此不需要全库索引。
PNG 那一侧靠 tEXt 承载它。ADR 0004 自己认下的代价里就有这一条：
「写进 PNG tEXt 区块的判定记录要为 AVIF 另找载体，各家格式的元数据能力不同，**尚未调研**」。
这张票把那句「尚未调研」了结掉。

**口径是这条链，不是格式规范。**问的不是「AVIF 规范支不支持 XMP／Exif」，
是「**我们手上这套依赖，编得进去、读得回来吗**」。

**结论无论正反都写下来**——查出来不行，下一个人就不必再查一遍。

**Blocked by:** 无——可以立刻开始

**Status:** ready-for-agent

- [ ] 答出四问：①写得进去吗；②读出来与写进去的**逐字节相同**吗；③`--no-metadata` 那条路照旧关得掉吗（能写就能不写）；④取值受不受 Latin-1 那一类约束（《记录》今天「取值一律 ASCII」正是被 tEXt 逼的）
- [ ] 口径写明是**这条链**：用到的编码器与解码器**各自的名字与版本**写进结论
- [ ] 结论落进 `docs/research/`，与既有那两篇同一个位置、同一个形状
- [ ] 结论里说清它对 ADR 0009 那道闸意味着什么——AVIF 过不过得去，以及过不去的话卡在四问里的哪一问
- [ ] **不碰生产代码**，不加任何运行时依赖
