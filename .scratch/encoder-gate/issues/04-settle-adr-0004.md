# 04 — 按数处置 ADR 0004

**What to build:** 让 ADR 0004 与事实对得上，`encode.rs` 与 `CONTEXT.md` 里那几句话跟着改。

03 的数回来之后走两支之一：

- **AVIF 保得住落格**（解回来仍是 29 级）→ 决定第 2 条站得住，给它**补一条依据**，
  并把「第二个编码器要过的**两道闸**」写进《后果》：《落格》（`CONTEXT.md`《量化》）
  与**页内元数据载体**（ADR 0009，结论引 02）。
- **AVIF 保不住落格** → 决定第 2 条与 ADR 0003 的灰阶硬上界打架，**整篇取代**：
  新一篇把 PNG 定成唯一输出编码器、理由是《落格》，
  WebP／JPEG／AVIF 三种各自的数写进《备选方案》，ADR 0004 标为被取代。

**两支都原样留着《不要做的「简化」》那三条**——「两个编码器都试编码、每页选体积小的那个」
被否掉的那三条理由（可读性逐页漂移、两条曲线形状不同单一阈值比不了、
按体积选优会让 2bit 以下那段非对称看不见）**与 AVIF 保不保得住落格无关**，它们照旧成立。

**Blocked by:** 01 — 《落格》在 `run` 那条缝上立成用例；02 — AVIF 的页内元数据载体调研；03 — 补 AVIF 那一格测量

**Status:** ready-for-agent

#### Q958 — 「页内元数据载体」这道闸要求的是哪一格，没有一处拆开写过——而 `04` 要据本票处置 ADR 0004

- **From:** 票 `encoder-gate/02`
- **Kind:** 我确实拿不准的单项（这是领域决定，不是实现细节）
- **Where:** ADR 0009《不要做的「简化」》末段那一句「**一个编码器进不了这个项目，除非它有页内元数据载体**」；
  `CONTEXT.md` 的《记录》《指纹》；`04` 号票验收第三条「《后果》写进『第二个编码器要过的两道闸』，
  元数据那一道**引 02 的结论**」
- **Why it did not block:** 本票的职责是交出四问的答案，不是定义那道闸。
  票面原话「结论无论正反都写下来」——写下来了。
- **What this ticket actually did:** 四问答齐，其中三问（写得进、关得掉、不受 Latin-1 约束）
  在这条链上都成立，**卡在第 ② 问**。而第 ② 问被探针拆成了**两半，答案相反**：
  **字节挂得住**（写进去、自己走 ISOBMFF 取回来，去掉 HEIF 那 4 字节头之后逐字节相同，
  空载荷与 64 KiB 两端都对）；**这条链取不回来**（`image` 与 `mp4parse` 都没有 Exif 访问器）。
  **那道闸今天的措辞判不了这一格。**
- **Why it matters:** 「载体」这个词只被 PNG 的 `tEXt` 一个实例定义过，而 `tEXt` 两头都现成，
  从没逼人区分「字节挂得住」与「链上现成地读得回」。AVIF 第一次把这两件事分开了：
  - 按**「字节挂得住、自己读得回」**读 → AVIF **过得去**（本票那 40 行就是存在性证明）；
  - 按**「链上现成 API 读得回」**读 → AVIF **过不去**，且卡在上游、不在我们手上。
  **`04` 号票缺的正是这一格**：它走「AVIF 保得住落格」那一支时要把两道闸写进 ADR 0004 的《后果》
  并引本票，而引过去的结论**本身是有条件的**。
- **Options:** ① 闸读作「字节挂得住 + 我们自己读得回」——AVIF 过，代价是接 AVIF 的那张票
  要自带一份 ISOBMFF 走箱（约 40 行，本票的探针是现成的形状），且要认下 Q957 那个哑巴 `None`；
  ② 闸读作「链上现成 API 读得回」——AVIF 不过，而且这一条**不由我们决定什么时候变**；
  ③ 在 ADR 0009 那一句上把这两档写开，闸从此判得了这一格
- **Recommend:** ③ 先做——①②之争是因为那句话今天没说清，先把它说清，
  ①②哪一支成立就自己浮出来了。但**这是领域决定**，按 `CLAUDE.md`《改 CONTEXT.md 的规矩》
  「改写已有词条的含义要先拍板」，本票不动它一个字。
- **Whose call:** 拍板的人（动 ADR 0009 那一句）；`04` 号票要先知道答案
- **处置：** **拍板（2026-09-20）：按「链上现成 API 读得回」读——AVIF 过不了这道闸。** ADR 0009 那句「页内元数据载体」要求的是**这条依赖链上有现成的读回口子**，不是「字节挂得住、我们自己走箱取得回」。据此：AVIF 卡在第 ② 问，而那一条**不在我们手上**（要等上游 `image`／`mp4parse` 补访问器）。`04` 号票据此走「ADR 0004 保不住那一支」还是「保得住」，由它按这一判处置；Q957（读不回来恒 `Ok(None)`、不报错）与 Q960（《记录》两句是 PNG 专属说法）跟着这一判一起读。

#### Q960 — `CONTEXT.md` 的《记录》两句都是 PNG 专属的说法，而本票量出那两句各自的来源不同

- **From:** 票 `encoder-gate/02`
- **Kind:** 记下（词汇表与实现今天对得上，是**将来**才对不上）

- **Why it did not block:** 今天一个字都不错：今天只有 PNG 一个编码器，那两句逐字成立。

#### Q937 — **spec 那一句本身是错的**：它把 `truncated_page` 当「坏页」，而那张夹具是**残缺页**、有判定

- **From:** 票 `encoder-gate/01`
- **Kind:** 派活文件里的一处事实错误（**错的是 spec 那一行，不是实现**），外加一个由它带出来的真缺口
- **Where:** `.scratch/encoder-gate/spec.md` 的《Testing Decisions》一，
  「用一个混排卷一次盖住：彩页、坏页（`truncated_page`）、透传文件、灰度页各一」；
  夹具那一侧 `tests/fixtures/mod.rs` 的 `truncated_page` 文档写着
  「这是**残缺页**——三种页状态里的第三种（04 号票）：它照常缩放、判定、写出」
- **Why it did not block:** 混排卷那一条要的是**没有判定**的那一侧，而残缺页有判定——
  拿 `truncated_page` 摆进去，双向对应那半边就问成了「有判定的页落不落格」，
  与灰度页那一格重复，而「坏页凭什么不在这条不变量里」一句都问不出来。
  换一张就行：字节根本读不出来的那一张（`volume.file("003.png", b"not a png at all")`，
  `tests/idempotency.rs` 已有先例）才走到 `PageOutcome::Failed`、才出那张空白占位页。
  **要点在于 spec 那一行点的夹具名产不出它被引来说明的那一种页**——
  下一个人照着 Testing Decisions 一去读，会把实现「改回」那张错的夹具，
  而改回去之后双向对应那一侧当场就空了（它不会红：`truncated_page` 有判定，
  `classify` 认得出它，只是那一格问的变成了与灰度页重复的那一问）。**所以该改的是 spec，不是用例。**
  另：`salvages_nothing_page`（一行像素都救不回来的那一张）**是坏页**——
  `PageOutcome::Failed` 收着「救回了却一个像素都没解出来」这一种（12 号票的三种加 04 号票补的第四种，
  见 `src/report.rs`）。那张夹具文档里「带着正常的判定元数据」说的是 **04 号票之前**的形态，
  是它要拦的那件事，不是今天的行为；拿它当坏页也成立。
- **What this ticket actually did:** 混排卷用的是读不出字节的那一张。
  **由此带出一个真缺口，要说清楚，不然下一个人会以为四支已经穷尽了**：
  残缺页在这条不变量的**里面**（有判定、照常量化写出），而本票**一格都没盖到它**——
  八条验收一条都没点它，`Written::Judged` 那一支走到的全是完好页。
  它不是「第五种」（`classify` 认得出它，记录里写的就是候选，不会 panic），
  因此**双向对应没有漏**；漏的是「三种页状态各走到一次」这条更强的性质。
  今天挡着它的是别处：`tests/pipeline.rs` 另有三条用例专问残缺页
  （`a_salvaged_page_answers_the_geometry_gate_for_itself_only` 那一批），
  但那三条问的是几何与卷级，**没有一条问它落不落格**。
- **Options:** ① 记下，不补（残缺页与完好页在写出环节走的是同一段代码——
  两者都经 `quantize` 再进 `encode::png`，落格这件事上分不出两条路）；
  ② 往混排卷里再加一张 `truncated_page`，把「它也在里面」钉一次（一行夹具加一格断言）；
  ③ 修 spec 那一句的字样
- **Recommend:** ③ 加 ②：那一句是**派活文件里的事实错误**，会把下一个读它的人引到同一处；
  而残缺页多加一页只要一行，买的是「三种页状态各走到一次」
- **Whose call:** 记下即可（spec 那一句归开票的人；②归下一张碰这批用例的票）
- **处置：** 待处理。

#### Q938 — `8bit` 那一档上《落格》恒成立：它在闸底下，却一句话都问不出来

#### Q939 — 这道闸守得住「换掉默认编码器」，守不住「加一条默认走不到的岔路」

- **From:** 票 `encoder-gate/01`
- **Kind:** 票面根因只说了九成，差的那一角直接决定 `04` 走哪一支
- **Where:** 这道闸的入口 `tests/pipeline.rs` 的 `classify`／`assert_on_grid`
  （四条用例全部经 `fixtures::request` 那一趟，**一个 flag 都不加**，或只点
  `--bit-depth`／`--dither`／`--gray-levels`）；
  对面是 ADR 0004 的《决定》第 2、3 条（`--codec=avif` 作显式可选项、编码器抽成接口）
- **Why it did not block:** 票面那句「让下一个想加有损编码器的人，在写第一行代码之前就撞上一条会红的用例」
  **在「换掉默认编码器」这条路上成立**——本票拿三处故意弄坏证过：把 `encode::png`
  改成按 8bit 原样写、取值挪开一级，`every_candidate_…` 当场红在
  「判定 2bit，却写出了格点外的 84」。
  **在「按 ADR 0004 抽接口、AVIF 挂在 `--codec=avif` 后面」这条路上不成立**：
  这四条用例一趟都不开那个开关，默认走不到的岔路它们一条都踩不着，
  新编码器进来时**一条用例都不会红**。
- **What this ticket actually did:** 没有自作主张改票面，也没有去按编码器维度铺开——
  那要先有编码器接口，而接口是 `04` 的地界，本票写死了不碰生产代码。
  闸按今天的形状立着：它守的是**写出去的那条既有主缝**。
- **Options:** ① 现状：这道闸只守默认那一条路，`--codec` 真加进来时另开一张票；
  ② `04` 落地时**按编码器维度铺开**——若走「决定第 2 条站得住」那一支，
  `every_candidate_the_pipeline_writes_comes_out_on_grid` 要变成每个编码器各走一遍
  （`classify` 与 `assert_on_grid` 眼下写死了 PNG：`recorded_verdict` 认 PNG 头、
  `assert_on_grid` 走 `fixtures::read_png`，两处都要跟着开一维）；
  若走「整篇取代、PNG 是唯一输出编码器」那一支，这个缺口**当场消失**——
  没有第二个编码器，也就没有默认走不到的岔路
- **Recommend:** ②，并且注意这一条**与 `04` 的两支强相关**：取代那一支不必做，
  保留 `--codec=avif` 那一支非做不可，否则 ADR 0004 的《后果》里写着的「两道闸」
  有一道在用例上是空的
