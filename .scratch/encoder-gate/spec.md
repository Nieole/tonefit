# encoder-gate — 接第二个编码器之前，先把两道闸立起来；再看 ADR 0004 还站不站得住

**Status:** ready-for-agent

## Problem Statement

ADR 0004 在 2026-08-25 拍了四条决定（默认 PNG、`--codec=avif` 作显式可选、编码器抽成接口、
判据层对编码器无知），**今天一条都没落地**：`--codec` 在 `src/` 里一处都没有，
`encode.rs` 的模块文档自己写着「ADR 0004 的编码器接口本身还没抽出来——P0 只有 PNG 一个实现，
AVIF 输出不在范围内」。

而「加第二个编码器」这个提案一直有人提，而且形态每次不同：WebP lossless（无损比 PNG 小）、
JPEG（三家设备都支持）、AVIF（中高质量区双轴都优于 PNG）、以及「每页试编码取体积小的那个」。
这些提案各自都有道理，**而它们被否掉的理由散在四处**：
一条在 ADR 0004 的《不要做的「简化」》里、一条在 measurements 的一张表里、
两条到这一轮设计评审才第一次写下来（《落格》那条不变量、页内元数据载体那道闸）。
散着的理由拦不住人——下一个提案会照旧从 `encode.rs` 上加一个 `match` 开始。

**更要紧的是 ADR 0004 自己可能站不住。**它收下 `--codec=avif` 的时候，
**从来没量过 AVIF 编完再解回来还剩多少级灰**。而《有损转存与灰调级数》量过另外两个：
真 29 级源 → JPEG q95 **215–217 级**、q85 **256**、q70 **256**、WebP q90 **200–202 级**、
PNG 重存 **29 级**。**那张表上 AVIF 一行都没有。**

如果 AVIF q60 也把 29 级还成 200 以上，那 ADR 0004 决定第 2 条就与 ADR 0003 的
**灰阶硬上界**当场打架：硬上界裁的是候选，而一个有损容器把像素还原成连续调，
阅读器拿到手还得自己降一遍——那正是 README 第一段说这个工具要防的事。
**一篇 ADR 自己和自己矛盾，而今天没有任何东西会红。**

## Solution

**不接任何编码器**，先把闸立起来，再去看 ADR 0004 还站不站得住。三件加一件调研：

1. **《落格》那条不变量在 `run` 那条缝上立成用例**。写出去的每一张灰度页，
   解回来的取值都还落在它那一档判定的格点上。它立起来之后，
   **任何有损编码器加进来当场红**——理由从一段文字变成一道机械的闸。
2. **补 AVIF 那一格测量**：同一个 29 级源、同一套口径，量 AVIF 编完解回来还剩多少级灰。
   `_samples/` 到位就跑得了。
3. **按数处置 ADR 0004**：数回来之前**不动它一个字**。AVIF 保得住落格，
   第 2 条站得住、只补一条依据；保不住，整篇取代。
4. **调研 AVIF 的页内元数据载体**（ADR 0009 新写下的那道闸：一个编码器进不了这个项目，
   除非它有页内元数据载体）。这一件不等素材，随时可做。

这张票交出来的不是一个新功能，是**两道闸加一个判决**。

## User Stories

### 立闸

1. 作为下一个想加 WebP 的人，我想在写第一行代码之前就撞上一条会红的用例，这样我不必等到 review 才知道这条路是封的。
2. 作为动管线的人，我想让「写出去的页还落在格点上」这件事由用例钉着，这样我改错了当场就知道，而不是等用户在真机上看见色带。
3. 作为读 `CONTEXT.md`《落格》那一条的人，我想知道它不只是一句话、有用例撑着，这样我信得过它。
4. 作为动彩色分支的人，我想让「彩页不在这条不变量里」也由用例说出来，这样例外是被测过的，不是被忘掉的。
5. 作为动坏页占位那一段的人，我想让占位页照旧说得出它为什么不在里面，这样例外的名单不会悄悄变长。
6. 作为动《留下的页》那一段的人，我想让原样搬过来的页照旧落格，这样「与整卷重做逐字节相同」这条性质连带被验了一次。
7. 作为在 LCD profile 上跑的人，我想让 8bit 那一档也在这条不变量里，这样它不因为「上界是 256」就被跳过。

### 量 AVIF

8. 作为要判 ADR 0004 还站不站得住的人，我想拿到 AVIF 编完解回来的灰调级数，这样那条决定不再站在一个没量过的假设上。
9. 作为量它的人，我想用与 JPEG／WebP **同一个源、同一套口径**，这样新数并得进那张表、比得了。
10. 作为量它的人，我想让**编码器与版本一并记下来**，这样后来的人不会再撞上《编码器对比》那张表「施测工具未记」的毛病。
11. 作为量它的人，我想在多个质量档上各量一次（q60 / q75 / q90），这样我看得出它是「某一档保不住」还是「哪一档都保不住」。
12. 作为量它的人，我想顺带量一格**无损 AVIF**，这样「有损才还不回来」这句话有对照撑着。
13. 作为没有 `_samples/` 的人，我想让这一格**明确跳过**而不是假装跑过了，这样 CI 日志读得出真假。

### 处置 ADR 0004

14. 作为几个月后读 ADR 0004 的人，我想看到它与灰阶硬上界的关系已经被量过、写清了，这样我不必自己重新推一遍。
15. 作为提「加 JPEG 吧，三家设备都支持」的人，我想在 ADR 里读到**真正的理由是有损、不是设备不支持**，这样我不会以为那是一条查漏就能补上的。
16. 作为提「加 WebP lossless 吧，无损比 PNG 小」的人，我想读到无损那一侧的数（三种无损均为源的 252%~291%），这样我知道那条路本来就是死的。
17. 作为提「两个编码器都试编码、每页选体积小的那个」的人，我想读到那三条理由，这样我不必再提第二遍。
18. 作为将来真要接第二个编码器的人，我想读到**进来的两个条件**（落格、页内元数据载体），这样我知道该先证明什么。

### 调研元数据载体

19. 作为将来要接 AVIF 输出的人，我想知道《记录》能不能挂进 AVIF 并读得回来，这样我不必在写完编码器之后才发现幂等没有落脚点。
20. 作为调研的人，我想让口径是「这条链上编得进、读得回来吗」，而不是「格式规范支不支持」，这样结论对我们手上这套依赖成立。
21. 作为调研的人，我想让结论**无论正反都写下来**，这样下一个人不必再查一遍。

### 边界

22. 作为用户，我想让这张票**一个字节的产物都不改**，这样我不必重跑任何东西。
23. 作为项目所有者，我想让这张票**不接任何编码器**，这样它不会在数回来之前就把结论烤进代码。
24. 作为读 `encode.rs` 的人，我想让那句「ADR 0004 的编码器接口本身还没抽出来」跟着这一轮的结论更新，这样代码里的话与决定对得上。

## Implementation Decisions

### 一、零新缝

这张票**一条新缝都不加**，三件各自落在已有的地方：

- 《落格》测在 **`run(Request) -> Report` 这条既有的主缝**上（见第二条）；
- AVIF 那一格是**一次性量具**，不是常驻用例，落在 `.scratch/encoder-gate/` 下
  （`.scratch/metric-recalibration/calibration/` 底下那几个标定脚本是现成的先例）；
- 元数据载体那件是**调研**，碰不到生产代码，结论落进 `docs/research/`。

### 二、《落格》逐页拿判定比，在 `run` 那条缝上

跑一卷，把**报告里每一页写出的那个文件**读回来，数它解出来的灰调级数，
比它那一页**判定的那一档**的格点数（`2^灰阶档位`）。
`tests/pipeline.rs` 头一条用例已经是这个形状——读回写出的页、拿判定比它的位宽，
落格只是在同一处多问一句。

**调色板那一支要单独走到。**`encode.rs` 在灰度与调色板之间按字节取小者，
两种写出的像素完全相同——两支都必须被这条用例盖住，
否则「取小者不牵动画质」那句话只有一半被验过。

### 三、「哪些页在这条不变量里」由**有没有判定**说了算

不另列一张例外名单。《灰阶分布》那条词条已经写着「**彩页与坏页没有判定**，不在里面」，
因此：

- **有判定的页** → 落格必须成立；
- **没有判定的页** → 它必须是彩页、坏页占位，或透传文件。

这样例外不是被跳过的，是**被测出来的**：将来多一类没有判定的页，这条用例会逼人说清它是什么。
《留下的页》照旧在里面——它从上一趟原样搬来，判定随字节一起搬来，落格跟着成立
（顺带把「与整卷重做逐字节相同」那条性质又验了一次）。

### 四、AVIF 那一格的施测条件

- **源**：与《有损转存与灰调级数》同一个——改革之獸的那 3 页真 29 级灰源。
  那一节没记是哪 3 页，这一趟按「灰调级数恰好 29」现挑并**把页名记下来**。
- **档位**：q60 / q75 / q90，与《编码器对比》那张表对齐；**另加一格无损 AVIF** 作对照。
- **编码器**：`[dev-dependencies]` 里现成的那一份（`image` 的 `avif` 特性，走 ravif）。
  **不加任何运行时依赖**——这张票不接编码器。
- **口径**：编出来再解回来，数解出来的灰调级数，与「原」和「PNG 重存」并排。

**新数单独成一小节，不并进《编码器对比》那张表**：那张表的 AVIF 与 WebP
用什么编的没有记（`dr/01` 已经在那儿补了一句「施测工具未记」），
两把尺子并排摆就是再造一次同样的毛病。新这一节**编码器与版本一并写进施测条件**。

### 五、数回来之前不动 ADR 0004 一个字

两种处置，形状差得远，不值得先写一版再推翻：

- **AVIF 保得住落格**（解回来仍是 29 级）→ ADR 0004 决定第 2 条站得住，
  给它补一条依据，并把「第二个编码器要过的两道闸」写进《后果》。
- **AVIF 保不住落格** → 决定第 2 条与 ADR 0003 的灰阶硬上界打架，
  **整篇取代**：新一篇把 PNG 定成唯一输出编码器，理由是《落格》，
  并把 WebP／JPEG／AVIF 三条各自的数写进《备选方案》。

**无论走哪一支，「不要做的『简化』」那一节原样留着**——那三条理由（可读性逐页漂移、
两条曲线形状不同单一阈值比不了、按体积选优会让 2bit 以下那段非对称看不见）
与 AVIF 保不保得住落格无关，它们照旧成立。

### 六、元数据载体调研的口径是**这条链**，不是格式规范

问的不是「AVIF 规范支不支持 XMP／Exif」，是「**我们手上这套依赖，编得进去、读得回来吗**」：
写一段进去、读出来逐字节相同吗；`--no-metadata` 那条路照旧关得掉吗；
取值要不要像 tEXt 那样受 Latin-1 约束（《记录》今天「取值一律 ASCII」就是被 tEXt 逼的）。
**结论无论正反都写下来**，落进 `docs/research/`，与另外两篇同一个位置。

### 七、`encode.rs` 那句模块文档跟着这一轮改

它今天写着「ADR 0004 的编码器接口本身还没抽出来——P0 只有 PNG 一个实现，AVIF 输出不在范围内」。
这句话在 2026-08-25 是「还没做」，这一轮之后它要么是「不做」、要么是「要过两道闸才做」。
**代码里的话与决定对得上**是这张票的一部分。

### 八、这张票不接任何编码器

不加 `--codec`、不抽编码器接口、不动 `encode.rs` 的编码逻辑。
**产物一个字节都不变**——黄金回归因此一格都不该动。

## Testing Decisions

**什么是好的测试**：只断言**外部看得见的事实**——`Report` 里的内容、写出的文件有什么性质。
不断内部怎么走。这一条与 `tests/pipeline.rs` 的模块文档同一句话。

### 一、《落格》那条用例摆在哪

摆在 `run` 那条缝上，与 `tests/pipeline.rs` 现有那批同处。要盖住的：

- **六个候选各走到一次**（1bit、1bit+FS、2bit、2bit+FS、4bit、4bit+FS）：
  造得出各档判定的夹具在 `tests/fixtures` 里都有（`solid`、`gradient`、`screentone`、`line_art`）；
  盖不全时用 `--bit-depth` / `--dither` 顶死，顶死的页照样要落格。
- **灰度与调色板两支各走到一次**（第二条）。
- **8bit 那一档**：`--gray-levels` 开到 LCD 那一档走得到。
- **有判定 ⇄ 落格、没判定 ⇄ 彩页／坏页／透传**这条双向对应（第三条），
  用一个混排卷一次盖住：彩页、坏页（`truncated_page`）、透传文件、灰度页各一。
- **《留下的页》**：跑两趟、第二趟按页跳过，搬过来的页照旧落格
  （`tests/idempotency.rs` 有现成的两趟夹具）。

### 二、AVIF 那一格不是用例

它是一次性量具，产出是 `docs/measurements.md` 里的一节，不是一条断言。
没有 `_samples/` 时**明确跳过**，走 `tests/smoke.rs` 那条自带 harness 的路——
内建 harness 的跳过印出来是 `test ... ok`，读 CI 日志的人会把它当证据。

**如果量出来 AVIF 不落格**，那结论**顺带变成一条常驻用例**：
「AVIF 编一张真 29 级页、解回来的灰调级数大于 29」——
它钉住的正是新那篇 ADR 的依据，将来有人换编码器换出别的结果时当场红。
量出来保得住就没有这一条，只有那一节数。

### 三、单一出处

`tests/single_source.rs` 那一批加一条：**《落格》那条不变量的说法只有一处**
（`CONTEXT.md` 的《量化》），用例与 ADR 里都只指过去、不抄第二份。
这一条与那一批既有的形状相同（`CLAUDE.md`《文档写作》第 4 条：单一出处）。

### 四、闸门

这张票触及编码器与位深——按 `CLAUDE.md` 的《闸门》，落地收尾**三条都跑**
（`cargo xtask gate`），另过一遍 `cargo xtask polish`，票据的《数》记下各自最后一行。
**黄金回归一格不该动**：这张票不改一个字节的产物，它动了就是有人碰了编码。

## Out of Scope

- **接任何第二个编码器。**AVIF、WebP、JPEG 一个都不接。这张票只立闸、只量、只判。
- **抽编码器接口**（ADR 0004 决定第 3 条）。等这一轮判完再说：
  要是走「整篇取代」那一支，这个接口根本不该存在。
- **`--codec` 这个命令行出口。**同上。
- **《放大那一支》那一格测量。**它与编码器无关，虽然和 AVIF 那一格一样等 `_samples/`；
  数出来之后再决定要不要为它开票。
- **给 AVIF 真的挂上元数据。**这张票只调研「挂得上吗、读得回来吗」，不实现。
- **有损输出在「第三方阅读器＋用户自己负责」那一格要不要开。**
  那一问在这一轮之后才问得起，且它先要过《落格》那条不变量——
  按今天写下的形状，它进不来。

## Further Notes

**这张票的三件事不是一条链。**《落格》那条用例与元数据载体调研**都不等 `_samples/`**，
可以立刻开工；只有 AVIF 那一格等素材，而 ADR 0004 的处置等那一格。
排期上因此是「两件先走，一件等，最后一件收口」。

**与 `proof-sheet` 那张票的关系**：两张各自独立，只在一处搭界——《落格》那条不变量
两边各测一半：这一批测 `run` 写出的页，那一批测样张写出的图。
谁先落地都行；那一张不等任何东西。

**为什么闸要立在用例上，而不是只写进 ADR。**这个项目已经有九处交付过的文档与事实对不上的先例
（`p4-parking-lot` 的《Problem Statement》记着那件事：`fast` 模式在实现里并不存在、
80 页/秒、折算系数 8、31 个内置型号……「它们各自都曾是真话」）。
一条只写在文档里的约束，靠的是下一个人读到它。**一条写成用例的约束，靠的是它会红。**
