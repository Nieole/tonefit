#### Q500 — 「众数尺寸」那一栏钉不住一卷，而它被当成过「这一趟用的是哪一份语料」的证据

- **From:** 票 `two-pass-rework/08`
- **Kind:** 我确实拿不准的单项（一栏数据被引到了它撑不住的用途上，五卷里只核了一卷）
- **Where:** `docs/measurements.md`《A 类素材普查》那张表的**众数尺寸**栏
- **Why it did not block:** 那一栏写的就是众数，没有说错；错的是**引它的人**——
  从前《这张表有两格……》拿「普查已经把这一趟的 Venus 钉在 2108×3000 上」来论证素材不是变量。
  实测：Venus 129 页高恒 3000、宽 1884–2211、共 47 种尺寸，众数 2108×3000 只占 **12 页（9.3%）**。
  本票已经把那句改掉（改用哈希钉），论证不再靠它。
- **What this ticket actually did:** 只在《A 类素材普查》被引的那一处旁边订正了引法，
  **普查表本身一格没动**；另外四卷（棋魂、改革之獸、哆啦A梦、JOJO）的尺寸分布**没有量**。
- **Options:** ① 照现在，只订正引法；② 五卷各补一个「尺寸种数 / 众数占比」栏；
  ③ 五卷各补一个容器哈希，让「用的是哪一份」永久答得出。
- **Recommend:** ③ 优先于 ②。「这一卷长什么样」有别的栏在答，而「用的是哪一份」今天全库只有
  Venus 一卷答得出——同一个坑在别的卷上照样开得起来。③ 的代价是五条 sha256（本票量 Venus
  那一条不到十秒）。② 是好看不解决问题的那种补法。
- **Whose call:** 落地的人（`16` 重跑那两张体积表时顺手，它本来就要写施测条件）
- **处置：** 待处理。

#### Q530 — 票面第 3 条那个 94.6%，在它自己点的那一节里查不到

- **From:** 票 `tone-alignment/02`（第 3 条：「绝大多数页是 0 或 1（全语料 94.6%）」）
- **Kind:** 实测数字的单一出处破了一个口
- **Where:** `docs/measurements.md` 的《全语料普查：四成三的页纸白不落在格点上》；
  `.scratch/tone-alignment/spec.md` 的《Solution》与《Implementation Decisions》第 6、10 条
- **Why it did not block:** `CLAUDE.md` 写着「需要实测数字时，来源只有 `docs/measurements.md`」，
  而那一节的表只给两档：离格量 **0 是 57.0%**、**1–2 是 41.5%**。
  94.6% 要拿 spec 正文里那个更细的拆分（**37.6% 离格 1 级、3.2% 离格 2 级**）
  才凑得出（57.0 ＋ 37.6 = 94.6），而**那个拆分不在 measurements**——它只在 spec 里。
  顺带：37.6 ＋ 3.2 = 40.8，与表上那一档的 41.5 也差 0.7 个百分点，两处对不上。
  代码里不写 94.6 就绕得开，因此不阻塞。
- **What this ticket actually did:** 代码注释与用例文档**不引 94.6%**，
  改引那一节真写着的两档（57.0% 与 41.5%），再说一句「绝大多数页的钳制宽度因此是 0 或 1」。
  measurements 与 spec 都没动。

  **落地时漏了一处，`/code-review` 的 Standards 那一轴抓了出来**：`render.rs` 一处用例
  文档还引着 94.6%，而本条与票面第 3 条那两句都写着「代码不引它」——**一个数漏进代码，
  让两份声称它没漏的文档同时说谎**。这一处本身就是「单一出处」为什么是硬规矩的样本：
  破口不在那个数算得对不对（它算得出来），而在**同一件事从此有两个地方各说各的**——
  其中一处一漏，另一处当场变成假话，**而没有任何东西会因此变红**。
- **Options:** ① 照现在（绕开那个数）；
  ② 把 1 级／2 级那两档补进 measurements 那张表，让 94.6% 有出处，
  顺带查清 40.8 与 41.5 差的那 0.7 是取整还是两次普查口径不同；
  ③ 把 spec 与票面里的 94.6% 改成 measurements 真写着的说法。
- **Recommend:** ②。那两个数是同一次普查算出来的，补进表里不必重跑；
  而 0.7 那个差**要查**——两处不同源的话，spec 里那句「≤4 覆盖 99.1%」也跟着可疑，
  而 `05` 号票要拿它当抬默认值的依据。③ 只改口不补数，下一个要这两档的人还得再找一遍。
- **Whose call:** 拿得到 `_samples/` 与普查脚本（`survey_flat.py`）的人
- **处置：** 待处理。

#### Q413 — `docs/measurements.md` 的《介质与读取策略》没说那批「归档卷」是哪种格式，而摊开的那种从此不按顺序扫读

- **From:** 票 `p4-parking-lot/14`
- **Kind:** 落地时走的那条路（票面给了「真需要就记停车场，别编」，而这一处要真实素材才量得回来）
- **Where:** `docs/measurements.md`《介质与读取策略》——探测那张表第一行「归档卷两遍串行、幂等那一道并发 32」，
  代价那张表底下「归档卷是一条顺序扫，机械盘只贵两成半」；另有《收益随源字节走，不随页数走》底下那句
  「目录卷不在这张表上——它的幂等那一道本来就并发」。
- **Why it did not block:** 那几处记的是**跑出来的数**，不是实现此刻的行为，数本身一格没变。
  变的是「归档卷」这个词从此不再指同一批卷：`.cbz` / `.zip` 仍是一条顺序扫，
  `.7z` / `.rar` 摊开之后按那个临时目录所在的介质走，两路取同一个数。
- **What this ticket actually did:** 一个字没动。整份 `grep` 过 `cbz` / `.7z` / `.rar` / `zip`，
  `docs/measurements.md` **一处都没有**——那批卷是哪种格式，这份文件自己说不出来，
  我因此判不出那几行今天是不是仍然照实。`_samples` 语料不在这台机器上（派活说明已核实），
  重量一遍这一轮做不到。
- **Options:** ① 照现在（数照留，措辞不动）；② 把那几处的「归档卷」改成「随机取的归档卷」——
  前提是那批卷真的是 `.cbz`，而这一点眼下没有出处；③ 在有 `_samples` 的机器上重跑一遍，
  两种读取端各记一行。
- **Recommend:** ③，落到有语料的机器上。**②在拿到出处之前不能做**：改了措辞就等于替那批跑过的卷
  认下一种格式，而那正是编数。①是拿到出处之前唯一照实的状态。
- **Whose call:** 拍板的人
- **处置：** 待处理。
