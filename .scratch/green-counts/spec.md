# green-counts — 绿要作数：闸门工具补齐，黄金快照说得出它看了哪几维，本机语料上把欠着的数补量

**Status:** ready-for-agent

## Problem Statement

维护者每落一张票都靠三样东西证明「没改坏」：三条闸门全绿、黄金快照一个字节没动、实测文档里的数。三样都有说不清的地方：

1. **绿说明不了它没看的地方。**
   - `xtask` 自己不在任何一条闸门里，两遍 clippy 也扫不到它；它那个把 `test result:` 数成两个数的纯函数一条用例都没有（停车场 Q208）。
   - bin 的文档链接没有人验——`cargo doc` 跳过与库同名的那个 bin，一跑 `cargo rustdoc --bin` 就是几十条告警，
     其中一整类是「数 `super::` 数错了级」「少写了 `terminal::` 那一段」（Q511、Q508、Q509）；
     「跨可见性写代码跨、不写方括号链接」那条写法一直没写进规矩（Q512）。
   - `cargo xtask gate` 跑满三条时中途不印任何一条的结果，想中途掐掉或降并发只能连头一条的数一起丢（Q284）；
     《数》那张表不带平台，同一份代码 Linux 与 Windows 差一两条，读的人不知道该跟谁比（Q562）。
2. **「黄金没红」被读成「判定没变」。**快照一卷覆盖顶死都没有（Q544）；贴着界的逐页理由只有一行，还是一张离界很远的救回页（Q473）；
   一页纸白钳得动的都没有，抬默认值那一次它一个字节都没拦住（Q550）；`--envelope` 那一组与默认组重复跑着一批短卷（Q634）；
   纯色 96 那个夹具原本演示两套机制，界降到 5.123 之后两条路演示的是同一套（Q467）。
   **快照到底盖住了哪几维，从来没人系统答过**，于是每张票都各自以为它兜着自己。
3. **实测文档里欠着几个数。**`_samples/` 从前不在开发机上，这几件就挂着——而语料如今就在这台机器上（16 GB）：
   - 画集 Venus 的「4bit 不抖」读数中位从 5.011 挪到 5.300，那一档不该被地板碰到，没人知道是哪一次改动动的它（Q469）；
   - `two-pass-rework/12` 那句「峰值内存显著下降」一次都没量过（Q429）；
   - 五卷里只有 Venus 说得出「这一趟用的是哪一份语料」（Q500）；
   - 「全语料 94.6% 的页钳制宽度是 0 或 1」那个数在实测文档里查不到，拼出它的两档与表上那一档还差 0.7 个百分点（Q530）；
   - 纸色提白默认开着之后，它单独摘出来会不会进前三大开销，没人量过（Q517）；
   - 《介质与读取策略》那批「归档卷」没说是哪种格式，而摊开的那种如今不按顺序扫读（Q413）。
4. **判读工具里两处会误导下一轮。**造包的配平按隔对交替，判读者察觉得到——「位置偏好已排除」因此是循环论证（Q462）；
   「连续灰调面积」那一支名字听上去就是「色带风险」，下一个人会拿错那一支（Q463）。

## Solution

- **闸门工具补四处**：`xtask` 进 clippy、有自己的用例；跑满三条时每跑完一条就印那一条；《数》带平台；
  `cargo rustdoc --bin tonefit` 收进 `polish`，告警数记进《数》只降不升，那两类指不到的链接顺手清掉，写法规矩进 `docs/agents/`。
  **闸门照旧三条。**
- **黄金快照有一张覆盖表**：模块文档里答清它盖住了哪几维、各由哪一卷盖住；照表把已知的三个空维各补一个短卷，
  砍掉 `--envelope` 组里重复的短卷，纯色 96 那个区分挪到一条独立用例。
- **本机语料补量**：上面那六件在本机量完，写进实测文档，施测条件照规矩写全（包括逐卷读数落在哪儿）。
- **判读工具两处订正**：配平只剩一份不可预测的实现；历史口径那一支标明是历史口径。

## Implementation Decisions

### 闸门工具（Q208、Q284、Q562、Q511、Q508、Q509、Q512）

- **闸门照旧三条。**多出来的检查全进 `polish`：`clippy -p xtask`、`xtask` 自己的用例、`cargo rustdoc --bin tonefit`（带私有项）。
  `polish` 从四步变七步；`gate.md` 那张表与《读结果》跟着改。
- **逐条印结果**：每跑完一条闸门，当场印那一条的通过与失败数（一行），末尾照旧印整张《数》。
- **《数》带平台**：表头一行印平台（操作系统与架构）；`gate.md`《读结果》写一句「数只与同一平台的上一趟比」。
- **bin 的文档检查**：告警条数与 `cargo doc` 那一条同一副做法——印出来、记进票据的《数》、只降不升，不由工具写死阈值。
  落地这一张先把会话里那两类指不到的路径改对（少写了 `terminal::` 那一族、`super::` 数少了一级那一族；落地时用一条 `git grep` 数现存的，
  不抄停车场里的数），基线从改完之后那个数起。
- **写法规矩**进 `docs/agents/`（与闸门那一篇同处）：跨模块指路写 `crate::` 全路径、不数 `super::`；跨可见性写代码跨、不写方括号链接
  （方括号链接按可见性解析，指向私有项的那一条本身就是一句假话）。
- `xtask` 里值得用例的是纯函数：数 `test result:` 那一行、逐条那一行的措辞、平台那一行；要跑进程的部分不写用例。

### 黄金快照的覆盖表（Q473、Q544、Q550、Q634、Q467）

- `tests/golden.rs` 的模块文档立一张表：**维度**（路径：默认逐页 / `--envelope`；适配方式；裁边与拆分；彩色分支；坏页与残缺页；
  覆盖顶死；界边的逐页理由；纸色提白钳得动；上包络与迟滞……）× **由哪一卷盖住** × **明写不在的维度与理由**。先写表，再照表补。
- **已知三个空维各补一个短卷**（两三页）：
  - 覆盖顶死：两维都点了的那一种（默认路径上唯一还叫覆盖顶死的那一种，见 `one-source` 那一批）；
  - 界边的逐页理由：逐页展开、不走卷级摘要；页上的取值**相对阈值算出来**（读画质门槛的那一处出处），不写死一个数；
  - 纸色提白钳得动：一页纸白 253（现成的夹具）。
- **`--envelope` 组砍掉与默认组重复的短卷**，只留默认组够不着的（长卷、彩色、fit-inside、`keep`）；「`--envelope` 那条路逐字节不变」的证人照旧是那几个长卷。
- **纯色 96 那个区分**挪到 `tests/pipeline.rs` 一条独立用例：「门成立那一支走界内最低一档」用一张读数相对阈值构造的页钉住，不依赖某个纯色取值落在界的哪一侧。
  那个纯色常量照旧在，文档照实说它今天演示的是哪一套。
- 快照为这一批显式接受一次；diff 里只有新加的三卷与砍掉的那几卷。

### 本机语料补量（Q469、Q429、Q500、Q530、Q517、Q413）

- **一律照实测文档的规矩写**：数只进 `docs/measurements.md`；施测条件写全（机器、提交、参数、语料、施测日期）；
  一趟宽跑写明**逐卷读数落在哪儿**；画质分的数一律取 `tonefit --dry-run` 的输出（这两条是实测文档开头「记进这里之前」那两条规矩）。
- **Venus 二分（Q469）**：在旁开的工作树里建旧版本，从 `476462d` 到 `b6106fb` 之间逐版重扫画集 Venus（fit-inside、不裁边、不拆分、boox-poke6），
  钉死中位那 0.289 落在哪一次改动上；结论与三组数写进《几何门不成立的代价》那一节，替掉那条「本轮断不出」的引言。
- **峰值内存（Q429）**：同一卷、同一台机器，`two-pass-rework/12` 之前与今天各量一次进程峰值常驻（本机取峰值工作集），
  写进《缓存溢写》；「显著下降」照数改口或落实。
- **容器哈希（Q500）**：《A 类素材普查》五卷各一条 sha256（Venus 那一条已有）。
- **94.6% 的出处（Q530）**：重跑纸白普查那支脚本取离格 1 级、2 级两档，补进《全语料普查》那张表；查清 40.8 与 41.5 差的 0.7；
  `tone-alignment` 的 spec 与票面里那几处照查清的结果改口。
- **纸色提白的开销（Q517）**：`profiling` 构建下临时把提白单独掐一次表，按 `Stage` 自己那条判据（单独摘出来会不会改变前三大开销的名单）判：
  进了就正式加一格，连带《阶段》词条与闸门 3；没进就只把量到的数写进剖面那一节、不加格。
- **介质那一节的措辞（Q413）**：那一卷是棋魂完全版 Vol.01（609 MB），语料里只有 `.cbz` 与 `.zip` 两份，都是随机取；
  那几处「归档卷」改成「随机取的归档卷」，并写明摊开的那种（`.7z`／`.rar`）按临时目录的介质走、这里没有量。

### 判读工具（Q462、Q463）

- **配平只剩一份**：`arrange` 那一行换成打乱一份配平好的翻转表（第十轮那一支的做法）；文档写明第七、九轮是旧编排、老数据对的是已落盘的答案键。
- **历史口径标明**：「连续灰调面积」那一支的模块文档写明它是第九轮分层选页用的历史口径、量的是代理量；新用途一律走色带风险面积那一支。脚本不删。
- 两支改完在本机各跑一次自带的自检。

## Testing Decisions

### 什么是好测试

只断言外部行为：`xtask` 印出来的那几行、黄金快照的字节、一趟跑出来的判定与理由。实测那一半没有「测试」——**数本身就是交付物**，
它的可信度来自施测条件写全、读数落处写明、画质分取自 `--dry-run`。

### `xtask`

- 纯函数的用例：数通过与失败（几种 `test result:` 的写法、带颜色转义的那一种）、逐条那一行、平台那一行。
- 跑的地方是 `polish`（闸门照旧三条）。

### 黄金快照

- `tests/golden.rs` 照旧是那一篇；覆盖表在它的模块文档里。新三卷进快照、显式接受一次；「改了快照绝不会被静默接受」那条用例照旧守着。

### 独立用例

- `tests/pipeline.rs` 添一条：门成立那一支走界内最低一档，页的读数相对阈值构造。先例：那一篇里既有的「抖动能把一页拉回界内」一族。

### 闸门

- 三条闸门跑满；`polish` 七步过一遍，bin 的告警数与 `cargo doc` 的告警数都记进《数》。

## Out of Scope

- 把 bin 改名好让 `cargo doc` 自然收得到它（动 crate 布局，牵一大批路径）。
- 为 Python 判读脚本另立测试框架。
- 「黄金快照每条改像素的管线步骤都至少有一卷走得到」立成一条机器守卫——本批只立覆盖表并补已知的三维。
- 阈值窗口在今天的几何上重扫（Q723，拷问判不做）。
- `.7z`／`.rar` 摊开之后在机械盘上的读取代价（要一块机械盘与那种卷，另一回事）。
