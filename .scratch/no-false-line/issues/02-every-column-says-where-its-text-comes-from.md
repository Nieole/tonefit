# 02: 每一列说得出自己的字面出处

**What to build:** 「哪几格的字面要过宽度这一关」在仓库里有**两处出处**——
三个 `Column` 枚举，和措辞那一层用例里一份手抄的名单。往表里加一列，
那份名单不跟着加**也不会红**。

逐页表添了五格几何列之后，裁边与缩放两格进了对齐的列，而名单没跟着添——
**预言过的后果原样发生了**，而那两格的字形是歧义宽度，CJK 终端上此刻就在错位。

收拢：**每一个 `Column` 变体自己声明它的[字面出处](../../../CONTEXT.md)**——
[措辞](../../../CONTEXT.md)（界面层造的）、[原样](../../../CONTEXT.md)（用户数据）、
还是[记号](../../../CONTEXT.md)。加一个变体不写这一格，**编译就过不去**。
手抄那份名单改成从它导出，然后删掉。

**字形本身不在这一票查。** 三档各归一条已经存在的规矩：措辞 → 造字面的那一层管
（库出的归 `p4-parking-lot/30`，bin 造的归措辞那一层既有那条用例）；
原样 → 摆不下时从中间省略（[砍列](../../../CONTEXT.md)那条）；记号 → 表这一层那条。
`Column` 只负责**说出这一格该归谁管**。

收拢做得成的前提是一处事实：**`session::columns` 不在 `tui` 特性后面**，
只有画法与终端那两个模块在。挡住上一次的墙比记的窄——真正在特性后面的只有
「格到列」那份**映射**，而字面出处不必走那份映射。

列与格**不是一对一**（记号那一列压根不是一格字、页名那一列从另一行补上、
判定那一列对的是另一个名字的格），所以出处挂在**列**上，不挂在格上。

收停车场的 **Q187** 的 bin 那一半、**Q188**。

**Blocked by:** `p4-parking-lot/30` — 库认下字形约定。
名单一从字面出处导出，裁边与缩放就进了闸门，而它们的字形还是歧义宽度（在库里）——
**30 落地之前这一票跑不绿**。
