# 02 — 从设计稿导出快照、场景数据与交互期望屏，测试侧逐格比对

**What to build:** 让「照设计稿实现」成为一条会变红的用例（spec《设计快照是验收标准》《导出》）。

**导出**（脚本放在设计稿旁边，node 在伪 DOM 里跑设计稿自己的脚本，不需要浏览器）：

- 冻结 `performance.now`；场景推进用 `fastForward` 的固定步长；屏底的回话与按键提示照样导出；
- **快照**：11 个场景 × 120×36、80×24，外加 56×14「窗口太小」两份（还没开始、转换中）。每一份一张**字**网格、
  一张**样式**网格（每格一个代号，代号表随那一份附着），一行一屏行、两侧加引号；宽字符后半格按 `TestBackend`
  的读法跳过；顶栏版本号导出成占位；
- **场景数据**：每个场景那一刻的语义数据——处理路径与勾选、清点清单（卷根、源页数、步数）、每卷此刻怎么样与它的
  逐页结果（档位、原因的种类、失败原因、需留意的几样，**不是屏上的字**）、非漫画文件与无法访问的地方、耗时
  （已乘设计稿的时间倍数）、会话状态（视图、光标所在行、展开的目录、每页结果开着哪一卷、覆盖层、输入行）、设置与预设；
- **交互期望屏**：每一串输入在设计稿里用它自己的按键分派回放（鼠标按格坐标回放），导出走完那一屏。序列里可以夹
  「推进模拟 N 秒」这一步。每串有名字。要导出的是 spec《交互序列》列的每一条，**外加本目录各票验收里点名的序列**——
  后面的票只按名字认领，不再往设计稿那边加。
- **样式对照表**：设计稿类名 → 16 个具名色与修饰（加粗、压暗、下划线、斜体），一张；`c-fg` 是终端默认色。

**测试侧**（Rust）：读快照与期望屏；给 `TestBackend` 画出的整屏逐格比字、前景色、修饰；代入 crate 版本号；
对不上时印出实际那一屏的两张网格。现成的 `same_screen` 只比字、`OnScreen::colours` 是每行去重的颜色集合，都不够。
