# 04 — 非卷文件清单

**What to build:** 跑完一趟，报告上多出**第三张表**：发现走完之后没被任何卷收下的东西，逐条列出，每条带路径与一句为什么。它不转，也**不拷进输出目录**——这正是触发这一轮的那件事。

三类：卷架上既不是页也不是归档的文件、一页都没有的归档、发现出来但点不开的归档。

它挂在报告上而不是只印在 stderr：《进度》明写「CLI 与 TUI 拿的是同一份数据，不是两套」，进报告两边就都有。

**非卷文件不是失败**，四个退出码一格不动。

**卷内的透传文件不在这份清单里**，也照旧搬进输出容器。两者是两件事：`ComicInfo.xml` 是产物的一部分（阅读器靠它读作者、卷号、阅读方向），砍掉是净损失；而触发这一轮的那批 cbz 全在清单这一群，发现规则一落地就自己了结了。

**Blocked by:** 03 — 发现（这份清单是发现的另一半产出）。

**Status:** resolved

- [x] 造一棵树（两层 cbz、混装目录、一页都没有的 zip、坏 zip、卷架上的 txt），跑一趟，清单与输出树的形状**逐条**对得上
- [x] 三类各自印出自己那句为什么，分得开
- [x] CLI 与 TUI 印出来的是同一份数据
- [x] 清单不为空**不影响退出码**
- [x] 卷内的透传文件仍原样搬进输出容器，且**不出现在清单里**
- [x] `CONTEXT.md`《失败》写明非卷文件不是失败
- [x] 三条闸门全绿

## 落地记录

### 第三张表在哪里算出来

不在 `discover` 里，在 `survey` 里。理由是一句能立住的：**发现不打开任何东西**
（`src/discover.rs` 的模块抬头），而三类里有两类只有开卷才答得出——「这个归档一页都没有」
与「这个归档点不开」。剩下那一类（卷架上既不是页也不是归档的文件）同样要开卷才定得下来：
同一个 `说明.txt`，躺在**有页**的目录里是那一卷的透传成员、照旧搬走，躺在**没有页**的
目录里才是非卷文件——分界只有「它躺的那一层有没有页」这一条。

因此 `discover::of` 的签名**没有改**。改了也只能交出一批「疑似」，`survey` 还要按开卷的
结果再筛一遍，而且 `discover` 那一侧还得自己再写一遍「什么算页」「什么是打包环境的垃圾」——
`03` 刚把那两条收敛到 `source` 一处。落到 `survey` 之后这两条一个字都不必再抄：
一页都没有的候选，目录卷交出来的 `extras` 就是它没能收下的那些（归档、子目录、垃圾文件
都已经被 `source::open_directory` 摘掉了），照单收下即可。

`Survey` 因此有了第二半，`into_volumes` 改成 `into_parts` 一次交出两半：卷那一半是被
逐个吃掉的，分两次取就得给它留一份克隆。

### 三类怎么分

库这一侧只出数据：`NonVolumeFile { path, reason }`，`reason` 是三个变体的
`NonVolumeReason`，**措辞在界面层**（`render::non_volume_reason`）——这与 `VolumeVerdict`
同一条规矩，也是 `render` 模块抬头那句「库那一头出数据，措辞是这一侧的事」。
点不开那一条带着由内到外的错误链，与 `VolumeFailure::reason` 同一个待遇。

**空目录与纯粹的卷架一条都不留**：那张表列的是**文件**，而它们没有落下任何文件。
每个卷架都占一行的话，一座正常的库就能把清单刷满。这一句补进了 ADR 0014 决定第 3 条——
spec 的《卷至少有一页》把「空目录」也写进了那一栏，与《非卷文件》那三类对不上（见下）。

### 命令行与会话是同一份

数据只有 `Report::non_volume_files` 一列，文字只有 `render::non_volume_tail` 一处，
而末尾那几小结两边都走 `render::tail`（命令行经 `render::report`，会话经
`session::draw` 的报告区）。**没有第二份实现，因此不必靠用例去拴住两边一致。**
`src/session/` 只动了一处：`Live::new` 里那份攒到一半的报告要多填一格 `Vec::new()`——
不填编不过。会话那一侧的分组展示仍是 `08` 的事，`draw.rs` 一个字没动。

### 那一小结排在末尾几小结的**最前面**

`render::tail` 的次序是「按出的事有多重往下排，最重的压在末尾」。非卷文件是这一列里唯一
**连失败都不是**的一种，因此打头。同一个理由让它不进任何一条退出码判据：
`any_isolated` 与 `any_volume_failed` 都不看它。

### 「一页都没有的卷是 `None`」那处旧措辞

spec 点名要清掉的那一处（`render.rs` 的 `verdict_lines`）**`03` 已经清掉了**
（`4fe683d`：「一页都没有的卷只装着透传文件」→「一张灰度页都没有的卷（只装着彩页的、
整卷全失败的）」），`report.rs` 那一句同批改过。本票复查了全仓库，没有第二处。

### ADR 0014 就地修订

状态行那句「决定第 3 条的非卷文件**清单**尚未实现」删掉；决定第 3 条补上「另一半」——
那张并列的第三张表、三类、为什么挂在报告上、卷内透传文件为什么不在上面、以及空目录与
卷架为什么一条不留；《要认的代价》里「用户看不出哪些东西没被转」那一条随之作废，
换成「多开那一次顺带答出了没被收下的是哪几个」。**不新增 ADR。**

### 停车场

新开四条，都留在《待处理》：

- **Q114**（既有缺陷，非本票造出）——缩进后面跟着一长串断不开的字（长路径）时，
  `wrap::fold_line` 先折出一个空行。非卷文件与卷级失败两小结逐字同形，撞上的是共用的那份
  折行，没有动它。
- **Q115**（路过发现）——「列前几条，剩下的说个数」现在是第五处，而 Q49 记的还是四处。
  照 Q49 自己立的规矩，没去改 Q45／Q49 的正文，条数记在新条里。
- **Q116**（spec 内部不一致）——《卷至少有一页》把「空目录」算进非卷文件那一栏，
  而《非卷文件》把那一栏定成三类**文件**。按后者落地，分别写进 ADR 0014 决定第 3 条。
- **Q117**（既有缺口）——发现出来的一个**目录**读不动时至今一声不吭。本票把这一格
  明确成「跳过」（见下），补上它要么给非卷文件加第四类、要么另立一栏，两条都是拍板级。
- **Q118**（既有缺陷）——闸门 2 的 `the_minutes_spent_deciding_are_charged_to_nobody`
  五趟里红三趟：`Live::overall` 在一句里读了两次表，机器一忙、两次之间被抢走就掉到
  300s 以下一点点，而那条断言一格余量都没有。与本票无关（三条证据记在条目里）。

### 评审那一轮改了什么

`/code-review` 两轴各报了一批。**Spec 一轴查出一处真错**，照单改掉：

- **`Unopenable` 会落在一个目录上。** `source::open` 对**目录**候选出错时（权限不足、
  盘拔了）与归档走的是同一支，于是一个目录路径会进这张表——而 spec 的第三类写的是
  「发现出来但点不开的**归档**」，`CONTEXT.md` 的词条把三类都写成**文件**，
  ADR 0014 决定第 5 条同样只说归档。四份文档一致，代码是那个不一致的。
  改法：`discover::Candidate` 多带一格 `container`（列目录时本来就知道，不必再 stat），
  预扫按它分岔——点不开的**归档**上表，点不开的**目录**整棵子树跳过，
  与 `push_children` 里「列不动这一层」同一条处置。那条处置至今说不出口，记进 Q117。

Standards 一轴的几条：

- **一条断言其实什么都没问住**——`the_report_names_every_file_no_volume_took_and_why`
  原本拿一份 `volumes: Vec::new()` 的报告去断言退出码是 `0`，而那种报告本来就是 `0`：
  清单哪天被记成失败，这条也照旧通过。改成先用 `one_page_report` 真做成一卷，
  再把三条非卷文件挂上去——「做成了一卷 + 清单不空 ⇒ 仍是 0」才是要问的那件事。
  同一处的注释「这一趟正常做完了一卷」当时还与代码相反，一并改真。
- **`04 号票` 是个会撞车的引用**——`render.rs` 里既有的「04 号票」指的是部分救回那一批。
  本票新写的七处全部改成 `volume-discovery/04`，与 `03` 落地时的写法一致。
- **`into_parts` 说不出交出来的是什么**——改名 `into_volumes_and_non_volume_files`，
  预扫那条用例也不再拿 `.0` 取值，改成具名解构。
- **`WithoutAPage` 少说了一半**——那一类只可能是归档（目录那一侧落到 `NeitherPageNorArchive`），
  改名 `ArchiveWithoutAPage`。
- **`space.dir("")` 是拿目录构造器当根用**——给 `Workspace` 加了一个说得出口的 `root()`。

**没收的两条**：

- `non_volume_tail` 与 `failed_volume_tail` 的「截断清单」骨架重复——那正是 Q45／Q49
  挂着等拍板的那件事，抽件会顺手改掉既有两处的输出，因此照既有办法写第五处，
  条数记进 Q115。
- 「CLI 与 TUI 印出来的是同一份数据」没有用例——它不是一条测得出来的性质，是一条
  **结构事实**：数据只有 `Report::non_volume_files` 一列，文字只有 `render::non_volume_tail`
  一处，两边都走 `render::tail`。没有第二份实现可以走散，也就没有东西可拴。
  真要拴，得在会话那一侧造一趟带非卷文件的真跑，而 `src/session/` 归 `08`。

### 闸门

三条按 1→2→3 的次序跑满，与基线（613 / 575 / 干净）对齐：

| 闸门 | 结果 | 与基线的差 |
|---|---|---|
| `cargo test` | **618 通过 0 失败**（18 个测试二进制） | +5 |
| `cargo test --no-default-features` | **580 通过 0 失败** | +5 |
| `cargo check --features profiling` | 干净 | — |

闸门 2 那一格要加一句：`the_minutes_spent_deciding_are_charged_to_nobody` 是一条
**既有的**概率性红（本机串行五趟红三趟），撞上时 cargo 在那个二进制上停下、
后面的不再跑，总数看着少一截。上表取的是没撞上的那一趟。它与本票无关，
三条证据与修法记在停车场 **Q118**。

闸门 1 在闸门 2 之后跑要先 `cargo build`（停车场 Q95）：两种特性组合的 `tonefit.exe`
共用同一个 target 目录，不重建的话 `tests/session.rs` 会假红。本票撞过一次，照这条走通。

多出来的 5 条，两条闸门上是同一批：

- `src/render.rs` 2 条（三类各印各的那句为什么且退出码仍是 0；一个都没有就一个字不说）；
- `tests/discovery.rs` 2 条（清单与输出树逐条互补；卷内透传成员不上表且照旧搬）；
- `tests/exit_code.rs` 1 条（三类一次全摆上，退出码仍是 `0`）。

### 票面与 spec 的出入

spec 的《卷至少有一页》写着「一页都没有的东西不是卷，归入非卷文件。字体包、源码包、
**空目录**都落在那一栏」，而同一份 spec 的《非卷文件》把那一栏定成三类**文件**——
空目录一个文件都没有，两句对不上。落地取的是《非卷文件》那三类（票面的硬约束也是它），
并把这条分别写进了 ADR 0014 决定第 3 条。
