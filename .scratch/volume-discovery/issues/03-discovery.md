# 03 — 发现：点名的路径展开成一批卷

**What to build:** 点名一个目录，底下的卷各自转换、各自重新打包，按镜像结构写到输出根。点名 `网络资源` 得到 `输出根\网络资源\N和S\第10话.cbz`——98 话一趟走完，而不是点 98 次。

发现两条规则：

- 路径是**归档** → 一个卷，**内部结构照收**；
- 路径是**目录** → 直接躺着页就**同时**是一个卷（**只收直接那层**），并且**继续往下发现**。

**卷与卷架不互斥**：同一个目录可以既是卷又装着卷。这条是从孤立封面图倒推出来的——`N和S/` 里一张 `cover.jpg` 加 56 个 cbz，若「直接有页就整个子树归它」则 56 个 cbz 变回透传文件，若「混装当场拒绝」则一张封面能让整个库跑不起来，而源库只读、tonefit 修不了它。不互斥是唯一不猜、不拒、也不靠名字表的走法。

**输出镜像的基准点是点名路径的父目录**——点名路径自己的名字恒出现在输出根下，卷与卷架两种点名共用一套规则。取「点名路径自己」当基准点的话，点名一个卷时页会直接撒进输出根。

三件事绑在这一张票里，因为它们拆不开：不改卷边界就做发现，混装目录的子目录页会**被处理两遍**；不做输出镜像，一个作品目录下四个「第01话.cbz」当场撞车。

**卷至少有一页**：一页都没有的东西不是卷，归入非卷文件（清单本身是 04 的事，这张票只保证它**不产出任何字节**）。

**点名的 / 发现的**只决定一件事——点不开时的处置：点名的整趟拒绝，发现的记下来、其余照做。对推测出来的东西不用最重的处置。

**Blocked by:** 01 — 预扫只数不留（前置重构：发现产出的卷只有路径，而按路径再开是 01 引进的）。

**Status:** resolved

- [x] 点名一个两层库（`作品/第N话.cbz`），每一话各自成卷，输出镜像成 `输出根\<点名路径名>\作品\第N话.cbz`
- [x] 点名一个目录卷（直接躺着页），产物与改动前**逐字节相同**
- [x] 混装目录：一张封面图 + 若干 cbz → 封面自成一个一页的卷，每个 cbz 各自成卷，**一页都不被处理两遍**
- [x] 分目录装的**归档**一页不少；分目录装的**目录**裂成几个卷，各自一份上包络
- [x] 一页都没有的归档、空目录、底下一个卷都没有的目录，输出里一个字节都没有
- [x] **点名**一个点不开的归档 → 整趟拒绝、退出码 `1`；**发现**出来的点不开的归档 → 退出码 `0`，其余卷照常跑完
- [x] 输出根落在点名路径底下仍当场拒绝；符号链接与 junction 不跟进

## 落地记录

### 发现独立成一个模块

新增 `src/discover.rs`。它做的只有一件事：**点名的一个路径展开成一批候选**，
按先序深度优先、同层按阅读顺序排（`source::reading_order`，与卷内的成员共用同一条规矩）。

它**不打开任何东西**——「里面到底有没有页」由预扫开卷时才答得出。因此这里列出的
目录候选比真正的卷多：一个纯粹的卷架（只装着子目录与 cbz）也会被列出来，
开出来是空的，随即丢掉。这笔多余换掉的是在两处各写一遍「什么算页」。

递归用的是一个**显式的栈**而不是函数递归：库的深度由用户的目录树说了算，
而爆栈是一种没有报告、也没有退出码的失败。符号链接与 junction 不跟进
（`DirEntry::file_type` 问的是链接自己），环因此进不来，深度不必设上界。

### 预扫变成两步

`src/survey.rs` 的 `Survey::of` 现在是**发现 + 计数**。三条分岔全在这一处：

- 点名的路径自己点不开 → 收进那张逐条列出的清单，整趟拒绝（退出码 `1`）；
- 发现出来的归档点不开 → 跳过，其余照做（退出码一格不动）；
- 开出来**一页都没有** → 跳过，它不是卷。

### 输出镜像

`Surveyed` 多带一条 `output_relative`，`process_volume` 的干净去处与隔离去处都由它接出来
（隔离只是在中间插一级 `_isolated`，镜像出来的结构一模一样）。基准点是**点名路径的父目录**，
一套规则管两种点名。

`source::planned_output` 随之退场：去处不再只由「卷名 + 容器形态」决定，末一级的名字
由新的 `source::output_name_of` 出，前面几级由发现拼。

### 撞名那一道挪到了预扫之后

撞在一起的是**发现出来的那些卷**，发现之前问不出来。签名从 `&Request` 改成
`(&[Surveyed], &Path)`。挪位带出来的一个小副作用记进了停车场（Q112）。

那句话跟着改了半句：「输出名取自卷名」→「输出**按源的结构镜像**，末一级取自卷名」——
镜像之后，同一棵树底下的四个「第01话.cbz」自己就分得开，撞得上的只剩「点名了多处」
与「扩展名归一」两种。

### 目录卷不再递归收页，这笔代价打到了哪几条既有用例上

`open_directory` 里的 `WalkDir` 换成一次 `read_dir`：子目录不收，躺在这一层的**归档**
也不收——它是一个卷，不是这一卷的透传文件。三条既有用例靠旧行为立着，全部改掉：

1. **`tests/pipeline.rs` 的 `pages_come_out_in_reading_order`**——它拿
   `ch2/1.png`、`ch10/1.png` 造「逐层比」。**拆成两条**：目录卷那条只留直接那一层；
   多级那一半新开 `the_members_of_an_archive_are_ordered_level_by_level`，造在**归档**上。
   归档内部结构照收，那是这条顺序唯一还落得到实处的地方。
2. **`tests/pipeline.rs` 的 `each_volume_mirrors_its_source_tree_under_its_own_output_directory`**
   ——它的 `volume-a` 只有 `ch1/001.png`，如今 `ch1` 自己成卷、输出落在 `out/volume-a/ch1`。
   改成直接那一层的一页；归档那一侧的多级镜像由 `tests/container.rs` 的
   `parallel_top_level_directories_are_not_a_wrapper_and_stay` 接着钉。
3. **`tests/idempotency.rs` 的 `a_volume_without_pages_is_never_skipped`**——它靠
   「一页都没有的卷是合法状态」立着，而 spec 明写那条作废。改名成
   `something_without_a_page_never_gets_as_far_as_idempotency`，问的是「它连卷都不是」。

外加两处**会话的夹具**，那是最难查的一处：`src/session/run.rs` 与 `src/session/terminal.rs`
里几条真起线程跑一趟的用例，从前用的是一个「只装透传文件」的卷。那个卷如今不是卷，
预扫当场丢掉，那条线程于是永远走不到决策点——用例**挂住而不是红**
（`until_deciding` 是个 `yield_now` 的忙等）。夹具收进
`src/session/live::fixture::a_real_volume`（一页加一个透传文件，页压到最便宜的那一张：
高恰是基准面板的高、纯墨到边，管线在它身上一步都不做）。

### 顺带

`walkdir` 从 `[dependencies]` 挪进 `[dev-dependencies]`：库这一侧从此不再递归遍历任何东西，
只有断言还要铺平一棵树。

### 停车场结转

**Q110 了结**，原文连同处置照录如下；索引在 `.scratch/非阻塞问题.md` 的《已了结》里
留了一行指回这里。**新开 Q111、Q112、Q113 三条**，都留在《待处理》：

- **Q111**——互相嵌套的点名会把同一个卷发现两遍、各写一份输出；
- **Q112**——撞名那一道挪位之后，点名一个不存在的路径时输出根探针会先动一次盘；
- **Q113**——混装目录的输出去处同时是它兄弟卷的父目录，目录卷收尾时那句
  `remove_dir_all` 会把它们整个删掉。**这一条是评审那一轮查出来的**，
  也是本票造出来的唯一一处真缺陷；代价同时写进了 ADR 0014 的《要认的代价》。

#### Q110 — 《处理对象》的「源」「输出容器」两条词条还按「CBZ」写，输出那半句已经不全

- **From:** 票 `volume-discovery/02`
- **Kind:** 本票造出来的不一致
- **Where:** `CONTEXT.md` 的《处理对象》——「源 (Source)」的「目录与 **CBZ** 在它之下同形」，
  「输出容器 (Sink)」的「形态随输入而定：输入是 **CBZ**，输出也是 CBZ」
- **Why it did not block:** 本票把 `src/source.rs`、`src/sink.rs` 两处抬头的同一句改成了
  「归档」，词汇表却停在原处。「源」那条只是**词旧**（`.zip` 在它之下同样同形，说的事没变）；
  「输出容器」那条则**说不全了**——点名 `.zip` 进来，出去的是 `.cbz`，「形态随输入而定」
  只对**形态**成立，对**扩展名**不成立。不咬人是因为归一这条事实已经有一处权威位置：
  本票按 spec 的《要改的领域文档》写进了《输出》，而《处理对象》复述它反倒破了单一出处。
- **What this ticket actually did:** **没有动这两条词条**，按 `CLAUDE.md`
  《改 CONTEXT.md 的规矩》记到这里——「改写已有词条的含义要先拍板……撞见词汇表与实现
  对不上，记进 `.scratch/非阻塞问题.md`，不要顺手改」。而且这不是本票一家的事：
  spec 的《要改的领域文档》把《处理对象》的「源」「成员」「卷」「处理范围」四条
  一并派给了 `volume-discovery/03`，那张票落地时这两条本来就要重写一遍——
  在这里先改一手，等于同一段话改两次、且中间那一版还没人拍过板。
- **Whose call:** 拍板的人（「输出容器」那条要不要把扩展名归一写进去，还是只指向《输出》）
- **处置：** 已了结（`volume-discovery/03`）。两条都改了：「源」那条改成
  「目录与归档在**读取与输出**上同形，在**卷边界**上不同形」，「输出容器」那条改成
  「输入是归档，输出也是归档；扩展名一律归一成 `.cbz`（ADR 0015）」——归一那件事
  的权威位置仍是《输出》，词条只点一句并指过去，不复述去处怎么算。

### 评审那一轮改了什么

`/code-review` 两轴各报了一批，照单改掉的有这几条：

- **`source::identity_of` 的文档当场就是假的**——它写着「发现出来的候选不经这一道」，
  而预扫对每一个候选都调 `source::open`，`open` 第一句就是它。改成实话：
  它认「这是不是一个卷」，点名的那个路径与发现的起点都经它；发现**往下走**时才走
  `name_of`。同一处两句错误文案（「无法决定输出位置」，而 `open` 不决定去处）
  一并改成「说不出这是哪一个卷」。
- **「卷架」进了标识符**——ADR 0014 决定第 1 条明写不给「装卷的目录」造词条，
  而 `CLAUDE.md`《写代码前》要求测试名取自 `CONTEXT.md`。测试名与夹具名里的
  `shelf` 全部改掉，`src/` 与 `CONTEXT.md` 的正文里也不再出现这个词。
- **同一条论证抄了三到五遍**——孤立封面那个倒推、「归档的边界由打包者定死了」、
  `.git`/回收站那段理由，各自收回一处权威位置（分别是 ADR 0014 决定第 1 条、
  `source` 的模块抬头、`JUNK_DIRECTORIES`），其余各处只指过去。
  `src/discover.rs` 的模块抬头也不再复述 ADR 0014 的《背景》。
- **去处被手拼了三处**——收进 `survey::Surveyed::output_path(&root)`，
  `output_relative` 转成私有字段。三处（干净去处、隔离去处、撞名校验）从此共用一条算法。
- **`a_pass_through_volume` 这个名字开始说谎**——它现在造的是「一页 + 一个透传文件」，
  改名 `a_one_volume_run`。
- **spec 点名的「卷架上的 txt」缺一条**——补进
  `nothing_without_a_page_writes_a_single_byte`。
