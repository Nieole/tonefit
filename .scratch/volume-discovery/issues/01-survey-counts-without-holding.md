# 01 — 预扫只数不留

**What to build:** 预扫列完成员、算完步数就把归档放掉，只留计数与卷的路径；处理那一卷时按路径再开一次。用户看得见的变化只有一个——点名成百上千个归档卷不再因为句柄与常驻中央目录而胀死。产物、报告、行为一字不变。

这是 03 的**前置重构**：它引进的「处理那一卷时按路径再开」正是发现产出的卷唯一有的东西。先做它，03 就是在轻的那个形状上加东西。

代价要认下来：归档卷的中央目录读两遍。`survey` 模块文档里「枚举很便宜，扫两遍也无妨是不成立的」那一段说的正是这件事，要重写——换来的不是「不扫两次」，是「不攥着几千个句柄」。

**Blocked by:** None — can start immediately.

## 落地记录

### `Surveyed` 退成一份摘要，`Volume` 与 `Reader` 一个字没动

```rust
pub(crate) struct Surveyed {
    pub(crate) root: PathBuf,       // 卷根，也就是点名的那个路径
    pub(crate) steps: u64,          // 预扫那一遍算出来的步数
    pub(crate) enumerating: Duration, // 预扫那一遍花了多久
}
```

原先的 `volume: Volume` 与 `members: MemberCounts` 都没了。`Survey::of` 数完就让那个
`Volume` 在循环体末尾析构——归档卷的 `ZipArchive` 连同文件句柄跟着还回去；
`process_volume` 收到这份摘要，**按 `root` 再开一次**。

**公开形状一个字没改。**票面说明提醒「`Volume` 与 `Reader` 都是 `pub`，改它们是公开 API 的
改动」——本票**不必**改它们：要放掉的是「谁攥着一个 `Volume`」，不是 `Volume` 长什么样。
Q42 当初设想的出路是「让枚举与取字节的那一半分家、改 `source::Volume` 的形状」，
而票面给的这一条更轻：把整个卷放掉、按路径重开，形状与 `source::open` 都原封不动。

### 重开插在哪一格

```rust
events.volume_started(&root, steps);          // 这一卷的第一件事，报得出卷根与步数
ensure_the_volume_root_is_still_there(&root)?; // 这一卷最早的一个 Err
let mut volume = source::open(&root)?;         // 按路径再开一次
let members = MemberCounts::of(&volume, request);
```

三条边各有各的理由。**开卷那条事件仍在最前**：往后每一条出口都在它之后，画进度那一层
因此不必分「这一卷开过头没有」——而它要的卷根与步数正是预扫留下的那两样，重开还没发生
也报得出。**「卷根还在不在」仍抢在重开之前**：不问的话报出来的是 `source::open` 的
「X 不存在」，说不出「它是在预扫之后不见的、不是它里面的页坏了」。**重开落在 `started` 之内**，
因此照样算进这一卷的墙钟。

`ensure_the_volume_root_is_still_there` 的签名从 `&Volume` 改成 `&Path`，
文档里《只问目录卷》那一节改成《两种容器形态都问》：归档卷从前豁免的理由是
「字节从预扫时就打开、此后一直握着的那个句柄里出」，预扫不再攥着它，豁免跟着没了。

### `enumerating` 那格算的是**预扫那一遍**，`elapsed` 装着两遍

这是本票必须拍板的那一件。中央目录现在读两遍，两遍各归各的地方：

| | 哪一遍 | 落在哪 |
|---|---|---|
| `Surveyed::enumerating` | **只有预扫那一遍** | 由 `process_volume` 加进这一卷的 `elapsed` |
| 重开那一遍 | 在 `process_volume` 之内 | 本来就落在 `started.elapsed()` 里 |

于是 `VolumeTiming::elapsed` 与 `VolumeTiming::outside_the_segments` **各装着两遍枚举**。
字段、格式、来源一个都没变，但 `outside_the_segments` 的**含义**多了一遍打开与枚举——
这一条按票面要求写进了 `src/report.rs` 那两处文档（`elapsed` 与 `outside_the_segments`）。

不那么办的另一条路是「丢掉 `enumerating`，只算重开那一遍」：那样预扫在慢盘上花的时间会
从每一卷的报告里静默消失，而 `outside_the_segments` 的文档正指着它说「少掉的那一截恰恰是
枚举」。三段（`fingerprint` / `first_pass` / `second_pass`）一格没动——重开不在任何一段里。

### 成员数改从**重开的那一份**数，公式收进 `MemberCounts::of`

`Surveyed` 不再带 `members`：步数出自预扫那一遍（它已经加进开工那条事件报出去的全局总步数），
成员数出自重开那一遍（报告说的得是真做了的那一卷）。两处共用一个构造 `MemberCounts::of`，
公式只有一份。

**不这么办会真出事**：`process_volume` 里那条区间 `debug_assert!`
（产出张数落在 `[源页数, 上界]` 之内）比的两个数，一个来自成员表、一个来自第一遍的产出。
两个数分属两遍枚举时，两遍之间源多出几页就会当场炸在调试构建上。这一笔记进 **Q93**。

### 句柄那条用例：库内一条，库外一条

- `src/survey.rs` 的 `a_survey_keeps_no_archive_open`——**300 个空归档卷**（手搓 22 字节的
  ZIP 中央目录结束记录，不必造页），预扫一趟之后问两句：Linux 上数 `/proc/self/fd` 里落在
  那棵临时树下的句柄（只数自己那棵树，别的用例干扰不到）；Windows 上问不出句柄数，
  改问**装着这些归档的目录还改不改得动名**——那个平台上目录里只要还开着一个文件，
  重命名就会被拒。两句在对方的平台上都恒成立，谁也不会误报。
  **前提验证过**：临时在用例里开着其中一个归档再改目录名，`rename` 当场回 `Err`，
  证明这一句在 Windows 上是一个真的句柄探针，不是恒真断言。
- `tests/isolation.rs` 的 `an_archive_volume_whose_file_is_gone_did_not_get_made`——
  开工那条事件上把中间那一卷的 `.cbz` **删掉**，它记一笔卷级失败、前后两卷照常做完。
  这一条**两个平台上都算数**：句柄还攥着的话那一卷会照常做出来（Windows 上 Rust 开文件带
  `FILE_SHARE_DELETE`，删得掉、句柄照读），报告里就没有这一笔。
  它同时是 `p2-loose-ends/05` 那条目录卷用例的归档孪生——那五件事这里同样问。

**这两条盖住的与盖不住的**（评审 Spec 轴指出来的一档）：验收说的是「**整趟**打开的句柄数不随
卷数增长」。第一条钉住「预扫开完是 0，与 N 无关」；第二条钉住「整趟跑到一半，**还没轮到**的
卷也没被攥着」——删掉的是第二卷，而删的那一刻第一卷还没开工。
**没有断言**的是最后那一档：「正在处理的那一卷开着一个句柄、做完就还」。它由构造保证——
那个 `Volume` 是 `process_volume` 的一个局部变量，函数返回即析构——而要断言它得在
「这一卷正开着」的当口去数句柄，Windows 上没有不引依赖就问得出句柄数的路。
上界因此是 **1**，与 N 无关，验收那句话成立。

### 一条既有用例翻了面

`tests/events.rs` 的 `the_pipeline_reuses_what_the_survey_enumerated` 钉的正是本票要拆掉的
那条性质（「同一个卷不被枚举两次」）。它改名成 `the_pipeline_opens_the_volume_again_by_path`，
断言从「开工之后才塞进去的那张页**没**被做掉」翻成「**被**做掉了」。
文档里写明它钉的是**重开**，不是「源在跑的中途改了要跟着变」那条性质——那是一种竞态，
谁也没有承诺过；而源没动的那一趟里重开与不重开逐字节相同，正因如此「相同」在这里
当不了判别式。它的兄弟 `the_survey_lists_members_without_reading_a_single_pixel` 照旧绿，
只把文档里指着它的那一句改准。

### 卷级失败的窗口跟着挪了位（Q92）

**一头收窄。**三条靠「抽走一个成员」造卷级失败的用例改了动手的时刻。从前抽在 `RunStarted` 上就够——
成员表由预扫列定、此后不再刷新；现在那一刻这一卷还没重开，抽走的成员根本不进成员表，
这一卷会照常做完、只是少一个成员。新夹具 `RemoveOnceTheVolumeIsOpen` 记着点名那一卷开工了
没有，在它的**第一条 `PassStarted`** 上动手——那一刻刚重开完、一个字节都还没读。
抽**卷根**的那两条不受影响，仍在 `RunStarted` 上动手，`RemoveOnceTheSurveyIsDone`
的两个构造因此改名成 `archive` / `directory`（它现在只抽卷根，不抽成员）。

**一头加宽。**重开自己也会失败——归档被删、损坏、权限变了——那是一类从前不存在的卷级失败。
最明显的一例就是上面那条归档卷用例：卷根在预扫之后消失，从前照读不误、整卷做得出来，
现在记一笔卷级失败、退出码 `3`，与目录卷同形。

> ### Q42 — 点名的每一个归档卷，整趟都占着一个打开的文件句柄
>
> - **From:** 票 `p1-session/03`
> - **Kind:** 票面没想到的第三种情形
> - **Where:** `src/survey.rs` 的 `Survey::of`；`src/source.rs` 的
>   `Reader::Archive(zip::ZipArchive<BufReader<File>>)`
> - **Why it did not block:** 票面要「枚举结果交给管线复用，不扫两次」，而归档卷那次枚举**就是**
>   `ZipArchive` 本身——中央目录读出来之后住在它里面，放掉它就等于要再读一遍。
>   因此预扫打开的卷全部留到各自被处理时，点名 N 个归档卷即同时占着 N 个句柄
>   （目录卷不占：它的读取端只是一个 `PathBuf`）。眼下不咬人：处理范围是用户点名的子集
>   （ADR 0009），一次几十个卷，而 Windows 的句柄上限是百万级、Linux 默认软上限 1024。
>   真要摘掉这笔代价，只有让枚举与「取字节的那一半」分家——那要改 `source::Volume` 的形状，
>   是一件独立的事。内存那一侧同量级、更小：一份中央目录约每成员几十字节。
> - **What this ticket actually did:** **认下这笔代价，写进 `src/survey.rs` 的模块文档**
>   （《要认的代价》那一段），并说清它是「不扫两次」的必然结果而不是疏忽。
>   没有引任何句柄池或惰性打开。
> - **Whose call:** 拍板的人（点名上千个归档卷要不要支持）
> - **处置：** 待处理。**这笔代价本身已经由本票消掉**：走的是本条挂出来的「分家」那条出路，
>   但不是本条设想的形状——没有改 `source::Volume`，而是**预扫数完就把整个卷放掉、
>   处理那一卷时按路径重开**。现状：预扫开完一个归档句柄都不攥着（300 个卷的用例钉着），
>   常驻中央目录同步归零，一趟同时开着的从「点名几个就是几个」变成「正在处理的那一卷一个」。
>   **那道线该不该划仍归 `p2-loose-ends/12`**——见上面《票面与队列》。
