# volume-discovery — 点名的路径展开成一批卷

**Status:** ready-for-agent

## Problem Statement

今天的模型里藏着一条没写出来的恒等式：**点名的路径 = 一个卷**。`source::open` 照它实现——
是目录就整个当目录卷，是 `.cbz` 就当归档卷，没有第三种。

这条恒等式在真实漫画库上当场失效。所有者点名 `_samples/_cbz`，得到的是：

- `改革之獸-Vol05/`（目录里直接躺着 185 张 png）——转了；
- 三个 `.cbz`——**原样拷进输出目录**，报告写着「0 页」。

报告说的是真话：`_cbz` 整个被当成**一个卷**，三个 cbz 在它眼里既不是页也不是卷，
于是按《处理对象》的「非图片文件原样透传」搬了过去。而真实的库形状是
`网络资源/<作品>/<第N话>.cbz`——**两层**，恒等式够不着。

四类真问题：

1. **卷的边界只能是点名的那一层。** 库里一个作品目录装 56 话，用户要么点 56 次，
   要么点一次得到一个 56 卷合一的怪物（上包络按卷取，判定因此也错）。
2. **归档只认 `.cbz` 一个扩展名。** `.zip` 与 `.cbz` 字节完全同形却被拒之门外，
   `.rar` / `.7z` 同理。所有者的 `高像素` 五个文件一个都跑不了。
3. **说不出「什么没被转」。** 没被当成页的东西一律透传，产物里因此混着源库的杂物，
   而报告里没有任何一处列得出它们。
4. **「一页都没有的卷」是合法状态。** `.zip` 一旦收下，一个字体包就会在输出里得到一个空 `.cbz`。

## Solution

在《预扫》里加一步**发现**：点名的路径展开成一批卷，外加一批**非卷文件**。

```
点名的路径 ──[ 发现 ]──► 一批卷 ──► 各自走管线 ──► 镜像到输出根
                     └──► 非卷文件 ──► 报告第三张表（不转、不拷）
```

管线本身一个字不改——发现只决定「有哪些卷」，卷进管线之后与今天逐字相同。

## User Stories

1. 作为有一个 `作品/第N话.cbz` 两层库的人，我希望点名作品目录就把 56 话各自转成 56 个 cbz，而不是点 56 次。
2. 作为点名了一个目录的人，我希望里面的 cbz 被**转换并重新打包**，而不是原样拷过去。
3. 作为收到 `.zip` 片源的人，我希望它直接能跑——它与 `.cbz` 本来就是同一种字节。
4. 作为收到 `.rar` / `.7z` 片源的人，我希望不必先解压一遍再喂给 tonefit。
5. 作为跑完一趟的人，我希望**没被转换的东西单独列出来**，而不是混在输出目录里等我发现。
6. 作为跑完一趟的人，我希望输出目录里**只有产物**——源库的杂物不该跟着进来。
7. 作为库里有 `cover.jpg` 的人，我希望那一张封面不会让整趟跑不起来。
8. 作为库里混着一个坏 zip 的人，我希望其余几百卷照常跑完，而不是被一个坏文件挡在门外。
9. 作为**点名**了一个坏卷的人，我希望当场被拒——我明说了要处理它。
10. 作为点名了一整个库的人，我希望输出目录的结构与源目录一致，好按原样拷进设备。
11. 作为点名了几千个卷的人，我希望预扫不因为攥着几千个打开的归档而胀死。
12. 作为在会话里调参数的人，我希望点名一个目录之后仍然**逐卷试算、答继续就接着做**，而不是因为「多卷」退回两遍的价。
13. 作为批量跑几十卷的人，我希望答一次「剩下都这样」就能挂着去泡茶。
14. 作为看几百卷报告的人，我希望默认按目录折起来，而不是滚 500 行找那一卷。
15. 作为把 `.zip` 与 `.cbz` 同名放在一起的人，我希望撞车那句话说得出**是扩展名归一造成的**。

## Implementation Decisions

### 缝

**不新开缝。** 发现整个落在 `run(Request) -> Report` 之内、`survey` 之中。
`Request` 的 `inputs` 语义从「一批卷」变成「一批**在里面找卷的地方**」，类型不变。

### 发现：两条规则

- 路径是**归档** → 一个卷，**内部结构照收**。
- 路径是**目录** → 直接躺着页就**同时**是一个卷（**只收直接那层**），并且**继续往下发现**。

**卷与卷架不互斥**：同一个目录可以既是卷又装着卷。因此**不给「装卷的目录」造词条**——
它不是一种东西，只是目录的一面。

这条规则是从 `cover.jpg` 那个场景倒推出来的。`N和S/` 里一张封面图加 56 个 cbz：
若「直接有页 → 整个子树归它」，56 个 cbz 又变回透传文件；若「混装当场拒绝」，
一张 `folder.jpg` 就能让整个库跑不起来，而**源库只读**，tonefit 修不了它。
不互斥是唯一不猜、不拒、也不靠名字表的走法：封面自成一个一页的卷，56 话各自成卷。

**代价要认下来：目录卷不再递归收页。** `某卷/特典/x.png` 今天归某卷，改后特典自己成卷，
两边的上包络因此分家、位深判定可能不同。

### 卷的边界：两种容器不同形

`CONTEXT.md`《处理对象》的「源」词条今天写着「目录与 CBZ 在它之下**同形**」。这一句要改写：
两者在**读取与输出**上同形，在**卷边界**上不同形。

理由是一句能立住的原则：**归档的边界由打包者定死了，目录的边界可以再分。**
一个 cbz 里 `第01话/001.png`、`第02话/001.png` 这样分目录装着是真实的打包习惯，
归档若也只收顶层，整卷一页不剩。

### 卷至少有一页

**一页都没有的东西不是卷**，归入非卷文件。字体包、源码包、空目录都落在那一栏，
输出里一个字节都没有。

《报告》的「一页都没有的卷（只装着透传文件）是 `None`」与 `render.rs` 里对应的措辞
**一并作废**。

### 归档格式与读取形态

认 `.cbz` / `.zip` / `.rar` / `.7z`，**输出一律 `.cbz`**——产物是给阅读器的，
而 `.cbz` 是那边认的名字。

读取形态**按格式分**，不逐卷探固实与否：

| 格式 | 读法 | 理由 |
|---|---|---|
| `.cbz` / `.zip` | 今天这条：`by_index` 随机取 | 每个成员各自 deflate，随机取 O(1)，摊开是白付一次全量写盘 |
| `.rar` / `.7z` | **开工前整卷摊到临时目录**，之后完全按目录卷走 | 固实归档取第 N 个成员要从块头解起，随机取 O(N)、全卷 O(N²)，而源字节**读两遍**（幂等一遍、第一遍一遍） |

摊开借《缓存》的溢写那套 `tempfile` 机制，**不新开预算旋钮**：`--cache-budget` 限的是内存，
磁盘今天没有旋钮，加一个会让「限制占用」这件事有两个说法。摊了多少字节印进那一卷的报告；
磁盘不够是**卷级失败**，其余卷照做。

`.rar` 的依赖带 UnRAR 许可（禁止据其反推解压算法），要在 `THIRD-PARTY-NOTICES.md`
与 `licenses/` 各留一份。`.7z` 取纯 Rust 实现。

### 非卷文件

发现走完之后没被任何卷收下的文件。三类，每条带路径与**一句为什么**：

- 卷架上既不是页也不是归档的文件（`_对比-libra2/答案.txt`）；
- 一页都没有的归档；
- **发现出来**但点不开的归档（损坏、权限不够、根本不是归档）。

它挂在 `Report` 上，与 `volumes` / `failed_volumes` **并列的第三张表**——
《进度》明写「CLI 与 TUI 拿的是同一份数据，不是两套」，进报告两边就都有。

**非卷文件不是失败，不影响退出码。** 四个码的含义一格不动。

**卷内的透传文件照旧搬。** 甲乙两群是两件事：`ComicInfo.xml` 是产物的一部分
（阅读器靠它读作者、卷号、阅读方向），砍掉是净损失；而触发这张票的那批 cbz 全在乙群，
发现规则一落地就自己了结了。《处理对象》的「源」「输出容器」「成员」三条词条
在透传这一点上**一字不改**。

### 点名的 / 发现的

新增一条分别，只决定一件事——**点不开时的处置**：

- **点名的**卷点不开 → 照旧**整趟拒绝**（《失败》的「拒绝执行」，他明说了要处理它）；
- **发现的**归档点不开 → 进非卷文件清单，**其余照做**。

对推测出来的东西不用最重的处置。加密的 `.rar` / `.7z` 走同一条，不另开一种。

### 输出布局

镜像，**基准点是点名路径的父目录**——点名路径自己的名字恒出现在输出根下。

```
点名 _samples\网络资源          → D:\test\网络资源\N和S\第10话.cbz
点名 _samples\_cbz\改革之獸-Vol05 → D:\test\改革之獸-Vol05\CMR_05_000-1.png
```

一套规则管两种点名。取「点名路径自己」当基准点的话，点名一个**卷**时页会直接撒进输出根，
于是实际要两套规则。

`ensure_output_is_elsewhere` 双向查嵌套且比规范化后的绝对路径，**不必改**：
输出根落在点名路径底下当场拒绝，发现因此不会把上一趟的产物当成源。

`WalkDir` 默认 `follow_links(false)`，符号链接与 Windows junction 都不跟进，**环进不来**，
深度不必设上界。

`JUNK_DIRECTORIES` 补上递归之后才撞得到的几个：`.git`、`#recycle`（群晖）、
`@Recycle`（QNAP）、`.@__thumb`。

### 撞车的措辞

输出扩展名归一之后，同一目录下的 `第10话.zip` 与 `第10话.cbz` 撞同一个去处。
拒绝执行本身**已经成立**（`ensure_no_two_volumes_share_an_output`），但那句「输出名取自卷名，
同名的卷因此撞在一起」说不出是扩展名归一造成的。措辞要改。

### 预扫：只数不留

`survey` 今天把**打开了的卷**留到处理那一刻，模块文档把这笔代价写在明处：
「点名的每一个归档卷在整趟里都占着一个打开的文件句柄与一份中央目录」。

点名 3 个 cbz 时这笔代价可以忽略；发现之后点名一个库就是几千个句柄，
外加每份常驻内存的中央目录（一卷 200 页 × 约 200 字节 × 几千卷 ≈ 几百 MB）。

**改成只数不留**：列完成员、算完步数就把归档放掉，处理那一卷时再开一次。
代价是归档中央目录读两遍——而 `survey` 模块文档里「枚举很便宜，扫两遍也无妨是不成立的」
那一段正是说这个，要**重写**，把「不扫两次」换成「不攥着几千个句柄」。

预扫的定义随之变成**发现 + 计数**，两步都在开工前。发现本身不碰像素、不占步；
慢盘上它要花时间，而命令行那条转轮已经在了（ADR 0011）。

### 会话：逐卷等答话

ADR 0012 决定第 1 条把续做限在单卷上，理由是内存——
「全量试算要续做，就得同时押住**全部卷**的参照」。

**这条理由不覆盖逐卷决策点。** 决策点本来就是逐卷的（《会话》：「每一卷的『汇总之后、
第二遍之前』，一卷一次」），逐卷停下来问，缓存**始终只押着当前那一卷**，内存一点不涨。
真正拦住多卷续做的是决定第 **3** 条——那是会话的策略，不是内存。

改决定第 3 条：**多卷也逐卷等答话**。否则发现落地那天起，「试算满意就接着做」
这条回路（会话存在的理由）就基本再也命中不了。

答话多一个手势：**「剩下的卷都这样」**。它**不进那个闩**——《会话》明写
「决策点认的是当场答的那个字，不是闩」，而这个手势也不是闩：闩只升不降，
它却是个可以是「继续」的粘性答案。它记在观察者那一侧「决策点的默认答案」上，
与库那一侧记「至今收到过最强指令」的那一格分开放。

### 会话：报告按目录分组

默认每个目录一行（N 卷 · 基准档分布 · 多少卷进了隔离），**展开到卷、再展开到页**。
《会话》的「展开」从一级变两级，命令行那一侧要有对应的折叠。

### 要改的领域文档

**就地修订**（照 0002 / 0007 / 0012 / 0013 的样子，状态行记一句）：

- **ADR 0009 决定第 1 条**——「点名的子集」要说清楚：点名的是**在哪里找**，不是**找到什么**。
  《不要做的「简化」》那一节**保留原样**：它反对的是默认扫库根，而发现仍然只在点名的路径底下走，
  索引、断点续传、watch 三件事一件都没回来。
- **ADR 0011 决定第 3 条**——预扫改成只数不留。
- **ADR 0012 决定第 3 条**——多卷改为逐卷等，加一节说明决定第 1 条那个内存理由为什么不覆盖它。

**新增两篇**，各承载一件事：

- `docs/adr/0014-*` —— 发现规则、卷边界、非卷文件、点名/发现的分别、输出镜像。
- `docs/adr/0015-*` —— 归档格式、输出扩展名归一、rar/7z 摊到临时目录。
  它带依赖与许可，将来最可能被单独推翻，因此不与 0014 合篇。

**`CONTEXT.md`**：

| 小节 | 动作 |

| 《处理对象》 | 改「卷」「源」「成员」「处理范围」；新增「发现」「非卷文件」 |
| 《失败》 | 改「拒绝执行」（点名的 / 发现的）；写明非卷文件不是失败 |

| 《输出》 | 交代扩展名归一对幂等去处的影响 |

## Testing Decisions

外部行为是：**盘上的字节**、**报告的字节**、**退出码**、**屏幕缓冲**。

- 发现规则走**盘上的字节**：造一棵树（两层 cbz、混装目录、一页都没有的 zip、坏 zip、
  卷架上的 txt），跑一趟，断言输出树的形状与非卷文件那张表**逐条**对得上。
  `cover.jpg` 那个场景要有自己的用例——它是这条规则的来由。
- 卷边界那条不对称各一条：分目录装的 cbz 一页不少；分目录装的**目录**裂成几个卷。
- 「点名的 / 发现的」比**退出码**：同一个坏 zip，点名它得 `1`，发现它得 `0` 且清单里有它。
- 归档格式四条各跑一遍，比产物哈希：同一批页从 `.cbz` / `.zip` / `.rar` / `.7z`
  进去，出来**逐字节相同**。
- 摊开那条比**在途的盘**：跑到一半断言临时目录里有东西、跑完断言它没了。
- 预扫只数不留：断言整趟**打开的句柄数不随卷数增长**（造几百个小 cbz）。
- 逐卷等答话走 `Session::action` 那个纯状态机的快照，「剩下都这样」要有一条断言
  **按停的那一级不被它改动**。
- 报告分组走 `draw.rs` 的快照，宽字符按 `cell_width` 跳格（`p1-session/09` 立的规矩）。

## Out of Scope

- **`.rar` / `.7z` 的写出。** 输出一律 `.cbz`，两个格式只读不写。
- **全库扫描、索引、watch。** ADR 0009 关掉的三件事一件都不回来——发现只在点名的路径底下走。
- **源库整理。** tonefit 不移动、不改名、不删除源文件。混装、同名撞车都只报，不代劳。
- **`--recursive` 一类的开关。** 发现是默认且唯一的行为，不留旧路。
- **字号跳动的夹子。** 所有者已拍板「暂不加，先扩样本」，见《尚未确立》。

## Further Notes

依赖只有两条真的：

1. **发现排头。** 归档格式、非卷文件、输出镜像都挂在它出来的那批卷上。
2. **预扫只数不留排在发现之后、会话之前。** 会话的逐卷等答话要在几百卷上试得动，
   而攥着几千个句柄时试不动。

会话那两条（逐卷等答话、报告分组）彼此不相干，但队列照旧串行——
同一批文件上并发写，绿闸门不说明任何事。

三条闸门都要跑满：发现动 `source` 与 `survey`（默认那条），
会话那两条动状态机（`--no-default-features` 那条也编译得到），
摊开动 `cost` 里的段计时（`--features profiling` 那条）。
