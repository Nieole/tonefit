# 15 — 嵌套点名收编到最外层

**What to build:** 点名两个互相嵌套的路径（`库/` 与 `库/作品/`），同一个卷会被
**发现两遍**、各写一份输出——白做一遍，盘上两份同内容不同位置的产物。

发现之后按**卷根**折一遍：重叠的点名**收编到最外层那个根**上，镜像路径以它为准。
这与「点名一个目录就把底下的卷全找出来」是同一条读法——点名 `库/` 已经包含了
`库/作品/` 底下的一切，再点一次不该改变结果。

收停车场的 **Q111**。

**Blocked by:** None — can start immediately

**Status:** resolved

> 代码、用例、文档都落地了；**闸门待主仓**——支线上跑不出可信的数（见下面那段「勾得有保留」
> 与停车场 **Q244**）。主仓合流后那一趟绿了，末一条验收与《数》一并补上。

- [x] 点名两个嵌套的路径，同一个卷只被做一遍
- [x] 镜像路径以**最外层**那个根为准，输出结构确定且可预测
- [x] 预扫报出的总步数与实际做的卷数对得上（不再多数一遍）
- [x] 点名同一个路径两遍与点名嵌套路径走同一条收编
- [x] 非卷文件那几栏不因收编而重复列出
- [ ] 三条闸门全绿——**支线上跑不出可信的数，改由主仓合流后跑**（见下）

> **勾得有保留，两处：末一条没勾，第一条勾了但有边界。** 先说这两处，再说四处判断。
>
> **末一条「三条闸门全绿」没有勾——支线上跑不出可信的数。** 三条线共用一套 `target`

> 单元哈希逐字相同，产物同名可互换，cargo 判它「新鲜」就直接拿别人那份来跑。
> `flock` 挡不住（锁只保证不同时跑，不保证跑的是自己那棵树编出来的），
> `touch` 自己的源码也救不了（那些单元的 dep-info 记的是**别的树**的文件路径）。

>
> **第一条勾了，但边界要写明：「同一个卷」认的是「同一个卷根」，而「同一个」按字面路径比。**
> 收编那张表按 `PathBuf` 查，`Path` 的相等在哪个平台上都逐字节比。于是把同一个库写成两种

> ——盘符大小写不同就够了，而在不区分大小写的文件系统上那是同一个文件；
> `tonefit 库 ./库` 与「点名一条软链加它指向的那棵树」同理。
> Q111 自己举的那个例子（`tonefit --out D:\out 库 库\作品`）是修好的，跑得出来；
> 上面那三种没有。**没有在本票里修**：三种都要一把「文件系统认不认成同一个东西」的尺子，
> 而那把尺子已经在 `src/lib.rs` 的 `collision_key` 上（撞名那一道用它），

> ——派活说明写死了本票能动哪几个文件。记进 **Q241**（评审撞见的大小写那一半连同
> 初稿里一条站不住的理由，一并改在那条上）。
>
> 四处**判断**（不是保留，但要写明读法）：
>
> - **折的是卷根，不是点名路径之间的前缀关系。** 票面说的是「按卷根折一遍」，
>   照字面做。另一条更省事的路是先把嵌套的点名路径本身折掉、只展开最外层那几个——
>   那条会把 `tonefit 库 库/#recycle` 里用户**明说要**的那个回收站连同它底下的卷一起
>   吞掉：发现根本走不进打包环境留下的目录，两个点名因此一个卷根都不重叠。
>   钉这一条的是 `a_junk_directory_named_on_its_own_is_not_folded_away`。
> - **收编改的是去处，不是「点名的 / 发现的」那条分别。** 一个卷根同时是点名的与发现出来的
>   时候，那顶帽子留着——用户明说了要处理它，点不开仍是整趟拒绝（ADR 0014 决定第 5 条，
>   票面写死不许动）。被收编掉的那个点名路径因此**不再排在候选队头**，
>   `survey` 那一处报的路径从 `input` 改成了候选自己的卷根（两者对点名的候选恒相等）。
> - **收编排在枚举之前。** 票面写的是「发现之后按卷根折一遍」，而「发现之后」有两个位置：
>   开卷之前与开卷之后。折在开卷后面的话，步数、非卷文件、走不进去的地方这三份产出
>   已经各把同一个卷数了一遍，而预告出去的总步数收不回来。
> - **`CONTEXT.md` 与 ADR 0014 一个字没动**，撞见的那一处对不上记进了停车场
>   （**Q240**，不是票面点的 Q163——理由写在那一条里，也写在下面《停车场结转》）。
> - **候选按「头一回被发现」占座**，因此 `tonefit 库/作品 库` 与 `tonefit 库 库/作品`
>   得到同一棵输出树、同样多的卷、同一份非卷文件清单，而**报告里的卷序**不同
>   （评审撞见，记 **Q243**）。跨几个点名路径的次序从来是「用户点名的次序，
>   各自内部按阅读顺序」，本票没有改这条。
>

## 落地记录

### 一、收编成一批：`discover::Found`

`discover::of` 一次只看一个点名路径，这一票不动它。新的那一层是 **`discover::Found`**，
它把几个点名路径各自展开出来的候选**按卷根**收成一批：

```rust
pub(crate) struct Found {
    /// 收编之后的那些候选，按发现顺序。
    candidates: Vec<Candidate>,
    /// 卷根 → 它占着上面哪一格，加上收编下它的那个点名根**有几级**。
    at: HashMap<PathBuf, (usize, usize)>,
}
```

`absorb(named, candidates)` 逐个看：卷根头一回见就原样进队，见过就往那一格上收编——
**去处**换成最外层那个点名根算出来的那一条，**「点名的」那顶帽子**两边有一顶就留着。

**「最外层」按点名根的级数认**（`named.components().count()`，少的在外）。这么认得住的前提
写在那张表的字段文档上：两个点名根展开出同一个卷根**当且仅当**它们互相嵌套——
发现只在点名的路径底下走、也不跟符号链接，子树因此严格按路径前缀嵌套；而嵌套的两条路径里，
级数少的那条在外层。

**代价**：一张随卷数长的表，活到 `into_candidates()` 为止。它攥的是路径，不是句柄，
与预扫那笔「不攥着几千个句柄」的账不是同一本——那一句写在字段文档里，免得下一个读到的人
以为这里破了预扫的规矩。

### 二、`survey` 那一侧：两段循环，中间隔着收编

`Survey::of` 从「一个点名路径展开完就地枚举」改成两段：

```rust
let mut found = discover::Found::default();
for input in &request.inputs {
    match discover::of(input) {
        Ok(candidates) => found.absorb(input, candidates),
        Err(error) => refused.push((input.clone(), error)),
    }
}
for candidate in found.into_candidates() { /* 枚举、计数、三份产出 */ }
```

三件事跟着定下来：

- **每个点名路径照旧各问一遍 `discover::of`**，被收编掉的那个也问。点名一个写错的路径
  仍是整趟拒绝——那一支在 `discover::of` 的第一句上（`source::identity_of`），
  与收编无关。
- **点不开时报的路径**从 `input` 改成 `candidate.root`。两者对点名的候选恒相等
  （`discover::of` 造的头一个候选，卷根就是那个点名路径），而收编之后它不一定还排在队头，
  循环里也不再有 `input`。`survey::refuse` 的入参跟着从 `&[(&Path, _)]` 变成
  `&[(PathBuf, _)]`。
- **三份产出各只数一遍**：卷（连同步数）、非卷文件、走不进去的地方——它们都是同一遍开卷的
  产出，而开卷排在收编之后。
- **`discover::of` 照旧一个点名路径走一遍目录树**，`tonefit 库 库` 因此走两遍 `read_dir`。
  这一笔是上面第一条换来的：每个点名路径都得问一遍「它自己点不开吗」。
  贵的那一半（**开每一个卷**）已经收编掉了，剩下的是列目录；真在剖面上冒出来的话，
  只有 `source::identity_of` 是非做不可的，第二遍 `expand` 省得掉。

### 三、外面看得见的差别

`tonefit --out D:\out 库 库\作品` 从前得到：

```
out\库\作品\第1话.cbz     ← 来自点名的 库
out\作品\第1话.cbz        ← 来自点名的 库\作品
```

如今得到的与只点名 `库` 逐条相同：

```
out\库\作品\第1话.cbz
```

报告里的卷数、开工那条事件报出的卷数与全局总步数、非卷文件那张表——四样都跟着只数一遍。
**输出那一层一个字节都没动**（`src/sink.rs` 是 16 号票的地界）：这一票只管
「有哪些卷、镜像到哪儿」。

### Q111 — 点名两个互相嵌套的路径，同一个卷会被发现两遍、各写一份输出

- **From:** 票 `volume-discovery/03`
- **Kind:** 本票造出来的新形状
- **Where:** `src/discover.rs` 的 `of`（一个点名路径一棵子树，各走各的）与
  `src/lib.rs` 的 `ensure_no_two_volumes_share_an_output`
- **Why it did not block:** `tonefit --out D:\out 库 库\作品` 这样点两处，
  `库\作品\第1话.cbz` 会被发现两遍：一遍来自 `库`，镜像成 `out\库\作品\第1话.cbz`；
  一遍来自 `库\作品`，镜像成 `out\作品\第1话.cbz`。**去处不同**，撞名那一道因此拦不住，
  同一卷做了两遍、写了两份。不咬人是因为两份都是对的产物、源库一个字节没动，
  代价只是白做一遍；而这不是本票造出来的**类**问题——从前点名这两个路径同样得到两个卷
  （一个 56 卷合一的怪物加一个），只是那时两边的内容不重叠。
  本票的「一页都不被处理两遍」说的是**一次发现之内**（卷与卷架不互斥那条规则），
  不是「用户点名的几棵树之间」。
- **What this ticket actually did:** **没有去重**。要拦它得在发现之后按**卷根**折一遍
  （而不是按去处），那要先答一个领域问题：两个点名路径重叠时，该拒绝（点名有歧义）
  还是该按最靠外那一个收编（去处只留一份）？两条都说得通，而选哪一条决定了
  报告里那一卷长什么名字。按本票的《硬约束》「其余一律自己判、记下来、往下走」记在这里。
- **Whose call:** 拍板的人（互相嵌套的点名是拒绝，还是折成一份）
- **处置：** **按最外层那个点名根收编**（本票）。本条自己列出的两条出路（拒绝点名有歧义 /
  按最靠外那一个收编）里走的是第二条——票面写死了它，而理由与「点名一个目录就把底下的卷
  全找出来」是同一条读法：点名 `库` 已经包含了 `库/作品` 底下的一切，
  **再点一次不该改变结果**。
  折的地方是新的 `discover::Found`，折的依据是**卷根**——不是去处（那正是从前拦不住的原因），
  也不是点名路径之间的前缀关系（那会把用户明说要的 `库/#recycle` 连同它底下的卷一起吞掉，
  见票面上方那条判断）。折的位置排在预扫**开卷之前**：步数、非卷文件与走不进去的地方
  是同一遍开卷的三份产出，折在开卷后面等于三份各已把同一个卷数了一遍。
  「点名的 / 发现的」那条分别一格没动：一个卷根同时是点名的与发现出来的时候那顶帽子留着
  （`Found::absorb`），点不开仍是整趟拒绝（ADR 0014 决定第 5 条）。
  本条点的 `crate::ensure_no_two_volumes_share_an_output` **一个字没改**——它比的是去处，
  而收编之后同一个卷根根本不会出现两次。
