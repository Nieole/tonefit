# 23 — 补全按运行期探大小写

**What to build:** 逐层补全认不认大小写今天按 `cfg!(windows)` 判，
而 **macOS 默认那套文件系统也不认大小写**——macOS 上敲小写补不出大写开头的卷名，
补全在那台机器上是用不了的。

改成**运行期探**：在那个只读一次目录的地方多探一次，把结果记住。

收停车场的 **Q107**。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] macOS 上小写敲得出大写开头的卷名
- [x] Linux 上大小写仍旧敏感，行为不变
- [x] 那一次探测不让每敲一个字符都多一次系统调用
- [x] 判据只有一处出处，不再按平台常量猜
- [x] 三条闸门全绿

> **五条全做到。**三处**判断**（不是保留，但要写明读法）：
>
> - **第一条验收没有在真 macOS 上跑过。**验它的是两条用例合起来——「盘上开得出翻过大小写的
>   那个写法 → 答案是不认」与「答案是不认 → 敲 `d` 补得出 `Doraemon` 且补回来的是盘上那个写法」——
>   两条都在这台 Linux 上跑得到，因为**那一问与那条判据都从外面交进来**。
>   把它们接起来的是 `level` 那一行与端到端那条用例。**没有 macOS 机器**：这一条是
>   **由两条各自跑得到的用例接起来的，不是真机验的**——验证的边界照实写在这里，
>   比含糊地打个勾有用。
> - **记住的那一格是一个进程一格，不是一个挂载点一格**（**Q364**）。大小写敏感性其实是
>   挂载点的性质，跨挂载点补全会拿到头一处那个答案。
> - **撞名那条判据没动**（**Q366**）：`src/lib.rs` 的 `collision_key` 仍按 `cfg!(windows)` 折，
>   而 macOS 上 `Abc.cbz` 与 `abc.cbz` 真的会撞。那是**拒绝执行**的一条判据，改它是领域决定，
>   值得一张自己的票。新立的词条因此**限在补全上**，不替撞名那一处发言。

## 落地记录

### 一、判据换成了运行期探出来的那一格

`const CASE_INSENSITIVE: bool = cfg!(windows)` 没了，**全仓一处不剩**（连用例里按它分岔的那一支
也换掉了）。接替它的是一个取值两格的类型，名字取自 `CONTEXT.md` 新立的词条：

```rust
enum CaseSensitivity { Sensitive, Insensitive }
```

这个病的要害是**编译期常量冒充运行期事实**：Windows 不认大小写没错，
但 **macOS 默认那套文件系统也不认**，`cfg!(windows)` 在 macOS 上恰好全错——
那台机器上敲小写补不出大写开头的卷名，补全在那儿是用不了的。

### 二、「探」收在三个缝后面

三个缝，各挡住一样在这台机器上造不出来的东西：

| 缝 | 它把什么交给了调用方 | 钉住它的用例 |
|---|---|---|
| `level_asking_case(typed, ask)` | **这一层认不认大小写**这条判据 | `the_case_the_level_folds_is_the_one_that_decides_the_prefix`——注进「不认」就补得出 `Doraemon 01/`，注进「认」就一条都补不出 |
| `probe(names, open)` | **翻过大小写的那个写法开不开得开**这一问 | 五条：开得开→不认（并钉住问的是 `dORAEMON 01`）、开不开→认、那一问自己失败→探不出来、两个只差大小写的名字同时在场→不问就答完、没有带大小写的名字→探不出来 |
| `asked_once(known, ask)` | **那一格**本身 | 记下之后再问就恐慌；探不出来的那一次不记 |

`level` 自己只剩一行 `level_asking_case(typed, remembered)`，`remembered` 只剩把
模块级那一格与真 `symlink_metadata` 接起来的三行。

**为什么非要这些缝**：探测问的是**跑着的这台机器**，而两边的行为得在**每台**机器上都验得到。
用例自己再按平台分岔一次，就是把这张票刚治好的那个病又犯一遍。

### 三、探法：只读，最多一次 `symlink_metadata`

拿刚 `read_dir` 回来的一个名字翻一次大小写，先看**翻出来的那个名字是不是也在这一层里**——
两个只差大小写的名字同时在场，不认大小写的文件系统装不下它们，**已经答了「认」，那一问都省了**
（问了反倒答反：翻出来的那个写法正是旁边那个货真价实的兄弟）。不在才真问盘一次。

**不造探针文件**（**Q365**）：补全打到的那一层就是源库，而 ADR 0009 决定第 1 条是「源库只读」；
何况源库那一层多半根本不可写，那种探法在那儿自己就失败，还失败得更贵。

翻法只认「翻出来仍是一个字」的那些（`ß` 的大写是两个字母，翻出来的名字在任何文件系统上都问不着），
名字里带 U+FFFD 的一并不认——那是 `to_string_lossy` 给非 UTF-8 名字留下的记号，
拿它去问盘必然问不着，答出来的「认」是假的。

### 四、一个进程只探一次

那一格是**模块级**的 `static KNOWN: OnceLock<CaseSensitivity>`，不是 `remembered` 里面新起的一格——
两者**除了一条用例外谁都分辨不出来**，那条用例（`the_answer_lands_in_the_one_the_whole_process_shares`）
因此是「一个进程只探一次」唯一的落点。**当场做过变异检验**：把那一格挪进函数里，
16 条里只有它一条红，其余 15 条照绿。

「不让每敲一个字符都多一次系统调用」就落在这里：探测在 `ask` 里面，那一格落下来之后不问它，
一次盘都不动。

### 五、探不出来时按「认」走（Q363）

探不出来有两种：这一层里一个带大小写的名字都没有（整层 CJK 名或纯数字），
或者那一问自己失败（权限不够）。默认走**严的那一边**，而且**那一次不记进那一格**——下一层也许答得出。

选严的理由是两边的**失败模式不对称**：严的失败起来是「补不出来」，用户当场看得见、
把字敲全就绕过去了；宽的失败起来是**补出一个盘上不存在的名字**，那一串会进缓冲、进处理范围，
直到预扫才炸——错误被往下游带了一程。

而且这个默认**几乎碰不到**：探不出来的主因是「这一层里没有带大小写的名字」，
而那种情形下折不折大小写对匹配结果一格都不影响（名字里没有翻得动的字，折法就是恒等）。

### 六、`CONTEXT.md` 加了一个词条

《会话》多一条 **大小写敏感性 (Case sensitivity)**——新概念当场加进词汇表是落地的一部分，
类型名 `CaseSensitivity` 取自它。词条只说领域那一层（运行期探出来、只读、一个进程一格、
探不出来按认走、不认那一档上补回来的是盘上那个写法），探法与那一格的粒度留在模块文档里，
**一处出处**。词条末尾点明**只管补全这一处**，撞名那条判据另有自己的判法（Q366）。

`src/session/state.rs` 那句「不递归、不建索引、不缓存」补了唯一那一格例外。

### 评审两轴提的几条

**Spec 轴四条，三条是真的，三条都照改**：

- **「macOS 上小写敲得出大写开头的卷名」当时只验到一半。**`level` 那个缝是够的，
  但 `probe` 里那一问是直接的 `symlink_metadata`、**没有第二道缝**，
  「不认大小写那一档答什么」在 Linux 上无从触发，靠推理接上。
  改法：那一问也从外面交进来（`probe(names, open)`），macOS 那半条从此有自己的用例。
- **「一个进程只探一次」钉在了错的对象上。**当时那条用例验的是 `asked_once` 的语义
  （函数内新建的一格），`remembered` 里那个 `static` 一条用例都没碰过——
  把它换成每次调用新起的一格，全部用例照绿。改法：那一格挪到模块这一层，
  添一条直接读它的用例；**做过变异检验**，只有它一条红。
- **有一条用例是同义反复。**对照量取的是 `symlink_metadata(root/"dORAEMON 01")`，
  而 `flipped("Doraemon 01")` 恰好就是它——两边是同一条路径上的同一次系统调用，
  探法翻错了字它照样绿。改法：那条删掉，换成五条注进去问的；
  端到端那条的对照量取 `DORAEMON 01`（全大写），与探法翻出来的那个写法不是一个。
- **`src/lib.rs` 的 `collision_key` 仍按 `cfg!(windows)` 折**——同一个病，另一处。
  不在本票范围内（那是**拒绝执行**的一条判据），记成 **Q366**，词条限在补全上。

**Standards 轴四条**：

- **「Q363/Q364 是悬空引用、停车场只到 Q205」——假阳性**，它读到的是我追加之前的那一份；
  Q363–Q365 在文件第 1135/1156/1174 行，停车场待处理里 Q206–Q322 也都在。
- **单一出处**：词条与模块文档把探法逐句各写了一遍。**照改**——词条瘦到领域那一层，
  模块文档留实现，并在开头点明「含义由 `CONTEXT.md` 的《会话》定」。
- **类型名与词条对不上**（词条立的是《大小写敏感性》，类型叫 `Case`）。**照改**：
  类型改名 `CaseSensitivity`。顺带把 `level_where` 改成 `level_asking_case`
  （`where` 读起来像过滤谓词）、`kept` 改成 `asked_once`。
- **ADR 0009 决定 2 那条原则**（文件系统的性质按路径各判各的）与「一个进程一格」相左。
  它管的是介质探测（寻道惩罚与并发度），不是大小写，**不是直接冲突**；
  这一笔补进了 Q364。

**判断题里没照做的两条**（理由写在这里，不另记停车场）：

- **Middle Man / Speculative Generality**（`level`→`level_asking_case`→`remembered`→`asked_once`→`probe`
  几层转发，`asked_once` 只有一个调用方）。这几层**就是这张票要的东西**：
  票面点名「探测本身要可测」，而三样在这台机器上造不出来的事实各要一个缝。
  合并任何一层，对应那一档验收就回到「只能在 macOS 上验」。
- **Data Clumps**（`(directory, names)` 结伴）。`probe` 改成只收 `names` 之后，
  结伴的只剩 `remembered` 一处，不成泥团。
