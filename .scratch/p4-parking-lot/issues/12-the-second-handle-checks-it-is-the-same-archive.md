# 12 — 重开归档时核一次指纹

**What to build:** 归档卷的成员表出自开卷那个句柄，字节出自重开的那个。
两者之间归档被换掉（下载工具补完、用户手动替换），并发那一支就会
**静默读到别的字节**——不报错、不退回，产物里混着两个版本。

重开时拿一次**指纹**（中央目录偏移 + 条目数，或 mtime + 大小）与开卷那一份核对，
核不上就**退回串行**读。

**不是把源再读一遍**：那会把并发省下的当场还回去一大半。指纹要便宜。

收停车场的 **Q99**。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 重开的句柄核一次指纹，核不上退回串行、并说得出为什么
- [x] 核得上时并发照走，开销不显著（指纹不重读全部字节）
- [x] 有一条用例造出「跑到一半被换掉」的归档，断言它退回串行而不是读错
- [x] 那笔句柄账仍只有一处出处
- [ ] 三条闸门全绿　——**没跑成，见表底下那一段**

> **勾得有保留：两条。**
>
> **一、「三条闸门全绿」那一条没有勾——本票一条闸门都没跑成。**
> 三棵 worktree（`/tmp/tonefit-A`／`-B`／`-C`）共用主仓那一个 `target`，
> 在 cargo 眼里是同一个包、单元哈希相同，产物文件名一样，于是互相当成「新鲜的」直接拿来用。
> **这是并行方案本身的缺陷**（根因与证据记在 **Q244**），不是这一票改出来的：本票只动了
> `src/source.rs` 与 `src/read.rs`，一个字节都没碰别的层。
> 同一棵树上跑了四趟，**四趟四个数**——lib 应当是 216（基线 213 + 本票 3 条），
> 实际报出 219 / 219 / 213，第四趟加了 `flock` 也不管用（锁只保证不同时跑，
> 不保证跑的是自己那份产物）。**红绿都不可信，而假绿比假红更坏。**
> 因此《数》那一节写的是「**待主仓闸门**」，不是一个数——填进去就是往记录里写假话。
> **闸门由主仓合流之后跑**；红了的话失败原文回到这一票上。经过记在 **Q223**。
>
> **二、头一条的末半句「并说得出为什么」。** 那句话是拼出来了的——两个印记都摆着、
> 指得出是哪一个卷、说得出接下来怎么走，`source` 那两条用例读得到它。**可它没有到用户手上：**
> 报告里没有「这一卷退回过串行」这一栏，`read::reads` 那一支把它绑成 `_why` 就丢掉了。
> 要让它到用户手上得动 `crate::report`、命令行的 `render::tail`、会话那一侧的画法，
> 而本票的文件清单写死了「只动 `src/source.rs`、`src/read.rs` 与它们的用例」，
> 票面自己也写着「不新开对外 seam……别新开第五张表」。记进了停车场 **Q222**，去处一并写在那里。
> 与 11 号票那条规矩不冲突：**没有任何一样东西没被处理**——这一卷、其余卷、其余页一页不少，
> 变的只是这一卷这一趟不吃并发。用户看到的是慢一点，不是少一点。
>
> 另有三处**判断**（不是保留，但要写明读法）：
>
> - **类型没叫 `Fingerprint`。** 票面写的是「拿一次**指纹**」，而 `CONTEXT.md`《输出》里
>   《指纹 (Fingerprint)》已经是**幂等的依据**——作用域是一卷的内容，还要把源字节整个读一遍。
>   照字面取名就会有一个同名两义的词条，`CLAUDE.md` 那条「类型名一律取自 `CONTEXT.md`」
>   跟着执行不了。新类型因此叫 **`ArchiveStamp`（印记）**，文档头一句写明它不是那个《指纹》。
>   **词汇表没加这一条**（`CONTEXT.md` 是三条线共用的文件，本票的文件清单不许碰），记进 **Q221**，
>   去处是 28 号票。
> - **核不上时手里已经核上的那几份也丢掉，整卷退回串行**，不是「用已经开出来的那几条接着做」。
>   那两件事在 `read::reads` 里从此走两条路：句柄开不出来是「少几条读取」，核不上是「整卷退回串行」。
>   理由是「核上了」只说明那两个数撞上了，而此刻**已经知道这个文件动过**，那点证据不够；
>   而退回串行读的是**卷自己那个句柄**，成员表就是它解出来的。
> - **`Reader::independent` 的返回类型从 `Result<Reader>` 变成 `Result<Independent>`。**
>   不这么改就分不开上面那两条路（`Err(_) => break` 把两件事并成了一件）。
>   `Independent` 与 `ArchiveStamp` 都住在 `mod source` 里，而 `mod source` 是私有的——
>   `run(Request) -> Report` 一格没动，事件流一格没加，**对外一处 seam 都没新开**。

## 落地记录

### 一、印记：两个数，一次系统调用都不多花

`src/source.rs` 新增 `ArchiveStamp`，`Reader::Archive` 多一格装着**开卷那一刻**的那一份：

```rust
pub struct ArchiveStamp {
    /// 中央目录在文件里的偏移。任一成员的压缩后大小变了，它就变。
    central_directory: u64,
    /// 中央目录里的条目数。**不是这一卷的成员数**——垃圾成员与目录项这时还没摘。
    entries: usize,
}

impl ArchiveStamp {
    /// 从一个已经开着的句柄上取印记。**不碰盘**：`&` 而不是 `&mut`，游标动不了。
    fn of(archive: &zip::ZipArchive<BufReader<File>>) -> Self { /* …… */ }
}
```

**「不便宜那一条」因此一格没变。**两格都是 `zip::ZipArchive::new` 解中央目录时顺手就在内存里的
东西（`central_directory_start` 与 `len`）。**签名自己就是那条证明**：取字节要 `&mut`（游标要动），
而 `of` 拿的是 `&`——它做不出一次 `seek`，也做不出一次 `read`。
`Reader::independent` 本来就已经是「一次开文件加一次中央目录解析」，
再把源读一遍核内容等于把并发省下的当场还回去，而票面把那条写死了。

**它拦得住什么、拦不住什么**写在 `ArchiveStamp` 自己的文档里：真实的那一种换法它认得出
（下载工具补完、用户手动替换、另一份同名的包盖上来——成员多一个少一个，
或随便哪个成员的压缩后大小差一个字节，中央目录的偏移就跟着变）；
撞上同一副印记的另一份包、以及原地改写同一个 inode，它认不出（**Q220**）。

### 二、再要一份读取端时那一副分岔

```rust
pub enum Independent {
    /// 核上了：这一份读的是同一个源。目录卷恒走这一支。
    Same(Reader),
    /// **核不上**：归档在开卷之后被换掉了，这一份不敢用。
    Replaced(String),
}

pub fn independent(&self) -> Result<Independent>
```

三支各走各的，与票面逐条对得上：

- **`Directory`**——**不核**，恒 `Same`。它只把卷根抄一份、不碰盘，没有「另解一遍中央目录」
  那一步，也就没有两份解析可以对不上；读的时候按名字现取，手上没有开卷那一遍的下标。
- **`Archive`**——重开一个句柄，取印记，与开卷那一份比。核不上交出 `Replaced`，
  带着 `archive_was_replaced` 拼的那句话（两个印记都摆出来，差在哪一格看得见）。
  **不是一个错**：其余卷、其余页照常。
- **`Unextracted`**——照旧 `bail`。`open` 恒不返回它那条不变量一个字没动。

### 三、读取层：核不上就整卷退回串行

`src/read.rs` 的 `reads` 里那个循环，从前两件事共用一个 `Err(_) => break`，如今分开：

```rust
match reader.independent() {
    Ok(Independent::Same(opened)) => own.push(opened),
    // 核不上：整卷退回串行，手里这几份一并丢掉（见本函数的文档）。
    Ok(Independent::Replaced(_why)) => {
        same_archive = false;
        break;
    }
    // 句柄开不出来：用开出来的那几条接着做。
    Err(_) => break,
}
```

**那一趟仍旧跑完**，只是不吃并发：串行读的是**卷自己那个句柄**——成员表就是它解出来的，
字节与成员表因此出自同一份。换掉的是路径上那个名字，那个句柄攥着的还是原来那些字节，
退回串行于是不是将就，是这一趟唯一还说得清的读法。

**并发那一层的策略一格没动**（ADR 0009 与 `p4/14` 的地界）：介质探测没碰，
`IoPlan` 派几条没碰，`--io-mode` 没碰。这一支是**异常路径**上的一道岔，不是一条新策略。

### 四、那笔句柄账仍只有一处出处

`source::Reader` 的《一趟同时开着几个句柄》**一个字没改**，而它仍然成立：
`independent()` 每次调用照旧至多开出一个句柄；核不上那一次开出来的那个当场析构，
**峰值因此比账上说的少，不会多**。核不上之后 `read::reads` 把手里那几份一并丢掉，
那一趟走串行——中间那一格是 1，比 `min(并发度, 成员数)` 更小。

### 五、`.rar` / `.7z` 那一档为什么不在这条路上

摊开那一档的读取端是一个**目录**（`Reader::Directory`，字节在临时目录里），
而摊开发生在 `open` 里、第一次读**之前**。源包在那之后被换掉，这一卷读的字节一个都不受影响——
它们已经不在源包里了。这一档因此既不需要印记，也没有印记可核。

### 六、用例照 `tdd` 那几条审了一遍

**缝**由派活说明给死：`Reader::independent()` 那个公开边界（外部观察得到的是「再要一份读取端」
拿到的是不是同一个源），以及 `run(Request) -> Report` 那一层报告里说不说得出退回了串行。
三条新用例逐条对照下来：

- **两条落在头一个缝上**（`source::tests` 那两条）：都走 `open()` 开卷、再问
  `reader.independent()`，断言的是它**交出来的那个值**（`Independent::Same` / `Replaced`）
  与那句话的内容。**没有对私有结构写断言**——`ArchiveStamp` 是私有的，一条用例都没直接碰它；
  也**没有数调用次数**、没有 mock 任何内部协作者。
- **第三条落在 `read::reads` 上**（`an_archive_swapped_under_us_falls_back_to_serial`），
  断言的是它**返回的那个值**是 `Reads::Serial` 还是 `Reads::Concurrent`，加上交付出来的字节。
  这是本文件既有用例的同一个断言法（`one_reader_is_the_serial_path_whatever_the_container`
  就是这么断的），不是绕后门查状态。**没有学**同一文件里
  `a_concurrent_read_holds_one_reader_per_worker` 去数 `concurrent.workers.len()` 那个私有字段。
- **第二个缝上一条用例都没有**——因为那个缝上**本票一格行为都没加**：退回串行不进报告
  （判断见验收表底下第二段与 **Q222**）。没有行为就没有用例，而不是有行为却没测。
- **同义反复**：期望值不是按代码的算法再算一遍。`Replaced` 那一条断言的是票面要的两样东西
  （指得出是哪一个卷、说得出接下来怎么走），换掉的那一份是**手写的另一个字面量**
  （`&[("001.png", b"a different first")]`，成员少一个、字节也不同）；
  `read.rs` 那一条断言的是「读到的是开卷那一份的 4 个 64 字节成员」，
  而换上去的那一份是 2 个 128 字节的——**两份分得开**，用例因此真的会与代码分歧。
- **横向切片**：本票是**先写实现、后写用例**，不是红→绿那一段。据实记在这里。
  三条用例都不是「先把用例全铺开」那种——它们各钉一件票面点名的事
  （核不上、核得上、目录卷不核），一条也没测「想象中的行为」。
  **重构不在这一段里**：`read.rs` 那个 `write_archive` 是为第三条用例抽出来的辅具，
  抽出来的那几行与从前逐字节相同。

### 评审提的两条

**两条都是真的，两条都照改**，另有一条「不是 bug、供参考」的，读法写在末尾。
**评审只读代码、没跑任何 cargo、没碰工作区**（本线不跑 cargo 的理由见 Q223）。

- **[高] Windows 上一步 `fs::rename` 盖掉一个正开着的文件会红。**两条新用例都是这么换源的，
  而换的那一刻卷的读取端正开着那个文件。`std::fs::rename` 在 Windows 上是
  `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)`，不带 `FILE_RENAME_POSIX_SEMANTICS`：
  Rust std 开文件确实让了 `FILE_SHARE_DELETE`，那个文件因此搬得走、删得动，
  **可删只是打上 delete-pending，目录项要等最后一个句柄关掉才消失**——名字没让出来，
  搬进来的那一份落不下去，回 `ERROR_ACCESS_DENIED`。红在 `.expect` 上，不在断言上。
  **两条用例都改成两步**：先把开着的那一份**挪开**（只要 DELETE 权，两个平台都合法——
  rustup 搬走正在跑的 exe 就是这么干的），再把新那一份搬到空出来的名字上（目标已不存在）。
  Linux 上与一步盖过去逐字节等价。为什么要两步写在了用例里。
- **[低] `Err(_)` 那一支不置 `same_archive`，「被换掉就整卷退回串行」不是无条件成立。**
  换上去那一份**解不开**时（下载到一半的 `.part`、根本不是 zip），
  `independent()` 回的是 `Err`，走「句柄开不出来」那一支，那一趟未必退回串行。
  **字节仍是对的**（手里那几份攥的是换掉之前那一份，每一份都在它自己开出来那一刻核过印记），
  因此**不是读错**，12 号票要拦的那件事没有漏——漏的是那句话的普遍性。
  **行为一格没动，收窄的是说法**：`reads` 的文档改成「换成另一份**仍然解得开**的归档」，
  底下补一段写明解不开那一种走哪一支、字节为什么仍是对的、以及这一层为什么分不开
  （`open_archive_handle` 对两种失败回同一种错，而那句话只有一处出处是 `p2-loose-ends` 立的）。
  记进新开的 **Q224**。

**另一条「不是 bug、供参考」的没有改：**`source` 那条用例断言那句话里有「退回串行」，
评审说这等于一条 `source` 的用例钉住了一句关于 `read` 层策略的措辞。
**没改的理由：那句话本身就住在 `source.rs`**（`archive_was_replaced` 拼的）。
退回策略哪天改了，要跟着改的正是那句话，而红在 `source.rs` 指的就是该改的那个文件——
这是那条断言在做它该做的事，不是错位。

**评审另外核过、确认没问题的四点**：`ArchiveStamp::of` 拿 `&ZipArchive` 那条证明站得住
（对着 zip 8.6.0 的源核过，`central_directory_start` 与 `len` 都是已解析元数据上的纯访问器，
取字节的 `by_index` 要 `&mut`）；`same_archive` 三支除上面那一条外没别的漏
（每个 `Same` 句柄都在它自己开出来那一刻核过印记，循环中途被换掉塞不进没核过的句柄）；
三条用例没测到私有结构上去、没数调用次数、不是同义反复；
`Result<Independent>` 的波及面干净（非测试调用处只有 `read.rs` 一处，`tests/` 十七个文件
一个都没点到 `mod source`，`Reader::Archive` 两处构造点都补上了 `stamp`，
`Ok(Independent::Replaced(_why))` 是具名绑定、不会冒「field is never read」）。

> **评审这两条改完之后一条用例都没再跑过**——本线不跑 cargo（Q223）。
> 改动是两处 `rename` 各拆成两步、加一段文档与两条注释，`src/` 里的**行为一格没动**。

**Q99 那半个窗口**——`source::open` 与 `Reader::independent` 之间、随机取归档卷上
「成员表出自这个句柄、字节出自那个句柄」那一半；**Q93 那半个一格都没盖住**，两条理由各自都够：
预扫 `enumerate` 与处理 `open` 是两次各自独立的开卷，中间没有一个印记被带过去（预扫那一份卷
连同读取端当场析构，活下来的只有一条路径）；而 Q93 的两个数一个是预扫那一遍的步数、
一个是重开那一遍的成员数，与是不是归档卷无关——目录卷上同样分得了家，而目录卷连印记都没有。
按 29 号票那句「指纹盖得住就了结，盖不住就升进《尚未确立》」：**盖不住**。

### Q99 — 成员表出自开卷那个句柄，字节出自重开的那个，两者之间归档被换掉就会静默读错

- **From:** 票 `p2-loose-ends/11`
- **Kind:** 路过发现（评审 Spec 轴指出）
- **Where:** `src/source.rs` 的 `Member::entry` 与 `Reader::independent`；
  `src/read.rs` 的 `Concurrent::spawn`
- **Why it did not block:** `Member::entry` 是**开卷那一次**解析出的中央目录下标，
  而 `independent()` 是按路径重开、**重解一遍**中央目录。两次之间源归档被替换成另一份，
  同一个下标就指到另一个成员上——越界那一支报得出错，不越界那一支**静默读到别的字节**。
  从前全卷共用一个句柄，这条不存在。眼下不咬人：源是只读的，而「跑到一半有人换掉源文件」
  这件事本来就没有任何一处防着——`volume-discovery/01` 之后预扫与处理之间也是按路径重开，
  那一趟同样能撞上（只是它重开时连成员表一起重数，因此错的形式不同：那边是「数错」，
  这边是「读错」）。真要拦死，得让 `independent()` 拿开卷那一次的某个指纹去核
  （中央目录的偏移与条目数，或整个文件的 mtime + 大小），核不上就退回串行——
  那是给读取端加一道校验，不是本票的形状。
- **What this ticket actually did:** **认下这一条，没有加校验。**并发那一支照旧按
  `member.entry` 取成员。写进这里而不是就地加一句注释，是因为它跨着 `source` 与 `read`
  两层，而处置要拍板的人看见。
- **Whose call:** 拍板的人（源在跑的过程中被换掉，要不要有一道防线；那道防线该在哪一层）
- **处置：** **了结。**走的是它自己列出来的那条去处：**让 `independent()` 拿开卷那一次的
  印记去核，核不上退回串行**。判据取的是那两个候选里的头一个——中央目录的偏移与条目数——
  因为它一次系统调用都不多花（两格都是 `ZipArchive::new` 解中央目录时顺手就在内存里的东西），
  而 mtime + 大小要另问一次文件系统，且在「同一秒内换掉、大小又恰好相同」上比前者更松。
  防线落在**读取端**这一层（`source::Reader::independent` 拿主意、`read::reads` 照它走），
  不在读取层之上：`Member::entry` 那个下标是 `source` 的东西，认得出它指错了的也只有 `source`。
  **它盖的是 Q99 这半个窗口，不是 Q93 那半个**——预扫与处理之间那一次重开没有印记可带，
  两条理由写在 Q93 上（本票在那一条上补的那一段）。
  认不出的两种换法（撞上同一副印记的另一份包、原地改写）记进了新开的 **Q220**。
