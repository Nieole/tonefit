## 落地记录

### 一、按的地方：`Ctrl-C` 记进一条闩

`src/main.rs` 多了一格 `static PRESSED: Latch`，与一句装键：

```rust
fn install_the_stop_key(frame: MultiProgress) {
    let _ = ctrlc::set_handler(move || {
        if let Some(pressed) = PRESSED.press() {
            let _ = frame.println(pressed_note(pressed));
        }
    });
}
```

升级那张表拎成了 `next`（继续 → 收尾 → 中止 → 中止），与会话那一侧
`Session::raise_stop` 里那个 `match` 逐条相同，库那一侧的 `fetch_max` 说的是同一件事。
`Latch::press` 走 `fetch_update` 而不是 `fetch_add`（加下去按满 256 次就绕回「继续」，
而闩不许退回去），并**交回升到的那一级**——第三下交回 `None`，两级停就是两级，
命令行这一头没有第三种停法。那个 `Option` 同时就是屏上那一句的开关：一级只说一次，
不必另记一格「说过了没有」（按下 `Ctrl-C` 的那条线程只有一条）。

装在 `execute()` 里、`tonefit::run` **之前**：

- 会话那一岔在函数头上就让开了（`without_arguments`），那一路一个字都动不到——
  会话进 raw mode 之后 `Ctrl-C` 是一个**按键**、意思是退出会话，与这里的信号不是一回事；
- **预扫在 `run` 里面**，装晚一步那一段就按不动（那一下会丢，而不只是晚一点停，见 Q261）。

装不上**照旧硬杀**，这一趟不因此拒绝执行：那时的行为与本票落地之前逐字相同，
而「一个键没装上」不在 `CONTEXT.md` 的《失败》那张单子上——为它新开一种拒绝，
换来的是一趟本来跑得完的活儿跑不成。

### 二、停在哪儿：一格新代码都没有

`Bar::observe` 从「恒回继续」改成回**闩记着的那一级**，中间过一遍 `answer`：

```rust
answer(at_the_decision_point, PRESSED.pressed())
```

停在哪一道边界上**库那一对检查点早就写好了**（卷边界管收尾、页边界管中止，
`progress::Events` 的 `standing` 与 `aborting`），本票一格都没动它们——
命令行这一头因此不是「另立一套停法」，是「多了一个按的地方」。
`tests/events.rs`、`tests/resume.rs`、`tests/container.rs` 那一批（自己造观察者答
`Finish`／`Abort`）验的正是这一对检查点，本票一条都没改。

`answer` 那一条规矩（**决策点上的收尾要让、中止不让**）是本票必须复制的第二样：
决策点问的是「这一卷的第二遍还做不做」，拿闩去答，第一遍里按下的收尾会顺手把当前卷的
第二遍吃掉——那一卷等于走了一次试算，盘上少的**正是收尾说好要留下的那一卷**。
让掉的那一下不会丢：答复照样进库那一侧的闩（`fetch_max`），当前卷跑完之后卷边界那个
检查点照样停。

### 三、屏上那一句

**由信号那条线程当场说，不由 `Bar::observe` 说。**后者要等**下一条事件**才被调到，
而预扫那一段一条事件都没有（`Bar::survey` 的文档写着：那时这一层收不到任何事件，
转轮是自己转的）——几十个归档卷列归档头正是最长的那一段，在那里按下去而屏上一声不吭，
用户必然当它没收到、再按一下，而再按一下就是中止。`ctrlc` 的回调跑在它自己那条
**普通线程**上，这一句因此当场就说得出口。（这一条是评审提出来的，见第七节。）

话走 `MultiProgress::println` 而不是 `eprintln!`：横条归它画，绕过它插一行就把光标弄乱了。
`MultiProgress` 是个把手，克隆的与 `Bar` 手上的是同一份，因此在 `Bar` 交给 `Request`
之前把它取下来即可。印在进度条**上面**、不写进条上那行字：收尾要等当前卷跑完，
那可能是几分钟，而横条上那行字会被下一卷换掉；中止那一句更是只有留下来才看得见——
那一趟紧接着就收摊，横条整片抹掉。

**画出来那一截在一条真 pty 上看过一遍**（用例断言不了它——本仓没有任何一条用例断言过
进度条画出来的字节）。给子进程接一个 `openpty` 的从端当 stderr，按两下，终端上收到的是：

```
按停（收尾）：当前卷跑完就停，剩下的卷不开工。再按一次是中止——当前卷丢掉，立刻停。
按停（中止）：当前卷丢掉，立刻停。那一卷等于没做，最终位置上一个字节都没动过。
```

两句按次序印在三条横条上面，一句一级；那一趟的输出根随后是空的。

收尾那一句**把下一下是什么也说了**：

```
按停（收尾）：当前卷跑完就停，剩下的卷不开工。再按一次是中止——当前卷丢掉，立刻停。
按停（中止）：当前卷丢掉，立刻停。那一卷等于没做，最终位置上一个字节都没动过。
```

不说的话，用户会当它没收到、再按一下，而再按一下当前卷就丢了。
措辞留在 `main.rs` 而不是 `render`：那一份是**报告**的措辞，这两句是**进度显示**的，
与进度条上那几句（「点名 N 个路径……」「整趟 N 卷」）一个待遇——它们也都在这一层。

### 四、引了一个包：`ctrlc`

**为什么非引不可，全文写在 `Cargo.toml` 里那一条的注释上，这里不复述**（`CLAUDE.md`
《文档写作》第 4 条：单一出处）。三句话的结论：树里现成的 `signal-hook` 挂在 `tui` 后面而
闸门第二条把 `tui` 关掉；自己写要写 unix 与 Windows 两套，而后者本机编都编不到（Q263）；
它的回调跑在一条普通线程上，那个回调因此不必守异步信号安全那套规矩，
而它那个信号量**会计数**，两下挨着按不会并成一下。

代价也在那条注释里：Linux 与 Windows 上多编两个包，`Cargo.lock` 多六格。
另外 `libc` 进了 `[dev-dependencies]`（用例要往子进程送 `SIGINT`），不是新的一棵树。
许可是 MIT OR Apache-2.0，`THIRD-PARTY-NOTICES.md` 不必加——那一份只收
**随程序分发而许可与本体不同**的那几样。

### 五、用例：两个缝，四条加两条

`tdd` 那几条是实现落地之后才到手上的，因此**红→绿那一段没有走**。补用例时按那几条
回头审了一遍，两处照着改：

- **原本打算在 `main.rs` 里 `raise(SIGINT)` 给自己一下**，断言那格 `static` 升到了哪一级。
  撤掉了：它与进程那一层那两条**重合**（后者把同一条链子整个走了一遍），
  而它断言的是一个全局静态的内部状态——正是「绕后门查状态」那一类。
  `libc` 因此只留在 dev 依赖里给 `tests/stop.rs` 用。
- **原本会写成「送完信号睡一会儿再看盘上有什么」**。改成**盘上的记号**：转到那个记号
  成立为止，转多少圈不改变结论。（头一版挑的记号**挑错了地方**——挑在卷边界上，
  合流之后当场红，见第八节；换成一卷中段的那两个相之后才站住。
  「按记号不按时长」这条方向没变，变的是挑哪一个记号。）

两个缝，各自的用例：

| 缝 | 在哪 | 几条 | 问的是 |
|---|---|---|---|
| 进程这一层 | `tests/stop.rs` | 2 | 按下 `Ctrl-C` 之后盘上留下什么、退出码是几 |
| 观察者那条回路上的闩 | `src/main.rs` 的 `mod tests` | 4 | 按一次／两次各到哪一级，以及回给库的是哪个字 |

`tests/stop.rs` 那两条**都按在第一卷正写着的时候**，记号是那格临时容器的两个相
（为什么非落在一卷的中段不可，见第八节）：

- **按一次**（记号：`出/卷01.partial` 出现）：那一卷写完并改名到位，盘上是
  `["卷01"]`、二十四页一页不少，第二卷一页都没开工，退出码 `0`。
  **空的说明按下去把当前卷也丢了（那是中止），多一个说明根本没停。**
- **按两次**（第二下的记号：那格里出现第一页）：输出根**空的**——`卷01` 没有、
  `卷01.partial` 也没剩下，退出码 `0`。两下之间隔着头一批页的编（量出来 1.25 秒），
  因此**不会并成一下**（`SIGINT` 不排队，挨着送的第二下可能撞在第一下还没递到的时候
  被丢掉）；第二下按下之后还剩一整批的编，中止有余地在下一张页写出去之前停住。

**决策点那一让（`answer`）没有进程那一层的用例**：要按在一卷的**第一遍**里才试得到它，
而第一遍开头紧挨着卷边界那个检查点，盘上没有第二个记号把两者分开（见第八节）。
它由 `main.rs` 那条纯函数用例钉着。

`main.rs` 那四条：按一次交回收尾／按两次交回中止／第三下交回 `None`；手写的编码与
`Instruction` 派生的 `Ord` 对得上、升级那张表只升不降（与会话、库那两份同一条）；
决策点上收尾让、中止不让、别处照闩答；两级各说各的那一句。
库外造不出一条 `Event` 来（它两级非穷尽），`Bar::observe` 本身因此问不动——
与会话那一侧 `Watch::observe` 一个处境，整条链子接得上没有由 `tests/stop.rs` 在真进程上答。

**这两条在支线上跑不出可信的结果**（三棵 worktree 的产物混在同一个 `target` 目录里，
Q244／Q264），因此第一版是在主仓合流之后才第一次真跑的——**跑出来是红的**，
诊断与改法见第八节。

### 六、ADR 0013 决定第 3 条

### 七、评审提的几条

**两条轴子各报了几条，改了五处**（都在 `src/main.rs` 与两份 markdown 里）：

- **屏上那一句原本挂在 `Bar::observe` 上，而预扫那一段一条事件都没有**——
  按下去屏上一声不吭，而 `Ctrl-C` 又不再是硬杀，用户必然再按一下，而再按一下当前卷就丢了。
  **这一条是真的**：`Bar::survey` 自己的文档就写着「预扫期间这一层收不到任何事件」。
  改法见第三节：那一句移到信号那条线程上当场说，`Bar` 那格 `said: AtomicU8`
  与 `say_pressed` 一并删掉——评审另外提的两条（那一格是**同一个文件里第四份**
  「AtomicU8 + `code()`」的手工编码；`said` 这个名字读不出它装什么，还与
  `session::run::Asked::said` 同名异义）跟着一起没了。Q261 里那句「那一段里屏上那一句照说」
  当时是**假的**，一并改正。
- **`install_the_stop_key() -> Result<()>` 是个没有读者的 `Result`**（唯一的调用处

### 八、主仓那一趟两条全红——**是用例按错了地方，不是行为错**

合流进主仓之后闸门 1 上那两条全红：

```
one_ctrl_c_lets_the_volume_in_flight_finish_and_stops_there
  left: ["卷01"]   right: ["卷01", "卷02"]
two_ctrl_c_throws_the_volume_in_flight_away_and_the_final_place_is_untouched
  整趟都跑完了也没等到「第二卷开始写第二遍」
```

**两条是同一个病**：第一版把信号按在「`出/卷01` 出现」上，也就是**第一卷改名到位**那一刻。
而那一刻**恰好是卷边界**，卷边界上就摆着收尾那个检查点（`src/lib.rs` 的逐卷循环，
改名到检查点之间只隔着一次报告汇总加一条事件）。信号落在检查点前面还是后面因此是一枚硬币：
落在前面，第二卷压根不开工——第一条得到 `["卷01"]`，第二条连 `卷02.partial` 都等不到。
机器一忙（主仓那一趟三条闸门与别的用例一起跑），子进程在边界上被调度出去，硬币就总落在前面。

**先量再改。**拿真二进制跑了一趟，把输出根上每一件事按时刻印出来（12 核、每卷 20 页）：

| 时刻 | 发生了什么 |
|---|---|
| 0.01s | 输出根的写探针 |
| 4.64s | `卷01.partial` 出现（**第一遍走完，第二遍开始**） |
| 5.89s | 头一批 12 张页编完，2 毫秒里写完 |
| 6.85s | 第二批 8 张编完写完，`卷01` 改名到位 |
| 11.34s | `卷02.partial` |

这张表把两件事一起答了：**改名那一刻确实是边界**（6.851s 改名、下一件事就是检查点），
而**第二遍本身有两秒多**、中间还有一个「头一批写完了、下一批正在编」的相。

**改法：记号移到一卷的中段。**两条都按在第一卷正写着的时候——
第一下按在 `卷01.partial` 出现（窗口是整个第二遍，两秒多），
第二下按在那格里出现第一页（与第一下之间隔着头一批的编，1.25 秒，两个信号并不成一个；
之后还剩一整批的编，中止有余地停住）。第一卷因此要**核数两倍**那么多页
（本机 12 核即 24 张）：第二遍**按批**走（一批 `cores()` 张，整批并行编完再逐张写），
编是秒级、写是毫秒级，**两个空当靠的都是下一批的编**，页数多过核数才有第二批。
页数**照机器算而不是写死一个 24**——写死的话，核多过它的机器上会退化成单批，
那两个空当从「一整批的编」缩到「写完剩下几页」，两个半数量级（复评提的）。
页数跟着核数长不亏：第一遍与每一批的编都是并行的，多出来的页摊在多出来的核上。
后面两卷各一页——它们只用来说明「下一卷不开工」。

**行为一格没改**：`src/main.rs`、`src/lib.rs`、`src/sink.rs` 一个字节都没动，
改的只有 `tests/stop.rs`。改完在本机跑了五趟：三趟常态各 20 秒全绿，
另两趟**在 24 条 `yes` 撑起来的负载下**（load 29，两倍多超订）跑了 52 秒、53 秒，
仍旧全绿——那正是主仓那一趟红掉时的处境。

**复评又提了两条，都照改**（仍只动 `tests/stop.rs`）：页数从写死的 24 改成
**照核数算**（理由见上一段）；转圈那一处从 `yield_now` 改成歇一毫秒——
等的仍是那个记号、歇多久不改变结论，歇一下只为不把一个核空转掉，
而子进程正想拿满所有核编页。复评另外**独立核过那个诊断**：`["卷01"]` 只有两条路生得出，
而「决策点没让」那一条排除得掉（`ask_before_the_second_pass` 发的正是
`PassStarted{Second}`，`at_the_decision_point` 逐字匹配，`answer(true, Finish)` 答继续；
第二遍与写页只认 `aborting()`，收尾吃不掉当前卷）——**行为确实没错**。

### Q38 — 两级停是 `run` 的能力，而命令行这一路还没有按的地方

- **From:** 票 `p1-session/02`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/main.rs` 的 `Bar::observe`（恒回 `Instruction::Continue`）
- **Why it did not block:** ADR 0013 决定第 3 条明写「收尾与中止是 `run` 的能力，不是 TUI 私有的：
  命令行那一路同样用得上」。本票把回路立起来之后，库这一侧已经收得下那两个字，
  缺的只是命令行那一头的**按键**——而那要接 Ctrl+C 信号处理，并决定按一次与按两次怎么分。
  本票的硬约束是「命令行现有行为一字不变」，接线当场就越了界；而它也不该由本票定形状：
  `04`（中止）落地之后中止才真的停得比收尾早，在那之前接上去，用户按第二下看不出区别。
- **What this ticket actually did:** **没有接。**`Bar::observe` 恒回继续，并在文档里点名
  这是「还没有那个键」，不是「命令行不该停」，同时点了 ADR 0013 决定第 3 条。
  Ctrl+C 仍然只有杀进程一条路——与本票落地之前逐字相同。
- **Whose call:** 拍板的人（命令行那一头要不要接 Ctrl+C 信号处理）——
  `10` 已落地会话那一侧的两级停（`s` 按一次收尾、再一次中止），命令行这一头仍然空着
- **处置：** **了结。命令行这一头接上了。**`Ctrl-C` 按一次是收尾、按两次是中止，
  按下的那一级记进 `src/main.rs` 的 `PRESSED` 那条闩，`Bar::observe` 从「恒回继续」
  改成回那一级——它文档里那句「还没有那个键」因此删掉了。
  这一条当年列出的两个前提都已经成立：`04` 早就落地，中止**真的**停得比收尾早
  （页边界 vs 卷边界，用户按第二下看得出区别，`tests/stop.rs` 那两条断言的正是这个差别）；
  而「命令行现有行为一字不变」那条硬约束是 `p1-session/02` 的，不是本票的——
  本票的活儿就是改它。按的形状由票面定死：**一次收尾、两次中止**，
  与会话那两级同一条闩、同一对检查点，不新造第三种停法。
  ADR 0013 决定第 3 条就地修订，写明**两边都按得动**。
