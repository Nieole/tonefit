# 14 — 摊开的卷按它此刻住的路径探介质

**What to build:** `.7z` 与 `.rar` 摊开之后，那一卷的字节已经躺在一个**目录**里了，
读取策略却仍按「归档卷是一条顺序扫」派——它白白按串行读，吃不到并发。

**介质仍按路径探**（`ADR 0009` 那条边界不松），只是探对路径：探它**此刻真正住的那个**，
不是它原本来自的那个归档。

收停车场的 **Q119**。

**Blocked by:** 13 — 摊开一整卷途中的检查点（同一段代码）

**Status:** resolved

- [x] 摊开的卷按临时目录所在的介质派读取策略，吃得到并发
- [x] 「介质按路径探测」那条决定一个字不改——探的是路径，只是换了哪一个路径
- [x] 报告里那一行说得出这一卷这一趟是怎么读的，口径不变
- [x] 三条闸门全绿

## 落地记录

摊开的卷从此按**它此刻真正住的那个路径**探介质，也按**读取端**派读取策略。
`.7z` / `.rar` 摊开之后与目录卷同形：两路取同一个数，吃得到并发。

### 这不是松 ADR，是让实现追上已经定了的事

`ADR 0009` 一个字没碰。真正被违背的是 **`ADR 0015` 决定第 3 条**——它写着
「`.rar` / `.7z`：**开工前整卷摊到临时目录，之后完全按目录卷走**」，
《后果》再说一遍：「摊开一次之后，下游看到的就是一个目录卷，
**读取层**、缓存、幂等、隔离没有一处需要认识『固实』这个概念」。

而落地之前的读取层**恰恰认识它**：`IoPlan::decide` 收的是容器形态，
摊开的卷容器形态仍是归档，于是它被按在「归档卷是一条顺序扫」那一格上。
本票因此不是改一条行为，是**把实现搬回决定里**。
边界仍在 `ADR 0009` 之内：介质照旧按路径探，换的只是喂进去哪一个路径。

### 根因有两条，票面只点了一条

票面（与 Q119）点的是探测那一条。落地时发现**两条都得改，缺一条验收框第一条就打不上勾**：

| | 病 | 位置（落地前） |
|---|---|---|
| 1 | 探的是**原归档路径** | `src/lib.rs` 那句 `probes.medium(&surveyed.root)`，排在 `source::open` **之前**——而临时目录要摊开了才存在 |
| 2 | 派读取策略问的是**容器形态** | `IoPlan::decide(…, volume.container, …)`；摊开的卷 `container` 仍是 `Archive`，`readers` 因此被无条件钉成 `1 / ChosenBy::ArchiveScan` |

**只改第 1 条，介质探对了，那个数照样被第 2 条按在 1 上。**
这类「票面点了症状的一半」最容易让一张票看着做完了其实没做成：
代码更对了、验收却过不去，而下一个人不知道为什么。

第 2 条的改动**限定在分岔判据**（容器形态 → 读取端）。
`Container` 本身、以及它在**输出归一**上的用法（归档卷输出一律 `.cbz`，`ADR 0015` 决定第 2 条）
一格没动。

### 缝：读取端自己就知道字节在哪

不必新造一份记账。`Reader::Directory { root }` 在摊开的卷上装的**本来就是**那个临时目录
（`extracted_volume` 一直是这么建的），只是从前没有人问过它。
这是**补上一个已经存在的事实**，不是新增一份状态——与上面那条 ADR 论证是同一个道理。

落成两个方法加一个词，都在 `src/source.rs`：

| | |
|---|---|
| `Reader::reads_from` | 这一卷**此刻从哪儿取字节**：目录卷是卷根，随机取的归档卷是那个归档文件，摊开的卷是那个临时目录。介质探测的输入换成了它 |
| `Reader::reading_end` | 这个读取端是[哪一种](`ReadingEnd`)。`Unextracted` 保守归到归档那一头 |
| `ReadingEnd` | 新词，两格：`Directory` / `Archive`。**与容器形态不是一件事**，分岔正落在摊开那一档上 |

`reads_from` **借出去的是一段 `&Path`，不是那个 `TempDir`**：借用期不长于这个卷，
收摊照旧只由 `Extraction` 的析构管——`Volume::extraction` 那条「不多一处能让它活得更久」
的不变量一格没松。何况 `Reader::Directory { root }` 本来就是公开的，这个答案没多露一个字节。

`src/lib.rs` 那一侧只是把探测**挪到开卷之后**：`process_volume` 从收一个算好的 `Medium`
改成收那份 `Probes`（一次运行仍共用同一份按通道的缓存，`ADR 0009` 的《后果》要的正是它）。

### 口径不变

`ChosenBy::ArchiveScan` 印出去那句「（归档卷是一条顺序扫）」**一个字没改**——
摊开的卷从此不落在那一格上，而**还落在那一格上的，正是唯一还这么读的那种归档卷**。
摊开的卷那一行于是与目录卷同形：只说一次读取策略，不再分出「幂等那一道」。

### 并发那一头真的吃到了，链条四节各有用例钉着

| | 钉在哪 |
|---|---|
| 计划说并发 | `tests/concurrency.rs::an_extracted_volume_reads_concurrently_while_a_random_access_archive_still_scans` |
| 计划那个数就是读取层收的数 | `src/lib.rs` 把 `io.readers.count` 原样交给 `read::reads` |
| 摊开的卷读取端是 `Reader::Directory` | `src/source.rs::a_volume_reads_from_wherever_its_bytes_live_right_now` |
| **摊开的卷交到读取层，真的走并发那一支** | `src/source.rs::an_extracted_volume_really_takes_the_concurrent_path` |
| 目录读取端拿到 >1 真的开线程 | `src/read.rs::serial_and_concurrent_hand_over_the_same_bytes_in_reading_order`（目录卷那一半点名 8 条走并发，交出的字节与串行逐份相同且有序） |

第三行那条用例是 `/code-review` 要来的：**在它之前，没有一条用例让摊开的卷走过读取层**——
两头各钉一半，中间靠推理接上。只看[读取计划](src/medium.rs)那个数，
量到的是**打算**派几条，不是真派了几条。

新那条集成用例**与机器无关**：它点名 `--io-mode concurrent`，断言的是
`chosen_by == Named`、条数 == 核数、两路相等，
临时目录探出来是哪种盘都不改变这一条。同一趟里放一个 `.cbz` 当对照，
它仍印「顺序扫」——两个卷容器形态都是归档、输出都是 `.cbz`，读法却分了岔。
（赌盘的写法会在别人机器上飘，那正是这条用例不那么写的理由。）

### `CONTEXT.md` 改了什么

《I/O 与并发》加一行新词条**《读取端形态 (ReadingEnd)》**——实现引入的新概念，
按 `CLAUDE.md`「新词可以当场加」办。

**它一开始叫错了名。**我原本把词条起作《读取端》，而 `/code-review` 指出
「读取端」在基线的 `src/` 里已经用了 **31 处**、指的一直是 `Reader`（取字节的那一半）——
`src/source.rs` 基线原文就是「它的读取端却是一个目录」。一词二用会让
`CONTEXT.md` 开头那条「不要漂移到同义词」当场落空。改成《读取端形态》之后，
`读取端` 保留它原有的含义，新词说的是它**是哪一种**——而 Rust 那一侧的文档
第一句本来就写着「一个卷这一趟的**读取端形态**」，两边这才对上。

那段散文原先按**容器形态**分岔（「归档卷上两路的数不同」「目录卷两路恒相同」），
改成按**读取端**分岔；**两句的结论一个字没动**。
判断依据：那是散文不是词条，且它说的事 `ADR 0015` 决定第 3 条早就定了——
不改，落地当天它就成了一句假话。这条判断记在停车场 **Q414**。

### 「归档卷」这个词变成了会骗人的东西

落地之后它不再指同一批卷，凡是拿它当读法判据的句子都得收窄成
「读取端是一个归档句柄的卷」。**我第一遍只订正了三处，`/code-review` 抓出还漏一批**——
其中一处就在我改过那句的下面两行，另一处与它上面第四行当场自相矛盾：

| 位置 | 原先说的 |
|---|---|
| `src/read.rs` 模块头 | 「目录卷是抄一份卷根，归档卷是另开一个文件句柄」 |
| `src/read.rs` 的 `reads` | 「归档卷每条线程要一个自己的文件句柄」——摊开的卷抄卷根、不开句柄 |
| `src/read.rs` 两条用例文档 | 同款 |
| `src/cost.rs` 的 `Stage::Read` | 「归档卷上两遍是一条顺序扫」——而上面第四行写着「摊开之后那几步与目录卷一模一样」 |
| `src/medium.rs` 的 `Readers` | 「归档卷上这两路的数与出处都不同」 |
| `src/source.rs` 的 `Reader` | 《一趟同时开着几个句柄》那一格 |
| `src/lib.rs` 的 `volume_fingerprint` | 那一段的抬头 |

**句柄账那一节要单说**：峰值 `min(并发度, 成员数) + 3` 与那道「没有上限」的论证
**一格没变**（摊开的卷是 `0 + N + 2`，落在上界之内）。但同一节里另外两句必须改——
「主项在两种**容器**上同形」那句的式子只写了归档句柄那一档，
而「自变量只有三个：并发度、成员数、**容器形态**」的第三个，如今是**读取端**。
那一节自称「这笔账只有这一处出处」，所以只此一处要改，但非改不可。

收停车场 **Q119**。

**Q416 是审查抓出来的，我第一遍记错了。**我原本在 Q415 里写「不会比从前慢——
从前摊开的卷两遍恒串行」，那句话**只覆盖了两遍那一路**。幂等那一道不在里面：
它从前按**归档文件**所在的盘取数，如今按**临时目录**取。
源归档在固态盘、而 `std::env::temp_dir()` 落在机械盘上的机器，
这一道会从 `min(核数, 成员数)` 条掉回 1 条——而那一段没有可与之重叠的计算，
掉回串行是实打实的墙钟。

**新的数仍是对的那个**：那一道读的就是临时目录里的文件，按那条通道判正是
`ADR 0009` 决定第 2 条要的；从前是在拿一条根本不会去读的通道的结论派活。
但「对」不等于「不要认代价」，所以它单独成一条。


**Q413 一个字都没动 `docs/measurements.md`**：整份 `grep` 过 `cbz` / `.7z` / `.rar` / `zip`，
一处都没有——那批跑过的卷是哪种格式，那份文件自己说不出来，
因此判不出那几行今天是不是仍然照实。`_samples` 语料不在这台机器上，这一轮重量不了。
**在拿到出处之前不许改措辞：改了就等于替那批跑过的卷认下一种格式，而那正是编数。**
