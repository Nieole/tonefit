## 落地记录

### 一、出事行答「此刻」，报告末尾那几小结答「已定案」（Q148）

从前出事行的「失败 N 页」走 `Report::failures()`，那一份**只含收摊了的卷**——它因此比
同一屏的报告区晚一整卷：报告区已经写着「失败页（出现的当场……）解不出完整尺寸：
JPEG 数据截断」，而钉在它上面、专门答「这一趟到底怎么样」的那一行一个字都不说。

此刻它走 `Live` 新出的一条：

```rust
/// **到此刻为止坏了几页**：报告里那几页，加上报告收不了的那两截。
pub fn failures_so_far(&self) -> usize {
    self.report
        .failures()
        .count()
        .saturating_add(self.lost_failures)
        .saturating_add(self.in_flight_failures)
}
```

**三截拼出来的不是三个出处**：`live.rs` 开头那句「事件流就是报告的增量」说的正是这一件——
一卷跑完，它那几页从在途挪进报告，三截的和一格不变。两格新账各答一件事：

| 新添的一格 | 装的是 | 什么时候动 |
|---|---|---|
| `in_flight_failures` | 当前这一卷已经报过的失败页 | `PageFailed` 加一格；一卷收摊时清零（`finish_volume`） |
| `lost_failures` | **跟着没做成的那几卷一起没了去处的**失败页 | 一卷没做成时把在途那几格挪过来（`volume_failed`） |

**第二格是评审逼出来的**：起初只有一个水位，一卷收摊时推到当下的条数——而
`volume_failed` 与 `volume_finished` 走的是同一处 `finish_volume`，于是一卷先坏两页、
再整卷没做成的那一刻，那两页从「此刻」里整个消失：一个自称答「此刻出了多少事」的数
**往回走了一格**，而同一屏的报告区照旧一条不少地列着它们。那正是本票要治的 Q148 那个病
换了一种卷。此刻它**只涨不落**：一卷跑完时那几截只是换手。

**「这不是一个数摆两处」写进了模块文档**，那一节就叫《这一块答「此刻」，报告末尾那几小结
答「已定案」》，正文是一张两行的表：出事行答**此刻**出了多少事，末尾小结答**已定案**的
那几卷出了多少事，一卷收摊之后两个数又相等。措辞仍旧逐字相同（ADR 0016：措辞只有一处
出处），两处照旧没有合成一个函数——那几小结是成句的，这一行是一串数。

钉它的用例换了名字，也换了问法：

| 从前 | 此刻 |
|---|---|
| `the_trouble_row_counts_what_the_report_tail_counts`：同一份报告，两处**数得一样** | `the_trouble_row_says_now_while_the_report_tail_says_what_is_settled`：当前这一卷又坏一页时出事行说「失败 2 页」、末尾小结说「失败 1 页」，**故意不一样**；那一卷收摊之后两头又对着说出同一句话 |

`Report::failures()` 那一头一格没动——**报告末尾那几小结仍旧只数已定案的那几卷**。

### 二、试算那一副也带失败页与卷级失败（Q146）

从前两张单子按副二选一，而失败页与卷级失败在试算那一趟里照样出得来（解不出尺寸的页在
第一遍就失败，试算只是不走第二遍；卷根被删掉的卷同样记一笔卷级失败）。那两样因此从
分岔里摘了出来：

```rust
let mut listed = match live.started_as() {
    RunMode::DryRun => vec![特例页, 宽溢出, 几何门不成立],
    RunMode::Process => vec![隔离],
};
// **盘上出的那两样两副都有**（Q146），因此摆在分岔外面。
listed.extend([失败页, 卷级失败]);
```

压在末尾是**照重轻排**：前面那几样是「注意」，这两样是「出事」——而整行取列着的那几件里
最重的那一档（`p3/09` 立的那一条一格没动）。**「一条都没有时整行不出现」也一格没动**：
`count` 逢零一个字都不说，一件都没有时 `trouble_row` 答 `None`。

`the_settled_and_trouble_rows_say_different_things_in_each_mode` 那张「互不出现」的单子
跟着摘掉了这两样——**两副各说各的仍旧成立**，只是那两样不属于各说各的那一批。
新添的 `a_dry_run_says_what_broke_too` 问三件：试算那一副带得出这两样、不带「隔离」、
一趟干净的试算整行仍不出现。

### 三、这两行按「起手按的哪一个键」画（Q149）

`Live::mode()` 在决策点上答出第一个继续的那一刻从试算翻成执行。结论行与出事行跟着它走的话，
**同一帧里**：判定分布换成完成／跳过——用户刚据以拿主意的那一份没了；出事行从三样换成
一样，此刻多半全是零，于是整行消失、这一块矮一行、下面的报告整块上移。

两行因此改问 `Live` 新出的另一条：

```rust
/// **起手按的是哪一个键**：`t` 起的那一趟是试算，`x` 起的那一趟是执行。
pub fn started_as(&self) -> RunMode {
    match self.resumes {
        Resuming::Waits => RunMode::DryRun,
        Resuming::GoesOn => self.ran_as,
    }
}
```

它**一趟之内一格不变**，连收场之后也不翻面——翻面只是把那一跳挪到收场那一帧。
不是新开一个开关：`Resuming` 起手那一刻就定死（`resuming()` 判的，
`every_trial_resumes_however_many_paths_it_names` 钉着「试算续做、执行不续做」）。

**抬头照旧跟着 `Live::mode` 改口**（试算 → 执行）。Q149 原来那句「总览块另立一个判据就等于
屏上有两个说法」在这一副下不成立：两处答的本来就不是同一个问题——**抬头答「此刻在写没写」，
这两行答「这一趟交出来的是什么」**，而抬头摆在边框上，一行正文都不占。代价（续做那一趟
从此不给「完成 · 跳过」）新记在 Q196。

`answering_go_on_does_not_move_the_overview` 三问：答完继续之后结论行一个字不差、
出事行一个字不差、这一块不矮一行；外加抬头照旧改口。

### 四、横条按让位那一处收窄，溢出从中间省略（Q169）

**收窄那一下摆在让位那一处**，成了那一模块《宽度不够》的第三步（左栏 → 砍列 → 横条）：

```rust
/// 一条横条**在这么宽的一格里画多宽**：摆得下就照 `full` 那么宽，摆不下就一路收窄，
/// 窄过 [`BAR_MIN_WIDTH`] 就整条让掉（答 `None`）。
pub(super) fn bar_width(full: u64, room: u16) -> Option<u64>
```

**横条本身有多宽仍只有一处出处**：`full` 由调用方给，总览块那一份就是 `BAR_WIDTH`
（`crate::BAR_WIDTH`），`p3/07` 那句 `assert_eq!(BAR_WIDTH, crate::BAR_WIDTH as u64,
"横条宽度长出了第二份")` 一格没动，照旧绿着。这一层因此没有第二个宽度——
让位那一处答的是「这一格让给它几格」。

三件跟着定下来：

- **两行各按自己剩下的格算**（`with_a_bar` 一行一遍），不合成一个数。合成的话要取两行里
  更紧的那一个，而当前卷那一行的长短随**卷名**变、卷与卷之间整行还是空的——全局那一条的
  刻度会在换卷那一刻跳一下，同一个「走了六成」上一刻十八格、下一刻六格，看着像整趟往回退了
  （评审提的）。代价是同一屏上两条可以差一格；两行的横条本来就**对不齐**（从前就认下的），
  而它们量的本来也是两件事：一条整趟，一条这一卷。
- **量的与画的是同一份文字**：`head` 与 `tail` 拼一次、量一次、用一次，中途不再问第二遍
  那一趟走到哪儿了。各问各的话，`59s` 涨成 `1m00s` 的那一瞬画出来的那一行比量的时候宽两格，
  而宽出去的那两格由省略号收——省略号正好落在横条身上，切出半条没有 `]` 的横条，
  也就是本票要拦的那一副（同一条道理见 `Live::overall` 那段「一次读表算两个数」，Q118）。
- **整条让掉的那一档一个空格都不留**：那一行照旧成句，两个数之间不会多出一格没人解释的空白。
- **正文那几行摆不下时从中间省略**（`Overview::draw` 走 `yielding::pinned`）：与抬头
  同一处截法（Q147 立的）。`已用 5m00s` 由终端库硬截成 `已用 5m` 与抬头那一头
  `还剩约 3m20s` 截成 `还剩约 3m` 是同一种坏——读起来完整，而屏上没有一处痕迹说它被截过。

宽度一路量下来（`a_run_in_flight` 那一副，主区各档）：

| 主区几列 | 屏上 |
|---|---|
| 96 | 两条都是满宽 30 格 |
| 45 | 全局那一条九格、当前卷那一条八格（`BAR_MIN_WIDTH`） |
| 44 | 当前卷那一条整条让掉，全局那一条还剩八格 |
| 43 | 两条都不画，两行的数与「已用」整条在屏上 |
| 30（80×24） | 一条都不画，正文从中间省略：`│ 总体 3000/500⋯ · 已用 5m00s│` |

**末一档做不到票面那条验收**——正文本身就比那 28 格宽（算式、两条出路与代价记在新的
**Q194**）。Q169 头一句「右边那个方括号不在屏上」收掉了：半条横条一格都不画。

**这一块的宽度算与画同一个数**：`overview()` 多收一个 `width`（横条要照它收窄），
`Overview` 记着它，`draw()` 不再另收一个——从前那两处虽然恒等，但摆着两个入口就等于
两个宽度。

**做到的那一半在 80 列以上也看得见**：96 列的整屏快照上主区是 44 列，从前那一条横条
被切在 `] 300` 处，此刻是一条完整的八格横条加齐整的两个数
（`FOCUS_ON_THE_CONFIG` 那四张）。

### Q146 — 试算那一副的出事行里没有失败页与卷级失败，而试算同样出得了这两种

- **From:** 票 `p3-session-legibility/07`
- **Kind:** 票面没想到的一种情形
- **Where:** 票面第三段；`.scratch/p3-session-legibility/spec.md` 的
  《Implementation Decisions》第五条；`src/session/draw/overview.rs` 的 `trouble_row`
- **票面原话:** 「**试算**：结论行给判定分布（`6 卷 2bit+FS   2 卷 4bit+FS`），
  出事行给要注意的（特例页几张 · 宽溢出几页 · 几何门不成立几卷）。
  **执行**：结论行给完成与跳过几卷，出事行给隔离几卷 · 失败几页 · 卷级失败几卷。」
- **现状:** 两张单子是**互斥**的，而失败页与卷级失败在试算那一趟里照样出得来：
  解不出尺寸的页在第一遍就失败（试算只是不写第二遍），卷根被删掉的卷同样记一笔卷级失败。
  照票面走，一趟试算里坏了三页、废了一卷，总览块的出事行**一个字都不说**——
  而那正是这一块存在的理由（「这一趟到底怎么样」）。报告区与报告末尾那几小结说得出，
  但那要往下翻。
- **What this ticket actually did:** **照票面走，两张单子按 mode 二选一**，
  试算那一副只数特例页 · 宽溢出 · 几何门不成立。理由是本票的验收第二条明写
  「结论行与出事行按试算／执行给不同的内容」，而把三样合成六样就等于两副合成一副——
  那是改 spec 第五条的决定，不是落地的自由度。落地记录与快照
  （`the_overview_of_a_dry_run_that_finished`）钉住的正是票面那三样。
- **Whose call:** 拍板的人（试算那一副要不要把「失败几页 · 卷级失败几卷」也带上；
  带上的话两副各四到六样，行宽在 80 列上就要砍）。
- **处置：** **了结。**试算那一副的出事行此刻**也带失败页与卷级失败**：那两样从按副
  二选一的单子里摘了出来，摆在分岔外面（`src/session/draw/overview.rs` 的 `trouble_row`），
  两副都有。本条问的正是「试算那一副要不要把这两样也带上」，答案是要——理由就是上面
  《现状》那一段。行宽那一头的代价本条自己预告过（「两副各四到六样，行宽在 80 列上就要砍」），
  而窄档此刻由**让位**那一处收（横条先让，剩下的从中间省略，见 Q169 的处置与新记的 Q194）。
  用例 `a_dry_run_says_what_broke_too` 钉着这一条；
  `the_settled_and_trouble_rows_say_different_things_in_each_mode` 那张「互不出现」的单子
  跟着摘掉了这两样——两副各说各的仍旧成立，只是那两样**不属于**各说各的那一批。

### Q148 — 出事行的失败页数的是收摊了的卷，比同一屏的报告区晚一整卷

- **From:** 票 `p3-session-legibility/07`
- **Kind:** 票面没想到的一种情形
- **Where:** `src/session/draw/overview.rs` 的 `trouble_row`；
  `src/session/live.rs` 的 `Live::failed_pages`；`src/render.rs` 的 `isolation_tail`
- **现状:** 出事行的「失败 N 页」走 `Report::failures()`，那一份只含**收摊了的卷**；
  而同一屏的报告区走 `crate::render::failing_pages(live.failed_pages())`，
  失败页**出现的当场**就画出来了。于是有一段真实存在的窗口：报告区已经写着
  「失败页（出现的当场……）解不出完整尺寸：JPEG 数据截断」，而钉在它上面、
  专门答「这一趟到底怎么样」的那一行一个字都不说；等那一卷收摊，出事行才冒出来，
  同一刻这一块从五行涨到六行，报告区整块跟着挪一行。
- **What this ticket actually did:** **仍旧读报告那一份**，不换成事件流那一份。
  理由是本票立的形状：出事行的数与措辞要与**报告末尾那几小结**对得上
  （`the_trouble_row_counts_what_the_report_tail_counts` 两头对着问），
  换成事件流那一份就有了两个出处，而两者只在「一卷收摊之后」才必然相等。
  失败页出现的当场在报告区已经看得见，丢的只是「钉住那一行也说一句」。
- **Whose call:** 拍板的人（出事行要不要读事件流那一份，代价是与报告末尾那几小结
  在一卷跑到一半时对不上）。
- **处置：** **了结。**出事行改答「**此刻**」：失败页走 `Live::failures_so_far`——
  收摊了的那几卷仍旧数报告，**当前这一卷已经报过的那几条从事件流里数**
  （分界线是 `Live::settled_failures`，一卷收摊时推一格）。`live.rs` 开头那句
  「事件流就是报告的增量」说的正是这一件：两截拼出来的不是两个出处。
  它与报告末尾那几小结从此答**两个不同的问题**——一卷跑到一半时两个数**故意**不一样，
  一卷收摊之后又相等。这一刀写进了 `overview.rs` 的模块文档（那一节就叫
  《这一块答「此刻」，报告末尾那几小结答「已定案」》），措辞仍旧逐字相同（ADR 0016）。
  原来那条 `the_trouble_row_counts_what_the_report_tail_counts` 改成了
  `the_trouble_row_says_now_while_the_report_tail_says_what_is_settled`：两头对着问的
  从「数得一样」变成「跑到一半故意不一样、收摊之后又相等」。**词条那一步归 28 号票**
  （记在 Q163 第 11 条）。

### Q149 — 决策点上答出「继续」的那一瞬间，钉住的这一块换内容、并可能矮一行

- **From:** 票 `p3-session-legibility/07`
- **Kind:** 票面没想到的一种情形
- **Where:** `src/session/draw/overview.rs` 的 `settled_row` 与 `trouble_row`；
  `src/session/live.rs` 的 `Live::mode`
- **票面原话:** 「**结论行与出事行的内容随这一趟是什么而变**，而「是什么」手上已经有，
  不必多一个开关」
- **现状:** `Live::mode()` 在决策点上答出第一个继续的那一刻从 `DryRun` 翻成 `Process`
  （那一卷真写了出去）。屏上因此**同一帧里**：结论行从「判定分布」换成「完成 · 跳过」，
  出事行从「特例页 · 宽溢出 · 几何门不成立」换成「隔离 · 失败页 · 卷级失败」——
  前一副几乎恒有内容、后一副此刻多半全是零，于是出事行整行消失、这一块矮一行、
  下面的报告整块上移。而那一帧正是用户刚看完判定、按下 `x` 的那一下，
  他刚才据以拿主意的那份判定分布同时也没了。
- **What this ticket actually did:** **照票面走，不多一个开关**：`Live::mode()` 是「这一趟
  落过盘没有」的唯一出处，报告抬头（`render::header` 的 dry-run 那一行）跟的也是它，
  总览块另立一个判据就等于屏上有两个说法。这一下过渡票面没交代，记在这里。
- **Whose call:** 拍板的人（续做那一趟的总览块要不要在收场之前一直按试算那一副画，
  或者两副都给）。
- **处置：** **了结。**结论行与出事行的分岔从 `Live::mode` 换成 `Live::started_as`
  （**起手按的哪一个键**，一趟之内一格不变）——本条列的两条路里的第一条「续做那一趟
  一直按试算那一副画」，而且**连收场之后也不翻面**：翻面只是把那一跳挪到收场那一帧。
  抬头照旧跟着 `Live::mode` 改口（试算 → 执行）：本条原来那句「总览块另立一个判据就等于
  屏上有两个说法」在这一副下不成立——两处答的本来就不是同一个问题，抬头答「此刻在写没写」，
  这两行答「这一趟交出来的是什么」，而抬头摆在边框上，一行正文都不占。
  用例 `answering_go_on_does_not_move_the_overview` 钉着（两行一个字不差、这一块不矮一行、
  抬头照旧改口）。代价新记在 **Q196**。

### Q169 — 80×24 那一档主区只有 30 列，两条横条连同步数一起被切在半路

- **From:** 票 `p3-session-legibility/13`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/session/draw/overview.rs` 的 `overall_row`／`walking_line` 与 `BAR_WIDTH`；
  快照 `src/session/draw/yielding.rs` 的 `AT_EIGHTY_BY_TWENTY_FOUR_RUNNING`
- **现状:** 80 列的屏上左栏 50 列、主区 30 列（`MAIN_MIN_WIDTH`），而总览块那两行各要
  六十几格：一条横条 `BAR_WIDTH` 是 30，加上方括号、`3000/5000 步` 与 `已用 5m00s`。
  屏上因此是 `│ 总体 [==================>  │`——**右边那个方括号、步数与已用一起在框外**。
  切在半路的横条比截断的抬头更难读：没有收尾的 `]`，走过的比例看着比实际大。
  抬头那一头 13 号票收了（从中间省略，见 Q147），正文这一头没有。
- **Why it did not block:** 票面第一条的验收是「总览五行在、表至少一行、屏底的退出键在屏上」，
  三条在这一档上都成立（快照钉着）；横条被切是**正文摆不下**，而总览块**一行不砍**这一条
  正是票面写死的——不许拿高度换宽度。
- **What this ticket actually did:** **横条一格没动**，把这一笔记在这里。
  改它只有两条路，两条都是一处决定：① 让横条跟着这一格的宽度缩——而
  「横条画多宽与命令行那两条同一个出处」（`BAR_WIDTH`，`crate::bar_style`）是既有的一条；
  ② 窄档上换一副短正文（只给数、不给条）——那是总览块的第三副样子，
  而它眼下只有「有没有出事行」「收没收场」两条分岔。
- **Whose call:** 拍板的人（横条在窄格子里缩，还是窄档上换一副只给数的正文）
- **处置：** **了结。**走本条列的第一条路：**横条跟着这一格的宽度缩**，而收窄那一下
  摆在**让位**那一处（`yielding::bar_width`，那一模块《宽度不够》的第三步）——
  横条本身有多宽仍只有 `crate::BAR_WIDTH` 一处出处，`the_bar_fills_from_empty_to_full`
  那句 `assert_eq!(BAR_WIDTH, crate::BAR_WIDTH as u64)` 一格没动。摆得开 30 格，
  摆不开一路收窄到八格（`BAR_MIN_WIDTH`），再窄**整条让掉**；**两行各按自己剩下的格算**
  （合成一个数的话，当前卷那一行的长短随卷名变、卷与卷之间整行还是空的，
  全局那一条的刻度会跟着换卷跳一下——评审提的，代价是同一屏上两条可以差一格）。
  本条头一句「右边那个方括号不在屏上」因此不再成立：半条横条一格都不画。
  **80×24 那一档上一条横条都没有**——正文本身就比那 28 格宽，这一头连同溢出改成
  **从中间省略**（`Overview::draw` 走 `yielding::pinned`，与抬头同一处截法，Q147 立的）。
  算式与「步数与已用整条在屏上」那条验收做不到的地方新记在 **Q194**。
