**What to build:** `.7z` 与 `.rar` 开工前要整卷摊到临时目录。几百兆的卷上这一段要跑很久，
而**其间一条事件都不报、按中止也不停**——进度条一动不动，看着像挂死了。

给这一段加一个检查点：**按中止当场停得住，期间事件照报**。

**这是本批唯一一处新缝。** 读取那一层至今对进度、事件、指令一无所知。

## 落地记录

### 一、那一格新缝：`source::open` 收一个 `progress::Events`

读取那一层从此认得进度、事件与指令。**递下去的是既有那一条回路本身**，不是一个新的停止信号：

```rust
/// 「拿一个卷根，只列成员」——`enumerate` 那一条的形状。
type ListVolume = fn(&Path) -> Result<Volume>;

/// 「拿一个卷根，摊开它、交出一个卷」——`open` 那一条的形状。
type OpenVolume = fn(&Path, Events<'_>) -> Result<Volume>;

pub(crate) fn open(path: &Path, events: Events<'_>) -> Result<Volume>
pub(crate) fn enumerate(path: &Path) -> Result<Volume>          // 一格没动
```

**只有摊开那一条收它。**只列成员（`enumerate`）那一条一个内容字节都不解，没有可报的步、
也没有值得停的活，预扫又根本拿不出一份 `Events`（它排在开工那条事件之前）。
两条路的入口从此不同型，`SolidFormat` 那两格因此分成 `OpenVolume` 与 `ListVolume`；
共用的那副分岔（`open_taking_solid_archives`）收的从「在两个入口里挑哪一个」
改成「拿到一个格式之后怎么走」的一个闭包，`ARCHIVE_FORMATS` 那句
「加一项就只改这一处」一格没变。

`open` 也从 `pub` 收成 `pub(crate)`：`mod source` 本来就是私有的，
这一句只是让它与 `enumerate` 同一个可见性。用例那一头另开一个
`#[cfg(test)] source::open_unwatched(path)`——库内九处单元用例问的是成员表、读取端与
那个临时目录，与摊开途中的检查点一件都不相干，而 `Events` 的两格活在 `run` 的栈上，
各处自己摆一份还得让第一句活得比第二句长。**对外一处 seam 都没新开**——
`run(Request) -> Report` 一格没动，`Event` 没加变体也没加字段，`Instruction` 三个值原样，
`Progress` trait 仍是一个方法。

### 二、谁问、问谁、多久问一次

| | |
|---|---|
| **谁问** | `source::spread_seven_zip` 与 `source::spread_rar`——摊开那两遍顺序扫，各摆一副 |
| **问谁** | `Events::aborting()`，也就是 **ADR 0013 立的页边界那一级**（只认中止，不认收尾） |
| **多久问一次** | **一个成员一次**，摆在它自己那个循环的头上；落完一个成员的盘再报一次 `Events::step()` |

「一个成员」与「一页」是同一道边界：摊开那一遍走的正是这一卷的成员表。
**检查点因此仍是两个**——卷边界那个在 `run` 的逐卷循环里管收尾，页边界那个管中止，
只是后者问的地方多了三处（摊开那两遍，加上下面那一句收口）。
那张清单**只有一处出处**，仍在 `process_volume` 的《中止：回 `None`》里；本票把三处添了进去，
并点明其中两处**落在读取那一层**、末一处**不是循环头**。`progress.rs` 那两段文档
从此一律指着它、不再复述（第二轮评审提的，见末尾）。

**「当场收手」在两个格式上不完全同形**：`.rar` 那一遍是自己的 `while`，`break` 就走出去了；
`.7z` 那一遍的循环在 `sevenz_rust2` 手上，闭包回 `false` 只终止**当前那一个块**。
固实包只有一个块，两者没有分别；关掉了固实的 `.7z` 上剩下的块还会各被进一次
（一个内容字节都不解、一个文件都不落）。写进了 `extract` 与 `spread_seven_zip` 的文档，
记在停车场 **Q286**。

停下来那一支**不回 `Err`**：被停下来不是失败。`open` 交出的是一份**半摊开**的卷
（成员表齐、临时目录里只有停之前落下的那几个），`process_volume` 紧接着再问一次闩就把它丢掉：

```rust
let mut volume = source::open(&root, events)?;
if events.aborting() {
    return Ok(None);
}
```

**为什么这一句非在这里不可**：下面每一件事都要源字节，而半摊开的卷上取一个没落盘的成员
会报「读 …：No such file or directory」——那会把「被停下来」说成「这一卷坏了」。
靠闩而不是靠返回值，走的是这条管线既有的做法（闩只升不降，再问一次恒得同一个答案），
类型上没有东西说得出「这是半摊开的」，记在了停车场 **Q281**。

**「临时目录收干净、最终位置一个字节都没动」一格没变**：那一份活在卷上，`Ok(None)` 一返回
卷跟着析构，`TempDir` 把整棵子树收走（`source::Extraction`）。中止的清理范围仍只有
「本次运行自己建的那一格」，ADR 0013 决定第 2 条一个字没动。

### 三、摊开那一段报出去的步，与预告跟着长的那一段

摊开一个成员报一步（`Event::Stepped`），排在开卷那条事件之后、第一条 `PassStarted` 之前。
从前那一截是空的——几百兆的卷在那里进度条一动不动，看着像挂死了。

**光报步是不够的**：`CONTEXT.md` 的《进度》立着「预告的步数是**上界**」，
只报不预告，固实归档上的横条会冲过头（`pos/len` 印出 `130/100`，ETA 跟着骗人）。
因此 `volume_steps` 从三段变四段，`MemberCounts` 多一格：

```rust
struct MemberCounts {
    source_pages: usize,
    output_pages: usize,
    extras: usize,
    /// **开工前摊开**要落的成员数：固实归档是整卷（源页加透传），不摊开的卷是 0。
    extracted_members: usize,
}
```

判据是新添的 `Volume::extracts_before_work()`——**问容器形态与卷根的扩展名**，
两问缺一不可：扩展名那一问走 `archive_reading`（`ARCHIVE_FORMATS` 那张表仍是唯一出处），
而读取形态只在**归档卷**上作数——一个名叫 `第01话.7z` 的**目录**照样是目录卷
（`identity_of` 先问 `is_dir`），它一个字节都不摊开。少问容器那一句，
那种目录的步数会凭空多出一整段，进度条从此停在某个百分比上不动
（评审 Spec 轴提的，见末尾《评审提的四条》）。
两问都只看**做之前**答得出的东西，因此只列成员那一份卷（`enumerate`）与摊开了的那一份
（`open`）答出同一个数：预扫算步数那一遍卷还没摊开，两遍必须数得一样。

**这不是 14 号票。**那一票要的是「摊开的卷按临时目录探介质」（`Medium` / `IoPlan`），
本票一行都没碰 `medium`、没碰 `IoPlan`、没碰 `--io-mode`。

**代价**：`CONTEXT.md` 的《步》那句枚举（「幂等这一道 · 第一遍 · 第二遍」）从此少一段。
票面写死了「已有词条的含义一个字不许动，撞见对不上记 Q163」，因此**一个字没改**，
补在了 **Q163** 上（第 18 点，连同「要改的只有那一句枚举」）。
同一段的《遍 (Pass)》**不必改**：摊开没有成为第四遍，`Pass` 仍是三个值。

### 四、用例照 `tdd` 那几条审了一遍

**缝**由派活说明给死，两个：`run(Request) -> Report` 那一层的外部可观察事实，
以及事件流。三条新用例全落在这两个缝上，`source` 的私有结构一条都没碰。

- **`aborting_while_a_volume_is_extracted_stops_before_the_whole_volume_is_out`**
  ——**「整卷解完之前就停住了」这一条**。造一个装 **24 个成员**的固实 `.7z`
  （`many_member_seven_zip`，页取 `fixtures::TINY`：这一卷一页都走不进管线，
  用例问的只有摊开那一段），观察者在摊开的**第一条**报到上答中止。
  断言的是**那个临时目录最多装过几个成员**——盘上的事实，不是库里的调用次数：
  两头都收，**至少装过一个**（否则「少于全部」在一个压根没建出来的目录上也成立）、
  **少于 24**。认哪个 `tonefit-…` 是自己的，靠包里一个别处不会出现的成员名
  （`摊开途中-00.png`，摆在头一个，摊开按归档次序走，因此第一步就认得出）。
  它另问一句**「一遍都没走进去」**：这一卷一条 `PassStarted` 都不该有——那一句钉的正是
  `process_volume` 里 `source::open` 紧接着那个检查点（评审 Spec 轴指出它原本无人守）。
  另外三条与两级停的既有承诺同一批：那一卷不进报告、输出根是空的、见过的目录跑完都不在。
- **`extracting_a_volume_reports_steps_before_the_first_pass_starts`**
  ——**「摊开途中报得出事件」**，加上**「预告仍是上界」**。前者问的是流的形状：
  开卷那条事件与第一条 `PassStarted` 之间有没有步。后者拿这一卷真走过的步与开卷那条事件
  预告的那个数比，两个数都从事件流上取。
- **`a_rar_can_be_stopped_while_it_is_being_extracted_too`**
  ——两个格式各有一遍自己的顺序扫，只测 `.7z` 的话 `.rar` 那一遍漏掉了没有人会红。
  **这一条数的是步，不是盘上的文件**：`.rar` 那三份夹具是签进仓的字节、成员名固定成
  `ch1/001.png`，而同一个测试二进制里另有三条用例在往公共的系统临时目录里摊同一批名字
  ——头一版按名字认，跑起来当场红（认到的是别的用例那份已经摊完的目录）。经过记在 **Q282**。
  **它因此不问「临时目录收干净了没」**：那一问在这条路上问不出口。那条承诺由
  `.7z` 那一条与既有那一条守着，而收摊的机制与格式无关——两个格式共用同一份
  `source::Extraction`，收它的是同一个 `TempDir` 析构。

另有一条**单元用例**，落在 `src/source.rs`：
`a_directory_named_like_a_solid_archive_is_still_a_directory_volume`——
一个名叫 `第01话.7z` 的目录仍是目录卷、不摊开。这种名字不是造出来吓人的：
解压工具默认就把 `第01话.7z` 解成同名的一个目录。

三种反模式逐条对照：

- **与实现耦合**：没有。断言的是盘上的文件、事件流上的步与预告、报告里有没有这一卷、
  输出根里有什么。`Extraction`、`spread_*`、`MemberCounts` 一个都没被直接碰。
- **同义反复**：期望值不是按代码的算法再算一遍。`24` 是夹具那一侧的字面量，
  `fixtures::rar::members().len()` 是签进仓那份包的成员数，
  「预告的上界」是**库自己报出来的那个数**——用例没有重算一遍 `volume_steps`。
- **横向切片**：**先写用例、后写实现**（红→绿）。头一趟闸门 1 跑出来
  42 通过 1 失败，红的正是 `.rar` 那一条，而它红在一处**真实的**缺陷上
  （用例认错了临时目录，见 Q282），不是实现漏了检查点。

**每一处新代码各自会不会红**：把 `spread_seven_zip` 那一句 `aborting()` 拿掉，第一条当场红
（临时目录会装满 24 个）；把 `events.step()` 拿掉，第二条当场红（那一截一步都没有），
第三条也红（步数会是 0）；把 `spread_rar` 那一句 `aborting()` 拿掉，第三条当场红
（3 步而不是少于 3 步）；只报步不改 `volume_steps`，第二条的第二问当场红；
把 `process_volume` 里 `source::open` 之后那一句检查点拿掉，第一条的
「一条 `PassStarted` 都不该有」当场红；把 `extracts_before_work` 里容器那一问拿掉，
`src/source.rs` 那条单元用例当场红。

`src/lib.rs` 的单元用例 `the_write_segment_counts_output_pages_and_the_read_segments_count_source_pages`
末尾添了两句：摊开那一段在与不在各一句（含 dry-run——摊开在开工前，与写不写输出无关）。

**`cargo xtask polish` 四条也全绿**（`fmt --check`、两遍 clippy、`cargo doc`），

### Q121 — 摊开一整卷的中途没有检查点，几百兆的 `.7z` 上按中止要等它解完

- **From:** 票 `volume-discovery/05`
- **Kind:** 落地时走的那条路（新代码带进来的一个空档）
- **Where:** `src/source.rs` 的 `extract`（`for_each_entries` 那个闭包里没有停止信号）、
  `src/lib.rs` 的 `process_volume`（`source::open` 那一句排在卷边界检查点之后、页循环之前）
- **Why it did not block:** ADR 0013 的《后果》写着「`run` 要在**卷边界与页边界各留一个检查点**」，
  而摊开正好落在两者之间：卷边界那一道刚过、第一个页边界还没到。于是一卷几百兆的 `.7z`
  在摊开那一段里**按中止不会立刻停**，要等整卷解完、进到幂等那一道才停得下来，
  其间一条事件都不报（进度条停着不动）。票面第二条仍然成立——「中止之后临时目录不在」
  靠的是析构，而不是靠早停；不成立的是「立刻停」那半句。
  不阻塞是因为**补它要动 `source` 的公开签名**：`source::open` 得收一个停止信号
  （或收一个 `progress::Events`），而 `source` 至今对进度、事件、指令一无所知——
  那是一条跨模块的新依赖，本票的决定（ADR 0015）一个字没提它。
- **What this ticket actually did:** **没有补，把它标了出来。** `tests/container.rs` 的
  `a_seven_zip_leaves_no_temporary_directory_behind_even_when_the_run_is_aborted` 是
  **摊开完成之后**才答中止的（观察者要先看见那个目录才改口），它证的是「中止之后不留孤儿」，
  **不是**「摊开途中按得停」——那条用例的文档里明写着这一句，免得后来人以为这一格有人守着。
- **Whose call:** 拍板的人（`source::open` 要不要收一个停止信号；还是认下「摊开那一段停不住」
  并在 ADR 0013 的《要认的代价》里补一句）
- **处置：** **了结。**走的是它自己列出来的那条去处的**头一个**：让 `source::open`
  收一个 `progress::Events`（不是另立一个停止信号），摊开那两遍顺序扫在**成员边界**上
  问一次页边界那一级的检查点、落完一个成员报一步。
  **不新造回路、不新造停法**——`Event` 没加变体也没加字段，`Instruction` 三个值一格没动，
  检查点仍是两个（卷边界管收尾、页边界管中止）。「一个成员」与「一页」是同一道边界：
  摊开那一遍走的正是这一卷的成员表。
  ADR 0013 的《后果》最后一条跟着修订（那句「`run` 要在卷边界与页边界各留一个检查点」
  从此说得出「页边界那个还落在读取那一层的摊开里」），两笔代价一并写在那里。
  那条用例的文档也改了：`a_seven_zip_leaves_no_temporary_directory_behind_even_when_the_run_is_aborted`
  从前写着「这一格没人守着」，如今指向新添的两条
  （`aborting_while_a_volume_is_extracted_stops_before_the_whole_volume_is_out` 与
  `a_rar_can_be_stopped_while_it_is_being_extracted_too`）。
  摊开如今报步，预告的步数跟着长了一段——`CONTEXT.md` 的《步》因此与实现对不上，
  按票面记在了 **Q163** 上。
