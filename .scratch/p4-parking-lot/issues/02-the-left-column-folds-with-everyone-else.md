# 02 — 左栏与预设栏的折行搬进折行那一层

**What to build:** 左栏与预设栏此刻走的是终端库自带的折行，而视口数的是**逻辑行**——
两个数对不上。62–81 列那一段屏上因此有两个毛病：光标走到格子外面去，
而且**内容已经被截掉、滚动条却不画**。取值栏摊开之后左栏更长，这两处更显眼。

搬过来之后屏上**一个字不变**（折出来的样子与终端库那一套相同），换来的是视口数得准、
滚动条画得出来。

这一票**推翻 `p2-loose-ends/07` 那条「左栏那两栏原样留着」的决定**——那条决定的理由是
「折在哪儿读起来都一样」，而它没算上视口。理由与代价写进那张票的修订或本票的落地记录。

## 落地记录

### 折行搬到哪儿：`draw::folded` 一处

左栏与预设那一栏从前各自挂一个 `.wrap(Wrap { trim: false })`，交给终端库折。
搬过来之后两栏共用 `src/session/draw.rs` 里新添的 `folded`：

```
folded(rows: Vec<Styled>, cursor: usize, width: u16) -> (Vec<Line>, usize)
```

收的是 **`Styled`**（一行字 + 这一行挂哪一份样式），出的是折完的那几行连同
**光标落在折完的第几行**。折法一个字都不在这里——`crate::wrap::fold` 那一处
（本票一个判据都没加）。

**`Styled` 是个类型，不是一对裸值。** 头一版直接传 `Vec<(String, Style)>`，
评审引出 `paint.rs` 里 `Painted` 那一句自带的论证——「打成一个类型而不是一对裸值……
`(String, Tone)` 在调用处看不出哪一半是哪一半」——同一句话原样落在这一对上。
`Styled` 因此照 `Painted` 的样子立起来（`new` 与 `plain` 两个构造，字段各带一句文档）。

**为什么 `Styled` 与 `Painted` 是两个类型**：差的是「一行带的是什么」。`Painted` 带的是
**语义**（`Tone`：这一行讲的这件事怎么样，上不上色由 `paint` 一处定），`Styled` 带的是
**状态**（反白＝光标停在它上面、压暗＝整栏只读、加粗＝它是一层的抬头）。
状态不是语义，合成一个就得让「跑着时压暗」与「这一行出事了」共用一个取值。

**要一个空行就摆一个空格**，不是空串。`crate::wrap::fold` 给空文字**零行**
（屏底那一格靠这一条分得开「没有话要说」与「说了一句空话」），而层与层之间那一个空行是
屏上实实在在的一行。头一版在 `folded` 里为它开了个特例；评审指出屏上**早有这个写法**——
`overlay` 里那几组之间空的那一行摆的就是一个空格，旁边还写着为什么。
改成照那一份写，`folded` 因此一个特例都不开，与 `Painted::folded` 一个待遇。

### 每一行的样式一格没丢

折行只认字，因此把「配样式」与「摆字」拆开了：

| 那一处 | 从前 | 如今 |
|---|---|---|
| `config::row` | 出一个挂好样式的 `Line` | 出**一段字**，样式由 `config` 配 |
| `config::choice` | 出一个挂好样式的 `Line` | 出一个 `Styled` |
| 层抬头、层间空行、下钻那一行 | 就地 `Line::from` | `Styled::new` / `Styled::plain` |
| `picker::presets` 那几行 | 就地 `Line::from` | 同上 |

屏上留住的样式一样不少：左栏的**抬头加粗**、光标那一行**反白**、跑着时整栏**压暗**
（`Tone::Muted`，`a_run_in_progress_says_on_screen_that_the_three_layers_are_read_only`
连同 `reversed_rows` 一起钉着）、取值栏那一列的反白；预设栏的**文件位置压暗**与
光标那一行反白（`the_preset_column_keeps_the_config_in_sight_and_says_which_key_does_what`
那条 `reversed_cells` 钉着）。**折出来的那几行跟着上同一份样式**——它们本来就是同一行。

**「折下来那一截也反白着」另有一句断言**（评审指出前一版没人验这一条：既有那几条反白断言
跑的都是 52 列，那一档一行不折）：把光标停在型号那一行（40 格）上，34 列上它折成两行，
反白的格数与**同一行不折时**比多两格——多的正是补上的行首缩进。跟不下来的话这个数只会更小。

### 「这一格有多宽」从骨架来

两栏都用 `area.width.saturating_sub(2)`：`area` 是 `yielding::panes` 切出来的那一格
（左栏的宽度出处是 `yielding::config_width`，预设栏吃的是主区），两条框线各吃一格。
**两栏自己一个宽度都不猜**，与它们早就在用的 `area.height.saturating_sub(2)` 同一副写法，
也与报告区那一处（`report_pane` 的 `inside`）同一条路。

### 视口数的从此是屏上的行

`Viewport::new(lines.len(), …, cursor)` 收到的两个数都换成了**折完**的：
`lines.len()` 是折出来有几行，`cursor` 由 `folded` 换算。
一个卷都没打进来的二十一个逻辑行，**34 列上折成三十行**——两个数从前差九行，
那九行正是「内容已经被折掉、滚动条却不画」与「光标走到格子外面去」的来处。

新用例 `the_narrow_config_column_counts_the_rows_it_folds_into` 钉住这一条：
26 行的一格（正文 24 行）恰好夹在 21 与 30 中间，52 列上不画滚动条、34 列上画得出来，
而光标走到末尾那一行时它连同反白都还在屏上。

**预设那一栏同一条**（评审指出前一版一条都没加）：断言添在既有那条用例里——24 列上
抬头那条路径与末尾那一行各折成两行，五个逻辑行占七行，六行的正文因此装不下，
滚动条画得出来。按逻辑行数的话那一格「装得下」，滚动条一条都不画，而内容其实已经被折掉。

**光标那一行自己折成几行时指的是头一行**，与报告区那一处（`report::folded`）同一条——
屏上没有第二种「光标在第几行」。

### 推翻 `p2-loose-ends/07` 那条「两栏原样留着」

那条决定的理由是「**折在哪儿读起来都一样**」（那两栏摆的是标签加取值）。
**它没算上视口**——视口是 `p3-session-legibility/04` 之后才有的东西，而视口要的是
「这一栏在屏上占几行」。终端库折出来几行这一头数不出来
（`Paragraph::line_count` 至今挂着 unstable 的门，停车场 Q65），
于是视口只好数逻辑行，两个数在折得起来的宽度上就对不上了。
**决定的理由没错，是它的前提后来变了。**

代价照 Q104 当年算的那一份付：两栏每一行的样式逐行重挂、宽度一路传进去、
**两张快照重录**。换来的是 62–81 列那一段上视口数得准、滚动条画得出来。

`p2-loose-ends/07` 的《落地记录》里那句「两栏原样留着」**一个字没动**——
那是它落地那天的实情（`docs/agents/issue-tracker.md`：交付记录不因后来的工作被改写）。

  一个预设名），折在哪儿读起来都一样，而本票收的是长句从行尾切掉。
  换过去的代价是实打实的：那两栏的每一行各带一份样式（反白／压暗／加粗），
  折行之后要逐行把样式重挂一遍，还要把「这一格有多宽」从 `shell` 一路传进去；
  换来的是两张快照重录，屏上一个字不变。
- **What this ticket actually did:** **两栏原样留着**，并把「为什么留」写进 `crate::wrap`
  的模块文档与 `draw` 的模块文档——读代码的人一眼看得出这不是漏改。
- **Whose call:** 拍板的人（左栏那两栏要不要也换到本仓库这一套折行上）
- **处置：** **就地了结（`p4-parking-lot/02`）。** 照它自己算的那一笔账做完了：
  两栏搬到 `crate::wrap`，每一行的样式折完逐行重挂，宽度从骨架（`yielding` 切的那一格）传进去，
  两张快照重录。它当年判「原样留着」的理由是「折在哪儿读起来都一样」，
  而那句话**没算上视口**——视口是 `p3-session-legibility/04` 之后才有的。

### Q136 — 左栏折行走的是终端库那一套，而视口数的是逻辑行；窄终端上两个数对不上

- **From:** 票 `p3-session-legibility/04`
- **Kind:** 票面没想到的第三种情形
- **Where:** `src/session/draw/config.rs` 的 `config`、`src/session/viewport.rs`
- **现状:** 左栏折行走终端库自己的 `Wrap { trim: false }`（理由记在 `src/wrap.rs` 的
  模块文档：那一栏摆的是标签加取值，折在哪儿读起来都一样），而 `Paragraph::scroll`
  滚的是**折完之后**的行。视口这一头数的是**逻辑行**（一层抬头一行、一个字段一行）。
  两个数只在一行都不折的时候相等：52 列的标准左栏上只有长路径与长卷名折得起来，
  差一两行；窄到 34 列那一档（`MAIN_MIN_WIDTH` 让出来的退化）几乎每一行都折，
  二十一行的清单实际占三十来行，光标走到末尾时仍可能掉在格子下面。
- **它盖着本票的头一条验收:** 票面第一条是「左栏行数超过屏高时光标仍在屏上」。
  它在 **52 列那一档上成立**（标准左栏，本票新加的用例跑的就是它），
  **34 列那一档上不成立**——行行折，光标照旧掉得出去。同一个成因还有第二面：
  「装得下就不画滚动条」也是按逻辑行判的，折出第二行时会出现**内容已截、滚动条却不画**。
- **What this ticket actually did:** **按逻辑行数算，把差额记在这里，并在用例文档里点明
  它只在不折行的宽度上成立。** 算准只有一条路——把左栏的折行也交给 `crate::wrap`
  （报告区就是那么做的，折出来几行当场数得出）。那要改屏上的字节：`crate::wrap`
  给折下来的每一行补上行首缩进，终端库那一套不补。而 `src/wrap.rs` 的模块文档记着
  「左栏与预设那一栏**仍走终端库自己的折行**」——那是 `p2-loose-ends/07` 拍下的一条决定，
  而本票的派活说明同时写着「不要动 `src/wrap.rs`」与「屏上一个字节不该白变」。
  改它等于推翻一条仍然生效的上游决定，**不是实现能自己定的**。
  ratatui 那个直接答得出折完行数的 `Paragraph::line_count` 仍挂着 unstable 的门（Q65）。
  **预设栏同一笔账**，只是那一栏每一行都是一个短名字，折得起来的只有抬头那条路径。
- **`p3-session-legibility/05` 补的一句现状：** 取值栏落地之后左栏又长了一截
  （21 行加卷数，**再加摊开那一列的格数**——滤波器那一行摊开就是六格），
  这个毛病因此更显眼：34 列那一档上行行都折，摊开之后掉出格子的格数只多不少。
  **那一票也没收它**，理由与本条原样：改它要推翻 `src/wrap.rs` 那条仍然生效的决定。
  它新加的两条视口用例（`the_unfolded_values_that_do_not_fit`、
  `the_unfolded_values_keep_the_cursor_on_screen`）与 `04` 那两条同一条待遇：
  **只问一行都不折的 52 列那一档**，用例文档里点明了。
- **`p3-session-legibility/13` 补的一句：本条那个「34 列」的档没挡住 13 号票的验收。**
  13 号票按票面「宽度不够先把左栏让掉」做，把那一让改成了**有底的**：左栏窄过
  `CONFIG_MIN_WIDTH`（30 列）就整个让掉（`src/session/draw/yielding.rs` 的 `config_width`）。
  于是 **1–29 列那一段整个不存在了**——40 列的屏上左栏从前占 10 列、行行折成两三个字，
  此刻一格不画，主区吃满。剩下的窄档是 **62–81 列**（左栏 32–51 列）。
  **13 号票按 80×24 验收，那一档上左栏 50 列**，与标准的 52 列只差两格：
  只有长路径与长卷名折得起来，与本条说的「52 列那一档差一两行」是同一档，
  光标没掉出去（`the_whole_screen_reads_at_eighty_by_twenty_four` 那三张快照钉着）。
  **本条因此仍旧待处理，但它只在 62–81 列那一段上真咬人**，而 `src/wrap.rs` 一个字没动。
- **Whose call:** 拍板的人（要不要推翻 `src/wrap.rs` 那条「左栏走终端库的折行」，
  把左栏的折行也搬到 `crate::wrap`——那是一次屏上字节的变动）。
- **处置：** **就地了结（`p4-parking-lot/02`）。** 它写着「算准只有一条路——把左栏的折行
  也交给 `crate::wrap`」，本票走的就是那条路：`draw::folded` 一处，两栏共用，
  折出来有几行当场数得出，交给 `Viewport` 的两个数（总行数与光标）从此都是**屏上的行**。
