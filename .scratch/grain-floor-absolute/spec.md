# 颗粒地板回到绝对灰度级：一个数管三档，1bit 收费、2bit 不收

Status: ready-for-agent

## Problem Statement

一套参数批量转一整个库，**连续灰调的页选错档**。判据在那一类素材上一致地偏 `4bit 不抖`，
而真机一致地偏 `2bit+FS`——十六对里十五对（`judgements/第九轮闸1补测.json`
与《真机 AB 交错本十二对》），判据 0/16 同向。

判读者的原话把病灶指了出来：**「理由都是另外一张有轻微色彩断层」**，
并补一句 **「除了轻微色带之外的观感几乎一致」**。翻成判据的两项，那十二页上：

| | `2bit+FS` | `4bit 不抖` | 真机说 |
|---|---|---|---|
| 低通项 | 3.2 ~ 3.7 | 5.8 ~ 8.0 | 色带**看得见** |
| 颗粒项 | **13.7 ~ 24.2** | 0.00 | 颗粒**看不见** |

**低通项那一侧方向本来就是对的**（3.2 < 6.0，与真机一致）。
**问题全在颗粒项**——它给一堆判读者看不见的颗粒记了 13.7~24.2，把方向顶反了。

而颗粒项在 2bit 上之所以收得到费，是因为**可见度地板写成了《格点间距》的一个比例**
（`floor(n) = 比例 × 255/(2ⁿ−1)`）。这个形式把三档**绑死**：同一个比例
在 1bit 上给 55.0、2bit 上给 18.3、4bit 上给 3.7，于是「1bit 上收费」与
「2bit 上不收费」这两件真机都要的事，**没有任何一个比例同时做得到**。

两条被绑住的真机结论：

| 真机结论 | 出处 | 它要什么 |
|---|---|---|
| **`1bit+FS` 每页垫底** | 《位深盲测》，boox-poke6 与 kobo-libra-2 两块面板 | 1bit 上颗粒项**要收费** |
| **连续灰调上 `2bit+FS` 更优** | 闸① n=16、15:1 | 2bit 上颗粒项**不该收费** |

## Solution

**地板改回绝对灰度级：一个数，不乘《格点间距》。**

物理很直白：**1bit 的 FS 颗粒幅度约 127，2bit 的约 42**（`sqrt(u(s−u))` 在 `u = s/2`
取到 `s/2`）。一个绝对地板夹在中间，两头就都对了——1bit 的颗粒越得过它、要收费；
2bit 的越不过，不收费。

实测窗口 **45 ~ 65 灰度级**：在这一段里，真机排序 **21/21** 全对（撇开 `03` 标注
「不作定量依据」的那个反例），且 `1bit+FS` 在棋魂两页上**仍然垫底**。窗口两侧都塌：
≤40 时排序掉到 6~20/21，≥70 时垫底失效。

> **`GRAIN_FLOOR = 55.0` 正落在这个窗口的正中**——那是 `metric-recalibration/01`
> 改掉的旧值。`metric-recalibration` 的 spec 当初把「颗粒项只在 1bit 上生效、
> 2bit 及以上恒读零」当成缺陷去修，**真机说那不是缺陷**：2bit 上的 FS 颗粒本来就看不见。

**本 spec 覆盖 `metric-recalibration/01`。**那张票已 resolved，它的《落地记录》
**原样留着**——覆盖的理由与新取值记在本批自己的落地记录里
（`docs/agents/issue-tracker.md` 的规矩）。ADR 0002 决定第 5 条要跟着改。

顺带补两处，它们是这次改动的**安全网**与**护栏**：

- **`params_hash` 收判据参数**。今天它完全没收——地板、掩蔽、聚合改了，
  旧输出会被**静默跳过**（ADR 0002 的《后果》自己记着这一条）。
  不补就改地板，用户下一趟拿到的是上一趟的产物而不自知。
- **`tests/perceptual.rs`**：把四条真机事实钉成性质用例，写**性质不写读数**。

## User Stories

1. As a 用户, I want 连续灰调的页不再被判成 `4bit 不抖`, so that 渐变上不再出现我一眼就看得见的色带
2. As a 用户, I want 判据别为我看不见的颗粒收费, so that 该省的体积省得下来
3. As a 用户, I want 一套参数转一整个库、不同作品的观感不要差这么多, so that 我不必逐部作品调参
4. As a 用户, I want `1bit+FS` 照旧被判得很差, so that 它不会因为这次改动溜进候选结果里
5. As a 用户, I want 白底文字页照旧偏 `4bit 不抖`, so that 纸面上的抖动点不会回来
6. As a 用户, I want 改了判据参数之后旧输出**自动过期整卷重做**, so that 我不会拿到上一趟的产物还以为是新的
7. As a 用户, I want 报告说得出这一趟的地板是多少、出处是什么, so that 我能判断它对我手上那块面板成不成立
8. As a 用户, I want 报告也说得出掩蔽那两个数, so that 我知道判据里还有两个未标定的占位值
9. As a 用户, I want `--threshold` 覆盖项在新地板下仍然可用, so that 我能在自己那台设备上自己夹一个界
10. As a 维护者, I want 地板的形式由真机数据定, so that 它不是从一条推导里推出来的
11. As a 维护者, I want 「1bit 收费、2bit 不收」这条性质被用例钉着, so that 谁把地板改成比例当场会红
12. As a 维护者, I want 四条真机事实进测试, so that 判据的下一次改动撞到它们会红，而不是要再上一次机才发现
13. As a 维护者, I want 那四条写成**性质**不写读数, so that 换面板、换夹具不会假红
14. As a 维护者, I want 「亮度分歧」那条缺陷被记成用例, so that 判据将来真认得出亮度时，它红给我看
15. As a 维护者, I want 覆盖 `01` 的理由写在本批的落地记录里, so that `01` 那张票仍然是它当时那段历史
16. As a 维护者, I want ADR 0002 决定第 5 条跟着改, so that 后来的人不照着过期决定做设计
17. As a 维护者, I want 黄金快照的变化被显式接受, so that 判定的改变不被顺手覆盖掉
18. As a 维护者, I want 判据参数进哈希这件事有一条用例钉着, so that 将来再加参数时不会漏
19. As a 开发者, I want `Composition` 仍然只带一个数, so that 报告那一行不必变长
20. As a 开发者, I want 掩蔽那两个数有自己的类型, so that 报告读得到它们、哈希收得到它们
21. As a 开发者, I want 判据仍然是那个纯函数 seam, so that 数值测试与标定工具照旧调得动它
22. As a 开发者, I want 不新开测试接缝, so that 判据的验证仍然集中在 `score()` 与 `run()` 两处
23. As a 开发者, I want 下游只接 `Score` 这一点不变, so that `decide` / `envelope` / `report` 一行都不用改

## Implementation Decisions

### A 地板：`Composition` 存绝对灰度级

- `Composition` 的字段从 `grain_ratio: f32` 换成**绝对地板**，**仍然只有一个数**。
  `Composition::floor(depth)` 不再乘《格点间距》——三档拿到同一个值。
- 取值落在实测窗口 **45~65** 之内。**取 55.0**：它在窗口正中，且与 `01` 之前的旧值
  逐位相同，`01` 之前那批《位深盲测》数据因此仍可比。
- 报告《判据构成》那一行改回按绝对灰度级说，连同标定来源一并印（ADR 0016：措辞只有一处出处）。
- **为什么不是比例**：可见度问的是「起伏低到什么程度真的看不见」，那是**绝对幅度**的事
  ——127 的颗粒看得见、42 的看不见，与它占哪一档格点间距的几分之几无关。
  写成比例把三档绑死，是这次矛盾的**唯一**来源。

### B 掩蔽两个数抓进 `Masking`

- 新增 `Masking { floor, knee }` 与 `masking()`，与 `Composition`、`Aggregation` **平级**。
  ADR 0002 把前两者分成「一块的读数**由什么组成**」与「块的读数**怎么收成一个数**」，
  掩蔽是第三件：一块的读数**怎么加权**。
- **取值不动**（0.5 / 8.0），它俩仍是**未标定占位值**——本 spec 不标定它们。
  抓进类型只为两件事：报告说得出、哈希收得到。
- 报告照 `Aggregation` 印 K 的做法，把这两个数连同「未标定占位值」一并印出。

### C `params_hash` 收判据参数

- 收 `Composition`、`Aggregation`、`Masking` 三者的全部字段。
- 这是**已知缺口**，ADR 0002 的《后果》明写：「地板不在里面……单独落地这一步而不动那两样，
  旧输出会被静默跳过」。本 spec 改地板，缺口必须同批补上。
- **后果要写进 ADR**：补上之后，判据参数一改，全库旧输出自动过期整卷重做。

### D 覆盖与订正

- **覆盖 `metric-recalibration/01`**：那张票把地板从绝对值改成比例，本批改回来。
  `01` 的《落地记录》**不改写**，覆盖记在本批自己的落地记录里。
- **ADR 0002 决定第 5 条**：「地板是格点间距的一个比例，不是一个绝对值」这条决定要翻，
  连同它底下那条上界推导（`F < s·(sqrt(r(1−r)) − r)`）——那条推导把 FS 的低通项当成零，
  平坦调阶梯上实测不是零（`u ≤ 2` 上是 2.86 / 3.47，已高过不抖的 1.00 / 2.00）。
- **`metric-recalibration/05`**（掩蔽与阈值按标定结果落地）**不在本 spec**，
  维持 `needs-triage`：阈值今天的 5.5 是在**旧地板**上夹的，地板一改它要重新夹，
  而那需要另一次上机。

## Testing Decisions

好的用例只测**外部行为**：`score()` 交出来的数、`run()` 交出来的报告与判定。
不测私有函数、不主张任何具体秒数。

**零个新接缝。**主接缝 `score(&Reference, &GrayImage, BitDepth) -> Score`
（`tests/metric.rs` 现有 19 个用例走的就是它）；端到端那一条走 `run(&Request) -> Report`
（`tests/idempotency.rs` 的既有写法）。`tests/perceptual.rs` 是新**文件**，
但调的仍是 `score()`。

### 新增 `tests/perceptual.rs`：四条真机事实，写性质不写读数

夹具**合成**（照 `tests/fixtures/` 的既有做法），真实素材不入库：

1. **近白平坦调上 FS 不占优**——平坦调的背景够亮时，`2bit+FS` **永远不比** `2bit 不抖` 干净。
   （L 组近白那一列 5/5）
2. **亮度分歧是一条缺陷记录**——同一个《离格量》、三种背景亮度，**断言判据在这三格上
   结论相同**。这**不是**希望的行为：真机在这三格上给的答案相反。
   **加了亮度维之后它该红——红了就把它换成新的断言，那不是回归。**
   断言「结论相同」而不是「读数极差 < 某值」：不依赖任何具体读数，换面板换夹具都不会假红。
3. **离格 0 的页上 FS 够用**——纸白正落在格点上时 FS 在白底一个点都不撒。
4. **离格 1 的真实页上 `4bit 不抖` 更干净**——这一条合成不出来（依赖真实版面），
   走 **opt-in 真实素材**，照仓库既有的「真实素材冒烟照旧 opt-in」。

### 要跟着改的既有断言

它们钉的是**旧形状**，不是 bug：

- `src/metric.rs` 测试模块里钉「地板是《格点间距》的一个比例」那一条——**要翻**，
  改成钉「地板是绝对灰度级、三档同一个值」，并把「1bit 收费 / 2bit 不收费」这条
  真机性质一并钉住（谁把它改回比例，当场红）。
- `src/metric.rs` 里钉旧下界 `0.2071·s` 三档各钉的那一条——那条下界随
  「同一档上抖动恒优于不抖动」一起作废，重新表述。
- `src/render.rs` 报告抬头那条逐字断言、`src/session/draw/overlay.rs` 那行硬编码快照
  ——措辞变了要跟着改（多一个词整块要重排）。
- `tests/metric.rs` 里断言具体读数的那两条、`tests/fixtures/` 里写死读数的文档与取值。

### 黄金回归会动

判据一改判定就变，`tests/golden-snapshot.txt` 要**显式接受**（`TONEFIT_ACCEPT_GOLDEN=1`），
不能顺手覆盖。差异审查一次——那一篇存在的理由就是拦这种改动。

### 幂等那一条

`tests/pipeline.rs` / `tests/idempotency.rs` 上加一条：**改了判据参数之后旧输出过期重做**
而不是被跳过。写法照 `tests/idempotency.rs` 现有那几条。

### 验收：不必再付一轮判读人力

- **真机排序 21/21**：拿 `judgements/` 下已有的逐对数据（第六、七、九轮，共 22 页有排序结论）
  重算，新地板下判据与真机同向的页数不得低于 21（唯一容许的例外是 `03` 标注
  「不作定量依据」的 `1046-梦游盒-04-2`）。
- **`1bit+FS` 仍垫底**：棋魂 0060 与 0148 上，`1bit+FS` 的读数仍高过同页 `2bit 不抖`。
- **跨档相关性**（`metric-recalibration/02` 的那两个 ρ）重跑：跨档不得变负，同档不得变差。

## Out of Scope

- **掩蔽那两个数的标定**。它们仍是未标定占位值；本 spec 只把它们抓进类型、进报告、进哈希。
  要标定得另造一组「同一档、块内活动度分层」的材料——`04` 那一轮证明了平坦块钉不住它们。
- **阈值重标**。5.5 是在旧地板上夹的，地板一改它要重夹，而那要另一次上机（`05` 号票）。
- **低通项加地板**。`04` 算过：要挡掉 `4bit` 那 2.0 得 ≥0.1176，而比例才抬到 0.06
  B 组的 `2bit+FS` 就已归零。**那件事（Q433）该由纸白对齐治**，不是这道地板。
- **纸白对齐那一批**（`tone-alignment`）。它与本 spec 正交：一个改上游让那一撒不发生，
  一个改判据怎么读颗粒。**但注意时序**——`tone-alignment/05` 抬默认值之前要补一次真机
  （对齐后 B 组重判），那一条写在它自己的票面上。
- **聚合那三个数**（块边长 32、上分位 p99、K=8）。`04` 查出「聚合挑的是那一页上最平的
  一块」（闸① 12 页里 11 页），值得单独看，但它与本 spec 要改的地板正交。
- **`STRUCTURE_KERNEL` 等于 `TILE` 这件事**。`04` 查出 ADR 说「取局部均值是为了让平缓斜坡
  透明」，而核与块一样大时那条意图几乎不生效。**这是 ADR 与实现的一处偏差，另开。**
- **`4bit+FS` 退出候选集**（`metric-recalibration/06`）。独立，真机 A 组 8/8 确证过。

## Further Notes

### 这次改动为什么能只动一个数

判据的形状封在 `src/metric.rs` 一个文件里，下游（`decide` / `envelope` / `report` / `lib`）
**只接 `Score` 这一个数**，看不见形状。所以 A 那一改的辐射面是：结构体、构造函数、
`floor()`、报告措辞、那行硬编码快照、哈希，以及钉旧形状的那几条用例。**没有别的。**

### 一条方法论，值得写进记录

`04` 那一轮走岔过一次，代价不小：**约束被写成了「判定档」，而真机测的是「两档排序」**。

真机每一组问的都是「这两版哪个更干净」；把它翻成「这一页的判定档该是什么」会引进
真机没测过的档（`1bit`、`2bit 不抖`），于是**造出数据里本来没有的矛盾**。
`04` 票面那句「B 组必须落在阈值之外」，依据是《第五轮》**模型判读**的「零接受」
——而模型那几轮明写不作标定依据。改成排序之后，那个倒挂从 2.93 → 0.93 → 消失。

**约束要写成「真机比过的那两样东西之间的关系」。判定档是标定之后的推论。**

### 已经付过的账，可以再用

- **`judgements/` 下的逐对真机数据**（第六、七、八、九轮）——验收用它，零新人力。
- **`.scratch/metric-recalibration/calibration/`** 的实验台——逐块四原始量导出一次、
  任意参数重算，`export_tiles.py` 每跑一次重做口径自检（复现与 `--dry-run` 最大偏差 0.0008）。
- **绝对地板那个窗口**（45~65）已经量出来，不必重扫。
