# 颗粒项的可见度地板回到绝对灰度级

Status: ready-for-agent

## Problem Statement

一套参数批量转一整个库，**连续灰调的页被判成 `4bit 不抖`，而真机上那一档更难看**。

十六对真机盲测（Kobo Libra 2，整页 1:1，关缩放与白边裁切）问的是同一件事：
连续灰调页上 `2bit+FS` 与 `4bit 不抖` 哪个更干净。**15:1 偏 `2bit+FS`**，
而判读者给的理由每一次都是同一条——**另一版有轻微色彩断层**，并补了一句
「除了轻微色带之外的观感几乎一致」。

判据在那批页上 **0/12 同向**：它给 `2bit+FS` 读 16.2~27.2、给 `4bit 不抖` 读 5.1~8.0，
把真机一致淘汰的那一档读成好三倍。用户为此**多花体积**（连续灰调换 4bit 贵 1.02×，
而 B 类素材上默认比一刀切 4bit 还贵 7.3%），**换来的却是判读者一眼挑出来的色带**。

拆开看，判据的两项一项对一项错：

| | `2bit+FS` | `4bit 不抖` | 真机说 |
|---|---|---|---|
| 低通项 | 3.2 ~ 3.7 | **5.8 ~ 8.0** | 色带**看得见** |
| 颗粒项 | **13.7 ~ 24.2** | 0.00 | 颗粒**看不见** |

**低通项那一侧方向本来就是对的**（3.2 < 6.0，与真机一致）。**错的是颗粒项**
——它给一堆真机看不见的颗粒记了 13.7~24.2，把方向顶反了。

## Solution

**颗粒项的《可见度地板》从「《格点间距》的一个比例」改回「一个绝对灰度级」，取 55.0。**

判据里「颗粒低到看不见就不收钱」这件事，量的是**起伏有多大**，而起伏看不看得见由它的
**绝对幅度**决定，不由它占了那一档《格点间距》的百分之几决定。实测：
`1bit+FS` 的颗粒幅度约 **127**，`2bit+FS` 的约 **42**——**一个绝对地板夹在中间，
两头就都对了**：

- **1bit 上收费**：127 > 55，颗粒项照常生效，`1bit+FS` 每页垫底那条守得住
- **2bit 上不收费**：42 < 55，颗粒项归零，连续灰调上判据不再罚 `2bit+FS`

实测窗口是 **45~65 灰度级**（在这一段里，二十一条真机排序结论全部满足，
且 `1bit+FS` 仍每页垫底）。取 **55.0** 有双重依据：它落在这个窗口正中，
又正是《位深盲测》当初夹出的窗口 `[52.8, 60]` 里的值。

**1bit 上的行为因此逐位不变**（今天的 `0.215686 × 255 = 55.0`），
《位深盲测》整批数据的可比性保住。

同时补三件跟着来的事：**参数哈希收判据参数**（不收，这一改的旧输出会被静默跳过）、
**把这一轮的真机事实钉成用例**、**ADR 0002 决定第 5 条订正**。

## User Stories

1. As a 用户, I want 连续灰调的页选得到 `2bit+FS`, so that 我不必为一档更难看的输出多付体积
2. As a 用户, I want 渐变区不要出现色彩断层, so that 天空、墙面、皮肤这些大面积过渡看着是连续的
3. As a 用户, I want 白底文字页仍然选得到 `4bit 不抖`, so that 纸白离格的那些页不会在白底上撒点
4. As a 用户, I want 1bit 那一档的判定与今天一模一样, so that 我已经转好的那批 1bit 输出不必重做
5. As a 用户, I want 报告说得出这道地板是多少灰度级, so that 我能判断它对手上那块面板成不成立
6. As a 用户, I want 报告仍然标着这个数的标定来源, so that 我知道它是盲测夹的、不是拍的
7. As a 用户, I want 改了判据参数之后旧输出自动过期重做, so that 我不会拿到一半新一半旧的库
8. As a 用户, I want `--threshold` 覆盖项在新地板下仍然可用, so that 我能在自己那台设备上自己夹一个界
9. As a 维护者, I want 地板的取值由真机盲测夹出而不是推导出来, so that 它站得住
10. As a 维护者, I want 那批真机结论被用例钉着, so that 谁把判据改回去当场会红
11. As a 维护者, I want 「近白平坦调上 FS 不占优」这条事实进用例, so that 地板调得太高时立刻发现
12. As a 维护者, I want 「离格 0 的页上 FS 够用」这条事实进用例, so that 地板调得太低时立刻发现
13. As a 维护者, I want 判据参数进参数哈希, so that 以后每一次标定都不会静默跳过旧输出
14. As a 维护者, I want 掩蔽那两个占位值也进哈希, so that 它们将来被标定时同样拦得住
15. As a 维护者, I want 报告说得出掩蔽那两个数是未标定占位值, so that 与 `K` 一样的待遇、读的人心里有数
16. As a 维护者, I want ADR 0002 决定第 5 条改成当前成立的说法, so that 后来的人不照着过期陈述做决定
17. As a 维护者, I want `01` 号票的落地记录原样留着, so that 那次改动为什么做、后来为什么翻，两头都查得到
18. As a 维护者, I want 黄金快照的变化被逐条审查后接受, so that 判定的改变不被顺手覆盖掉
19. As a 开发者, I want `Composition` 仍然只带一个数, so that 报告那一行不必因此变长
20. As a 开发者, I want 判据仍然是那个纯函数 seam, so that 数值测试与标定工具照旧调得动它
21. As a 开发者, I want 改动落在既有 seam 上, so that 不为这件事新开一个测试入口
22. As a 开发者, I want 那条「地板下界」的算术不变量被撤掉而不是改数, so that 用例不再钉一条已经作废的推导

## Implementation Decisions

### A 地板：`Composition` 存绝对灰度级

- `Composition` 从 `{ grain_ratio: f32 }` 改回 `{ grain_floor: f32 }`，**仍然只有一个数**。
  `floor(depth)` 直接返回它，**不再乘《格点间距》**——签名保留 `depth` 参数与否由实现定，
  但地板不随位深变。
- 取值 **55.0**。三档因此都是 55.0，而各档 FS 的颗粒幅度上界是 `s/2`
  （1bit 127.5、2bit 42.5、4bit 8.5）——**只有 1bit 越得过这道地板**。
- **这正是 `01` 之前的行为**，但依据换了：当初那是「只有 1bit 有盲测数据」的将就，
  现在是十六对真机盲测直接要的结果。
- 报告《判据构成》那一行改回按灰度级说，措辞仍只有一处出处（ADR 0016），
  命令行纯文本与会话覆盖层共用同一份字。

**为什么不是比例**：地板问的是「起伏低到什么程度看不见」，那是**绝对幅度**的事。
写成《格点间距》的比例，等于断言「1bit 上看不看得见的门槛，是 2bit 上的三倍」
——真机说不是：`1bit+FS` 的颗粒（127）看得见，`2bit+FS` 的（42）看不见，
一道 55 的绝对门槛正好把它们分开。比例那个形式把三档**绑死**了，
同时归零或同时不归零，怎么调都满足不了两头。

### B 「2bit 及以上颗粒项恒读零」不是缺陷

`metric-recalibration/spec.md` 把这件事当成缺陷去修，`01` 号票落地了那个修法。
**真机说那不是缺陷**：2bit 上 FS 的颗粒本来就看不见（判读者原话「除了轻微色带之外的
观感几乎一致」），不收费是对的。

ADR 0002 说单靠低通项会**结构性地偏袒抖动**——那条担心在这批数据上**没有兑现**：
低通项自己在二十一条排序上全部判对，包括 B 组那四页白底
（`2bit+FS` 低通 3.25 > `4bit 不抖` 的 2.00，判 4bit 更干净 ✓）。
**低通项读得见白底上那一撒**，因为撒点在低通尺度上留下了残留。

### C 参数哈希收判据参数

`metadata::params_hash` 今天**完全没收判据参数**（ADR 0002《后果》已记着这是已知缺口）。
本 spec 一改地板，不补这一条旧输出会被**静默跳过**。收三样：

- `Composition`（地板）
- `Aggregation`（块边长、上分位、`K`）
- **新建 `Masking`**（`MASKING_FLOOR`、`MASKING_KNEE`）——这两个今天是私有常量，
  收进哈希得先有个类型装它们。与 `Composition`（一块的读数**由什么组成**）、
  `Aggregation`（块的读数**怎么收成一个数**）平级：它说的是一块的读数**怎么加权**。
  报告跟着印它，并标明**两个都是未标定占位值**——与 `Aggregation` 印 `K` 同一个做法。

### D ADR 0002 决定第 5 条订正

那一条现在写着「地板是**格点间距的一个比例**，不是一个绝对值」，并附一段从
「平坦调上抖动输不输」推出的上界。两处都要改：

- **比例改回绝对值**，理由是上面 A 那一段。
- 那段上界推导（`F < s·(sqrt(r(1−r)) − r)`）把 **FS 的低通项当成零**，
  而平坦调阶梯上实测不是零（`u=1` 上 2.86、`u=2` 上 3.47，都高过不抖的读数）。
  该条已由 `tonefit-c2` 那一路订正过一次，本 spec 只需保证决定第 5 条的**结论**
  与新地板一致。

`01` 号票的《落地记录》**原样留着**——它记的是当时那批证据支持的决定。
新 spec 是覆盖它的操作，不是抹掉它。

## Testing Decisions

好的用例只测**外部行为**：`score` 算出来的数、`run` 交出来的判定、印出来的那几行字。
不测私有函数。**三个 seam 全是既有的，一个都不新开**（`tests/perceptual.rs` 是新文件，
走的仍是 `score`）。

### 既有 seam

- **`composition()` / `Composition::floor(depth)`**——地板本身。断言三档**都是 55.0**，
  即地板不随位深变；1bit 上的取值与今天**逐位相同**。
- **`score(&Reference, &GrayImage, BitDepth)`**——判据的纯函数形态。断言同一页同一候选在
  **2bit 上的读数变了**（颗粒项回到恒零），**1bit 上没变**。这与 `01` 号票的验收互为镜像。
- **`run(&Request) -> Report`**——判定分布。既有的卷级档位一致性、逐页判定、幂等跳过都在这里。

### 要跟着改的既有断言

- `src/metric.rs` 的 `the_grain_floor_is_a_share_of_the_quantisation_step`
  ——它钉的正是要翻掉的那个形状，改成钉「地板是一个绝对灰度级、三档相同」。
- `src/metric.rs` 的 `the_grain_floor_stays_above_what_an_undithered_flat_tone_pays`
  ——它钉的是 `0.2071·s` 那条下界，而**那条推导已经作废**（ADR 0002 记着
  「同一档上抖动恒优于不抖动」不成立）。**撤掉它，不是改数**：留着会把一条已作废的
  推导继续钉在代码里。
- `tests/metric.rs` 的 `grain_below_the_visibility_floor_is_not_charged_for`
  与 `the_grain_term_reads_back_on_two_bits_too`——后者断言的正是 `01` 引入的行为，
  要重新表述。
- `tests/metric.rs::a_known_offset_reads_back_as_that_many_gray_levels` 的数值。
- `src/render.rs` 抬头那条用例的断言字串，以及 `src/session/draw/overlay.rs` 里
  **硬编码了 `21.6%` 那一行字**的整屏快照（多一个词整块要重排）。
- `tests/fixtures/mod.rs` 里三个纯色常量的读数注释与取值。

### 新增：`tests/perceptual.rs`

装**真机事实**，与 `tests/metric.rs` 装的「判据自己的性质」分开——两者验的不是同一件事
（一个问「代码做了它该做的」，一个问「代码合不合人眼」），出处也不同
（一个是 ADR，一个是 `judgements/`）。四条，**只断言性质、不写具体读数**，
夹具用合成图（真实素材不入库）：

1. **近白平坦调上 `2bit+FS` 不占优**——L 组近白那一列 5/5。地板调得太高时它红。
2. **离格 0 的页上 `2bit+FS` 够用**——C 组八页。地板调得太低时它红。
3. **`1bit+FS` 在同页上高过 `2bit 不抖`**——《位深盲测》两块面板，垫底那条。
4. **亮度分歧那条**：同一个《离格量》、不同背景亮度，判据在三格上**结论相同**。
   这一条**今天绿**，而真机在那三格上的答案相反——它是**缺陷记录**，
   文档里写明：判据将来若认得出背景亮度，这一条会红，**红了就换成新的断言，不是回归**。
   断言写成「三格的结论相同」而不是「读数差 < x」，**不依赖任何具体读数**，
   换面板换夹具都不会假红。

第四条那个「离格 1 的真实页上 4bit 更干净」（M 组 4/4，判读者备注「差距很小」）
**走 opt-in 真实素材**，与仓库既有的真实素材冒烟同一条路——信号弱，不适合当合成断言。

### 黄金回归

判定会变，快照要**逐条审查后显式接受**，不是顺手覆盖。这一改的证据就在那份差异里。

## Out of Scope

- **纸白对齐那一批**（`tone-alignment`）。它治的是上游——让白底那一撒根本不发生，
  与本 spec 正交。两者的交集写在 `tone-alignment/05` 的《落地之前要补一次真机》。
- **掩蔽两个数的标定**。本 spec 只把它们收进哈希与报告，**不改取值**——
  `04` 那次真机没有材料钉住它们的窗口两端（L 组是平坦块，逐块活动度几乎一致）。
- **阈值重标**。地板一改判据读数全变，阈值理应跟着重标；但真机在这一轮测的是
  **两档之间的排序**，不是「判定档该落在哪」，**夹不出阈值**。阈值维持现值与现有出处。
- **低通项加一道地板**。算出来与 B 组冲突：要挡掉 4bit 那 2.0 得比例 ≥0.1176，
  而比例才抬到 0.06，B 组的 `2bit+FS` 就已归零。那件事（Q433）由纸白对齐治。
- **`STRUCTURE_KERNEL` 与 `TILE` 相等这件事**。查出来 ADR 说的「让平缓斜坡透明」
  在当前取值下几乎不生效（两种活动度实测几乎相同），但改它要重估掩蔽整层，另开。
- **聚合取哪一块**。查出来判据挑的是那一页上最平的一块（闸① 12 页里 11 页），
  而判读者看的是整页观感。同样另开。
- **`1bit+FS` 该不该退出候选集**。它在三轮判读里全被否掉，却仍是活候选；
  但本 spec 恰恰**靠它撑着地板的上界**（垫底那条），动它要连着重估。

## Further Notes

### 这一改的证据链

- **闸① n=16、15:1 偏 `2bit+FS`**（`judgements/第七轮`、`第九轮`）。补测 12 对是
  按**连续灰调面积**分层挑的，不按判据读数挑——按读数挑等于用判据给自己出题。
- **`1bit+FS` 每页垫底**（measurements《位深盲测》，两块面板）。
- 两条对颗粒项的要求方向相反，而**一个绝对地板 45~65 同时满足**：实测在这一段里
  二十一条排序结论全对（撇开一个已知反例），且垫底仍成立。
- 唯一的反例是 `1046-梦游盒-04-2`，即原闸① 四对里反向的那一对——`03` 的落地记录
  早就写着它「不作定量依据」。n=16 里的 1。

### 一条要认下的口径

`04` 号票的《已经有的约束，不要重测》里有一条写着「B 组……真机**零接受**……
必须落在阈值之外」，而**「零接受」出自《第五轮》模型判读**，`judgements/README.md`
明写模型那几轮不作标定依据。真机在 B 组实际说的只是「4 对全部判 `4bit 不抖` 更干净」
——**两档之间的排序**。

照那条形式化会造出一个数据里本来没有的矛盾。**本 spec 的所有约束都写成
「真机比过的那两样东西之间的关系」**，判定档是标定之后的推论，不进约束。

### 已知的不确定

- **阈值没跟着重标**。地板一改，2bit/4bit 上的读数回到只剩低通项，而阈值 5.5 是在
  旧读数上夹的。判定分布因此会变，黄金快照那一步要认真看。
- **掩蔽那两个数仍是占位值**，本 spec 只让报告说得出这件事。
- **对齐落地之后这批约束要复核**：纸白对齐会改 43% 的页，B 组那四页对齐后
  `2bit+FS` 从 3.25 降到 1.70。届时「B 组该判哪一档」需要一次新的真机
  （已写进 `tone-alignment/05`）。

### 工具

判据的 Python 复现、逐块数据、这一轮全部搜索与证伪的跑法在
`.scratch/metric-recalibration/calibration/`，入口 `README.md`。
它的口径自检（复现与 `--dry-run` 逐格对得上）每次导出都重做一遍，
