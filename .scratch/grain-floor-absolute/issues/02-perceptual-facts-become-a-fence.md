# 02: 四条真机事实立成护栏，今天就是绿的

**What to build:** 四条真机判读的结论从 `judgements/` 里的 JSON 变成**跑得起来的用例**。它们在**今天的判据上就该绿**——于是 `04` 改地板时，它们是拦得住错的护栏，而不是改完之后的追认。

判据的下一次改动撞到这四条会当场红，而不是要再上一次机才发现。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 新开一篇 `tests/perceptual.rs`。真机事实与判据自己的性质是**两类东西**：后者验「代码做了它该做的」，前者验「代码合不合人眼」，出处也不同（一个是 ADR、一个是 `judgements/`）。每一条都要指得回它那一轮判读
- [ ] **写性质，不写读数。**换面板、换夹具不该假红
- [ ] **近白平坦调上 FS 不占优**：平坦调的背景够亮时，`2bit+FS` 永远不比 `2bit 不抖` 干净（出处：第七轮 L 组近白列 5/5）
- [ ] **离格 0 的页上 FS 够用**：纸白正落在格点上时，FS 在白底一个点都不撒（出处：第六轮 C 组）
- [ ] **亮度分歧——这一条是缺陷记录**：断言判据在同一个《离格量》的三种背景亮度上**结论相同**。**这不是希望的行为**——真机在那三格上给的答案相反（第七轮 L 组三行分歧）。判据将来真认得出亮度时它该红，**红了就把它换成新的断言，那不是回归**。用例的文档要把这一段写清楚
- [ ] 断言「结论相同」而**不是**「读数极差小于某值」——不依赖任何具体读数
- [ ] 前三条用**合成夹具**（照 `tests/fixtures/` 的既有做法），真实素材不入库
- [ ] **离格 1 的真实页上 `4bit 不抖` 更干净**（第七轮 M 组 4/4）这一条合成不出来，走 **opt-in 真实素材**，照仓库既有的「真实素材冒烟照旧 opt-in」
- [ ] 四条在**今天的判据**上全绿
- [ ] 闸门三条绿（`cargo xtask gate`）
