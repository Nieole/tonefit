# 02: 四条真机事实立成护栏，今天就是绿的

**What to build:** 四条真机判读的结论从 `judgements/` 里的 JSON 变成**跑得起来的用例**。它们在**今天的判据上就该绿**——于是 `04` 改地板时，它们是拦得住错的护栏，而不是改完之后的追认。

判据的下一次改动撞到这四条会当场红，而不是要再上一次机才发现。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 新开一篇 `tests/perceptual.rs`。真机事实与判据自己的性质是**两类东西**：后者验「代码做了它该做的」，前者验「代码合不合人眼」，出处也不同（一个是 ADR、一个是 `judgements/`）。每一条都要指得回它那一轮判读
- [x] **写性质，不写读数。**换面板、换夹具不该假红
- [x] **近白平坦调上 FS 不占优**：平坦调的背景够亮时，`2bit+FS` 永远不比 `2bit 不抖` 干净（出处：第七轮 L 组近白列 5/5）
      —— **只立到 u ≤ 21 那四格**。第五格（u = 42、灰度 213）今天的判据反着说 FS 更好，立不成，见 **Q447** 与《落地记录》二
- [x] **离格 0 的页上 FS 够用**：纸白正落在格点上时，FS 在白底一个点都不撒（出处：第六轮 C 组）
- [x] **亮度分歧——这一条是缺陷记录**：断言判据在同一个《离格量》的三种背景亮度上**结论相同**。**这不是希望的行为**——真机在那三格上给的答案相反（第七轮 L 组三行分歧）。判据将来真认得出亮度时它该红，**红了就把它换成新的断言，那不是回归**。用例的文档要把这一段写清楚
- [x] 断言「结论相同」而**不是**「读数极差小于某值」——不依赖任何具体读数
- [x] 前三条用**合成夹具**（照 `tests/fixtures/` 的既有做法），真实素材不入库
- [x] **离格 1 的真实页上 `4bit 不抖` 更干净**（第七轮 M 组 4/4）这一条合成不出来，走 **opt-in 真实素材**，照仓库既有的「真实素材冒烟照旧 opt-in」
- [x] 四条在**今天的判据**上全绿 —— **四条全绿，但第一条是收窄之后才绿的**（上面那一格）。原样立不绿的是近白列 u = 42
- [x] 闸门三条绿（`cargo xtask gate`）

## 落地记录

### 一、四条护栏落在哪儿

新开 `tests/perceptual.rs`，**自带 harness**（`Cargo.toml` 加一格 `[[test]] harness = false`），
理由与 `tests/smoke.rs` 逐字同一条：第四条要一手素材，**跳过要印得出跳过**。
四条都立在既有的主接缝 `score(&Reference, &GrayImage, BitDepth)` 与 `quantize` 上，
**零个新接缝**。

| 用例 | 断的性质 | 出处 |
|---|---|---|
| `near_white_flat_tones_never_favour_dithering` | 近白平坦调上 `2bit+FS` 不比 `2bit 不抖` 干净 | 第七轮 L 组近白列 5/5 |
| `on_grid_paper_white_takes_no_dither_dots` | 纸白落在格点上时 FS 在白底一个点都不撒；平移到离格 2 就撒得出 | 第六轮 C 组（对照同轮 B 组） |
| `the_metric_answers_the_same_at_every_background_brightness` | 同一个《离格量》的三种背景亮度上判据**结论相同**（**缺陷记录**） | 第七轮 L 组十五格 ＋ 第八轮复判的订正 |
| `off_grid_by_one_real_pages_still_favour_four_bit_plain` | 离格 1 的真实页上 `4bit 不抖` 读数低于 `2bit+FS` | 第七轮 M 组 4/4（opt-in） |

**一条模型判读都没引。**`judgements/README.md` 写着第四、五轮不作标定依据，四条全部取自
第六、七、八轮（人、真机、整页 1:1）。

**票面「第七轮 L 组三行分歧」是旧数，落地时按第八轮订正成两行。**第八轮复判包 04R
把第七轮里可疑的那两格各判两次、左右顺序相反：`u02_偏暗` **两次一致，真值是 2bit 不抖**
（第七轮那个 FS 是噪声），u = 2 那一行因此不再分歧；`u42_中灰` 两次相反、落在判读边界上、
记成「平」，而同行近白判不抖、偏暗判 FS，那一行照旧分歧。**今天站得住的是两行：u = 21 与
u = 42**（第八轮的四格锚 4/4 与第七轮一致，那一趟判读是稳的）。
断言一格不受影响——它断的是判据三格结论相同，与真机答什么无关；变的是**缺陷记录的证据有多大**，
说成三行就是把它说大了。

**合成夹具与一手素材贴得上。**近白列四格逐格对得上第七轮同格的一手素材读数——
合成那一列在《三》的「今天」那一栏，一手素材那一列在 `docs/measurements.md` 的
《判据缺的那一维》，两处各记一次，这里不复述。形状对得上，绝对值略低，
差在一手素材那一块 512×512 里还有 5 级起伏，纯色没有。

第二条的页是**白底在上、灰调带在下**：FS 的误差只往右和往下传，白底那一片因此收不到
带子漏过来的误差，「一个点都不撒」问得干净。带子不能省——没有它整页都在格点上，
量化成了恒等映射，这一条就什么都没验到。

### 二、第一条只立到 u ≤ 21：近白列第五格今天不绿

真机在近白列**五格全判「2bit 不抖更干净」，无一例外**（第七轮对 01/02/03/06/09）。
今天的判据在 **u = 42（灰度 213）** 那一格反着说 FS 更好：本树上量得 `2bit 不抖 42.000`
对 `2bit+FS 26.380`，与 measurements 的《判据缺的那一维》记的一手素材读数 27.036 同向。
断言因此收窄到 u = 1/2/8/21，**那一格排除在断言之外、写进用例文档与 Q447**，
而不是留一条今天就红的用例。

> **两处 27 不是同一个数，不必核对。**`judgements/第七轮真机包04.json` 与 measurements
> 那张表给的 **27.036 是近白那一格**；素材包 `真机包04/参照8bit/标定表.txt`（在仓库之外，
> 由 `calibration/ladder_calibrates_floor.py` 印出）那一行的 **27.266 是三种背景亮度取中位**
> （27.036/27.337/27.266 的中位）。两处各说各的量，都对。

**票面「四条在今天的判据上全绿」这一条，第一条原样立不成。**这是本票量出来最要紧的一件事。

### 三、这四条拦不拦得住 `04`：拦得住，而且现在就红

同一份夹具上多量了一次，**只量数、不改代码**（把 `GRAIN_RATIO` 临时摆成 `55/85`
使 `floor(2bit) = 55.0`，量完原样还原）：

| 近白格 | 今天（地板 18.33） | 地板绝对 55.0 |
|---|---|---|
| u = 1 · 254 | 不抖 1.000 · FS 2.738 → **不抖** | 不抖 1.000 · FS 2.738 → **不抖** |
| u = 2 · 253 | 不抖 2.000 · FS 3.319 → **不抖** | 不抖 2.000 · FS 3.319 → **不抖** |
| u = 8 · 247 | 不抖 8.000 · FS 10.508 → **不抖** | 不抖 8.000 · FS **3.393** → **FS** |
| u = 21 · 234 | 不抖 21.000 · FS 22.157 → **不抖** | 不抖 21.000 · FS **3.422** → **FS** |

**收窄之后的第一条护栏，在地板 55 下是红的**——u = 8 与 u = 21 两格翻向 FS。
机理直白：那两格的 FS 高频起伏是 24.82 / 36.66，绝对地板 55 把它们整条吞掉，
FS 那一侧只剩低通残留（3.4 上下），而不抖那一侧仍是整块偏 u。

护栏因此**确实拦得住 `04` 那次改动**——它不是摆设。代价是 `04` 票面那句
「`02` 那四条真机护栏仍然全绿」与它自己要改的地板**不能同时成立**，记在 **Q448**。
