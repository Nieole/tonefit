# 01: 掩蔽那两个数有自己的类型，报告说得出

**What to build:** 用户看报告时，除了《判据构成》与《判据聚合》，还看得到**掩蔽**那两个数是多少，并且标着「未标定占位值」——照 `Aggregation` 印 K 的做法。今天它们是两个私有常数，屏上一个字都没有，而它们改了判定就变。

**取值不动，判定逐字节不变。**这一张是给 `03` 铺路：哈希收不到私有常数。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 新增 `Masking { floor, knee }` 与它的构造函数，**与 `Composition`、`Aggregation` 平级**——ADR 0002 把前两者分成「一块的读数**由什么组成**」与「块的读数**怎么收成一个数**」，掩蔽是第三件：一块的读数**怎么加权**
- [x] 取值仍是 **0.5 / 8.0**，仍是**未标定占位值**；本张不标定它们
- [x] 报告印得出这两个数，连同「未标定占位值」一并说——措辞**只有一处出处**（ADR 0016），命令行的纯文本与会话的表共用同一份字
- [x] 会话那一层跟着走既有的摆法，不新造（会话「这一趟的前提」复用报告抬头那一份）
- [x] `CONTEXT.md` 的《尚未确立》里那两个数的记法跟着更新——它们现在有名字了
- [x] **黄金快照逐字节不变**——取值没动，判定就不该动。这是这一张最强的验收
- [x] 闸门三条绿（`cargo xtask gate`）

## 落地记录

### 一、`Masking` 与 `Composition`、`Aggregation` 平级

```rust
pub struct Masking {
    pub floor: f32,   // 打折打到头的那一档
    pub knee: f32,    // 加权正好落在「不打折」与地板中点的那个活动度，8 位灰度级
}

pub const fn masking() -> Masking {
    Masking { floor: MASKING_FLOOR, knee: MASKING_KNEE }   // 0.5 / 8.0，一格未动
}
```

摆在 `src/metric.rs` 里两个常数的正下方，与 `composition()` / `aggregation()` 一套写法：
私有常数留在原处当唯一取值出处，`const fn` 把它们包成一件东西，`Display` 出报告那一行。
`src/lib.rs` 导出 `Masking` 与 `masking`。

**ADR 0002 一个字没改。**第 4 条早就把掩蔽立成了判据形状的一件事（「叠加对比度掩蔽加权」，
连同「拐点仍未标定」），本票做的只是把它从两个私有常数抬成一个有名字的类型——
决定没变，能读到它的地方变了。

### 二、`masking_weight` 改成从 `masking()` 取数

```rust
fn masking_weight(activity: f32) -> f32 {
    let Masking { floor, knee } = masking();
    floor + (1.0 - floor) * knee / (knee + activity)
}
```

**这一步票面没要求。**只加 `pub` 字段也能满足「报告说得出、哈希收得到」，
但那样 `Masking` 与真正在算的两个常数之间没有任何东西逼它们同步：改一处忘一处，
报告会不声不响地印出一份与判据无关的数。f32 的运算次序**一格没动**
（同样的四则、同样的先后），黄金快照因此逐字节不变——这一条由 git 直接证明：
`tests/` 底下一个文件都没进本次改动。

`Aggregation` 那三个数**没有跟着收口**（`tiles()` 与 `aggregate()` 照旧直读常数），
理由与那张票的地界，记在 **Q438**。

### 三、报告：抬头从两行判据形状变成三行

```
判据构成 低通后的局部均值误差 ＋ 颗粒超出格点间距 21.6% 的那一部分（地板盲测标定于 boox-poke6，其余面板未复核）
判据掩蔽 平坦块不打折 ⋅ 结构越密折得越狠，压不到 0.50 以下 ⋅ 活动度 8.0 时落在两者中点（地板与拐点均未标定占位值）
判据聚合 分块 32x32 ⋅ 尾巴取 p99，但不宽于 8 块（K 未标定占位值）
```

新那一行夹在两者中间，照的是**一块读数走过的次序**：由什么组成 → 怎么加权 →
怎么收成一个数（ADR 0002 决定第 5、4、3 条）。次序本身由一条用例钉着，
不靠「摆在那儿看着对」。

**地板说成「压不到它以下」而不是「打到它」**：`拐点/(拐点+活动度)` 恒大于零，
加权是一条渐近线，永远到不了地板。头一版写的是「结构最密处打到 0.50」——
那是**屏上一句假话**，而这一行的收信人正是「不知道判据里还有两个未标定占位值」的用户
（spec 的 story 8）。**code-review 的 spec 轴逮住的**，同一条性质现在由用例钉着
（`masking_weight(255.0) > floor`，严格大于）。

这一处与 **`no-false-line`（屏上没有一句假话）**那一批是同一件事：屏上印出来的话
必须是代码真做得到的那件事。差别只在时机——那一批收的是**既有的**假话，
这一处是**新话在落地当口就被拦下来**，一行都没有交付过。

措辞出处仍只有 `metric::Masking` 的 `Display` 一处（ADR 0016）。字面本身票面没给，
落地时定的——为什么写成这几处而不是印那个式子，记在 **Q437**。

### 四、会话那一层：零行新代码

「这一趟的前提」那一张本来就整段吃 `render::header`（`overlay::premises` 那一句
`Painted::plain(crate::render::header(...))`），多一行自动跟上。动的只有那张
**录下来的屏**（`THE_PREMISES`）：多两行掩蔽、少两行空白，80×16 上正文落成 10 行、
剩 1 行空白，没有滚起来。再往抬头加一行它就要滚了，记在 **Q439**。

跟着改的是**四处**描述抬头装什么的散文（`overlay::premises`、`draw::report` 的模块文档
与 `body`、`state::Overlay::Premises`）：「判据构成与聚合」→「判据构成、掩蔽与聚合」。
连同 `CONTEXT.md` 的《覆盖层》，同一份清单**一共抄在五处**，没有东西逼它们同步——
本票一处不落地改了，但没有去拆那份重复，记在 **Q441**。

### 五、用例：一条新增，三条跟着改

| 缝 | 用例 | 变化 |
|---|---|---|
| `masking()` | `the_masking_weights_come_from_the_one_place_the_report_reads` | **新增**（`src/metric.rs`）。四个说得出名字的点加一条单调不增，**一个当前取值都不写死**：平坦处读 1.0、拐点上落在 1.0 与地板的中点、地板**到不了**（`> floor` 严格）、活动度大到余量并进地板才 `>=` |
| `header` | `the_report_renders_the_profile_then_one_line_per_volume_and_per_page` | 行数 15 → 16，并添三条断言：抬头**整段逐字出自** `Masking` 的 `Display`（`text.contains(&masking().to_string())`）、「地板与拐点均未标定占位值」那一句、以及三行的先后 |
| `header` | `a_skipped_volume_says_so_and_says_nothing_it_did_not_compute` | 行数 10 → 11 |
| `premises` | `the_premises_overlay_carries_the_header_the_volume_table_used_to_wear` | 快照照实际重录 |

派活点到的只有 `render.rs` 里那两处 `contains` 断言，而它们**同在头一条用例里**——
那条用例开头还按行数钉着抬头，另两条（另一处行数、那张快照）谁都没点。记在 **Q440**。

**新那条用例的取值写法**：`let Masking { floor, knee } = masking();`，
断言里出现的只有 `floor` 与 `knee` 这两个名字。标定把它们换掉时，
这一条与报告那几条都不必跟着改——与 `Aggregation` 的 K 同一条规矩。
比较一律走 `1e-6` 的邻域，不用逐位相等：加权那一步是 `(1−地板)·拐点/(拐点+活动度)`，
而 `(a·k)/k` **只在 k 是 2 的幂时**恰好还原 `a`——今天的 8.0 是，标定之后未必。

**报告那一头断言的是整段而不是几个片段**：抄片段等于把 `Display` 的格式（`{:.2}`
与 `{:.1}`）在用例里再写一遍，而 ADR 0016 要的正是措辞只有一处出处。
后两条（邻域比较、整段断言）都是 **code-review 逮住的**。

### 六、`CONTEXT.md` 三处

- **词汇表新增《判据掩蔽 (Masking)》**（`CLAUDE.md`：新词可以当场加）。摆在
  《判据构成》后面，说清三者是判据形状的三件事，并写明两个数都是未标定占位值。
- **《尚未确立》那一条**从点常量名（`MASKING_FLOOR` 与 `MASKING_KNEE`）改成点词条
  （《判据掩蔽》那两个数），并补一句「报告在判据掩蔽那一行连同『未标定』一并印出」——
  它们从此有名字、也上了屏。缺口本身**一个字没改**：该不该跟着参照自身的高频走，仍未定。
  **取值不抄进来**：头一版写了「地板 0.5、拐点 8.0」，那给取值开了第二处出处，
  与本票代码通篇「当前那两个数字一个都不写死」的规矩自相矛盾——**两轴 review 各自都逮到了**，
  已改成只点词条，并写明取值的唯一出处在 `metric` 那两个常量。
- **《覆盖层》**那一条列前提那一张装什么的地方跟着改：「判据构成与聚合」→
  「判据构成 · 掩蔽 · 聚合」。这份清单**一共抄在五处**（另四处是三个模块的散文），
  五处一处不落地改了，但没有去拆那份重复——记在 **Q441**。

`docs/measurements.md` 一个字没动——那两句引的是常量名，而常量还在原处。

### 七、没有动的

- **取值** 0.5 / 8.0 一格未动，仍标未标定占位值；标定归 `metric-recalibration/05`。
- **`GRAIN_RATIO`** 一格未动（`04` 号票的地界）。
- **`params_hash`** 一个字未动（`03` 号票）。本票只把三个字段摆到它够得着的地方：
  `metadata::params_hash` 在库内，`metric::masking()` 与两个 `pub` 字段拿得到。
- **ADR 0002**、**`docs/measurements.md`**、**spec 与其余三张票**，一个字未动。
- **`tests/`** 一个文件未动——包括 `tests/golden-snapshot.txt`。

### 八、code-review 逮到四处，四处都改了

两轴并行审，**两轴各自独立逮到同一处**（`CONTEXT.md` 抄下取值），另三处各出一轴：

| | 哪一处 | 为什么是真问题 |
|---|---|---|
| spec 轴 | 报告写「结构最密处**打到** 0.50」 | 地板是**渐近的下确界**，`拐点/(拐点+活动度)` 恒大于零，加权永远到不了它。说成到达就是**屏上一句假话**——与 `no-false-line` 那一批同一件事 |
| spec 轴 | `assert_eq!(masking_weight(0.0), 1.0)` 逐位相等 | 靠的是 `(a·k)/k` 恰好还原 `a`，只在 k 是 2 的幂时成立。与这条用例自称「标定换掉时不必跟着改」相抵 |
| 两轴 | `CONTEXT.md`《尚未确立》抄下「地板 0.5、拐点 8.0」 | 给取值开了第二处出处（`CLAUDE.md`《文档写作》第 4 条），且与本票代码通篇「一个数字都不写死」自相矛盾 |
| standards 轴 | 用例抄了 `Display` 的格式（`{:.2}` / `{:.1}`） | 把措辞的格式绑在两处，改精度时红的是「两处对不上」而不是「措辞变了」——ADR 0016 要的正相反 |

standards 轴还点出 `masking_weight` 的文档留着 ADR 原话「拐点仍未标定；地板与量法一起
重定」，而字段、常量与屏上那一行都说「两个都没标定」——同一件事两个说法，**分歧的那一版
上了屏**。改成「两个都是未标定占位值；地板的现值是量法换到块尺度那次跟着重定的，
那一次夹的是窗口、不是一次标定」，与 `CONTEXT.md` 和 measurements 对齐。

**这四处改完，上一轮的绿就不再说明这一版**，闸门整个重跑了一趟——下面《数》记的是
重跑那一趟。
