# 05 — 取值栏：左栏上就地摊开取值

**What to build:** 左栏每一行的取值从「只能一格一格转」改成「摊开来看」。光标那一行按
`⏎`（或空格）就在它**下面**摊开一列取值，选中的那一格前面一个记号，`↑↓` 选、
`⏎`／空格／`→` 定、`Esc`（或 `←`）**一格不改**地回去。**摊开的键只有 `⏎`／空格**——
`←→` 归环那一套（本票面「环那一套（`←→` 就地转一格）保留」那一段原样成立），
一个键做不了两件事。

要修的毛病是：环让「**这一项有哪几个取值**」在屏上根本不存在——用户只有把它轮询过
一整圈，才知道自己有哪些选择。取值只有两三个的那几行同样吃这个亏，只是按得少一点。

摊开的**第一格恒是那一行「没说」的那一格**：印成什么照那一行自己的写法——多半是
`默认（…）`，而**位深与抖动那两行是`自动（判据说了算）`**（这两项的默认不是一个定值，
是判据当场判出来的）。设备层与口味层的每一格都有一个「没说」的位置，而那正是存成预设时
写不写进去的分别。「没说」与「说了一个恰好等于默认的值」在屏上要分得开。

**环那一套（`←→` 就地转一格）保留**：知道自己要什么的人不必先摊开再选。摊开时
`←→` 归摊开的那一层（`→` 定、`←` 一格不改地退回去）。

取值栏与**预设栏**是两个状态、两个词：这一个就地摊在左栏，那一个占主区。

型号那一行归 06 号票（它多一层下钻）。

## 落地记录

### 取值栏落在哪儿

**状态机里一个与预设栏同级的新状态**：`src/session/state.rs` 的
`Mode::Valuing(Values)`——它挂在 `tui` **外面**（`src/session.rs` 里 `state` 与
`viewport`、`live`、`run`、`complete` 并排），`--no-default-features` 那一趟连它的用例
一起跑。

```rust
pub struct Values {          // 取值栏：摊开那一刻记下的那一列
    field:  Field,           // 摊的是左栏上哪一行
    cells:  Vec<String>,     // 那一列取值在屏上的写法，第一格恒是「没说」那一格
    at:     usize,           // 光标停在第几格
    chosen: usize,           // 此刻真正生效的是第几格——记号画在它前面
}
```

**「下钻到第几层」那一格不在这里**（spec 的《取值栏》说它带着三样）：下钻只有型号
那一处有两层，归 **06**；本票摊的每一行都只有一层，加一格现在没人读的东西就是
Speculative Generality。

`Values` 与 `Picker` 是**两个类型、两个词**（`CONTEXT.md` 的《会话》各一条词条）：
取值栏就地摊在左栏那一行**下面**、左栏其余各行还在场；预设栏占主区。

### 那一列就是那一行的取值环——没有第二份清单

`Session::unfold` 拿一份 `self.clone()` 当探针，**先转到「没说」那一格，再从那儿摊一圈**，
一步一步走的就是 `←→` 转的那个 `turn_field`（本票从 `cycle` 里拆出来的那一支）：

- 环上加一个取值，摊开那一列**当场跟着多一格**——那份「有哪几个值」的清单不存在第二份，
  用例 `every_row_whose_value_is_a_ring_unfolds_into_that_ring` 走一遍环逐格对着钉住。
- 每一格印成什么走 `Session::shown`，与那一行自己印的是**同一份**措辞。
- **此刻生效的是第几格是数出来的，不是认字认出来的**：从这一行此刻停的那一格起走
  `back` 步到得了「没说」，它就在环上倒数第 `back` 格。

`Session::choose`（`⏎` 定）**转到那一格上**：先转到「没说」，再往前走 `at` 格。
**摊开这一路因此根本没有自己的写入路径**——「两条路改的是同一格」不必靠自觉，
由 `unfolding_and_turning_in_place_write_the_same_cell` 逐行逐格钉死
（摊开来选第 k 格 ⇄ 就地转 k 下，两层逐格相同）。

**停着的还是生效着的那一格时一步都不走**：那一下与 `Esc` 一样一格不改。

### 「哪几行摊得开」只有一处出处

`Field::unfolds()`：取值是环的行都摊得开，**型号那一行除外**。按键表
（`Session::browsing_action`）、屏底摆不摆那个键（`draw::footer::browsing_keys`）、
摊开那一下自己（`Session::unfold`）、用例的助手，四处问的都是它——
与 `around` 那句「写两份就会有一处忘了绕」同一条规矩。06 号票要放开型号，改这一处。

它还是**「取值恒在环上」那条前提的守门人**：摊得开的九行取值都是枚举或布尔，一格不落
都在自己的环上；唯一可能落到环外的是型号（预设里塞进来的一个已删型号，见 `next_device`），
而它正被挡在外面——`unfold` 数「第几格」靠的就是这条前提。

### 按键：环保留，摊开之后归那一列

| 状态 | 键 | 做什么 |
|---|---|---|
| 浏览，摊得开的行 | `←→` | **就地转一格（一格没动）** |
| 浏览，摊得开的行 | `⏎`／空格 | **摊开**（从前是就地转一格） |
| 浏览，型号那一行 | `⏎`／空格 | 就地转一格（一格没动，归 06） |
| 取值栏摊着 | `↑↓`／`kj` | 在那一列上挪一格，两头绕回去 |
| 取值栏摊着 | `⏎`／空格／`→` | **定** |
| 取值栏摊着 | `Esc`／`←` | **一格不改地回左栏** |
| 取值栏摊着 | `q`／`Ctrl-C` | 退出会话 |
| 取值栏摊着 | 其余一律 | `Ignored` |

**`Esc` 一格不改是这张表的形状本身**：那个状态下派得出的动作里只有 `Choose` 写取值，
`Cancel` 一格都不碰。用例 `escaping_out_of_the_unfolded_values_changes_not_one_cell`
在那一列上**走到别的格子上去**再退出来，比的是三层的全部内容（不是那一行印出来的那句话）。

「哪些键在哪个状态下有效」仍旧**一处答完**：`which_keys_do_what_in_which_state`
添了两段——三之二（取值栏那几支逐条问过，连同十一个 `Ignored`）与三之三（型号摊不开）。

### 跑起来之后摊不开

`Mode::Valuing` 只从**浏览**进得去，而跑着与等答话那两张表一个改动键都不派——
`⏎` 与空格在那两段里本来就是 `Ignored`（用例第六段那张单子上加了一句为什么）。
**屏上看得出来**：屏底那一行不摆「⏎ 摊开」（`a_run_in_progress_says_on_screen_that_the_three_layers_are_read_only`
的黑名单里加了它），左栏抬头照旧改口说「只读」、各行压暗。

### 画法：就地摊在左栏，视口接得住

`draw/config.rs` 在摊开的那一行**下面**插进那几格，比那一行的取值再缩进一层
（缩进是屏上唯一说得出「这几格是上面那一行的」的东西——这一栏没有第二级框线）。

**两个记号分得开**（票面第二条）：`●` 画在此刻生效的那一格前，别的几格 `○`；
光标那一格**反白**。摊开着的时候**那一行本身不反白**——屏上只有一处反白，
它说的恒是「就在这一格上动手」。

**视口跟的是那一列上的光标，不是摊开的那一行**：跟着那一行走的话，摊开那一列的末几格
照旧掉在格子下面，而那正是本票要修的毛病的另一面。用的是 `p3/04` 那**一份**视口
（`src/session/viewport.rs`），一行实现都没新造；那张「哪几处共用它」的表上，
左栏那一行注明了「连同就地摊开的取值栏」。

屏底那两行（`draw/footer.rs` 的 `valuing_prompt`）：上一行行首是**摊开的是哪一行**
（窄到左栏让出宽度那一档上它整个不在屏上），`←→` 摆出来（它们在这个状态下按得动）；
下一行说清**第一格那件事**——「没说」与「说了一个恰好等于默认的值」的差别只有存成预设时
才看得见，而看不见的差别用户改不动。

### 评审

两轴各跑了一遍（**只读，没碰工作区，也没跑 cargo**——闸门当时正在另一个进程里跑）。
**Spec 轴**把九条验收与派活说明那八条硬约束逐条对过：环保留、`Esc` 一格不改、
跑起来摊不开、型号没碰、就地摊在左栏不占主区、后面几张票的东西（卷表、语义色、
两维模式、焦点、覆盖层）一样都没提前做、视口只有一份、`CONTEXT.md` 只加新词——全过。
两轴各提了几条，**收下的**：

- **「型号那一行除外」写了三份**（Standards 轴，Repeated Switches／Shotgun Surgery；
  Spec 轴同一处从另一头点出「型号摊不开只有一道闸」）：状态机的按键表、屏底那一行、
  用例的助手各判一次，而 `unfold` 自己的卫语句只判 `shape()`、与那条规矩已经对不上。
  **收成一处 `Field::unfolds()`**，四处一律问它；06 号票放开型号只改这一处。
- **「先转到『没说』那一格」的循环两份**（Standards 轴，Duplicated Code）：
  抽成 `Session::turn_to_unsaid(field) -> usize`，`unfold` 与 `choose` 共用它。
- **环上的位置靠屏上字符串认**（Standards 轴，Primitive Obsession）：
  `chosen` 从前是 `cells.iter().position(|cell| *cell == 这一行现在印的)` 求的，
  值的身份因此骑在渲染文本上（注释里还得声明「一个环上没有两格印得一样」）。
  **改成数步数**：走 `back` 步到得了「没说」，就在环上倒数第 `back` 格。
  `chosen` 随之从 `Option<usize>` 变回 `usize`——摊得开的那几行取值恒在环上，
  而守门的是 `Field::unfolds`（那条前提写在它的文档里，交给 06）。
- **画那一格的函数收两个裸 `bool`**（Standards 轴，Feature Envy／Data Clumps）：
  `choice(cell, under_cursor, chosen)` 让调用方替它各判一次。改成
  `choice(values: &Values, at: usize)`，两个记号在一处定。
- **一条弱断言**（Spec 轴）：`the_unfolded_values_keep_the_cursor_on_screen` 里
  `contains("lanczos3")` 恒真——第一格「● 默认（lanczos3）」也含着它。
  两头都换成**带着记号的那一整格**（`○ lanczos3` 与 `● 默认（lanczos3）`）。
- **停车场 Q138 少一个空行**（Standards 轴）：补上。

**没收的两条**，都是 Spec 轴点出、而它自己也认下的「票面自相抵触」：
