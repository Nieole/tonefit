# 06 — 型号按面板下钻两层

**What to build:** 型号那一行摊开的不是 31 个名字，是**八块面板**——每一行带着那块面板的
分辨率、PPI、灰阶数与黑白／彩色。`→` 下钻到那块面板下的型号（二到五个），`⏎` 定、
回到型号那一行；在型号那一层按 `←`（或 `Esc`）退回面板那一层。

领域上早就写着「**设备只是面板的别名，多对一**」，而未知型号那条错误消息本来就是
**按面板分组**端出来的，还写着「面板相同的型号输出完全一致，所以挑一个面板相同的型号
顶上是可行的一步」。挑替身本来就该从面板挑起——内置表里没有你那台设备时，你要挑的
从来不是名字，是那块屏。

**分组的规矩只有一处**：把库里那个「按面板分组列内置型号」的读法从私有提为公开，
取值栏与那条错误消息用同一份。这是本批唯一一处动到库的地方，不新增 seam。

**下钻只有这一处有两层**，别处一层。

## 落地记录

### 库那一侧唯一的动静

`src/profile.rs` 的 `devices_by_panel` 从**模块私有的自由函数**提成
**`Profile` 上的公开读法**，签名与实现一个字节没改：

```rust
pub fn devices_by_panel() -> Vec<(Panel, Vec<&'static str>)>
```

摆在 `Profile::devices()` 旁边（那一条是 `p1-session/08` 为会话加的同一种读法），
理由也是同一条：**它不是新 seam，是既有类型上的一个读法**——这份分组本来就从
`resolve` 的错误里出得来，公开只是让人不必先制造一次失败、再把那段文字解析回来。
`run(Request) -> Report`、事件流、判据那个数值 seam **一格没动**。

`mod profile` 在 `lib.rs` 里是私有的（`pub use profile::{Panel, Profile, …}`），
所以出口只能挂在 `Profile` 上，不能靠 `pub` 那个自由函数。返回类型里的 `Panel`
本来就是公开类型，`Vec<(Panel, Vec<&'static str>)>` 因此是个稳的类型。

**两处共用它**（票面第五条）：

| 谁 | 怎么用 |
|---|---|
| `unknown_device_error`（今天唯一的调用方） | 按面板分组端出内置清单，一块面板一段 |
| 会话取值栏的面板那一层 | 一块面板一格，格上的字面是 `impl Display for Panel` |

**面板那一行的字面走 `Panel` 自己的 `Display`**，会话这一侧一个格式串都没写：
分辨率 · PPI · 灰阶数 · 黑白／彩色四样是它给的，快照逐格钉着。

库这一侧新添一条用例 `every_model_sits_under_exactly_one_panel`：
每一个内置型号恰好落在一块面板底下，一个不多一个不少。屏上那两层要靠这条性质
**走得到每一个型号**——归并时漏掉一个，屏上就再也点不到它。

### 两层：面板 → 型号

`Values` 多了一格，装的**不是层号，是下钻进了哪一块面板**：

```rust
pub struct Values {
    field:  Field,
    panel:  Option<Panel>,   // 下钻进了哪一块面板；None 是第一层
    cells:  Vec<String>,
    at:     usize,
    chosen: Option<usize>,   // 此刻生效的是第几格；None 是「这一层里一格都不是」
}
```

- **层号答不出「进的是哪一块」**，而屏上那一行要印它（下钻那一层列的是型号名，
  不说一句就没有一处答得出这几个型号是哪块屏的）；退一步也要靠它落回那一块上。
- **`chosen` 从 `usize` 变成 `Option<usize>`**：型号停在内置表外的一个名字上时那一列里
  没有一格生效着（票面第七条），下钻进一块不含当前型号的面板时也一样。
  「随便点实一格」就是在指一个用户没挑过的型号。

两层各由一个函数摊出来，都只读不写：`Session::panels(cursor)` 与
`Session::devices_under(panel, devices)`。**不叫 `device_level`**——`CONTEXT.md` 的
《会话》里**设备层**是三层配置的第一层，领域词一词一义（评审 Standards 轴点出的硬违规）。

**第几格对着哪一块面板不记在 `Values` 里**——`drill` 再问一次
`Profile::devices_by_panel()`，与摊开那一列问的是同一份（内置表在一趟会话里不会变）；
它顺手把那一块底下的型号一起取出来交给 `devices_under`，同一张表不翻第二遍。
「第一格是『没挑』、面板从第二格起」这条偏移由**一个常量** `PANELS_START_AT` 答，
两头（摊开时 `+`、下钻时 `-`）都问它。

### 写型号只有一条路

`Session::set_device(Option<String>)` 是本票从 `turn_field` 的型号那一支里拆出来的：

```rust
fn set_device(&mut self, device: Option<String>) {
    self.device.profile = device;
    self.device.gray_levels = None;   // ADR 0002
    self.device.threshold = None;
}
```

`←→` 就地转一格与取值栏上定下来的那一下**落到的都是它**，
「换掉型号仍旧把标定出来的灰阶数与阈值清空」因此不会有一处忘了跟着做（票面第六条）。
`picking_a_model_and_turning_in_place_write_the_same_cell` 逐个内置型号问一遍：
摊开→下钻→定，与从「没挑」起就地转到它，**两条路走完设备层逐格相同**，两个数都清空了。

**型号那一行定的不是「环上走几步」**：那两层列的是面板与面板底下的型号，
环上第几格答不出来——`choose` 的型号那一支因此直接把那一格的名字交给 `set_device`，
而别的九行照旧「先转到『没说』，再往前走 `at` 格」。

### 按键：一个键的意思由它落在哪一格上说了算

| 状态 | 键 | 做什么 |
|---|---|---|
| 浏览，型号那一行 | `←→` | 就地转一格（**一格没动**） |
| 浏览，型号那一行 | `⏎`／空格 | **摊开**（转得动的行一律摊得开，型号也在内） |
| 面板那一层，停在「没挑」上 | `⏎`／空格／`→` | **定**（它是型号那一行真正的一个取值） |
| 面板那一层，停在一块面板上 | `⏎`／空格／`→` | **下钻**（面板不是取值，定不下来） |
| 面板那一层 | `Esc`／`←` | **一格不改**地回左栏 |
| 下钻那一层 | `⏎`／空格／`→` | **定**，回型号那一行 |
| 下钻那一层 | `Esc`／`←` | **退回面板那一层**（光标落回进来的那一块） |
| 两层 | `↑↓`／`kj` | 在这一列上挪一格，两头绕回去 |
| 两层 | `q`／`Ctrl-C` | 退出会话 |
| 两层 | 其余十一个 | `Ignored` |

- **新动作只有一个**：`Action::Drill`。**退回上一层没有新动作**——走的是 `Action::Cancel`，
  与打预设名退回那一栏的列表同一个形状（「**退一步，不是退到底**」那句话早就写在
  `Session::cancel` 上了）。
- **`⏎` 与 `→` 在这两层上仍旧同义**（`p3/05` 立的形状）：分岔不在键上，在**格**上——
  `Values::at_a_panel()` 一处答完「这一格是不是一块面板」，按键表与屏底那一行都问它。
  票面把 `→` 派给下钻、`⏎` 派给定，字面上读着像是面板那一层的 `⏎` 也是定；
  **面板定不下来**（它不是型号那一行的一个取值），而拆开这三个键要破 05 立的那条形状
  ——记进停车场 **Q144**。
- `which_keys_do_what_in_which_state` 的**三之三**整段重写：从「型号那一行摊不开」
  改成两层逐条问过，连同十一个 `Ignored` 与「两下 `Esc` 才出这一栏」。

### `Field::unfolds` 撤掉，换成 `Field::drills`

`p3/05` 立的 `Field::unfolds()`（「取值是环的行都摊得开，**型号除外**」）本票**删掉**：
型号放开之后它恒等于 `shape() == Shape::Cycle`，留着就是一个恒真的谓词。
换上的是 `Field::drills()`——**「哪一行是两层」的唯一出处**，三处问它
（`unfold`、`Values::drills`、用例的助手）。

`Field::drills()` 与 `Values::at_a_panel()` **是两个问题、两个名字**：前者问
「**这一行**摊开的是不是两层」，后者问「**这一格**按下去会怎样」。

它接手了 `unfolds` 那半条职责：**「取值恒在环上」那条前提的守门人**。
摊开走**环**那一路的九行取值都在自己的环上（`unfold` 数「此刻生效的是第几格」靠它），
唯一可能落在环外的是型号，而它走的正是另一路。

屏底那一行跟着并成一支：转得动的行一律 `←→ 换一个 · ⏎ 摊开`，
标定图那个键落在同一支里（设备层上转得动的行只有型号那一行）。

### Q140 怎么收的：`back` 加第二个出口

`back(value, next)` 从前一路往前走、走到「再走一步就回到出发点」为止。
**表外的名字不在型号那一环上**（`next_device` 对它给「没挑」），从它出发永远走不回它自己
——那个循环不停：套用一份写着已删型号的预设，停在型号那一行上按一下 `←` 就把界面挂死。

收法是**给这个循环第二个出口**：走满一圈回到了「往前一步落到的那一格」却始终没经过出发点，
说明出发点在环外；这时落回的就是那一格。

```rust
fn back<T: Clone + PartialEq>(value: T, next: impl Fn(T) -> T) -> T {
    let ahead_of_start = next(value.clone());
    let mut cursor = ahead_of_start.clone();
    loop {
        let ahead = next(cursor.clone());
        if ahead == value { return cursor; }          // 环上：出发点的上一格
        if ahead == ahead_of_start { return ahead_of_start; }  // 环外：落回环上
        cursor = ahead;
    }
}
```

**环上那几行一步都没变**（环上从出发点走一圈必然经过它自己，头一个出口先命中）；
落回哪一格**由环自己说了算**，不是这里挑的——型号那一环上正是「没挑」，
而那恰好就是票面第七条要的「落回『没挑』」。

`a_model_outside_the_table_falls_back_to_nothing_picked` 三件事一起问：
`←` 转得回来（**这一条要是回归，它不是红，是挂住**）、`←` 与 `→` 落到同一格、
摊开来那一列一格都不标而光标落回「没挑」。

### 画法

`draw/config.rs` 在摊开的那一行下面插进那几格，与 `p3/05` 同一套；本票加的是**两样**：

- **下钻那一层的抬头**：`    ▸ 1264×1680 · 300 PPI · 16 级灰阶 · 黑白`。
  `▸` 与 `●`／`○` **不是第三种「选中」**——那一行不是这一列上的一格，光标落不到它上面，
  也没有「生效不生效」可言，它是抬头。
- **再缩进一层**：型号那几格挂在面板那一行底下，缩进说的是同一件事
  （这一栏没有第二级框线）。两级缩进摆在一处定（`UNFOLDED_INDENT`／`DRILLED_INDENT`），
  与 `●`／`○`／`▸` 那三个记号同一条。

屏底那两行（`draw/footer.rs` 的 `valuing_prompt`）**三副措辞**，随光标停的那一格换：
停在「没挑」上是 `⏎／→ 定`，停在一块面板上是 `⏎／→ 看这块面板底下的型号`，
下钻那一层上是 `⏎／→ 定 · Esc／← 回到面板那一层`，行首还多印**进的是哪一块面板**
（屏窄到左栏让出宽度那一档上左栏整个不在场）。下一行说的是**为什么摊开的是面板**：
设备只是面板的别名，面板相同的型号输出完全一致。

**视口只有一份**（`src/session/viewport.rs`），一行实现都没新造：13 行的面板那一层
在 24 行的终端上照旧滚得动，跟的仍是那一列上的光标。

> ### Q140 — 型号停在内置表外的一个名字上时，按 `←` 会转不回来（死循环）
>
> - **From:** 票 `p3-session-legibility/05`
> - **Kind:** 路过发现的无关缺陷（本票之前就有）
> - **Where:** `src/session/state.rs` 的 `back`，经 `turn` 与 `Session::turn_field`
>   的 `Field::Profile` 那一支
> - **现状:** `back(value, next)` 一路往前走，走到「再走一步就回到出发点」为止。
>   型号那一环上**表外的名字不在环上**（`next_device` 对它给 `None`，见那个函数
>   自己的文档：「表外的名字落回『没挑』」），从那个值出发永远走不回它自己——
>   那个循环不停。套用一份写着已删型号的预设（`Session::took` 原样收下 TOML 里那个名字）
>   之后，停在型号那一行上按一下 `←` 就到得了。往前转（`→`）没有这个问题：
>   它只走一步。
> - **What p3/05 did:** **绕开**：取值栏摊开与定下来那两步走的都是 `Step::Next`，
>   一步都不倒着走；型号那一行 05 也摊不开。既有的 `←` 一格没动。
> - **Whose call:** 实现（`back` 该在走满一圈之后收在「没说」那一格上，
>   而不是无条件地找出发点）——但它要改的是环那一套本身，
>   而 05 派活说明的《不许动的》头一条把环立成了不许动的东西。留给收它的那张票。
> - **处置：** **本票了结。**本票的地界正是型号那一行（票面第七条要「表外的型号名不崩，
>   落回『没挑』」），而 05 交给「收它的那张票」的那个主意——`back` 走满一圈之后收在哪儿
>   ——答案是**收在往前一步落到的那一格上**：环外那个值两个方向都只能回到环上，
>   落回哪一格由环自己说了算，型号那一环上正是「没挑」。**环上那几行一步都没变**
>   （从出发点走一圈必然经过它自己，头一个出口先命中），05 立的「环不许动」因此没有破。
>   用例 `a_model_outside_the_table_falls_back_to_nothing_picked` 钉着，
>   而这一条要是回归，它不是红，是挂住。
