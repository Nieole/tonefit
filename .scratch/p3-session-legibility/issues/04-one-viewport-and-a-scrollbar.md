# 04 — 一套视口与滚动条，三处共用

**What to build:** 一个纯函数的「视口」：**列表有多少行、格子有多高、光标停在第几行**
→ **从第几行画起**，外加一条滚动条的位置与长度。屏上三处当场共用它（卷表那一处等 08）。

三处今天各有各的毛病，而**纵向一刀都没有**：

- **左栏根本没有滚动**——行数是 21 加卷数，24 行的终端上打进 3 个卷，光标就能走到屏外，
  而屏上看不出它去哪儿了。
- **预设栏**的视口跟着光标走，但屏上没有「上面还有、下面还有」的记号。
- **补全候选**硬性只列 12 条，第 13 条起没有任何交代。

「**滚动量是算出来的，不是记着的**」这条照旧：光标在哪儿，视口跟到哪儿。

这个纯函数摆在 `tui` 特性**外面**——它一个终端都不碰，`--no-default-features`
那一趟因此也跑得到它的用例。

## 落地记录

### 视口摆在哪儿、长什么样

新模块 **`src/session/viewport.rs`**，挂在 `src/session.rs` 里 **`cfg(feature = "tui")`
之外**——与 `state`、`live`、`run`、`complete` 并排（模块文档《终端库在哪一半》那句
「上面四个模块」跟着改成五个）。它一个终端库都不 `use`，`--no-default-features`
那一趟因此照编、照跑它自带的五条用例。

```rust
Viewport::new(rows: usize, height: usize, cursor: usize) -> Viewport
    .from()      -> u16                // 从第几行画起（终端库的 `scroll` 收 u16）
    .shown()     -> usize              // 格子里露出来几行
    .hidden()    -> usize              // 还有几行没露面
    .scrollbar() -> Option<Scrollbar>  // { rows, at, window }；没有可滚的东西时 None
```

`Scrollbar` 那三个数直接喂 ratatui 的 `ScrollbarState`（`content_length` / `position` /
`viewport_content_length`），**滑块画多长、画在哪一截归那个 widget**——本仓库不自己画一条。

**「屏上哪几处共用它、哪一处画滚动条」只有一张表**，摆在 `Viewport` 的文档上；
`draw`、`config`、`picker`、`footer` 一律引它，不抄第二份名单——往后 `08` 把卷表搬进来时
只改那一处。

**没有一个「滚到哪儿了」的字段**：`from` 就是 `cursor + 1 - height`（`saturating`），
光标在哪儿视口跟到哪儿。`cursor` 越界就近收到最后一行上（列表刚缩短时会遇到），
`height` 为零时从头画起——那种格子一行都画不出来，算一个非零的起点只会让人以为它有意义。

### 三处怎么用它

| 屏上哪一处 | 从前 | 现在 |
|---|---|---|
| **左栏** `draw/config.rs` | **一点滚动都没有**：21 加卷数行，24 行的终端上打进 3 个卷光标就走到屏外 | 视口跟着 `session.focus()` 那一行走；装不下时右边框线上一条滚动条 |
| **预设栏** `draw/picker.rs` | `opens_from` 自己算（算得对），屏上没有记号 | 换成同一个 `Viewport`，**屏上一个字节不变**；另加滚动条 |
| **补全候选** `draw/footer.rs` | 硬性 `.take(12)`，第 13 条起无声消失 | 列得下几条列几条，末尾「…还有 N 条」——那个数出自同一个视口的 `hidden` |

`picker::opens_from` **整个删掉**，它那句「只往下滚到光标那一行还在格子里为止，不多滚一行」
原样搬进了 `Viewport::new` 的文档。**预设栏那张快照 `THE_PRESET_COLUMN` 一格没改**，
就是新函数算得对的证据（派活说明点名要这条）。

`config` 与 `presets` 两个函数从「交出一个 `Paragraph`」改成「往 `frame` 上画」——
滚动条是 `StatefulWidget`，与正文是两次渲染，交不出一个值来。

**正文与滚动条一起画的地方只有一处**：`draw.rs` 的 `scrolling`。滚动条落在那一格
**右边那条框线上**（`Margin { vertical: 1, horizontal: 0 }`），一列正文都不吃——
有没有它，格子里的字逐格相同。

### 补全候选那一处没有滚动条（票面第二条与 spec 对不上，Q137）

票面第二条写着「三处都画得出滚动条」，而 spec《一套视口》那张表给补全候选的**光标**
一栏写的是**无**。没有光标就没有一个键翻得动它，而滚动条指的正是「按上下键还翻得到的
东西」；屏底那一格又是一整块 `Paragraph`，一两行高的轨道在 ratatui 的 `Scrollbar` 上
（两头各去一格箭头）根本画不出东西来。

取的是 spec 那一边：**三处共用同一份视口**（票面第五、第六条照办），
**滚动条只画在左栏与预设栏**，补全候选按票面第三条说「…还有 N 条」，那个数由同一个
视口的 `hidden` 出。**哪一处画、哪一处不画连同理由，写在 `Viewport` 那张表上**。

### 「列得下几条」是怎么算的

`footer::listed` 收 `width` 与 `room`（这一格分得到几行），**一条一条往上加，加到
`crate::wrap::fold` 折出来的行数超过 `room` 为止**。折的是它自己拼出来的那一整行，
走的就是屏底真正折行的那一套——两处因此不会一处说摆得下、另一处画不出来。

`room` **只算一次，就在 `footer` 里**：按键那几行与要说的那句话先占，`FOOTER_HEIGHT`
减掉它们剩下的就是这一半的份。编辑一行时说明那一半因此**不在那张 `match` 表里拼**——
它要等 `room` 出来才知道列得下几条，于是 `footer` 在算完 `room` 之后才补上它
（`editing_prompt` 拆成了只出按键那一行的 `editing_keys`）。两处各算各的，屏上就会
出现「说得出还有多少条，可那几条根本没画出来」。

**先砍一刀再逐条试**：一条候选最少占三格（一个字加两个空格的间隔），这一格顶天摆得下
`宽 × 行 / 3` 条。一层下面有上千个名字是常事，而逐条试一遍是平方的。

120 列的屏上实测列得出 **27 条**（40 条候选、屏底分给它 2 行），从前是 12 条封顶。

### 快照

**重录一张**：`draw.rs` 的 `TOO_NARROW_FOR_TWO_COLUMNS`（64×18 那一档）。左栏在那一档上
只有 34 列 13 行，二十一行的清单装不下，右边那条框线因此换成了 `▲`／滑块／`║`／`▼`。
**变的只有那一列，正文一个字没动**——逐行比过。

**新添一张**：`config.rs` 的 `THE_CONFIG_COLUMN_THAT_DOES_NOT_FIT`（52×24，打进三个卷，
正好 24 行摆进 22 行的格子）。同一条用例顺带钉住「装得下时一条滚动条都不画」。

### 左栏折行那笔账（Q136——**它盖着第一条验收**）

左栏折行走的是终端库自己的 `Wrap`（`src/wrap.rs` 的模块文档记着为什么），而
`Paragraph::scroll` 滚的是**折完之后**的行；视口这一头数的是**逻辑行**。两个数只在
一行都不折时相等：

- **52 列那一档**（`CONFIG_WIDTH`，这一栏正常的宽度）——一行都不折，第一条验收成立，
  本票新加的那两条用例跑的就是它。
- **34 列那一档**（终端窄到左栏让宽度时的退化）——行行都折，二十一行的清单实际占三十来行，
  **光标走到末尾时仍可能掉在格子下面**；同一个成因还有第二面：「装得下就不画滚动条」
  也是按逻辑行判的。

算准只有一条路——把左栏的折行也交给 `crate::wrap`（报告区就是那么做的，折出来几行
当场数得出）。那要改屏上的字节（`crate::wrap` 给折下来的每一行补行首缩进，终端库那一套
不补），而 `src/wrap.rs` 的模块文档记着「左栏与预设那一栏**仍走终端库自己的折行**」——
那是 `p2-loose-ends/07` 拍下的一条决定，派活说明同时写着「不要动 `src/wrap.rs`」与
「屏上一个字节不该白变」。**推翻一条仍然生效的上游决定不是实现能自己定的**，
账记进 **Q136** 等拍板，两条用例的文档里也点明了它们只问 52 列那一档。
ratatui 那个直接答得出折完行数的 `Paragraph::line_count` 仍挂着 unstable 的门（Q65）。

  各折了一次按键与那句话。改成 **`footer` 算一次**，编辑一行时说明那一半在 `room` 出来
  之后才拼（`editing_prompt` 拆成 `editing_keys`），`room_below` 那个助手随之取消。
- **`Viewport::new` 三个数两种类型**（Standards 轴，Primitive Obsession）：全改成 `usize`，

`shown`／`hidden` 答的是「列几条、剩几条」，后者三处同一份。
