# 13 — 窄终端那一档：80×24 上整屏过一遍

**What to build:** 把整屏在 **80×24** 上过一遍，把「摆不下时让谁」的次序定死并验收。
前十二张票各自顾各自那一块，而「让位」是**跨块**的事：三块都想要那几行，得有一处说了算。

- **宽度不够**：先把左栏让掉（今天就有的退化），再按 08 那条次序砍列。
- **高度不够**：**总览块不砍**（它是钉住的那一块，也是唯一答「这一趟怎么样」的地方），
  表压到最少一行，屏底照折行那一套长高。
- 三者都让完仍摆不下时，**宁可少画表，不少画总览**。

**Blocked by:** 09, 11, 12

**Status:** resolved

- [x] 80×24 上整屏读得下去：总览五行在、表至少一行、屏底的退出键在屏上
- [x] 让位次序**只有一处出处**，不是散在各块里各让各的
- [x] 极窄（40 列）与极矮（10 行）不崩、不画乱码、不无限折行
- [x] 取值栏、预设栏、展开那一副、两张覆盖层在窄档上各自过一遍
- [x] 快照：80×24 上的浏览、跑着、展开、取值栏摊开，各一张；再加一张极窄的
- [x] 三条闸门全绿

**勾得有保留（第一条）。** 那一条冒号后面列的三件——总览那几行在、表至少一行、
屏底的退出键在屏上——在 80×24 上逐件成立，快照钉着；勾的是这三件。

## 落地记录

### 让位收成一处：`src/session/draw/yielding.rs`

票面第二条是本票的要点。从前「让位」散在四处各让各的：`draw.rs` 的四个布局常量、
`config_width`、`footer_height`，以及 `main_pane` 里那一句 `Layout::vertical`。
四处都对，但**「谁先让」是跨块的事**，没有一处说得出整条次序。

新模块 `yielding`（`CONTEXT.md` 新加的那个词条就叫《让位》）收下**屏上那几块各占哪一格**
这一件事，模块文档上是两张表：

| 宽度不够 | 让的是 | 谁说了算 |
|---|---|---|
| 一 | **左栏**：先缩，缩到 `CONFIG_MIN_WIDTH` 以下就整个让掉 | `config_width` |
| 二 | 两张表**各按自己那个固定次序砍列** | `crate::session::columns` |

| 高度不够 | 让的是 | 谁说了算 |
|---|---|---|
| 一 | **屏底**按折出来的行数往下长，长到主区只剩 `MAIN_MIN_HEIGHT` | `footer_height` |
| 二 | **总览块一行不砍**——它有几行由它自己说了算 | `main_split` |
| 三 | **报告区吃剩下的**：宁可少画表，不少画总览 | `main_split` |

`shell` 从此只问一句 `panes(screen, expanded, 屏底折出来几行)`，拿回
`Panes { bottom, body, left, main }` 四格；`main_pane` 只问一句 `main_split`。
**块与块之间怎么让位，画法那一层再没有第二处算。**

**一格之内怎么再分仍归那一块自己**：展开那一副把自己那一格切成「钉住的抬头 + 正文」
（`report_pane` 里那一句 `Layout::vertical`）——那不是块与块之间的让位，本模块不收它，
两边的模块文档都点明了这一刀。

不在这里的两样也写进了模块文档：**屏底那一格里那三样谁先让**（说明那一行 →
要说的那句话 → 按键那几行）是一格**之内**的次序，仍在 `footer`；**砍列的次序**
仍在终端库外面的 `columns`，两张表各一份——本模块只说它排在左栏后面。

新词《让位》当场加进了 `CONTEXT.md` 的《会话》（`CLAUDE.md`《改 CONTEXT.md 的规矩》：
新词可以当场加）。已有词条一个字没改。

### 宽度那一让多了一个**底**

票面写着「先把左栏让掉（今天就有的退化）」。今天那一让**没有底**：
`CONFIG_WIDTH.min(total - MAIN_MIN_WIDTH)` 一路缩到一列，40 列的屏上因此留着一条
**10 列宽**的左栏——行行折成两三个字，一行取值都答不出来，而主区照旧只有 30 列。
两边都读不出东西，这不是「让」，是两边都没让成。

**这是票面之外的一次决定**（票面只说「先把左栏让掉」，没说加底）。
`CONFIG_MIN_WIDTH`（30 列）给它加了一个底：一行是「两格缩进 + 最宽 16 格的标签 + 取值」，
两条框线再吃两格，不到 30 列取值那一截一格不剩。**窄过它就整个让掉，主区吃满。**

| 屏宽 | 左栏 | 主区 | 变了吗 |
|---|---|---|---|
| 120 | 52 | 68 | 没变 |
| 80 | 50 | 30 | 没变 |
| 64 | 34 | 30 | 没变 |
| 60 | 30 | 30 | 没变（缩到底那一档） |
| 59 及以下 | **0** | 全部 | **变了**：从前是 1–29 列的窄条 |

**120／80／64／60 一格没动**，现存快照因此一张都不用为它重录。变的只有
**31–59 列**那一段，而那一段上从前没有一张快照。

### 抬头怎么截：Q147 收了

截法只有 `yielding::elided` 一处（交给 `columns::elide` 从中间省略——**与卷名那一列
同一副省略法**，屏上没有第二种省略号）。外面两个名字差的只是**两个角占不占格**：
`title` 给摆在**边框**上的那五个（左栏、总览块、报告区、预设栏、覆盖层），
`pinned` 给展开那一副**钉在格子里**的那一行。

80×24 上因此从 `┌执行 · 第 3/3 卷 · 还剩约 3m┐`（真值 `3m20s`，读起来完整而偏小）
变成 `┌执行 · 第 3/3 ⋯ 还剩约 3m20s┐`：**那个数一格不少，而截过的地方有记号**。

### 记号换成两种终端上一样宽的：Q154 收了

**本条的现状写错了**：`✓`(U+2713) 与 `✗`(U+2717) 在东亚宽度表上是 **Neutral**，
不是 Ambiguous。逐个问过之后真正歧义的只有三个：跳过那个 `–`(U+2013)、
`ABSENT` 的 `—`(U+2014)、`ELLIPSIS` 的 `…`(U+2026)。换成 `-`、`-`、`⋯`(U+22EF)。

判据立成了一条跑得动的规矩：`columns::width_is_stable(glyph)` ——
`width` 与 `width_cjk` 答得一样就是稳的。两张表各一条用例照着它问过全部记号，
`ELLIPSIS` 另一条。**添一种记号不过这一关就红**，不靠人记着。

**规矩的边界也写死了**：只管**表这一层自己造的**字形。尺寸那一格的 `×` 与判据那一串的
`·` 同样是歧义宽度，但它们出自 `crate::render`——命令行那一路印的是同一批格，
换它们是命令行输出的一次变动。那一半记进 **Q168**。

**spec 那张示意图跟着对不上了**：`.scratch/p3-session-legibility/spec.md` 第 255–256 行
的卷表示意图仍写着 `–     名侦探 05` 与 `—`。那是这一轮队列自己的 spec，
随队列一起收口；Q154 的处置里点明了这一处。

### Q147 — 总览块的抬头在窄终端上由终端库硬截，截出来的时长读起来像一个完整而偏小的估计

- **From:** 票 `p3-session-legibility/07`
- **Kind:** 路过发现的缺陷（本票把那几个数搬上抬头之后才够得着）
- **Where:** `src/session/draw/overview.rs` 的 `title`；`src/session/draw.rs` 的
  `TOO_NARROW_FOR_TWO_COLUMNS`（此刻在 `src/session/draw/yielding.rs`）；
  spec 的《Implementation Decisions》第十一条《窄终端》
- **现状:** spec 第五条把「这一趟是什么 · 走到哪儿 · 还剩多久」与收场那句话都摆在**边框的
  抬头**上，而抬头由 ratatui 硬截、没有省略号。80 列的屏上主区只有 30 列，抬头因此成了
  `┌执行 · 第 3/3 卷 · 还剩约 3m┐`——真值是 `3m20s`，截出来的 `还剩约 3m` 是一个**完整、
  而且偏小**的估计，屏上没有一处痕迹说它被截过。收场那一句同理：
  `收场 点名的卷都走过了 · 3 卷 · 用了 6m40s` 在那一档上只剩前半截，结局与耗时一起丢。
  合并之前这两样在**正文**里，截掉就是整段没了，不会读成另一个数。

### Q154 — 卷表的四种记号里三种是东亚歧义宽度，而对齐现在靠宽度吃饭

- **From:** 票 `p3-session-legibility/08` 的 `/code-review`（Standards 轴）
- **Kind:** 既有约定在新用法下露出的一处代价
- **Where:** `src/session/draw/table.rs` 的 `Mark::glyph`（`✓ ! – ✗`）与 `ABSENT`（`—`）、
  `src/session/columns.rs` 的 `ELLIPSIS`（`…`）；出处在 `src/wrap.rs` 的 `cells`
- **现状:** `✓`(U+2713)、`✗`(U+2717)、`–`(U+2013)、`—`(U+2014)、`…`(U+2026) 在 Unicode
  东亚宽度表上都是 **Ambiguous**。`wrap::width` 走的是 `UnicodeWidthChar::width`
  （不是 `width_cjk`），一律算**一格**。终端若按 CJK 配置（歧义宽度算两格），
  这几格实际占两格，而同一批记号里的 `!` 恒占一格——跳过那一行与隔离那一行的卷名列
  因此错开一格，整张表逐行参差。
- **Why it did not block:** 这套约定是仓库既有的（`crate::wrap` 那一头就是它，
  `width("·") == 1` 有用例钉着），本票没有引入它，也不该在这一票里单独换一套。
  换记号集又会与 spec 的《卷表》那张示意图对不上（`✓ ! – ✗` 是那里写死的四个字形）。
- **What this ticket actually did:** **把这条限制写进 `src/session/columns.rs` 的模块文档**
  《宽度一律是显示宽度》那一节，并指回这一条。记号集一个字没换。
  **新的不是这套约定，是「对齐」头一次成了屏上那一格存在的理由**——
  从前报告是散文，错一格看不出来。
- **Whose call:** 拍板的人（要不要改用非歧义字形，或者让 `wrap::width` 认一个「按 CJK 算」
  的开关；后者会波及折行与滚动量，不是画法一层的事）
- **处置：了结（`p3-session-legibility/13`）。** 先纠一处：**本条的现状写错了**——
  按 `unicode-width` 那张表逐个问过（`width` 与 `width_cjk` 答得一样就是稳的），
  `✓`(U+2713) 与 `✗`(U+2717) 是 **Neutral**、`!` 是 Narrow，**三个都不是歧义宽度**；
  四种记号里真正歧义的只有**跳过**那一个 `–`(U+2013)，另外两处是 `ABSENT` 的
  `—`(U+2014) 与 `ELLIPSIS` 的 `…`(U+2026)。
  **换的就是这三个**：`–`→`-`、`—`→`-`、`…`→`⋯`(U+22EF，两种终端上都是一格)。
  同时把判据立成一条可跑的规矩——`columns::width_is_stable`，两张表各一条用例
  （`every_glyph_this_table_makes_is_the_same_width_on_any_terminal`）加 `ELLIPSIS`
  那一条：**添一种记号不过这一关就红**。`wrap::width` 那一套约定一个字没动。
  **剩下的两格另立 Q168**：尺寸那一格的 `×` 与判据那一串的 `·` 出自 `crate::render`，
  命令行那一路印的是同一批格，不归画法这一层换。
  spec 的《卷表》示意图（第 255–256 行）上那两个字形因此与实现对不上了——
  那是这一轮队列自己的 spec，随队列一起收口。
