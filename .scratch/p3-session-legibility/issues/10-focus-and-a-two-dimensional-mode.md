# 10 — 焦点与两维模式

**What to build:** 会话的模式从一维拆成**两维**：

- **这一趟在哪个阶段**：没跑过 / 跑着 / 停在决策点上等答话 / 收场了
- **眼下在看什么**：左栏浏览 / 左栏摊着取值 / 编辑一行 / 报告区 / 展开着 / 预设栏 / 覆盖层

拆了之后：`⇥` 在左栏与报告区之间切焦点；**报告区有自己的光标**，`↑↓` 选一卷；
而且**跑着的时候一样能用**——几十分钟的一趟里想回头看第一卷，不必等它跑完。

**跟随**：跑着时卷表默认停在最后一行（跟着最新收摊的那一卷）；光标一动就停，
屏上说一句「跟随停了」；`g` 回到跟随。跟随是卷表**独有**的状态，别处的视口仍是
「算出来的」。

`⇥` **按状态分派，不冲突**：左栏 ⇄ 报告区切焦点；编辑一行时是逐层补全；
展开着时是换下一卷。

`p1-session/10`、`11`、`14` 先后三次判过「不拆」，依据都是「本票不需要」。
**这一张需要**，推翻的理由与代价落成 `docs/adr/0017-…`。

## 落地记录

### 两维叫什么，那张按键表怎么按两维查

`src/session/state.rs`：

```rust
pub enum Stage { Fresh, Running(Instruction), Deciding(Instruction), Ended }
pub enum Focus { Config, Editing(Edit), Report, Expanded(Expansion), Picking(Picker), Valuing(Values) }
```

`Mode` 那个枚举没了，它的六个取值分到了两维上。`Session` 上从一个字段变成三个：
`stage`、`focus`，外加**跟随**（`follow: Follow`，见下）。

**那张表先按焦点分岔，落到哪一支之后再按阶段分**（`Session::action`）：

| 焦点 | 按阶段分吗 | 谁答 |
|---|---|---|
| 左栏 | **分** | `Session::config_action` → 浏览那一副 / `stage_action` |
| 报告区 | **分** | `report_action` → 自己那四个键，剩下的交 `stage_action` |
| 展开着 | **分** | `expanded_action` → 滚动与换卷，剩下的交 `stage_action` |
| 编辑一行 · 取值栏 · 预设栏 | **不分** | `editing_action` / `valuing_action` / `picking_action` |

后三个不分**不是漏了一条**：它们只从左栏进得去，而跑起来之后左栏一个改动键都不派
——**两维不是笛卡儿积**（ADR 0017 决定第 8 条）。

**阶段那一维派得出的那几个键只有一处**（`stage_action`：按停、答话那三个、退出会话）。
「三层只读由阶段那一维说了算」因此是结构上成立的：那三块自己一个改动键都没有，
而这一处也没有——**焦点落到报告区不解锁任何一格**。

### 决策点上那一卷进表了，展开的索引换成了什么

**进了**（`p3/08` 就已经给它一行，本票让光标停得上、也展得开）。展开的索引从
「报告上第几卷」（`usize`）换成 `src/session/live.rs` 的：

```rust
pub enum Volume { Settled(usize), Summarized }
```

`Settled` 是收摊了的第几卷，`Summarized` 是**决策点上攒着的那一份**——它不在
`Report::volumes` 里，一个下标根本指不到它，而 `p2-loose-ends/08` 记着
**不许摊开上一卷冒充它**。这一改就是那条硬约束的解法（spec 的《焦点与两维模式》第五条）。

配套的三样：

- `Live::volumes()`——**表上停得住的那几卷**，按表上的先后（唯一出处）；
- `Live::volume(at)`——那一卷此刻对着哪一份报告；
- `Live::nearest(at)`——指不着就落到最后一卷上。**决策点上那一卷收摊之后光标跟着它走**
  就是这一条：那一刻它正是收摊了的最后一卷（用例
  `the_volume_waiting_at_the_decision_point_is_one_the_cursor_can_stand_on` 钉着）。

`Expansion` 跟着掉了一格：`volumes`（进来那一刻记下的「有几卷」）没了——
跑着的时候也展得开，而报告那时还在长，记下来的那个数下一卷收摊就不作数了。
要它的两处（换一卷转一圈、抬头上那个「第几/共几卷」）各自现问 `Live`。

**展开的是光标停着的那一卷**，不再恒是第一卷；视口对到那一卷的抬头上（`opens_at`），
与换卷那一下同一条。

### 跟随：记的是光标停在哪一卷，不是滚到哪儿了

```rust
pub enum Follow { Latest, Stopped(Volume) }
```

它挂在 `Session` 上，**不装进 `Focus::Report` 里**：`⇥` 切回左栏再切回来时它还在原处
——切焦点不是「重新开始读」。

**视口一格没改**（`src/session/viewport.rs` 只动了文档那张表）：跟随着的时候
报告区那一格仍旧钉在**末行**（与从前那一副逐格相同——表底下的失败页与末尾那几小结
跟着一起看得见）；跟随停了才改成跟着光标那一行走。`CONTEXT.md` 的《视口》那句
「滚动量是算出来的，不是记着的」因此一个字都不用改。

屏上两处说它：报告区那一格的抬头说**状态**（`报告 · 跟随停了`），屏底那一行摆**键**
（`g 回到跟随`）——与展开那一副「第几卷在抬头上、键在屏底」同一条分法。

### `⇥` 的三个意思，以及屏底那一行怎么拼

`⇥` 按状态分派，三个意思一个都没挤掉：左栏 ⇄ 报告区**切焦点**（`Action::Focus(Pane)`）、
编辑路径时**逐层补全**、展开着时**换下一卷**。一趟都没跑过时它在左栏上不派——
报告区里连一卷都没有，切过去无事可做。

屏底那一行的形状统一成**「这一块自己的键在前，阶段那几个跟在后面」**：

```
 报告区 · ↑↓ 选一卷 · ⏎ 展开 · g 回到跟随 · ⇥ 回配置 · 跑着…… · s 停（按一次收尾，再按一次中止）· Ctrl-C 退出会话（当前卷中止，盘上不留半卷）
```

左栏那一副在跑着与等答话时同形（`⇥ 报告区 · 跑着…… · s 停……`）。
按停与答话那两副措辞**一个字没改**，仍只有 `running_prompt` 与 `deciding_prompt` 两处。

### 反白落在哪一层

**没有落进 `draw/paint.rs`**：那一层的模块文档把反白与加粗、压暗一起划在四种语义色之外
（「三样各自留在用它的那一块里」），因此卷表这一处的反白就写在 `draw/report.rs` 里
（`highlighted`：给折好的那几行打一个 `REVERSED` 的补丁，语义色照旧上）。
`paint.rs`、`columns.rs` 两个模块**一个字节都没动**。

屏上仍旧**同一刻只有一处反白**：左栏那一处多了一个条件——焦点真落在左栏上、
而且三层此刻改得动（`Focus::Config | Focus::Editing` 且 `!stage.read_only()`）。

- **`Volume::Summarized` 是个「位置」，不是身份**（high，两条同一个根）。停在决策点上那一卷上
  之后按 `x`，那一卷收摊；**下一卷停到它自己的决策点上时，「攒着的那一份」这个位置归了它**——
  光标会从上一卷悄悄跳到下一卷身上（屏上还写着「跟随停了」、屏底还许着「报告再长光标也不动」），

### Q72 — 一趟跑着的时候展不开，而报告那时正在长

- **From:** 票 `p1-session/11`
- **Kind:** 确实拿不准的单项
- **Where:** `src/session/state.rs` 的 `Mode`、`running_action` 与 `expanded_action`
- **Why it did not block:** 票面没说展开在跑着的时候要不要有。真要有的话，
  `Mode` 就得拆成两维——「正跑着」与「正展开着」要同时成立——而那正是
  `p1-session/10` 在 Q69 上判过不拆的那件事。跑着时还有第二重代价：
  那一刻按得动的只有 `s`（按停），而展开态要吃掉上下左右与 `⇥`，
  按停那个键在一屏满是滚动键的提示条上会被挤没。
- **What this ticket actually did:** **展开只从浏览进得去。** 跑着时 `e` 派
  `Action::Ignored`（`running_action` 那一条 `Key::Char(_)` 收着它，
  `which_keys_do_what_in_which_state` 第六段逐个问过）。理由写进
  `CONTEXT.md` 的《会话》：报告那时还在长，而那一刻按得动的只该有停。
  代价是几十分钟的一趟里想回头看第一卷的逐页，得等它收场——而收场之后
  报告一行不少，展开看到的与跑完再看是同一份。
- **Whose call:** 拍板的人（跑着的时候要不要能展开，也就是 `Mode` 要不要拆成两维）
- **处置：** 待处理。**Q64 剩下的那一半也在这里**：跑着的时候报告区仍旧只滚到底、
  翻不回去，而翻回去落在展开那一副上——两件事同进同出，拍这一条就一起拍了。

  **`p1-session/14` 查过能不能一起收，结论是不能，理由多了一条硬的。**
  那张票加的「等答话」（`Mode::Deciding`）看上去正是「跑着但要收键」的那一刻，
  而且管线此刻**真停着**——报告不在长，本条头一条理由在那一刻不成立。
  但第三条理由挡在前面，而它不是权衡、是次序上的不可能：**展开数的是
  `Live::report().volumes`，而决策点上要看的那一卷根本不在里面**——它停在
  `Live::summarized` 上，要等答完话、那一卷收摊了才进报告（见 Q52 的处置）。
  在决策点上按展开，摊开的会是**上一卷**的逐页，而不是眼前正要拿主意的这一卷。
  真要收，得先把展开的索引从「报告上第几卷」改成一个认得出这两处的东西，
  而那一步会把 `Expansion::volumes`（进来那一刻记下的数）一并牵动。
  另外两条代价照旧：`Mode` 仍要拆成两维（Q69 判过不拆），
  而展开态要吃掉上下左右与 `⇥`，答话那两个键（`x`／`s`）在一屏满是滚动键的提示条上会被挤没。
  `14` 因此把等答话做成了一个**平的状态**（`Deciding` 与 `Running` 并列，不是 `Running` 上的开关），
  `Mode` 仍是一维的——与 `10`、`11` 拿的那一条同一个形状。

- **处置（本票）：了结。** 三条理由逐条答过：
  1. **`Mode` 拆两维**——就是本票做的那件事，理由与代价落成 **ADR 0017**
     （`p1-session/10`、`11`、`14` 三次判「不拆」的原话都在里面，逐条答过它们各自要防的事）。
  2. **展开的索引指不到决策点上那一卷**——换成 `live::Volume`（收摊了的第几卷 /
     攒着的那一份），`Expansion::volumes` 那个「进来那一刻记下的数」跟着掉了：
     跑着的时候也展得开，记下来的数下一卷收摊就不作数。
  3. **「展开态吃掉上下左右与 `⇥`，按停／答话那几个键会被挤没」**——**不成立**：
