# 07 — 总览块：横条与摘要合成一块，钉住

**What to build:** 主区顶上两条横条（各占三行、各一层边框）与新的摘要合成**一块**，
整块**钉住**，只有下面的报告在滚。五行：

```
┌ 执行 · 第 5/20 卷 · 还剩约 14m ────────┐   ← 这一趟是什么 · 走到哪儿 · 还剩多久
│ 总体 [=========>        ] 5/20 卷      │
│ 本卷 [=====>            ] 第二遍       │   ← 在走哪一遍
│ 完成 4 卷   跳过 1 卷                  │   ← 结论行
│ 出事 隔离 1 卷 · 失败 3 页              │   ← 出事行，没事就不出现
```

要修的毛病有两处：顶上九行里有一半是重复的（摘要第一行几乎就是全局条本身），
而屏上没有一处回答「**这一趟到底怎么样**」。

**结论行与出事行的内容随这一趟是什么而变**，而「是什么」手上已经有，不必多一个开关：

- **试算**：结论行给判定分布（`6 卷 2bit+FS   2 卷 4bit+FS`），出事行给要注意的
  （特例页几张 · 宽溢出几页 · 几何门不成立几卷）。
- **执行**：结论行给完成与跳过几卷，出事行给隔离几卷 · 失败几页 · 卷级失败几卷。

**出事行一条都没有时整行不出现**，那一行让给下面——与报告末尾那几小结同一条规矩。

`p1-session/09` 那条「三段各占一格，免得报告长起来把进度条顶出屏外」由**钉住**接住。

## 落地记录

### 一块，不是三段

`draw/bars.rs` 改名 `draw/overview.rs`（`git mv`，`p3/01` 的分法照旧：一块一个模块），
`main_pane` 从切三格改成切两格：

```rust
pub fn main_pane(frame: &mut Frame, area: Rect, session: &mut Session, live: Option<&Live>) {
    let top = overview(live, session.stopping(), session.deciding());
    let [pinned, report] =
        Layout::vertical([Constraint::Length(top.height()), Constraint::Min(0)]).areas(area);

    frame.render_widget(top.draw(), pinned);
    frame.render_widget(report_pane(session, live, report), report);
}
```

**钉住就是这一行 `Layout::vertical`**：总览块与报告区各占主区的一格，报告在它自己那一格里
滚（默认那一副滚到底、展开那一副按键翻），**一行都推不动上面这一块**。
`p1-session/09` 那条「三段各占一格，免得报告长起来把进度条顶出屏外」由它接住——
三段合成两块，钉住这件事一格没让。做成「跟着滚但滚得慢」的那条路一步都没走。

`the_overview_block_stays_put_while_the_report_scrolls` 钉的正是它：展开一卷、连按四下 `↓`，
每一帧的**头几行逐格比**，与总览块单独画出来的那一张一模一样；同一条用例还顺手确认
**报告真的在滚**（四帧里报告那一截不全相同），否则这一条什么都没证明。

### 它有几行由它自己说了算

```rust
pub(super) struct Overview {
    title: String,      // 边框上那一行
    rows:  Vec<String>, // 框里那三到四行
}
```

**先算出来再画**，因为「它有几行」要在分格子之前答得出：出事行不在场时那一行让给报告区，
而 `Layout` 要先拿到那个数。`height()` 与 `draw()` 因此读同一份 `rows`——
算与画不许各算各的。

| 这一趟 | 高 |
|---|---|
| 还没跑过 | **三行**：抬头 `总览` 加一行 `还没跑过。t 试算 · x 执行`（走 `START_KEYS`，措辞一处） |
| 跑着，出了事 | **六行**（抬头 + 全局 + 本卷 + 结论 + 出事） |
| 跑着，没出事 | **五行**（出事行不画） |
| 收场了，出了事 | **五行**（本卷那一行不画） |
| 收场了，没出事 | **四行** |

**让得出去的有两行，让出去的都归报告区：**

- **出事行**——票面点名的那一条：一条都没有就整行不出现。
- **本卷那一行**，只在**收场之后**：那时再没有「本卷」可说，而这一撤不会让屏跳
  （这一趟已经走完，这一块不会再变）。**卷与卷之间它是空的、行不撤**：撤了的话
  每过一卷下面的报告都要跳一格，而「编一条横条上去只会让人以为它卡住了」那条理由
  原样从 `volume_bar` 搬过来。

（收场之后那一行永远空着，是评审 Spec 轴揪出来的：80×24 上白丢一行报告。）

`MAIN_MIN_HEIGHT` 从 `BAR_HEIGHT * 2 + 3` 换成 `OVERVIEW_HEIGHT + 3`，**数没变，仍是 9**：
总览块最高那一副六行，报告区至少一行加上下两条边。让的次序照 spec 的《窄终端》——
屏矮下来时**先让报告区，总览块不砍**。

### 抬头

`总览` 只在还没跑过时出现；跑起来之后它是**这一趟是什么 · 走到哪儿 · 还剩多久**：

| 此刻 | 抬头 |
|---|---|
| 跑着 | `执行 · 第 3/3 卷 · 还剩约 3m20s` |
| 按过停 | `执行 · 第 3/3 卷 · 还剩约 3m20s · 收尾中`（走 `stopping_name`） |
| 等答话 | `试算 · 第 1/1 卷 · 等你拿主意`（顶掉「还剩多久」） |
| 收场了 | `收场 点名的卷都走过了 · 3 卷 · 用了 6m40s`（走 `render::outcome`） |
| 没做成 | `这一趟没做成：处理范围为空：至少点名一个卷`（库那一侧的原话） |

- **措辞出处一个没动**：按停那一级走 `footer::stopping_name`（屏底那一行用的是同一个，
  用例照旧两头对着问）；「等你拿主意」逐字照 `p1-session/14` 立的那一句搬过来；
  收场那一句走 `crate::render::outcome`；「用了」那个数走 `Live::overall()`——
  收场之后它是**库交出来的 `Report::elapsed`**，扣掉了在决策点上等人的那几分钟（Q41）。
  `the_overview_title_says_how_the_run_ended` 把 `report.elapsed` 设成 400 秒、
  会话自己那块表是 300 秒，屏上出的是 `用了 6m40s`。
- **等答话顶掉「还剩多久」**（从前那一格是整条换成「整趟 · 等你拿主意」，同一件事）：
  那一刻横条一动不动，报一个数出来说的就成了「用户还要想多久」。
  它同样顶掉按停那一级——与从前逐字相同（等答话是此刻更要紧的那一件）。
- **这一趟是什么走 `Live::mode()`**，不多一个开关（票面原话）：试算在决策点上答出第一个
  继续之后它就是执行了——那一卷真写了出去，而结论行与出事行说的正是「写出来的是什么样」。
  两个词与屏底那两个键同一批（`START_KEYS`：`t 试算 · x 执行`）。

### 结论行与出事行

两行都按 `Live::mode()` 分岔，**数与措辞跟报告末尾那几小结走**，不在这一层另数一份：

| | 试算 | 执行 |
|---|---|---|
| 结论行 | `判定 1 卷 2bit+FS · 1 卷 4bit · 1 卷 跳过` | `完成 1 卷 · 跳过 1 卷` |
| 出事行 | `出事 特例页 2 张 · 宽溢出 1 页 · 几何门不成立 1 卷` | `出事 隔离 1 卷 · 失败 1 页` |

- **判定分布按档分组，多的排在前面；一样多的按名字排**——屏上因此不会因为收摊次序
  而跳位置。
- **一卷收摊的都没有时两支都给一个破折号**（`NOTHING_SETTLED`，一处出处）：那时没有分布、
  也没有完成与跳过可说，编一个「0 卷」是在说一件没发生的事。**拒绝执行的那一趟走的正是
  这一支**——它一步都没开工，而抬头已经说了它没做成
  （从前只有试算那一支有这条门，两支自相矛盾；评审 Spec 轴揪出来的）。
- **一卷的基准档怎么称呼只有一处**（`base_name`），四支照卷级判定说的写、不编第二套说法
  （spec 的《卷表》：`--per-page` 与覆盖写「逐页」「覆盖 4bit」）。
  一张灰度页都没有的卷自成一档「无判定」——把它并进别的哪一档都是在说一件没发生的事。
- **隔离的卷算进「完成」**：它是处理过的卷，交出来了，只是带着坏页；「它出了事」由出事行说，
  两处不许各说各的。
- **出事行零就一个字都不说**（`count()` 那个小函数一处答完），三样全是零时**整行不出现**，
  那一行让给报告区——与报告末尾那几小结同一条规矩。
  `the_trouble_row_is_gone_when_nothing_went_wrong_and_the_report_takes_that_row`
  两头都问：这一块从六行缩到五行，**同一屏上报告那一格的上框线跟着往上挪一行**。
- **出事行的数与措辞与报告末尾那几小结对得上**，
  `the_trouble_row_counts_what_the_report_tail_counts` **两头对着问**：同一份报告，
  `隔离 1 卷`／`失败 1 页`／`卷级失败 1 卷` 三句在出事行与 `crate::render::tail`
  里逐字相同。**没有合成一个函数**：那两小结是**成句的**（隔离那一句还要说清失败页在输出里
  是什么样），而这一行是一串数——共用得先把句子拆成词，而措辞只许有一处出处（ADR 0016）。
  这一条用例就是那一处出处的闸门：改了一头，它当场红。
- **失败页数的是收摊了的卷**，因此比报告区晚一整卷（**Q148**）：出现的当场那几条
  在报告区已经看得见（`render::failing_pages`）。换成事件流那一份就有了两个出处。

### 横条的样子仍只有一个出处

```rust
const BAR_WIDTH: u64 = crate::BAR_WIDTH as u64;
```

`p3/01` 原样搬进 `draw/bars.rs` 的那一行，这一票原样搬进 `draw/overview.rs`——
**这一层没有长出第二个字面量**。`bar()`／`spell()`／`pass_name()` 三个**函数**
一个字节没改；用例只多了钉住出处的那一句——`the_bar_fills_from_empty_to_full` 头一行
`assert_eq!(BAR_WIDTH, crate::BAR_WIDTH as u64)`。

**当前卷那一行的卷名与遍数摆在横条前面**（与从前那一格逐字同序）：横条有 30 格加两个方括号
那么宽，摆在前面就把这两样顶到 80 列的屏外——那一档上主区只有 30 列，
而「在跑哪一卷的哪一遍」屏上再没有第二处说得出（`p1-session/09` 的验收）。
两行的横条因此对不齐，那是认下的代价：对齐是好看，这两样是内容。
（一版曾把它们摆在横条后面，`TOO_NARROW_FOR_TWO_COLUMNS` 上两样全没了；
评审 Spec 轴揪出来，已改回。）
