# 03: 展开一卷看得到各阶段花了多久

**What to build:** 展开一卷时，除了逐页那一副，另给这一卷**各阶段的耗时分布**——解码、转灰、裁边、缩放、判据、量化、编码、写出各占多少。数据今天已经在按阶段记着，屏上一处都不显示；这一票只是把它接出来，让「一趟跑得慢」答得出「慢在哪一步」。

**Blocked by:** None (can start immediately)

**Status:** wontfix

- [ ] 展开一卷看得到阶段耗时分布
- [ ] 一个具体秒数都不进快照用例——那是机器快慢，不是被测代码的性质
- [ ] 走过的阶段有数、没走过的阶段是零（试算没有编码与写出、跳过的卷两遍都没走）
- [ ] 阶段耗时是**各线程墙钟之和**，不是墙上过去的时间，措辞上不许混
- [ ] 卷表那一副不受影响，计时仍旧不进它渲染出的文字

## Comments

**判为 `wontfix`。**（2026-09-11）两条理由，各自单独就够：

**一、票面前提「数据今天已经在按阶段记着」不成立。** `cost` 那一层只在 `--features profiling` 下记
（`Cargo.toml`；特性关着时 `cost::stage()` 就是 `work()` 本身），而且是**进程级全局原子表**，
不按卷分——没有任何一卷级的阶段数据。「接出来」接不到东西，要做得先按卷加插桩。

**二、它正面撞三处明文禁令。** `p0-hardening/13` 明禁「把解码/缩放/判据/编码的分阶段计时塞进 `Report`」，
`src/cost.rs` 模块文档「两者一个是产品输出，一个是量具，不许合流」，`CONTEXT.md`《阶段》「只活在一个
feature-gated 的量具里……只印到 stderr」。禁令的理由今天仍成立：量具的数是各线程墙钟之和，是记账，
不是不变量（spec 自己第 152 行也这么说）。要推翻它得先立一条决定答「为什么现在要合流」——那是 ADR 级的事，
不是一张「接出来」的票。

spec story 5「一趟跑得慢时知道慢在哪一步」的需求是真的，**出口已经存在**：`profiling` 构建下 `cost`
印到 stderr 的剖面。记停车场 **Q624**。

spec 第 82 行那句「`cost` 那一层今天已经在按阶段记纳秒……只是把已经在算的东西接出来」**写下时就假**，
已订正。
