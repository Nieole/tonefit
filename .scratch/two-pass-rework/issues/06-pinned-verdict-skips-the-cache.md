# 06: 判定被覆盖顶死时，参照不必等到第二遍

**What to build:** 位深与抖动两维都被点名（或被面板灰阶数、几何门裁到只剩一个候选）时，第二遍要用的那一档在**开卷之前就已经定死**——判据说什么都不改结果。这种趟数上参照没有必要活到第二遍：量化与编码第一遍当场就能做完，缓存那一趟往返整个省掉。

要与既有的「覆盖了判定也照求判据曲线」分清：那一条是有意的（试算要说得出你点的那一档判据是多少），它只覆盖**判据求值**，不覆盖缓存这一趟往返。

**Blocked by:** 04

**Status:** resolved

- [x] 两维都被顶死的那一趟，参照进缓存次数降到零
- [x] 判据曲线**照旧求**，报告里各候选的判据值一个不少
- [x] 输出字节与顶死之前逐字节相同
      —— 验过：十二处校验和落地前后逐字对上（表见下）。但**这条验收在套件里没有长期守卫**：
      黄金快照写死不点覆盖项，从来没盖过这条路（**Q544**），那十二处是一次性的证据。
- [ ] 峰值内存不再随卷长线性涨
      —— **打不了勾，照实留空。**这一格是 spec 的 story **12**（P-C）的账，不是本票的：
      缓存照旧攒满整卷，攒的从参照换成编好的字节，**系数小一截、仍是 O(卷长)**
      （夹具上 18240 → 5828 字节）。要让它不再线性得让写出不再等全卷，
      而那条不变式被中止与决策点押着，spec 的 Out of Scope 头一条明写「真单遍」不做。
      本票买到的是「参照一张都不在缓存里过夜」，它由 `cached_references == 0` 与
      `cache.stored` 等于写出字节和两条断言钉着。详见停车场 **Q538**。
- [x] 只裁到一个候选的那几种来路都算数：显式点名两维、面板灰阶数裁、几何门裁
      —— **谓词对是谁裁的一视同仁，三条各有一条用例，各自会单独红。**但票面这三条不是并列的：
      **几何门裁不出一个顶死来**。抖动那一维只有 `--dither` 裁得动（面板灰阶数够不着它，
      而门是**页**的事实、碰卷之前没有页可判），**因此每一趟顶死都点着 `--dither`**；
      门在这一问上的作用是决定门不成立那一组**在不在**。一个覆盖项都没点而候选只剩一个的
      那一种（面板裁到只剩 1bit ＋ 门不成立）**按设计不算顶死**——那一档仍是判出来的，
      而且它的理由要等整卷汇总才定得下。详见 **Q540** 与 ADR 0005 那一节。
- [x] 没被顶死的趟数一切照旧

## 落地记录

### 票面那条界一格没碰

「覆盖了判定也照求判据曲线」是有意的（试算要说得出你点的那一档判据是多少），
它只覆盖**判据求值**。本票收的只有**缓存那一趟往返**：存参照 → 取回来 → 换成字节。
`candidate_scores` 一步没少，报告里 `PageBranch::Gray::scores` 那一格照旧摆着各候选的判据值
（顶死时候选只剩一个，那一个的值一格不少），`tests/counters.rs` 拿它当断言。

### 上游 `04` 交下来的东西，本票用得上

`04` 的《落地记录》对 `07` 写的是「这两个数一个都用不上」，对 `06` 写的是
「`cached_references` 钉得住，`a_pinned_verdict_still_caches_every_reference_today`
钉的正是今天不为零那个事实」。**同一张上游票，两个下游一空一实**——本票开工第一件事
就是核这一句，核出来是实的，那条既有用例（别人写的、不迁就本票）就是红的起点。

### 三条来路核出来是「谁裁位深 × 谁裁抖动」

票面写「两维都被点名（或被面板灰阶数、几何门裁到只剩一个候选）」。核下来：
候选集是两维的全积，要成单例，**抖动那一维必须先被裁到 1**，而面板灰阶数永远裁不动抖动
——它只裁位深（ADR 0003）。裁得动抖动的只有 `--dither` 与几何门（ADR 0007）。
三条来路因此各是一种组合：

| 来路 | 参数 | 谁裁位深 / 谁裁抖动 | 走 `pinned_up_front` 哪一支 |
|---|---|---|---|
| 显式点名两维 | `--bit-depth 2 --dither off` | 覆盖项 / 覆盖项 | `Ok(broken)`，两组答案相同 |
| 面板灰阶数裁 | `--gray-levels 2 --dither off` | **面板** / 覆盖项 | **同一支**，但 `--bit-depth` 一个都没点 |
| 几何门裁 | `--bit-depth 2 --dither fs` | 覆盖项 / 覆盖项（门决定另一组**在不在**） | `Err(_)`——门不成立那一组是一条拒绝 |

**头两条走的是同一支**（`/code-review` 的 Spec 轴订正了本记录先前那句「各走不同分支」，
那句是假的）。**但三条仍旧互不相遮，而且是构造上的**（停车场 Q521 那条教训的正面回答）：
判的不是「走哪一支」，是**每一条各自会被哪一种写错的谓词放过**——
写成「两维都被点名」，只有第二条红；只认「两组答案相同」、丢掉 `Err` 那一支，只有第三条红。
三条各死在一种错法上，**没有一条靠另外两条兜着**。
外加一条对照组（只点 `--bit-depth 2`，其余页那一组的门开着、抖动还有得判）钉住
「谓词别放得太宽」那一面，一条试算用例钉住「试算不在其内」那条界。

**第三条那个名字要小心读。** 它叫「几何门裁」，而门裁掉的**不是**那个单例——
`--dither fs` 才是。门在这一问上做的是让门不成立那一组整个成为一条拒绝，
`pinned_up_front` 因此走得到 `Err` 那一支。**几何门单独裁不出一个顶死来**，
理由与那一种「一个覆盖项都没点」的形态是同一条，见 Q540 与 ADR 0005 那一节。

**「一个覆盖项都没点而候选只剩一个」按设计不算顶死**（`decide::decide` 的文档明写：
那一档仍是判出来的，理由分得清报告才解释得了它）。票面那句因此该读成「各自都得与一个
覆盖项合用」，记 **Q540**。

### 改了什么

**`pinned_up_front` 一个字没改。** 它早就答得出这一问（`12` 号票为滚动窗口写的），
本票只是让第二个消费者用上它：从前那个答案只决定**窗口开不开**，现在它还决定
**那一格缓存里装什么**。

- `src/cache.rs` 新开一个入口 `PageCache::insert_encoded(&mut self, encoded: Vec<u8>, reference: &GrayImage)`。
  **不并进 `insert`**——`references()` 的文档早就写死「这个数只数参照，缓存改存别的东西
  那条路要另开一个入口」，本票把那句话兑现了。`raw`（压缩前）照旧按参照的像素数记：
  那一格说的始终是「这一卷有这么多像素过手」，与参照有没有在缓存里待过无关。
- `src/lib.rs` 新增 `pinned_for_the_first_pass`（顶死那一档 ＋ **只在照做那一遍**）与
  `pinned_verdicts`（对账用的那一份逐页判定）。**「只在照做那一遍」这条界是本票划的，
  票面没写**（票面第 1 条不带模式限定）：它照 `Window::open` 那条界抄的，代价记在 Q537。
  名字取 `pinned_for_the_first_pass` 而不是 `pinned_ahead`，是因为后者与既有的
  `pinned_up_front` 在英文里是近义词，同一个文件里两个名字读不出分别（审查指出）。
- **`Compute` 上那两个可空字段收成一个枚举 `Settles`**：`AfterTheVolume` / `InTheWindow` /
  `UpFront`。这一处照 `07` 号票的形状办——「窗口与顶死那一档不可能同时在场」从一条
  **要去两处对**的约定，变成一个表示不出那个组合的类型。`Window` 因此**掉了一个字段**
  （`pinned`），`Windowed::queue` 掉了一个参数，`rolls` 那一行少了一半条件，
  窗口里那句「覆盖项顶掉了判定」的分支整个不在了——顶死的那一趟一页都进不到窗口。
- `Compute::gray_page` 分两支：顶死那一支当场 `decide` → `gray_bytes` → `insert_encoded`；
  另外两支照旧压参照 `insert`。
- `FirstPass::rolled` 改名 `settled`：它现在装的是**两条**提前编好字节的路各自那份判定，
  叫 `rolled` 就是假话。那条既有的 `debug_assert!`（第一遍编字节用的档 ＝ 汇总定的档）
  因此**顺带盖住了新那条路**——它是「输出字节不变」在类型之外的第二道保险。

### 输出字节逐字节相同：证据

`tests/golden.rs` **按 `--no-metadata` 跑**，验的正是像素那一侧——它一个字节没动、
一次都没有显式接受过重录，那是这条验收长期留得下的担保。**但它盖不到本票动的那条路**：
`golden.rs` 的 `request()` 写死 `bit_depth: None, dither: None, per_page: false`，
七个卷一个都不点覆盖项——快照盖住的是**默认那条路**。它没红，在这条路上不是证据，
是它根本没看。**那是黄金快照的一处覆盖缺口，不是本票的问题**：本票走了之后它照旧缺着，
记 **Q544**（与 `mr/07` 的 **Q473** 是同一类，两条撞的是同一件事——
「黄金快照盖住的到底是哪几维」从来没人系统答过）。

### 峰值内存那一格

**照实留空**，理由写在票面那一格旁边，详见 **Q538**。一句话：本票把缓存里躺的东西
从参照换成了编好的字节（夹具上 18240 → 5828，3.1 倍），**系数降了，量级没降**；
「不再随卷长线性涨」要写出不再等全卷，而 spec 明写不做。
换上的那条断言是 `cache.stored` 恰等于写出去那几页的字节和——那才是本票买到的东西。

### 用例落在哪条接缝上

全部落在 spec 点名的 `run(Request) -> Report` 上，一条私有函数都没测。
`tests/counters.rs` 从**九条**变成十三条（`04` 号票的记录写的是七条，`05` 之后是九条）：原来那条 `a_pinned_verdict_still_caches_every_reference_today`
（名字在本票之后就是假话了）换成三条来路 ＋ 一条对照组 ＋ 一条试算界，另加一个共用的
`assert_the_pinned_volume_never_cached_a_reference`。

### 停车场

新记 **Q537–Q546** 十条：顶死的试算预告的缓存用量与照做不再相等（Q430 的第二处，Q537）；
票面「峰值内存」那一格在本票范围内打不了勾（Q538）；「续做：参照还在缓存里」那句话
**在本票之前就假了**、按规矩记着不顺手改（Q539）；票面把「几何门裁」列为一条来路而
一个覆盖项都没点时它按设计不顶死（Q540）；报告里那一行缓存用量在顶死那一趟变小了（Q541）；
量化与编码从第二遍那一段挪进第一遍那一段（Q542）；
以及 **Q383 预告的「两个数分家」提前到本票发生**——`12` 号票之后 `cache.pages` 与
`cached_references` 其实仍旧恒等（`insert` ＋ `replace`，参照照记），
真正分家的是 `insert_encoded`（Q543）；以及**黄金快照里一个顶死的卷都没有，那条路它从来没盖住过**
（Q544，与 Q473 同类）；以及 `pinned_up_front` 那个 `Option<Option<Candidate>>` 三态
**正是本票新造的 `Settles` 的形状，却建在下游**（Q545，审查指出的反讽）；以及**抄来的数比估来的数更危险**——本票《落地记录》里那个
从 `04` 抄来的「七条」（Q546，与 Q510 同族）。Q383 原文一个字没动。
