### 一、量了什么、怎么量

三批脚本都在 `.tmp/16/`（不入库，要点如下，照着能再跑一遍；三批各占派活时的一根接力棒，即一趟宽跑）。共用一个 `run1`：输出到空目录（幂等不命中），
进程墙钟取 `$EPOCHREALTIME` 之差，量 `.cbz`（目录卷是散页）的字节与图片条目数，量完即删；报告落 `log/<标签>.txt`，
stderr（`profiling` 那张剖面）落 `.err`。三批全部 `setsid` detached、按 `EXIT=` 读。

- **体积那一批**（`volumes.sh`）：新代码 `cf6947a`，`cargo build --release --features profiling`，`--profile kobo-libra-2`，
  几何一个开关都不加。棋魂 9 趟（默认逐页、`--envelope`、七档 `--bit-depth N --dither off|fs`，8bit 那一趟加 `--gray-levels 256`），
  再 area / bilinear / hamming / bicubic 各两趟（2bit+FS、8bit）；改革之獸 4 趟（默认、`--envelope`、2bit+FS 的 lanczos3 与 area）；
  画集、哆啦A梦、JOJO 各两趟（默认、`--envelope`）。27 趟全 `rc=0`。
- **卷级扫描那八卷**（`scan.sh`）：`--profile boox-poke6 --dry-run`，`--envelope` 一趟、默认一趟，八卷一次点名。
- **吞吐那一批**（`throughput.sh` + `throughput2.sh`，机器空着）：施测条件全在《第三批：同一台机器上两版代码，翻默认之后快了多少》那张表里。
  第一趟脚本里旧代码在棋魂、哆啦A梦、N和S 上没跑成——**不是失败，是 `be1018f` 那时还不认这几种输入形态**：
  `.zip` 它不收（只认 `.cbz`），目录底下的 `.cbz` 它不各自当卷（喂整目录得到「0 页 + 56 个透传文件」）。
  补跑 `throughput2.sh`：两份 `.zip` 各做一个同 inode 的 `.cbz` 硬链接、N和S 56 份逐个点名，两版重新交替各三趟。
  改革之獸、棋魂 `--envelope`、量具开销、`.rar` 形态那几组第一趟就有效。

### 二、旧代码怎么在本机建起来

`git -C <tree> archive be1018f | tar -x -C .tmp/old-be1018f/`，再 `cargo build --release --features profiling`（1m 17s）。
**一处修补**：解出来的 `Cargo.toml` 末尾补一个空 `[workspace]` 表——它解在主树底下，不加会被主树的 workspace 认领、cargo 拒建。
代码一字未动；二进制在棋魂上写出 34 529 748 字节，与 `p2-loose-ends/11` 落地记录记的 34 529 786 只差 38 字节（tEXt 里的版本串）——
是那一批的同一版。

**`be1018f` 读不了 `.rar`**（`.rar` 支持是 `d0f8aa4`，在它之后），而改革之獸在本机只有 `.rar`。本机没有 unrar，
用 `vendor/unrar-ng` 写了个 30 行的 `unrar-tool`（`Archive::new(rar).open_for_processing()?.extract_all(dir)`，
`Cargo.toml` 里 `unrar-ng = { path = "<tree>/vendor/unrar-ng", default-features = false }` 加空 `[workspace]`）
摊成目录卷（页数与字节在《第三批：同一台机器上两版代码，翻默认之后快了多少》的素材那一格，与第二批那一行的「入 634 MB」对上）。两版喂同一份目录。

#### Q34 — A 类那两张体积表没有跟着新默认重跑，重跑的只有「哪一档更优」那一组

- **From:** 票 `06`
- **Kind:** 票面没想到的第三种情形
- **Where:** `docs/measurements.md`《A 类位深实测》的逐档体积表与「整卷入出比」那一句
- **Why it did not block:** 票面点名要重跑的是那四个「哪一档更优」的页数，那一组用 `--dry-run`
  就量得出来。体积表要**落盘**跑五卷（4.4 GB 源、几百 MB 输出），而它们摄于页几何批之前那一套
  几何（fit-inside、不裁边、不拆分）——换成今天的默认，页尺寸与页数都变，那是重做一次测量，
  不是订正一句话。
- **What this ticket actually did:** 五卷各跑两趟 `--dry-run`（旧几何一趟、今天的默认一趟），
  **boox-poke6**，逐页比 4bit 不抖与 2bit+FS 的判据读数，两列一并写进那一节。
  旧几何那一列**逐卷复现了** `metric-ordering/01` 给的 177/230、156/185、3/413、40/129——
  原文缺的那句「在哪块面板上数的」因此也补出来了。体积表没有重跑，改为在节首标出施测条件，
  并点明重跑过的只有末尾那一组。顺带量到一件写进了那一节的事：今天的默认下画集 Venus 的
  卷级基准档从 2bit+FS 变成 **4bit 不抖**，换它的是**裁边**——隔离验过，单开裁边就够
  （`--fit inside`，拆分开关无所谓），而裁边关掉、只换适配方式仍判 2bit+FS。
- **Whose call:** 拍板的人（要不要在今天的默认下把 A 类的体积表整批重跑）
- **处置：** 了结于 `two-pass-rework/16`——两张表连同整卷入出比按今天的默认整批重跑，施测条件四格齐全，数在《A 类位深实测》第一批。
