# 11 — `Report` 补上计时

**What to build:** 调用方能从 `Report` 拿到每卷与整体的耗时，不必自己在外面掐表。

粒度按会话层的消费方式定：**每卷一个墙钟耗时进 `VolumeReport`，整体一个进 `Report`，就这两个。**

不做分阶段（解码/缩放/判据/编码）：满核并行下「解码耗时」是墙钟还是 CPU 时间说不清，聚合出来的数会骗人，而插桩点全在热路径上。它是调优的量具，不是报告的内容——13 号票要更细的粒度，走事件流（ADR 0011：进度是事件流，开工前先预扫）或 feature-gated 插桩。

不做逐页增量计时事件：进度的 ETA 由消费方按「已走步数 / 总步数」自己算，库再报一遍时间是单一出处违规。

**跳过的卷也要有耗时。** 幂等命中要读遍全部成员才能判断，那不是零成本，报告里得看得见。

**Blocked by:** None — can start immediately.

**同文件争用**：`p1-session/01`（报告渲染搬出 CLI 主文件）也动 `Report`。两者逻辑上无关，
物理上要串——先 `p1-session/01`，本票接在它后面改动最小。

**Status:** resolved

- [x] `VolumeReport` 带该卷的墙钟耗时，`Report` 带整体墙钟耗时
- [x] 幂等跳过的卷也报耗时，不报零
- [x] 计时进结构，但**不默认进渲染出的文字**——印不印由调用方决定
- [x] 黄金快照不因计时而 flaky
- [x] 不引入分阶段计时，不引入逐页计时事件——**卷级粒度比票面多一级**，理由见《落地记录》

## 落地记录

计时进了 `Report` 与 `VolumeReport` 两处，**一个字都没有进渲染出的文字**。
`src/render.rs` 一个计时字段都不读，命令行输出与本票之前逐字节相同，黄金快照未重录。

### 粒度：为什么比票面多一级

票面定的是「每卷一个墙钟耗时进 `VolumeReport`，整体一个进 `Report`，就这两个」。
落地时**所有者当场改口**：字段要够 13 号票用来定位瓶颈，分到哪一级由落地方按 13 号票的需要判断。
于是卷级那一个拆成了 `VolumeTiming`：

| 字段 | 罩住什么 |
|---|---|
| `fingerprint` | 幂等这一道：算出本卷指纹，再与上一趟写在输出里的比 |
| `first_pass` | 第一遍：解码、彩页识别、几何、缩放、算判据、进缓存 |
| `second_pass` | 第二遍：建容器、量化、编码、写页、搬透传、收尾改名 |
| `elapsed` | 这一卷的总耗时。三段之外那一截由 `outside_the_segments()` 给出 |

`Report::elapsed` 是整趟一个数。

**这不是票面禁掉的那个「分阶段」。** 票面把它括号定义成「解码/缩放/判据/编码」，
拒它的理由是那几步在满核并行里交错、墙钟与 CPU 时间说不清、插桩点全在热路径上——
三条对本票落地的这三段一条都不成立：段是 `process_volume` 里首尾相接、互不重叠的墙钟，
**一个卷总共只掐三次表**，热路径上零插桩。分界线也不是新画的，就是 `CONTEXT.md`
《进度》里**步**已经用着的那一条。词汇表里补了「段」与「卷级计时」两条。

**对 13 号票只解了一半，不要多说。** 13 号第一条验收是「指明前三大开销」，
而前三大按它自己的估算全挤在第一遍那一格里。这批字段答得了「第一遍 / 第二遍 / 幂等谁更贵」
与「一处优化动的是哪一半」，答不了「前三大是谁」——那仍要走事件流或 feature-gated 插桩。
13 号正文里「都不要把分阶段计时塞进 `Report`」那句现在与实现对不上了，
不由本票顺手改（改一张 `ready-for-agent` 票的正文是改它的范围），记进《非阻塞问题》。

### 段界踩过一次坑

第一版只把 `volume_fingerprint` 罩进 `fingerprint` 段，`can_skip` 落在段外。
那是错的：`can_skip` 要开输出容器、逐成员读回记录，是真 I/O，而
`CONTEXT.md`《管线》给幂等这一道的定义本来就是**算指纹加拿它去比**两半。
段外那一截于是吞掉了跳过一卷开销的后半段，正好是本票「跳过的卷也要有耗时」要看见的东西。
自检查出来后改成两半同在一段里。

`--no-metadata` 下整道不在，那一段是 `Duration::ZERO`——不是一个「什么都没做」的很小的数。
掐表因此在 `if request.metadata` 之内，不在之外。

### 三段不求和

三段之和**小于** `elapsed`：打开卷、枚举成员、查重、汇总、定去处都在段外。
差额由 `VolumeTiming::outside_the_segments()` 给出，饱和减法。名字不叫 `elsewhere`——
那个词在 `src/lib.rs` 里已经指着「卷的另一个去处」。

`Report::elapsed` 同理装得下各卷 `elapsed` 而不等于它们的和：开工前那几道检查与
逐卷的介质探测都在卷外。

### 测试

新开 `tests/timing.rs`（4 条）。**一个具体的秒数都不主张**——那是机器快慢，
钉住它就是把红绿交给当时的负载。断言的是结构：走过的段有数、没走过的段是零、
`三段 + 段外 == elapsed`（这条等式是**段重叠的哨兵**：真有两段叠在一起，`outside_the_segments`
被饱和成零，等式当场不成立）、整趟装得下各卷。

`src/render.rs` 补一条 `the_rendered_text_says_nothing_about_how_long_it_took`：
同一份报告把每个计时字段改成一小时，四段逐段画出来逐字节相同。
写成「两份画出来一样」而不是「文字里找不到某个数」——后者只挡得住恰好那个写法。

`src/report.rs` 补一条单元用例钉 `outside_the_segments()` 的饱和：段重叠时答零、不恐慌。
`Duration` 的减法下溢会恐慌，报告里一处掐表出岔子不该让整趟炸掉。
