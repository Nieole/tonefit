# 05 — 归档成员名的现实形态

**What to build:** 别的工具打出来的 CBZ 也能正常处理，而不是整卷进隔离或被拒。

两种常见形态现在都会出事：

- **Mac 打的包**带一个 `__MACOSX/` 兄弟目录，里面的 AppleDouble 边车文件扩展名也是图片扩展名。它们被当成页、解不出图、成为失败页，整卷因此进隔离目录还被插了白页；包装层也因为「这一层有兄弟」而一层都剥不掉。
- **老式 Windows 打包工具**把成员名写成反斜杠分隔。现在它触发的是为路径穿越准备的那条拒绝，整卷被拒，错误信息读起来像安全拦截。同一份归档在非 Windows 平台上行为还不一样。

**Blocked by:** None — can start immediately.

**Status:** resolved

- [x] `__MACOSX/` 下的成员与 AppleDouble 边车文件被忽略，不当页也不当透传文件
- [x] 同类系统垃圾文件一并忽略
- [x] 忽略这些之后包装层能正常剥掉
- [x] 反斜杠分隔的成员名被归一，不再触发路径拒绝
- [x] 真正的路径穿越与盘符仍被拒，错误信息与「分隔符不规范」分开表述
- [x] Mac 打包与反斜杠打包各有一条端到端用例，断言不进隔离目录

## 落地记录

两件事都收在**源枚举成员的那一刻**：`open_archive` 与 `open_directory` 各自在
「算出相对路径」与「记下这个成员」之间加了一道门。往下的每一层——分页与透传、包装层剥离、
阅读顺序、读取预算、判定、写出——看到的都是已经筛过的那张成员表，一处都不必知道垃圾存在。

### 垃圾成员既不当页也不当透传文件

`is_junk` 两条规则：路径里**任何一级**命中 `JUNK_DIRECTORIES` 就整棵子树不要
（`__MACOSX`、`.Spotlight-V100`、`.Trashes`、`.TemporaryItems`、`.fseventsd`、`@eaDir`）；
文件名命中 `JUNK_FILES`（`.DS_Store`、`Thumbs.db`、`desktop.ini`）或以 `._` 开头
（AppleDouble）就这一个不要。一律大小写不敏感——这些名字来处的文件系统本就不分大小写。

「不当页也不当透传文件」是一句话两件事：边车的扩展名照抄本体，当页解必然解不出图，
按 12 号票整卷进隔离目录还被插上白页；当透传文件搬过去，则是把打包环境的产物带进成品。

**目录卷与归档卷共用这一条**，尽管票面两个形态说的都是归档。`CONTEXT.md` 说两者在源之下同形，
而同一份卷解开到磁盘上再处理换一个答案说不通——拷到 exFAT 上的漫画目录里就躺着 `._001.png`，
它在目录卷这一侧同样会变成失败页。`CONTEXT.md` 的《成员》一条因此补了一句：
边车与索引文件两样都不算成员。

### 剥包装层要排在筛垃圾之后

`__MACOSX/` 与 `.DS_Store` 都是包装层的**兄弟**。剥的判据是「这一层有没有兄弟」，
留着它们，`volume-a/` 那一层一层都剥不掉，输出于是多一级。顺序因此是载重的，
`strip_wrapper_directory` 的文档里点了名。

### 分隔符归一，拒绝只说「指着卷外」

`relative_path` 现在按 `/` 与 `\` 两种分隔符切。归一之前，反斜杠名撞的是为路径穿越准备的
那条拒绝，整卷被拒、错误信息读起来像安全拦截；而在非 Windows 平台上它连拒都不拒——
`Path::new("ch1\001.png")` 在那里是一个**普通文件名**，反斜杠被当成名字里的一个字符。
同一份归档两个平台两种结果，这是本票要消掉的第二样东西。

代价写在文档里：文件名里真带一个反斜杠的成员会被劈成两级。那种名字在 Windows 上根本建不出来，
而反斜杠分隔的包是眼下就在流通的东西。

拒绝这一侧拆成两句，都只说「这个名字指着卷外」，与分隔符写法无关：

| 名字 | 拒绝理由 |
|---|---|
| `..` 一级 | `片段 .. 指着上一级，会走出卷外` |
| 盘符（`C:`、`C:001.png`） | `片段 C: 是一个盘符，会走出卷外` |

盘符自己认而不交给 `Path`：`C:` 在 Windows 上是路径前缀、在别的平台上是一个普通名字，
交给 `Path` 就等于让平台决定这份归档收不收——正是票面点的那条平台差异。

### 六条用例，五组变异各转红

新增六条（`tests/container.rs`），全套 `cargo test` 266 条全绿：

| 变异 | 转红 |
|---|---|
| 归档枚举不筛垃圾 | 2 条——Mac 打包那条、边车挨着页那条 |
| 目录枚举不筛垃圾 | 1 条——目录卷那条 |
| 分隔符只认 `/` | 2 条——反斜杠打包那条、反斜杠写的穿越那条 |
| 去掉盘符那条拒绝 | 1 条——盘符那条 |
| 去掉 AppleDouble 前缀规则 | 2 条——边车挨着页那条、目录卷那条 |

Mac 打包那条一条钉三件事：不进隔离目录、边车不混进页数与输出成员、包装层剥得掉。

夹具改了一处：`Volume::file` 现在跟着 `Volume::page` 一起建父目录，
名字带目录的非图片文件才写得出来（目录卷那条要往 `__MACOSX/` 里放一份边车）。

### 两处够不着的边

**`relative_path` 里那条「不是一个普通的路径分量」的兜底现在够不着了。**
分隔符已经归一，`.`、`..`、盘符都在它上面拦掉，而 `Path` 的其余几种分量（根、UNC、设备名）
无一不带分隔符。留着它是因为「片段最终必须是一个普通分量」这条不变量要写在它成立的地方，
而不是靠上面那三条各自的正确性去推——代码里已按此注明。

**`JUNK_DIRECTORIES` 里的 `__MACOSX` 这一项没有被单独钉住。**
真实的 macOS 归档在 `__MACOSX/` 下放的全是 `._` 开头的边车，去掉这一项，
那些成员照旧被 AppleDouble 那条规则筛掉，Mac 打包那条用例不会转红。
钉住「整棵子树都不要」这个机制的是 `@eaDir/001.png@SynoResource`（边车挨着页那条），
它不以 `._` 开头，只有目录那条规则拦得住。两条规则因此都是活的，
只是这一项的名字本身没有专属用例——造一个不以 `._` 开头的 `__MACOSX` 成员要凭空编一种
现实里不存在的包，那种夹具钉住的是夹具自己。
