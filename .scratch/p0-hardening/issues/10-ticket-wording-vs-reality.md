# 10 — 三处票面措辞与实现对不上

**What to build:** 已交付票据上的三条标准，字面与实现不符，需要各自收口。

- 骨架票的「输出 8bit 灰度 PNG」已被位深判定票与 ADR 0004：输出以 PNG 为默认，AVIF 为显式可选 顶掉。默认输出既不是 8bit 也不一定是灰度颜色类型，而该票列了退场项却独漏这一条。
- 幂等票的「输出被移动或改名后幂等判定仍然成立」实际做不到：定位上一趟输出靠源卷名算出的路径，输出目录改名后整卷重做还白留一份重名副本。挂在这条名下的用例断言的是元数据不丢，不是还找得到。
- 标定票的「图内含判读说明，脱离文档也能用」——说明只有英文，而这是一个全中文界面的工具。
- P0 spec 与判据票里 dry-run 的承诺写作「一个文件都不落盘」。ADR 0012：试算与执行之间续做
  把它重述为「不写输出」——单卷试算保留参照时，越过预算的页仍建溢写临时文件，运行结束即收走。
  行为本身没问题，输出目录确实一个文件都没有；是字面不准。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 骨架票那条改写或标注退场，与位深判定票的口径一致
- [ ] 幂等票那条二选一：改写成「记录随文件走」并另记已知限制，或真做到按记录反查
- [ ] 标定票那条二选一：改成「含英文说明」并留后续项，或图内补中文说明
- [ ] dry-run 的承诺在 spec 与票面统一为「不写输出」，与 ADR 0012 同口径
- [ ] 每处的用例与被勾选的标准对得上
