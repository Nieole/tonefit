# 01 — 标定图一并回答「阅读器有没有原样贴像素」

**Status:** resolved

**Blocked by:** `p0-hardening/12 — 标定图的落盘移进库`

落盘还在 CLI 里的时候，这张图改完只有命令行用得上；会话层要一键写出它（`p1-session/13`）
得先有个库侧的写入口。先移，再改内容。

## 要做到的

`calibrate` 出的图拷进设备、打开一次，同时回答两件事：

1. **最右那条阶梯还分得开几级** → 回填 `--gray-levels`（现状，ADR 0003）
2. **抖动块与同均值实心块分不分得开** → 这台设备加这个阅读器，像素是不是原样贴上的

两件事有先后：**缩放没关掉时数灰阶本身就不准**——阶梯被重采样过，数出来的不是面板能显示的
级数。现在这个先后关系不存在，两张图各在一处，其中一张还不在产物里。

实测依据见 measurements 的《真机像素完整性》：同一台 Poke6、同一张图，阅读器开着「适应页面」
缩放时抖动块糊成一片、1 像素周期光栅无纹理；改成不缩放后与系统自带阅读器近乎相同。
**抖动这条分支成不成立全看这一件事**，而 tonefit 探不到它（ADR 0007 的备选方案：
看不到阅读器的显示管线）。用户没有别的办法知道自己该关哪个开关。

## 验收

- [x] 图内含抖动块与同均值实心块的并置，取若干个灰度档
- [x] **两块的均值严格相等**——不相等的话，重采样过也仍然分得开，判读会给出假的「通过」
- [x] 图内含 1 像素周期光栅（棋盘／竖／横／斜），它比抖动块更早暴露非 1.0 的缩放
- [x] 四角压在第 0 行列与末行列上的直角标记，用来发现边距与裁切
- [x] 判读顺序印在图内：先看像素完整性，不通过就别数灰阶——阶梯被重采样过，数出来的
      不是面板能显示的级数
- [x] **判读说明含中文**。这是一个全中文界面的工具，而「脱离文档也能用」对只有英文的说明
      并不成立（`p0-core-pipeline/14` 的那条标准因此现在写作「含**英文**判读说明」，
      中文那一份指到本票）。代价要认：中文字模按 16×16 算，一句话就是几十个字形，
      现有的 5×7 大写 ASCII 点阵撑不住——这笔投入摊在本票这次重画上才划算
- [x] 图仍恒等于面板分辨率，仍不经位深判定，仍无损写出、不带自描述元数据
- [x] `-h` 的短帮助说得出这张图现在回答两件事
- [x] 一条用例钉住均值相等；一条钉住四角标记落在第 0 行列与末行列上；
      一条钉住中文说明真的画进了图里

## 落地记录

图重画了一遍，自上而下六段，尺寸仍恒等于面板分辨率：

| 段 | 内容 |
|---|---|
| 抬头 | 型号、分辨率、PPI、灰阶数 |
| 先后 | 以原尺寸打开；先做一，一不过就别做二；阶梯被重采样过，数出的不是面板能显示的级数 |
| 英文 | 同一套做法的英文五行，三样检查各点一次（14 号票的「脱离文档也能用」） |
| 一 像素完整性 | 说明三行，紧接**四对**抖动/实心方块，再接**四种** 1 像素周期光栅 |
| 二 感知可分辨级数 | 说明四行，紧接并排的各候选位深阶梯（原样保留，每一级仍标着自己的号） |
| 四角 | 四个直角标记，压在第 0 行列与末行列上，最后画，谁都盖不住 |

四角标记之外，方块与阶梯的黑边一律**画在外沿**（`Canvas::outline`），一个格子都不动块里的像素。
阶梯那一圈原来是压在栏内的，跟着改了：256 级那一条上一级只有两三行高，压一圈边就等于少两级。

### 均值严格相等：靠构造，不靠事后凑

抖动块每 15 格里恰好 `level` 格纸白，其余是墨黑。**255 = 15 × 17**，所以一行的均值恰好是
`17 × level`——整数，且正好落在 16 级面板的格点上；实心块填的就是那个数。
块宽取 15 的整数倍，每一行都走完整数个周期，整块的均值于是与逐行的均值同一个数。
四对取 `level = 3、6、9、12`，均值 51、102、153、204，摊在整个灰度区间上。

散布用 `(4x + P[y mod 15]) mod 15 < level`：步长 4 与 15 互素，因此**任何** level 都恰好取到
`level` 格；`P` 是 0..15 的一个排列，各行的相位互不相同，图案才不塌成竖条纹或斜纹。

两条用例分头钉：

- `a_dithered_patch_and_its_solid_twin_have_exactly_the_same_mean`——从**解回来的 PNG** 上
  逐台设备比两块的**和**（像素数相同，和相等即均值相等，整数比得起「严格」二字），
  并顺带钉住抖动那一半真有墨黑与纸白两种取值。
- `each_period_of_the_dither_holds_exactly_its_level_of_paper`——钉推理的前提：255 除得尽 15、
  `P` 是排列、**每一档**（不只图上取的那四档）每 15 格恰好 `level` 格。
  最后这一条堵的是步长：取 3 时图上那四档照样恰好，而第 1 档会塌成周期 5 的规则条纹。

### 中文字模：不手写，摘 GNU Unifont

票面认的代价是「一句话就是几十个字形」。实测 190 个：ASCII 全集 95 个（半宽 8×16）
加汉字与全角逗号 95 个（全宽 16×16）。手写画不出也验不了，因此不手写——
`src/calibrate/glyphs.hex` 是从 GNU Unifont 16.0.01 摘出来的子集，格式保持上游 `.hex` 原样，
一格都没有改过；来源与许可（SIL OFL 1.1）写在文件头上。5×7 那份手写点阵表随之撤掉：
一张图上两套字模，混排时字距与行高对不齐。

「真的画进了图里」由 `the_chinese_instructions_are_painted_on_the_chart` 钉：逐台设备把每一行
含汉字的说明按版式给的落点与字号重印一遍，与图上那一块**逐像素**比。它与
`every_character_the_chart_can_print_has_a_glyph` 是一对，各堵一半——前者管「印上去了、
没被裁掉也没被盖住」，后者管「字模不缺」（两边走同一个 `Canvas::text`，缺字时都画空框）。

### 光栅：斜线取周期 3

棋盘、竖线、横线三种是 1 像素周期。斜线取周期 3：**周期 2 的斜线就是棋盘**，
与头一块重复；取 3 才既是 1 像素宽的线、又不与棋盘同形。用例除了逐块问「该变的方向变没变」，
还钉住四块**互不相同**——只问方向的话，斜线与棋盘答得一模一样。
